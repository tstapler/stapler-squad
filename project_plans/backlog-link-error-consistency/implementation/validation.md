# Validation Plan: backlog-link-error-consistency

**Date**: 2026-08-16

## Happy Path Scenario

Given a backlog item that exists and has a committed `ItemSession` link row for the calling session's UUID with the correct role, when the session calls any of `report_progress`, `request_review`, `submit_review_verdict`, `report_pr_created`, or `submit_triage_result` (or `get_backlog_item`) for that item, then the call succeeds exactly as it does today (`success: true`, no error object) — this fix touches only the two failure branches, not the success branch.

### Structural "5th call site" guard (adversarial-review.md Concern 2)

**Decision: add as a lightweight assertion, not leave purely manual.** The reviewer's own framing — "cheap insurance the research already flagged" — holds: a `grep`-based guard in Go test form costs one small test function and catches a class of miss (a 6th mutating tool added later, or one of the 5 stories silently skipped) that the table-driven test in Epic 2.1 does *not* structurally catch, since that table only proves correctness for entries a human remembered to add to it. A manual verification step is exactly the kind of check that erodes with each future edit to this file; a compiled Go test does not.

| Requirement | Test File | Test Name | Type | Scenario |
|---|---|---|---|---|
| Structural guard against "fixed 4 of 5" / future 6th-tool regression (adversarial-review.md Concern 2, pitfalls.md §3) | `tools_backlog_test.go` | `TestBacklogHandlers_should_HaveNoRemainingRawLinkCheck_When_SourceIsScanned` | Unit (source-scan, not runtime behavior) | Reads `tools_backlog.go`'s own source text (`os.ReadFile` on the file relative to the test, resolved via `runtime.Caller` or a package-relative path — matching how this file is already colocated with the source it tests) and asserts it does **not** contain the string `errors.Is(linkErr, session.ErrNotFound)` immediately followed by an unconditional `ErrPermissionDenied` — i.e., asserts the raw pre-fix pattern is gone. Implementation note for the implementer: a precise regex is fragile against reformatting; the simplest robust check is asserting the source contains exactly one definition of `resolveItemLink` (the new symbol) and zero occurrences of the literal string `"this session is not linked to the specified backlog item"` outside of `resolveItemLink` itself (that string is the old inline message every raw call site used, per Tasks 1.2.1a–1.2.5a's "Replace" blocks) — a substring-count assertion is far less brittle than parsing the `errors.Is(...)` + branch shape. |
