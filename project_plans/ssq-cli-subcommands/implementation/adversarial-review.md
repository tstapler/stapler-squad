# Adversarial Review: ssq-cli-subcommands

**Date**: 2026-10-18
**Verdict**: BLOCKED

## Blockers

- [ ] **`--wait` exits zero on session-creation failure** — The polling termination condition "exit when `status != SESSION_STATUS_CREATING`" also exits on `SESSION_STATUS_FAILED` (12), `SESSION_STATUS_PERMANENTLY_FAILED` (11), and `SESSION_STATUS_CRASHED` (10). Per the proto, `SESSION_STATUS_FAILED` is explicitly the state a session reaches when "Session's async creation pipeline (Background Resolution Pipeline) failed before the session ever reached ACTIVE." A CI job running `ssq create-session --wait` against a repo whose clone/worktree setup fails will receive exit code 0 and proceed as if the session is ready. Fix: replace the exit condition with a terminal-state table — exit 0 on `SESSION_STATUS_ACTIVE`; exit 1 on `FAILED`, `PERMANENTLY_FAILED`, `CRASHED`; continue polling on all other states.

## Concerns

- [ ] **`http.DefaultClient` has no timeout — polling loop can hang indefinitely** — All commands construct `NewSessionServiceClient(http.DefaultClient, ...)`. `http.DefaultClient` has `Timeout: 0` (no timeout). In the `--wait` polling loop, a server that accepts the TCP connection but never writes a response header will block `GetSession` until the OS closes the connection — potentially minutes. Fix: create a per-command `http.Client{Timeout: 15s}` (or expose `--request-timeout` flag) rather than using the package-level default.

- [ ] **`steer --help` documents incorrect semantics** — The plan says to document "steering only takes effect when the session is in autonomous mode." This is factually wrong per the current server implementation. `session_service_update.go:336` and test `TestUpdateSession_SteerMessage_NonAutonomousSession_SendsViaSendKeys` confirm that `steer_message` works on non-autonomous sessions by falling back to `Instance.SendKeys` (the same PTY primitive as the MCP `steer_session` tool). Writing "only meaningful when autonomous_mode is true" in `--help` will cause users to give up on steering ordinary backlog/review sessions when it would actually work. Fix: document the actual behavior: "For autonomous sessions, steering is injected via the orchestrator. For non-autonomous sessions, the message is sent as keystrokes directly to the terminal."

- [ ] **No test stories** — Four new commands (`create_session.go`, `list_sessions.go`, `steer.go`, `get_diff.go`) and the shared `client.go` have zero planned tests. The CLAUDE.md requires `make ci` to pass before pushing; `make ci` runs `make test`, which will find no new coverage for any of these files. The `ResolveServerURL` priority logic (flag > env > default) and the `--wait` terminal-state table are both correctness-critical and easy to unit test without a real server (a ConnectRPC test handler suffices). Fix: add a Story 5 for `cmd/commands/*_test.go` covering `ResolveServerURL` and at minimum table-driven happy/error paths for each command using an in-process test server.

- [ ] **`get-session` JSON format may change silently if Story 2.1 adopts `MarshalProtoJSON`** — The current `get-session` uses `json.MarshalIndent(resp.Msg.Session, "", "  ")` (`encoding/json`), which serializes proto enum fields as integers and ignores `protojson` options. The refactor in Story 2.1 adds `MarshalProtoJSON` as the shared helper in `client.go`. If the implementer naturally reaches for the new helper when rewriting `NewGetSessionCmd()`, proto enums change from integers to their string names (e.g. `1` → `"SESSION_STATUS_ACTIVE"`). Any script already parsing `ssq get-session` output against integer enum values will silently break. The plan does not mention this format change. Fix: Story 2.1 must explicitly state whether `get-session`'s JSON format is preserved or migrated, and if migrated, document it as a breaking change with a migration note.

- [ ] **`get-diff` default output is ambiguous: "no changes" vs error** — The plan specifies "empty stdout if no changes." An empty diff and a silent failure (e.g. the server returned an empty `DiffStats` due to an internal error) are indistinguishable to a pipeline reading stdout. `diff | patch` workflows would silently apply nothing instead of surfacing the error. Fix: on empty diff print `# no changes` (or similar) to stderr (not stdout), or use a distinct exit code for "no changes" vs "error."

## Minors

- **`--wait-timeout` default 60s may be too short for large repos** — Session creation involves a git worktree setup (which includes a branch checkout or clone depending on session type). On a large monorepo `git worktree add` can exceed 60s. The timeout cuts off a legitimately in-progress creation without surfacing that the session is still being created. Consider 300s or making the default configurable via an env var alongside `SSQ_SERVER`.

- **`FormatConnectError` covers only `CodeUnavailable`** — The plan says it gives an "actionable" message for `CodeUnavailable` (server not running). `CodeNotFound` (session ID not found), `CodeInvalidArgument` (e.g. `steer_message` over `MaxSteerMessageLength`), and `CodeFailedPrecondition` (SendKeys failed) are all common in normal use and currently get the raw connect error string. These are the error codes users will actually hit when they mistype a session ID or exceed the steer limit.

- **`get-diff` stats-to-stderr-on-TTY is not in any AC** — No acceptance criterion requests a summary line ("+N -M lines") written to stderr when stdout is a TTY. This is mild scope drift that adds a TTY-detection call with no stated requirement. If it's kept, it should be called out explicitly in AC-4 so it's testable.

- **`list-sessions --status all` requires an explicit nil proto field** — The plan maps `--status all` to "omit status filter." In Go, `ListSessionsRequest.Status` is `*sessionv1.SessionStatus` (optional). The implementer must leave it `nil` (not zero-value `SESSION_STATUS_UNSPECIFIED`) for "all" to work correctly. Zero-valued `SessionStatus` is `SESSION_STATUS_UNSPECIFIED`, which the server may or may not treat the same as absent. This is a one-line mistake (`req.Status = sessionv1.SessionStatus_SESSION_STATUS_UNSPECIFIED.Enum()` instead of leaving it nil) that would silently filter out everything. Worth a comment in the code.
