## 1. Harnesses stapler-squad supports

VERIFIED: built-in detectors are `agy`, `aider`, `claude`, `gemini`, `opencode`, `pi` (`session/detection/binaries/{agy,aider,claude,gemini,opencode,pi}.go`; `"antigravity"` aliases to `agy` at `session/detection/detector_snapshot.go:153`). The requirements' "Codex" mention should be treated as a survey item only; Codex docs are included below for reference.

`ssq-hooks` (`cmd/ssq-hooks/main.go`) is the cross-harness bridge: subcommands `check|serve|proxy|install|export-rules|version` (`:38-48`); install targets `claude, gemini, agy/antigravity, open-code, pi` (`:815-827`). All feed `PermissionRequestPayload` (`pkg/classifier`) to `/api/hooks/permission-request`.

### Degrade ladder (INFERRED design implication, matches requirements "Feasibility Risks")
1. Claude + hook-mediated answer (if spike passes): `PreToolUse` HTTP/command hook returns `allow`+`updatedInput.answers`. Deterministic, no keystrokes.
2. Any harness: terminal-text detection (`session/detection`) + tmux keystroke reply (the ADR-010 "one digit, one write" path).
3. Dead/stopped session: durable `GuidanceRequest` record only; answer delivered on next start/resume.

## 3. Repo precedents that constrain the design

- **ADR-010** (`project_plans/notification-tray-and-hidden-session-gate/decisions/ADR-010-audited-reply-to-pending-question.md`): `ReplyToPendingQuestion{session_id, question_id, reply_text, reply_id}`; reply = single ASCII digit; typed `ReplyOutcome` enum (not Connect errors); never reuse `SubmitContentWithEnter` blindly because `SubmitDriverContent` can write a second Enter on no pane change (`session/pane_submit.go:95-161`, per ADR). Hidden sessions only; visible -> `NOT_HIDDEN`. Status Proposed, "implemented 2026-10-10" per its header (verify state of code before building on it).
- **AskUserQuestion is not a durable entity today**: `broadcastQuestionNotification` (`server/services/approval_handler.go:759-776` per ADR-010) publishes INPUT_REQUIRED with nil metadata; hook defers to native dialog.
- **GuidanceRequest** (VERIFIED `proto/session/v1/guidance_request.proto:44-60`): fields id, scope (`backlog-item|session|standalone`), item_id, session_uuid, question_text, question_type (`yes-no|multiple-choice|short-answer`), options[], answer, created/notified/answered/cancelled timestamps, derived status. RPCs: Create/Answer/Get/List/ListAllPending (`:18-31`). `question_type`+`options` already fit AskUserQuestion's single-select; **gaps**: multiSelect, multiple questions per call (1-4), `header`, option `description`, asker/answerer identity (Open Q3), tool_use_id/correlation to the live hook call. Ent schema: `session/ent/schema/guidance_request.go`.
- **Wake substrate**: `wait_for_backlog_event` MCP tool (`server/mcp/tools_backlog.go`, `tools_backlog_dependencies.go`); in-process eventbus ADR `project_plans/backlog-event-subscribe/decisions/ADR-001-in-process-eventbus-subscribe.md`. Ent has `trigger_fire_event.go`, `workflow.go`, `webhook_*` schemas - check for reuse before adding a wake table (not read in depth).
- **Rules**: `noarchivedrevival` (wake path must check `IsArchived()`), `instance-lock-free-reads` (use `Snapshot()`), `norawghrequest`.

## 5. Recommended spikes (to close UNVERIFIED items before ADR sign-off)

1. Interactive Claude TUI: does `PreToolUse` on `AskUserQuestion` returning `allow`+`updatedInput.answers` skip the dialog? (Decides ladder step 1.) Capture a real `tool_input` payload at the same time.
2. Claude `Channels`: can ssq act as a channel MCP server to push re-prompts/wake events into a live session without keystrokes? Requirements (flags, enterprise gating, research-preview stability).
3. OpenCode: confirm whether a `question`/permission reply can be sent via plugin `client` or server API; confirm sending a prompt to an idle session.
4. Gemini/agy: confirm no native question tool; otherwise keystroke-only.
5. pi extension API: can the extension return an answer to a pending prompt?
