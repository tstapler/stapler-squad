# Validation Plan: up-next-tabs-pr-nudge

**Date**: 2026-10-05 (re-synced after plan Repair log items 14-25, then 26-33 from the first triad review, then 34-47 from triad round 2: access guard, list freeze, manual tab activation, account states, label-in-name, estimates, story splits)

## Happy Path Scenario
Given a fresh browser (empty localStorage, no query params) on `/unfinished` with a connected GitHub account and an open non-draft PR `acme/api#42` whose CI is failing and which has two local sessions (`fix-ci` idle and most recently active, `review-bot` paused), when the user lands on the page and clicks "Ask fix-ci to fix" (accessible name "Ask fix-ci to fix CI on PR #42") once, then the PRs tab is already selected with the PR card visible without scrolling, both sessions are listed, the server (not the browser) builds the prompt from freshly fetched PR state, writes it exactly once to `fix-ci`, and the card shows "Fix request sent to fix-ci" with an Open session link and a disabled "Requested just now" button.
