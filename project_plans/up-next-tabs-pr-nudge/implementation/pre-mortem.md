# Pre-mortem: up-next-tabs-pr-nudge
**Date**: 2026-10-05

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | The shared readiness gate (`IsReadyForSteer`) returns false unless `IsControllerActive` (plan l.362). Many real sessions (autonomous, no controller/status source, post-restart) therefore always answer BUSY, and the one-click nudge works for few sessions, so the "one click to nudge" success metric is missed. | User clicks Nudge on most cards and gets "Session isn't being monitored" or "busy"; nudge usage stays near zero. | Add an early Phase 2 spike task: count how many real linked sessions pass `instanceReadyForSteer` against the live session list. If it is below about 70%, the plan must either widen the gate for the manual path (idle + pane-ownership check) or give the BUSY-no-controller outcome an in-card "Open session" action. Make the UI show the no-controller reason, not generic busy. | P1 |
| 2 | Changing `BranchKey`/`PRKey` to `host/owner/repo@branch` (Task 1.3.1a) silently stops linking existing sessions. `RepoRef` on sessions may have an empty host, an SSH remote, a `.git` suffix, a fork origin, or a different repo name than the PR base. `LinkedSessions`, `LocalWorktreePath` and the existing "Open Session" link all go empty, and `SESSION_NOT_LINKED` blocks every nudge. | PR cards that used to show "Open Session" now show "+ Session" for branches with live sessions. | Before changing the key, add a characterization test built from real-shaped `annotateUserPRCache` output (https and ssh remotes, `.git` suffix, empty host, GHE, fork). Log a count of sessions with a branch but no match. Task 6.1.1d must verify that sessions linked before the change still link after it. Keep the old key as a fallback index until the new key is verified. | P1 |
| 3 | The widened viewer-poll query fails as a whole. An older GHE host rejects the unknown field (`reviewThreads`, `contexts`) with a GraphQL validation error, so there is no partial result. Separately, the combined node count (50 PRs x contexts 25 x threads 50) can exceed GitHub's node limit regardless of `rateLimit.cost`. The AC fixture only models "key missing", not an `errors` response. | The PRs tab shows an error or "Connecting..." for every PR on the GHE host, and the existing PR list regresses. | Add to Task 1.2.1b/c: on a validation or node-limit error, retry once with the legacy query, set `DetailsLoaded=false`, and cache the capability per host. Add an AC with a fixture whose response is `{"errors":[...]}` and no data. Task 1.2.1a must also record the node-limit estimate. | P1 |
| 4 | The post-mount tab resolution makes the first render "prs" and then switches to Stuck on `?item=`. `StuckItemsSection`'s focus/scroll effect runs after mount, but the Stuck panel was unmounted on first render, and `setTab` also deletes `item`. The deep link fails to expand or scroll the item, and a back or forward navigation can fight localStorage. | Notification or backlog deep links land on the PRs tab, or on Stuck without expanding the item. | Compute the tab synchronously from `searchParams` on the first render (only the localStorage read is post-mount), so `?item=`/`?tab=` never flash "prs". Add a test where the Stuck panel receives `focusItemId` on its first mount. Add a test for browser back/forward between tabs. | P2 |
| 5 | The scope exceeds the 1-2 week appetite: new proto, two Go ports, a guard, a rewrite of the auto-steer call path, a PR key refactor, a tab shell, and a seam extraction. The change to `steerActiveSessionForPRFix` and the `SessionSteerer` fakes regresses `pr-fix-steering`, or the work stalls half done. | The pr-fix-steer backlog tests fail or the PR sits unmerged for weeks. | Split delivery into two PRs: (A) tabs, persistence and the PR card data (Phases 1.1-1.3, 3, 4.1, 4.2); (B) nudge RPC, guard and auto-steer integration (Phase 2, 4.3). Make the auto-steer guard integration its own task with a pinned regression test of existing `steerActiveSessionForPRFix` behavior before it is edited. | P2 |
