# Validation Plan: session-retry-backoff

**Date**: 2026-08-29

## Happy Path Scenario
Given a session running with a configured retry policy (`enabled=true, max_attempts=3, backoff=exponential`), when the session's agent process crashes three times in a row, then each crash schedules a backed-off restart in the same worktree with a "Previous attempt failed due to {reason}" continuation prompt, the session card shows "Attempt N/3" after the first retry, and after the third failure the session transitions to `permanently_failed` with exactly one notification fired. *(Anchors AC1, AC3, AC4, AC5 — all other tests below are variations: gating conditions (AC2), regression preservation for the unconfigured case (AC7), and the manual override path (AC6).)*

## Test Stack
- **Unit**: Go stdlib testing + testify (this repo's convention — see `golang-testing` skill)
- **Integration**: Go stdlib testing, exercising real `Instance`/driver/config plumbing (no ent DB involved for this feature — persistence is JSON-file-backed per the plan's Migration Plan, not a new datastore)
- **Frontend unit/component**: Jest + React Testing Library (`web-app/`, pnpm-managed)
- **E2E / UX**: Playwright (`tests/e2e/`, per `.claude/rules/e2e-test-conventions.md` — `@feature` header, no `waitForTimeout`, `data-testid`/ARIA locators only)

## Coverage Targets and How to Measure

| Stack | Coverage command | Target |
|---|---|---|
| Go | `go test ./... -coverprofile=coverage.out && go tool cover -func=coverage.out` | ≥80% line, run via `make test` |
| TypeScript/Jest | `cd web-app && npx jest --coverage --coverageThreshold='{"global":{"lines":80}}'` | ≥80% line |

- All public methods touched by this feature (`RetryNow`, `evaluateSessionRetry`, `backoffDelay`, `classifyFailureReason`, `resolveRetryPolicy`, `markSessionPermanentlyFailed`, `RetrySession` RPC handler): happy path + error path covered per the table above.
- The two concurrency-sensitive paths (`retryInFlight` CAS race, restart-grace exemption) each have a dedicated integration test — these are exactly the two mechanisms `research/pitfalls.md` and adversarial-review.md identified as the highest-risk spots in this plan.
- All 16 UX acceptance criteria from `design/ux.md` have a corresponding automated or manual test above; 6 of the 16 are manual because they require true race conditions (criterion 5), destructive filesystem state (criterion 6), or are code/visual audits not meaningfully automatable (criteria 8, 13, 15, 16 partially covered by CI).
- **Migration test**: N/A. Per plan.md's Migration Plan, this feature has no schema/data migration — proto changes are additive-only (new field numbers, new enum value) and `config.json` gains one new optional key handled by the existing nil-means-unset defaulting idiom (covered by `TestLoadConfigFromPath_should_ResolveAC7Defaults_When_RetryPolicyKeyMissing` above, which is the closest analog to a migration test: verifying an old on-disk artifact still loads correctly).
