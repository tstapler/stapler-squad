# Fix Browser Passthrough — Stack Research

## Technology Stack (no new dependencies)

This fix is purely in the React/TypeScript frontend. No new packages or build changes are
required.

| Layer | Technology | Notes |
|---|---|---|
| Proto / types | `@bufbuild/protobuf` + generated TS | `CDPStatus` / `CDPState` already generated by `make build`; import from `@/gen/session/v1/types_pb` |
| Session state | WatchSessions ConnectRPC stream | `session.cdpState` already delivered on every session update event |
| React components | React 18 + TypeScript | `SessionDetailView.tsx`, `BrowserTab.tsx` |
| Testing | Jest + React Testing Library | Update existing fixtures; no new test infrastructure |
| Linting | ESLint + TypeScript strict | No new lint rules; fix must pass `make lint` (zero-warning gate) |

## CDPStatus Enum Values (proto)

```
CDP_STATUS_UNSPECIFIED = 0  → no CDP data yet (hide tab)
CDP_STATUS_WAITING     = 1  → polling for Chrome (show "Connecting..." placeholder)
CDP_STATUS_STREAMING   = 2  → connected + screencast active (show CDPViewer)
CDP_STATUS_NO_BROWSER  = 3  → port allocated, Chrome not launched yet (show "No browser" placeholder)
CDP_STATUS_UNAVAILABLE = 4  → Chrome not found or disabled (hide/disable tab)
```

## Equivalent VNCStatus → CDPStatus Mapping (for test migration)

| Old VNCStatus | New CDPStatus | Notes |
|---|---|---|
| `VNC_STATUS_UNSPECIFIED` | `CDP_STATUS_UNSPECIFIED` | Both are zero-value / not-initialized |
| `VNC_STATUS_STARTING` | `CDP_STATUS_WAITING` | Display allocation / Chrome poll in progress |
| `VNC_STATUS_NO_BROWSER` | `CDP_STATUS_NO_BROWSER` | Port ready, Chrome not yet connected |
| `VNC_STATUS_READY` (+ `browserWindowDetected=true`) | `CDP_STATUS_STREAMING` | Actively streaming |
| `VNC_STATUS_UNAVAILABLE` | `CDP_STATUS_UNAVAILABLE` | Deps missing or feature disabled |
