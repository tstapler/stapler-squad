## Blockers
- [ ] **Queue vs. layer diff base is self-contradictory and can corrupt the prompt on replay (Stories 3.1.3 / 3.1.4)** — 3.1.4 resets `sent` to empty when the sink returns `queued`, so a later rewrite `"hel"` -> `"help"` queues `"help"` with no DELs; replay yields `"helhelp"`. Meanwhile 3.1.3 allows `\x7f` in the queue, and overflow drops oldest-first, which can drop the text half of a DEL+text atomic edit and replay orphan DELs that erase pre-disconnect prompt text. Decide one model: either queue whole `AtomicEdit`s and keep `sent` (drop/discard whole edits only, never split), or queue only final committed text and never DELs. Add AC for "autocorrect during disconnect" and "overflow with DELs".
- [ ] **Queue replays `\r` into an unknown screen state (Story 3.1.3)** — `\r` is queueable, so Enter typed offline is replayed up to 30 s later, possibly into a Claude Code permission/confirm prompt where Enter approves, or a shell after the screen changed. Strip `\r` (and everything after it) from queued input, or require an explicit user tap on a "Send queued (N chars)" chip instead of auto-flush. ADR-004 owner approval does not cover this specific hazard.
- [ ] **Diagnostics "no content" contradicts `reportToTrace` (Story 4.1.1)** — the redacted report keeps only `dataClass`+`len` (AC: `hello` absent), yet `reportToTrace` must emit a `ReplayTrace` that validates against `fixtureSchema` and replays, and `MobileInputEvent` needs `data`, `value`, `selStart/selEnd` for the reducer to run. A replayable device fixture cannot be built from a content-free report, so Story 5.1.4's "device 1/1" AC is unachievable as written. Also unresolved: a committed device fixture carries whatever the owner typed (possibly a secret). Define a separate explicit "record for fixture" mode (typed-in-a-scratch-field only, content shown for review, with a pre-commit scrub step) and keep the default report content-free.
- [ ] **Platform gating: layer attaches on every "touch" device, including iOS Safari and touch laptops (Story 1.2.1/1.2.2/1.3.2)** — `isTouchDevice()` is `pointer: coarse` OR `maxTouchPoints>0`; there is no Android/Chromium gate. Requirements say iOS must not regress, and desktop must be unchanged. A Windows/Chromebook touchscreen with a hardware keyboard would get the layer plus a forced xterm swap (`resolveRenderer` isTouch) off ghostty, and iPad/iPhone Safari get an untested IME path. Gate on a platform predicate (Android Chrome, or require both coarse primary pointer and no fine pointer via `any-pointer`) and add test cases for iPadOS+keyboard and touch-laptop; flag-off/other-platform must be provably zero-listener.

## Concerns
- [ ] Secrets typed at echo-off prompts (sudo, ssh, tokens) go through a textarea with autocorrect/suggestions deliberately left ON, so Gboard can show them in the suggestion strip and learn them into the personal dictionary; the layer cannot know echo state. Document the risk, and consider setting `autocomplete="off"`, `autocorrect`/`spellcheck` off for a "secure input" toggle or when the pane cursor-hidden/echo heuristics fire. The diagnostics ring buffer with "Reveal text" also holds content in memory; state it is cleared on close and excluded from `cm.*`, console, and `onAnomaly` payloads, and add a test that `console.error` anomaly output never includes `data`.
- [ ] Glossary/AC mismatch: the reducer is driven by `tick` (Story 1.1.2 watchdog) but `MobileInputEvent.kind` has no `tick`; also `Anomaly`/`EnterDeferred` outputs vs `Rewriting is not a state` is fine, but `tick` needs to be in the sum type or the exhaustive switch fails.
- [ ] Story 1.1.2 Enter AC is inconsistent: with `Composing{sent:"ls"}` the "ls" was already emitted, so "total bytes are `\r`" is wrong unless it means bytes after the Enter; also what happens to the ordering when `compositionend` arrives before `insertLineBreak`, and when Enter arrives with region unsent (deferred mode)? State exact expected byte strings including both orders.
- [ ] Sticky modifiers during a live composition are unspecified: Ctrl armed + first IME char of a multi-char composition is consumed on the first `beforeinput`, then later rewrite DELs/text run unmodified; Alt+ESC prefix on a rewrite. Add ACs (modifier applies only to single-grapheme non-composing commits; armed modifier with `insertCompositionText` is ignored and cleared).
- [ ] Multi-line `insertText` -> `a\rb` with `paste:true` is emitted raw when bracketed paste is unavailable (Unresolved Q6 is only listed as blocking 4.2.1b, but 1.1.3 and `insertFromPaste` depend on it too). Pasting multi-line text into Claude Code as raw `\r` submits each line. Make the DECSET 2004 spike (0.1.1) block 1.1.3 and the executor's paste handling.
- [ ] Double-send protection has only a unit-level AC for one case (Enter). For Ghostty the container's own `beforeinput` handler and its internal textarea remain live; require a test asserting that, with the layer attached, neither renderer's own `onData` fires for the same keystroke (e.g., hardware keyboard on a phone, focus bouncing between layer textarea and renderer textarea after `terminal.focus()` calls elsewhere such as in `useTerminalGestures`).
- [ ] Story 1.4.2 (mount `GhosttyTerminal` in jsdom) is probably infeasible: ghostty-web needs WASM + canvas. Provide the mock strategy or move that coverage to the Playwright spec; otherwise the AC cannot be verified. Likewise Story 1.2.1's "className contains the vanilla-extract hash" depends on how jest handles `.css.ts` (check the jest config) and Story 5.1.1's CDP-IME path is only a hypothesis until spike 0.1.2 (the e2e AC should state a fallback when `imeSetComposition` does not produce `insertCompositionText`).
- [ ] Session-switch/replay safety: the queue lives in a per-terminal hook keyed by `sessionId`, but the AC only covers reconnect to S1 vs S2. Add: terminal pool reuse for another session, tab/refresh (queue must not persist to localStorage), session paused/restarted behind the same id (pane state differs), and TTL expiry while a composition is still live (does `sent` reset?).
- [ ] Scope drift versus requirements: the compose bar (4.2), the `fallbackDetector`, long-press/query-param diagnostics sheet, EditContext source (6.1) and five follow-up issues are not in requirements' In Scope (only "optional client beacon" and a test corpus). Keep the sheet minimal (needed for device corpus), and justify or defer compose bar and EditContext explicitly.
- [ ] Requirements say the flag is "default on for touch devices once verified, off elsewhere initially"; the plan ships default ON on merge for all touch devices before owner acceptance (5.1.4 occurs after deploy). Either default OFF until acceptance or record the deviation as an owner decision.
- [ ] Flag-off regression: with `mobile_input_layer` off on touch, `resolveRenderer` silently flips ghostty users to xterm. That is intended, but the reducer-less xterm path is still the known-flaky one; the 3.1.1 "flag off keeps the exact old warn" AC should also assert `sendInput` return type change (void -> `SendResult`) does not alter existing callers/tests, and `ensureConnected`'s warn is shared by resize/other dispatchers.
- [ ] Story 5.1.1 AC "chip visible within 250 ms of expect polling" is not a measurable assertion in Playwright (polling is not a clock); assert presence with a default expect timeout and leave the 250 ms to the fake-timer unit test.
- [ ] Observability: requirements name `input_dropped_disconnected_total` and `ime_event_sequence_unrecognized_total`; the plan's `cm.input{event=dropped_disconnected}` / `cm.ime_anomaly{kind}` mapping is not stated, and 4.2.1's AC references `ime_event_sequence_unrecognized` which is not in the `ImeAnomaly` enum. Reconcile names. The 2.1.2 enumeration test that greps for `SendInput(` callers is brittle; prefer an allow-list keyed on the `inputReadLoopParams.onInput` wiring.
- [ ] Dependency graph gap: Phase 3.1.4 changes the `onData` signature in `attachMobileInput.ts`/`composition.ts` after Phase 1 is "done" and after 1.4.2's integration test; plan the `SendResult` return type in 1.2.2 up front to avoid reworking tests twice. Story 1.4.1 depends on 0.1.1 (helper-textarea behavior) and 0.1.3 on a manual instance, but 0.1.3's owner step is a human blocker listed as "not on the critical path" while 5.1.2 wording depends on it.

### Walkthroughs

**Seq 1: partial delivery, then drop.** `"he"` -> seq1 `sent` (baseAfter `"he"`); `"l"` -> seq2 `dropped`; link up; region `"help"`. Rule: base = baseAfter(last delivered) = `"he"`, edit `{0,"lp"}`, model `"help"`. No DEL, no duplicate. Variant: region autocorrects to `"world"` -> `{backspaces:2, insert:"world"}`, DELs delete only the `"he"` this layer delivered. Correct. Variant: whole-queue discard after `"he"` flushed -> same via `deliveredThroughSeq:1`. Correct. Spec gap (CONCERN C2): the plan says a drop "ends the live composition as deferred" (commit on `compositionend`, nothing emitted until then) but the AC expects `"lp"` to be emitted "when the region becomes help". Pick one: either emit the delta on the next region change (live resumes from the rebased base) or hold until `compositionend`; the fixtures must assert which.

**Seq 2: reconnect with a live keystroke before queue flush.** PR-A (no queue): trivially in order, `sendInput` is synchronous. PR-B: queue `["l"]` (seq2, base kept `"hel"`), reconnect, flush starts, user types `"p"` -> `queued` behind (strict FIFO), sink order `l`,`p`. A second flap mid-flush: flushed `l` is in the ledger, `p` discarded with `deliveredThroughSeq:2`; no DELs. Correct. Chunked path check: in PR-A `sendInput` still chunks > 512 bytes (Task 3.1.1b, which removes chunking for atomic edits, is PR-B); `MAX_REGION` 64 graphemes plus DELs stays under 512 bytes except emoji-heavy cases (64 x 4-byte graphemes + 64 DEL = 320, fits), so atomic edits are safe in PR-A, but state that bound in 1.2.4a. TTL variant (CONCERN C1): `"hel"` queued at t=0, `"p"` queued at t=29, reconnect at t=31: whole queue discarded (notice says discarded), then the layer rebases and, per 3.1.4, "emits the safe reconciliation", i.e. re-sends `"lp"` after telling the user it was discarded, and committed words in the discarded prefix are permanently lost while the tail of the live region reaches the prompt (`"lp"` without `"he"`... or appended garbage). Not destructive (plain text, no DELs) but contradictory UX; decide: after a discard, abandon the live region (emit nothing for it) rather than reconcile.

**Seq 3: session switch mid-composition.** S1 prompt, composition `"hel"` live, `Composing{region:"hel", sent:"hel"}` in the reducer, ledger holds seq1-3. The pool reuses the terminal for S2 (or `sessionId` prop changes). Nothing in PR-A resets the layer: 1.4.1 only disposes on hidden/undocked, ADR-004 and 3.1.3 discard the QUEUE on session switch (PR-B, and the queue is empty in PR-A anyway), and `DeliveryReport`-driven abandon needs a report that no one sends. Next `compositionupdate` `"hel"` -> `"yo"` emits `\x7f\x7f\x7f` + `"yo"` through `onDataRef` -> `sendInput`, which now targets S2. That is three DELs into a different session's prompt (S2 text the user never typed here), exactly the destructive outcome Story 1.2.4 claims is impossible. -> **B5.**

### New blocker

- [ ] **B5: the layer's reducer state and ledger are never invalidated on a session or transport boundary, so DELs/text can reach the wrong session or erase prompt text after an undetected loss (Story 1.2.4, Task 1.2.4c, 1.4.1a; PR-A).**
  (a) Session switch / pool reuse / `sessionId` change while `Composing` or with an unconfirmed ledger: add an `invalidate(reason)` on the controller (state -> `Idle`/`AbandonedRegion`, clear ledger, reset textarea), called by `useMobileInput` on `sessionId` change and on the session `session_generation` change, with a jsdom test: composition live, `sessionId` changes, next `compositionupdate` emits zero bytes.
  (b) `sent` is not `delivered`. `sendInput` returns `sent` after `pushMessage` returns (`useTerminalFlowControl.ts:~250`); a half-open mobile socket (or a close that lands one frame later) loses that frame silently, the ledger counts it as delivered, and the next autocorrect emits `backspaces` computed from a base longer than what is on screen, deleting pre-region prompt text (`"$ he"` on screen, base `"hel"`, region `"yo"` -> 3 DELs eat `"he"` and the space). Fix: treat any `isConnected` true->false transition (and any reconnect) as a ledger boundary: units sent in the current region before the transition are unconfirmed, so the in-flight region is abandoned (zero DELs) at reconnect. Add a replay case `sent-then-close-then-autocorrect.json` asserting the model line never shrinks below the pre-region text. Also specify that a thrown `pushMessage` (caught by `handleError`) returns `dropped`, and that a paste larger than 512 bytes aborted mid-chunk on disconnect returns `dropped`/reports a short `deliveredThroughSeq`.
  The claim "PR-A never emits orphan DELs after a reconnect" (plan header, ADR-004) is not true until (a) and (b) are specified.

### Walkthroughs (against the written rules)

**W1: session switch mid-composition.** `Composing{region:"hel",sent:"hel"}` for S1; `sessionId` prop changes (or pool reuse) -> 1.4.1a calls `invalidate('session'|'pool_reuse')` -> state `Idle`, `AbandonedRegion`, ledger and base cleared, textarea reset. The next composition starts from an empty base, so it cannot DEL. No DELs for pre-boundary text. PASS.

**W2: sent, socket closed, autocorrect.** "hel" sent (ledger B="hel"); `isConnected` true->false -> `invalidate('transport')`: epoch bump, region deferred. Autocorrect to "yo" emits nothing live; at `compositionend` "yo" does not start with B, so zero bytes plus `unrecognized_sequence`; model line never shrinks below "$ " (fixture `sent-then-close-then-autocorrect.json`). Detection-late variant: frames are lost as a suffix of an ordered stream, so a DEL that was sent after a lost text frame is lost too; nothing erases earlier prompt text. Residual (stated in the plan header): a text frame lost exactly at the flip leaves a truncated word, insert-only. PASS.

**W3: chunked paste aborted midway, then a keystroke.** A paste is not a composition region, so no later rewrite can reference its text. The abort comes with `isConnected` false (or a `sessionId` change), which fires `invalidate('transport')` or `invalidate('session')`. The keystroke while down is `dropped` (no DEL); after reconnect it opens a new composition in a new epoch with an empty base and emits only its own text. No DEL for pre-boundary text. PASS, but see C-A: the plan's stated mechanism for the abort result is not what the code can do.

### Concerns (non-blocking)

- **C-A (spec vs code, Task 1.2.4a/AC "Honest sent")**: the plan says a mid-chunk-aborted paste makes `sendInput` return `dropped` with a short `deliveredThroughSeq`. In the code (`useTerminalFlowControl.ts:~262-300`) a > 512-byte input returns synchronously and the remaining chunks run later in a `CHUNK_DELAY_MS` loop (`sendChunk`), so the abort (disconnect, session change, thrown push) happens after the return value is gone. The AC test as worded cannot pass without an async report path. Fix: either add a callback (`onUnitAborted(seq)` -> `invalidate('transport')`) in 1.2.4a, or reword to say the abort is covered solely by the `isConnected`/`sessionId` invalidate triggers and the paste is simply absent from `deliveredThroughSeq`. Safety does not depend on it (W3), only AC testability. Related: the "atomic edits fit under 512 bytes" bound assumes ASCII-ish graphemes; `MAX_REGION=64` ZWJ emoji can exceed 512 bytes and be chunked asynchronously in PR-A (ATOMIC_EDIT_MAX_BYTES bypass is PR-B, Task 3.1.1b). Either cap `MAX_REGION` by bytes too (switch the region to deferred above 512 bytes) in 1.2.4a, or document it.
- **C-B (undefined trigger)**: `session_generation` appears in 1.2.4 and Task 1.4.1a but no client or proto field by that name exists (grep of `web-app/src` and `proto/` finds none; the only nearby thing is the connect-generation ref at `useTerminalStream.ts:232`, which is a reconnect and already covered by the `isConnected` trigger). Name the real source (e.g. that ref, or the session's restart/pause event) or drop the trigger so Task 1.4.1a's "one test per trigger" is implementable. A session paused/restarted behind the same id with the socket staying up is the only case that depends on it.
- **C-C (invalidate during live IME)**: `invalidate` resets the textarea value, which ADR-006 forbids while a composition is live. Add an AC that after a mid-composition reset a Gboard-style trailing `compositionend`, orphaned `input` (Degraded path, Story 1.1.2) and Backspace `beforeinput` while `AbandonedRegion` emit nothing from the stale region (a user Backspace in `Idle` still emits one `\x7f`, which is intended). Cheap to cover with one fixture variant of `session-switch-mid-composition.json`.
