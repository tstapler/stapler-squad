# Pre-mortem: mobile-input-layer
**Date**: 2026-11-08

Scenario: a month after PR-A merged with `mobile_input_layer` ON by default, the owner's phone still cannot type, or typing corrupts a prompt, or the deploy broke desktop. Sources are `implementation/plan.md` and `requirements.md`. Claims marked INFERRED are not verified against code or a device.

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | The layer merges ON with only synthetic traces (`device 0/0`). The owner's Gboard emits a sequence the reducer mishandles (e.g. suggestion-strip pick wrapped in `deleteContentBackward` plus `insertText`, or swipe word as `insertReplacementText`), so words arrive doubled, truncated or with extra DELs. The ledger bounds DELs to the current epoch, not to what the terminal app actually holds. | Owner types "the quick" and the prompt shows "thethe qui" or loses the previous word. No server signal separates this from correct typing, because `terminal_input_frames_total` counts frames, not correctness. | Make the owner's device run on the isolated manual instance (ports 62871/62872, reachable over Tailscale/LAN) a pre-merge gate, not a post-redeploy check. Pull the content-free ring buffer and "Copy report" (Story 4.1.1) and `?inputdebug=1` into PR-A, so a failing keyboard can be recorded the same day. Add a client anomaly rate metric to the diagnostic query. If the pre-merge run fails, merge with the server default OFF and use a per-scope override for the owner. | P1 |
| 2 | Rollback is too slow and per-origin. The kill switch needs two page loads. `ssq:flag:` lives in localStorage, which is per origin, so `:8543`, `:8444`, the Tailscale host and the LAN IP each need their own two loads. Flag off also lands the phone on xterm.js, which the requirements call weak on Gboard (#3600), so "rollback" may not restore typing either. | Owner flips the flag, reloads once, the layer is still attached, and the owner is still on a broken origin. Or flag off lands on xterm and typing is still wrong, with no known-good state. | Add an immediate client-side escape: a `?mobile_input=0` query param (and `=1`) that writes `ssq:flag:` and applies in the same load, plus a documented entry per origin. Record in the PR-A description, and in Story 5.1.4, the known-good fallback state (which renderer and flag combination typed correctly on this phone, from Story 0.1.3). Test that the preload honours the param before first mount. | P1 |
| 3 | The hidden textarea is reset to `""` at every commit boundary, and the plan assumes Gboard still emits `beforeinput deleteContentBackward` on it. On Android Chrome, Backspace on an empty field may emit only `keydown`/`keyup` (keyCode 8 or 229) with no `beforeinput`, or a 229 keydown the reducer ignores. Backspace after the first word would then do nothing. The same empty reset also removes Gboard's context for next-word suggestions and autocap. INFERRED, no spike covers it. | Backspace works mid-composition but is dead right after a space or a pick. Owner reports "can type but can't delete". | Add a Phase 0 spike (extend Story 0.1.2 and the owner checklist in 0.1.3) that records Backspace-on-empty on the device and in the CDP helper. Pick the design from the result: a sentinel character in the textarea (as xterm.js and CodeMirror do) or a keydown-8 fallback path. Add a corpus fixture `backspace-on-empty-after-commit` and a pass criterion in Story 5.1.4. | P1 |
| 4 | The soft keyboard does not open on tap. Focus on a 1px, opacity-0, `pointer-events:none` textarea needs a real user-activation path. `bindTapTarget` listens to `pointerup`, while the existing gesture code (`useTerminalGestures`) can `preventDefault` touches and fire `pointercancel` on scroll. Chrome may also scroll the page to a 1px element or refuse the keyboard. jsdom and Playwright's Pixel 7 emulation cannot show the real keyboard opening. | Tap shows no keyboard; owner can only use toolbar keys, the same symptom as the original bug. | Add a spike item to 0.1.2: verify on the physical phone that `focus()` from `pointerup` opens the keyboard, with the gesture handlers active. Fall back to a `touchend`/`click` bound path if not. Put the keyboard-opens check into the pre-merge device run from #1. In the e2e, assert the tap handler runs after a scroll gesture as well. | P1 |
| 5 | A ghostty-web upgrade changes behavior and the layer double-sends. The layer depends on 0.4.0 quirks (blanket `beforeinput` preventDefault, keyCode 229 early return). If a later release handles IME itself (PR #110 is already cited), ghostty's own textarea or handler emits bytes in parallel with the layer. The plan's no-double-send test uses a fake renderer, and real ghostty is covered only by the e2e. | Each letter appears twice on the Android class after a dependency bump; desktop is fine. | Add a jest test that reads the installed `ghostty-web` version and fails with an instruction to re-run the Story 0.1.1 greps on any version other than the verified one. Make the double-send e2e (ghostty variant) a required CI check on any `web-app/package.json` or lockfile change. Cite conditions by text (already planned) and keep the Dependabot/renovate group for ghostty-web labelled. | P2 |
| 6 | Remote listener (`:8444`) and non-secure origins differ from the tested path. `navigator.userAgentData` exists only in secure contexts; a plain-HTTP LAN origin falls back to the UA regex, which the plan covers, but the private-CA HTTPS origin, a PWA/standalone window and the Tailscale path were never exercised. The e2e runs only against the isolated local server. Input via the remote listener may also take a different WebSocket/mux path with different `listener` labels, so the diagnostic query (`listener="remote"`) may show zero for a healthy path. | Diagnostic shows client `emitted` > 0 and server `received` == 0 even though typing works, or typing works on LAN and not on `:8444`. | Add the owner device run (from #1) against both `:62872` (remote) and the LAN/Tailscale URL, and state which origins were tested in `spike-findings.md`. Add a server test that the mux and remote-listener paths record `listener="remote"`. Add `shouldAttachMobileInput` cases for a missing `userAgentData` and for an installed-PWA display mode. | P2 |
| 7 | `make install-service` redeploy interplay. The restart drops every WebSocket (tmux sessions survive), so `isConnected` flips mid-typing and `invalidate('transport')` fires, which drops pending autocorrect tails. A phone with a cached PWA/service-worker bundle can keep the old build, so the owner's acceptance check tests the old code (or the ON default is not yet served to it). Server restarts also re-read the flag from the workspace config, which could pin an explicit value. | Owner reports "no change" after redeploy, or the first words typed right after a restart vanish. | Show the build id in the diagnostics header and the docs (verify before testing). Add a "hard reload / confirm bundle hash" step to Story 5.1.4 and the how-to. Redeploy only when no phone is mid-composition; the how-to should say that a restart is a transport boundary. Check `~/.stapler-squad/workspaces/*/config.json` for an explicit `mobile_input_layer` before the redeploy. | P2 |
| 8 | CI gates reject or churn PR-A. 19 near-identical JSON fixtures plus many new tests push the jscpd ratchet (0.14%, noted margin about 0.10%) over; the plan assumes JSON is not scanned, which is unverified. New Go work in the large `connectrpc_websocket.go` touches the `:1653`/`:2489` closures, so gocognit/funlen/dupl apply to those modified existing functions (a known gotcha in this repo). Zero-warning web lint catches `react-hooks/exhaustive-deps` in `useMobileInput` and `no-restricted-imports` on `next/*`. The registry check, `config_surface_proof_test.go` and BUG-087 ("gate" in test filenames) are also live. | `make ready` red at the end of the critical path, after W10, forcing a late refactor. | Run `make ready` on a stub PR-A branch in wave 1, before any feature code, to learn the baseline. Check `web-app/.jscpd.json` `format`/`ignore` for `__fixtures__` and add the directory to ignore. Extract the `connectrpc_websocket.go` change to a new file and thread only a returned `bool` through the closures. Run `make registry-generate` and the config-surface test in the same task as the flag (1.3.1a). | P2 |
| 9 | The worktree cannot build or test. This worktree sits under `~/.cache/`, has no `node_modules/ghostty-web`, gitignored `gen/` and `session/ent/*`, and needs `make build` and `bun install` with `npm_config_user_agent` unset. Workers launched in parallel in one worktree sweep each other's hunks, and `/tmp` is a RAM tmpfs where Bazel or Playwright scratch can OOM the live service (both are recorded repo incidents). Long paths also break unix-socket tests. | Wave 1 spike workers cannot run grep or jest. Intermittent failures from half-generated code or an OOM-restarted service. | Add a Wave 0 task: `unset npm_config_user_agent && bun install` in `web-app/`, `make build`, a `go test` smoke on one package, and a jest smoke, recorded in `spike-findings.md`. Give each parallel worker its own worktree from the feature branch (as the memory notes say). Keep scratch on disk (below 1 GB) and check `free -g` first. Use a short `GOTMPDIR`. | P2 |
| 10 | The PR-A scope is too large to review or finish. PR-A holds about 50 tasks across reducer, ledger, adapter, two renderers, focus ownership, server metrics, telemetry, e2e and docs. The repo's own memory warns that repeated review-repair rounds in one subsystem mean overbuilding. The delivery-ledger and invalidate machinery is the most complex part of a change that must be correct on a flaky link. | Review rounds keep finding new ledger edge cases; the PR sits open while the phone stays broken. | Split PR-A into PR-A1 (layer, gate, flag, e2e: the minimum that makes the phone type) and PR-A2 (Phase 2 observability, which is already independent). Set a stop rule: after two review rounds producing new blockers in 1.2.4, simplify to "abandon on any boundary" (zero-tail) and drop the insert-only tail logic. | P2 |
| 11 | Hardware keyboard or Bluetooth keyboard on the Android phone, or Samsung DeX. `shouldAttachMobileInput` matches coarse pointer with no hover; a connected keyboard or mouse changes `(hover: hover)` only at load time, and keys typed on the hardware keyboard go to the layer textarea as `keydown` with real key codes. A path where the renderer and layer both handle them was only asserted with a fake handle. | Doubled characters or dead keys when a hardware keyboard is attached to the phone or tablet. | Add a hardware-keyboard fixture (real keyCodes, `isComposing:false`) to the corpus and an e2e case using Playwright keyboard on the Pixel 7 profile. State the DeX and tablet behavior in the docs. | P3 |
| 12 | Secret entry at echo-off prompts with default ON. The suggestion strip and Gboard learning can capture a `sudo` or token typed into the layer textarea (ADR-008 accepts this, but only for opted-in use; default ON makes it every phone session). | The owner sees a token suggested in a later text field. | Keep `autocomplete="off"` and also set `autocorrect="off"` plus `spellcheck="false"` unconditionally if the spike shows suggestions still work for typing quality; if not, keep the limitation but surface it in the first-run PR-A description (already planned) and add a `?` entry in the toolbar docs. Re-evaluate once the device corpus exists. | P3 |
| 13 | Ctrl-W (`\x17`) is not honored by Claude Code's input box, so `deleteWordBackward` (Gboard long-press Backspace) does nothing or deletes the wrong text. Listed as unresolved, to be answered in Story 0.1.3. | Long-press Backspace deletes nothing, or only one character at a time. | Make the Story 0.1.3 result a hard input to Task 1.1.2a. If `\x17` fails, map `deleteWordBackward` to repeated `\x7f` bounded by the word length from the textarea value. | P3 |
