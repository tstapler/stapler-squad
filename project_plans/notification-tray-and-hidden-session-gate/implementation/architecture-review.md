## Blockers

### NB7 The UI-stream primitive list of check (d) omits the real pane-write helpers `sendInputToTmux` and `sendInputToTmuxWithRetry`, so "no exemption list; `./server` has no internal caller" is false (Story 5.1d check (d), Story 5.1 site `connectrpc_websocket.go:3337`, T-RO-10, T-RO-44)
Violation: Check (d) applies R1/R2 to every `./server` function that calls `WriteToPTY`, `SendInputViaControlMode`, `ResizePTY*`, `SetWindowSize*`, `RequestResize` or `ForwardScroll`, and the plan states "There is no exemption list: `./server` has no internal caller of these primitives". The real tree has a second, direct write path in `./server`: `sendInputToTmux` (`connectrpc_websocket.go:3532`, a `safeexec` `tmux send-keys -H` subprocess), its retry wrapper `sendInputToTmuxWithRetry` (`:3576`), and `resizeExternalCapturePaneSession` (`:3395`, `resize-window`/`resize-pane` subprocesses). Callers: `connectrpc_websocket.go:1414,2150` and `connectrpc_websocket_shell.go:304` (fallbacks inside functions that also call a listed primitive, so R1/R2 reach them by luck) and `handleCapturePaneInput` (`:3350-3361`, which calls **only** `sendInputToTmuxWithRetry`). `handleCapturePaneInput` is the input handler of one of the four Story 5.1 sites and calls no member of check (d)'s set, so R1/R2 and the pinned-caller table never see it. Today it is protected only by the per-site test (T-RO per-site, Task 5.1a); a new capture-pane-style handler, or a refactor that splits the fallback out of an existing function, regresses silently. T-RO-44 (the "real tree passes") would pass with the hole. This is the "blind spot (1)" the plan accepts as hypothetical, but it already exists in the tree, which the "no exemption" sentence and the 17-file grep (it matches method calls, not these helpers) missed.
Remediation: (1) add `sendInputToTmux`, `sendInputToTmuxWithRetry` and `resizeExternalCapturePaneSession` (and the `runResize` closure's helper if it is split out) to check (d)'s UI-stream primitive set, so `handleCapturePaneInput` and `handleCapturePaneResize` need a `TerminalWriter` and must use it; (2) add one cheap literal lint that closes the whole exec class: a type-checked string-literal scan for `"send-keys"`, `"paste-buffer"`, `"load-buffer"`, `"resize-window"`, `"resize-pane"` in non-test files outside `session/tmux`, `session/tymux` and the named helper functions; (3) delete the sentence "`./server` has no internal caller of these primitives" and have Task 5.1d-0 report the real list of `./server` pane-write helpers it finds; (4) T-RO-44 gains a fixture that adds a handler calling only `sendInputToTmuxWithRetry` and asserts check (d) fails.

### NB8 The proof-header hook is fail-closed: a missing headers file stops the approval hook from sending anything, for every session (Story 5.6 hook bullets (a), (b), Task 5.6n, T-RP-73)
Violation: The injected command becomes `curl ... -H @<worktree>/.claude/ssq-hook-headers ...` for both curl builders (`hook_injector.go:380` `buildHookCommand`, `approval_handler.go:1001` `InjectHookConfig`). VERIFIED by running curl 8.22.0 here: `curl -s --max-time 2 -H @/nonexistent -X POST http://127.0.0.1:9/x -d x` prints "option -H: error encountered when reading a file" and **exits 26 without opening a connection**; `-K /nonexistent` behaves the same; the form `curl $( [ -r "$F" ] && printf -- '-H @%s' "$F" ) ...` proceeds (exit 7, connection refused). The headers file is an untracked file in the session worktree's `.claude/` directory: it disappears under `git clean -fd`/`-fdx` (an agent or an operator running it in the worktree), under `RemoveHooksConfig` if that deletes only the file (the plan does not say it removes the file or keeps entry and file in step), on a worktree recreate, or in the window of a non-atomic rewrite at injection. When that happens the permission-request hook of **any** session, visible ones included, never reaches `/api/hooks/permission-request`: no toast, no approval card, no driver auto-answer input, no Reply registration, and the pane waits at Claude's own dialog with the server unaware. The existing command has no such dependency, so this is a new single point of failure for the approval pipeline introduced to serve a hidden-session feature that sits last in Epic 5. The "curl older than 7.55 injects no proof header" fallback covers only an old curl, not a missing file.
Remediation: keep the hook fail-open. Build the command with a shell conditional that adds `-H@<quoted path>` only when the file is readable (the tested form above), so a missing or unreadable file degrades to `no_proof` and the request is still sent; write the file atomically (tmp file created `0600` with `O_EXCL`, `fsync`, rename); have `RemoveHooksConfig` remove entry and file together; add tests: T-RP-73 gains "file deleted after injection: the hook command still POSTs and the server reads `no_proof`" (run the real command string against an `httptest` server, with the file present, absent, unreadable and a path containing a space and a single quote), and the injector unit test asserts the command contains the `[ -r` guard.

## Judgement of the simplified guard design (question 2)
**Adequate for a single-operator tool, provided NB7 is closed.** The read-only guarantee decomposes into (i) streams, protected by a capability (`TerminalWriter`) that the params structs hold, so a handler without a capability cannot compile into a write; (ii) unary RPCs, protected by `AccessForUnary`, the descriptor classification (b) and the pinned callers; (iii) automated writers, protected by the `*HeldLease` parameter that every lease primitive takes. Each check is implementable with `go/packages` + `go/types` (C49 lists the details): (a) is one `ast`/`types.Info` walk, (b) is descriptor reflection, (c) is a call-graph-free "who calls these named methods" listing, (d) is a parameter-and-use check; none needs a handler set or a class partition, which is what produced NB1, NB3 and NB6. The real-tree run I did (grep over the primitive set: 21 files outside the PTY layer, matching the table's ui/acquirer/receiver/lifecycle rows, plus `command_executor.go:299` below `SendCommandImmediate`) found exactly one real gap, NB7, which is also the stated residual risk (1) in the plan, now shown to be non-hypothetical.
The three stated residuals are acceptable once NB7's literal lint exists: (1) a new helper without a capability is caught by the pinned-caller test only if it calls a primitive-set member, and by review otherwise; the added exec-literal lint covers the one class that is not a member (subprocess `tmux`); (2) a new `ProcessManager`/`TmuxManager` in the by-name exemption is a review item and cannot be reached from a handler without a primitive, which is in the table; (3) a nested lease acquire in code no chain test runs shows up as a spurious "busy", never as a double write, because the lease is exclusive and non-reentrant; the failure mode is availability, not safety. The typed `*HeldLease` plus `Try`-with-no-wait for Reply makes the interleave impossible by construction, which is the property that matters.
