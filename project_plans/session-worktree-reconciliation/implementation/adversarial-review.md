## Concerns

- [ ] **New: Task 1.2.2c's error-discrimination mechanism is copied from 1.2.2b but doesn't fit `git.CommitInfo`'s actual error type.** Task 1.2.2c says "Apply the same error-type discrimination as Task 1.2.2b" (i.e. `os.IsNotExist`), but `git.CommitInfo` (`session/git/ops.go:480-496`) resolves the commit via go-git's `repo.CommitObject`, whose not-found error is `plumbing.ErrObjectNotFound = errors.New("object not found")` (`go-git/go-git/v5@v5.19.2/plumbing/object.go:10`) — a plain sentinel, not an `fs.ErrNotExist`-compatible error, so `os.IsNotExist(err)` returns `false` for it. A literal reading of Task 1.2.2c would misclassify a genuine "commit not found" as transient and silently skip the finding — the opposite of Story 1.2.2's own AC (plan.md:212) that this exact case "returns one finding." Likely self-correcting in practice: Task 1.2.2d's test (a genuine object-not-found sha must produce a finding) would fail against a naive `os.IsNotExist`-only implementation and force the fix (`errors.Is(err, plumbing.ErrObjectNotFound)` or equivalent) — Task 1.2.2b's own "(or an equivalent check)" hedge already allows this. Recommendation: name `errors.Is(err, plumbing.ErrObjectNotFound)` explicitly in Task 1.2.2c's text so the correct mechanism isn't left to be discovered via a failing test at implementation time.
