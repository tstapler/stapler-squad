# Architecture Review: backlog-already-implemented
**Date**: 2026-07-14
**Verdict**: CONCERNS

## Constitution Check

`docs/adr/ADR-000-architecture-constitution.md` does not exist in this repository. No hard constitutional constraints apply — all findings below are lens-based (SOLID/Clean Architecture, type-driven design, GoF/PoEAA), not constitution violations.

## Blockers

None. Nothing in the plan introduces an illegal state, a layering violation, or an untestable-by-construction component severe enough to block Phase 5. The items below are real but are all cheap to fix now, before code exists, which is the point of catching them here.

## Concerns

- **Epic 2.2.2 / Epic 2.2.3 — `ReviewGateRunner.Run` and `TriggerReReview` grow further via inline branching, compounding an existing SRP violation.**
  `session/review_gate.go`'s `Run` method is already ~300 lines doing diff resolution, auto-repair, security scanning, snapshot merge, prompt building, the headless call, verdict parsing, AC-status writeback, session persistence, notification, and auto-reopen — all inline in one function. Task 2.2.2a proposes adding a `diff == ""` branch inside this same function that sets `codebaseWorkDir`, `AllowedTools`, `PermissionMode`, swaps the system prompt, and switches to `CallBlockingWithCostAndOptions`. That's readable in isolation but pushes an already-overloaded function further past the point where its 5+ responsibilities can be reasoned about together, and per Lens 1 point 4 it forces Task 2.2.2b's tests to exercise the full `Run` machinery (storage, pool getters, notifier) to test what is really a small decision: "which system prompt / CallOptions for this diff state." Same shape of problem in `TriggerReReview` (`server/services/backlog_service_triage.go:769-959`, already ~190 lines) for Epic 2.2.3.
  **Remediation**: extract the decision as a pure, independently-unit-testable function — e.g. `buildReviewCall(diff string, wt WorktreeData, item *BacklogItemData) (systemPrompt string, prompt string, opts headless.CallOptions)` in `session/backlog_review.go` — and have both `Run` and `TriggerReReview` call it, rather than each inlining the `diff == ""` branch separately. This also directly addresses the DRY concern below.

- **Epic 2.2.2 + Epic 2.2.3 — the empty-diff `CallOptions` construction (`AllowedTools: "Read,Grep,Glob"`, `PermissionMode: PermissionModeBypassPermissions`, `WorkDir` resolution) is duplicated at two call sites with no shared helper.**
  The plan's task list has Story 2.2.2 wire this in `review_gate.go` and Story 2.2.3 wire the *same* literals independently in `backlog_service_triage.go`. ADR-001 states the read-only tool grant is a hard invariant ("never `Bash` or any write-capable tool") — encoding that invariant as a string literal duplicated in two files means a future edit to one call site (e.g. someone "fixing" a permission-mode typo, or adding `Bash` to debug something) can silently diverge from the other, with nothing catching the mismatch.
  **Remediation**: same fix as above — a single constructor (e.g. `headless.ReadOnlyReviewOptions(workDir string) CallOptions` or bundled into the `buildReviewCall` helper) is the one place the "Read,Grep,Glob" / `bypassPermissions` pairing is written, and both call sites use it.

- **`CallOptions.AllowedTools string` / `PermissionMode string` — consistent with existing precedent, but the plan is a chance to close (not widen) a pre-existing primitive-obsession gap.**
  Verified in `session/instance.go:418-423`: `PermissionModeAuto`, `PermissionModeBypassPermissions`, etc. are untyped string constants (`PermissionModeBypassPermissions = "bypassPermissions"`), not a defined type (`type PermissionMode string`), and `InstanceOptions.PermissionMode`/`AllowedTools` are both raw `string` fields. So `CallOptions.AllowedTools string` / `PermissionMode string` (Story 2.1.1a) is *consistent* with how this codebase already does it — not a new violation. But per the type-driven-design lens, nothing stops `AllowedTools` from being set to `"Read,Grep,Glob,Bash"` at a review call site — the invariant ADR-001 cares about ("reviewer must never get write tools") is enforced only by code review discipline on a raw string, not by the compiler. Given the plan is already touching this exact surface, it's a low-cost moment to tighten it.
  **Remediation**: not a call to retype `PermissionMode` everywhere (out of scope, would touch `session/instance.go` broadly). Scoped fix: the shared constructor recommended above (`ReadOnlyReviewOptions`) is the *only* place `AllowedTools`/`PermissionMode` literals for the review path are written, so the invariant has exactly one point of failure instead of two, and a reviewer only needs to audit one function instead of grepping the codebase for every review call site.

- **API surface: `CallBlockingWithCostAndOptions` continues a combinatorial method-per-flag-combination pattern that Go idiom generally avoids.**
  Verified current `Pool` surface (`session/headless/caller.go`): `Call`, `CallWithOptions`, `CallBlocking`, `CallBlockingWithCost`, `CallBlockingWithOptions`, and now the plan adds `CallBlockingWithCostAndOptions` — 4 "blocking" variants distinguished only by whether cost is returned and whether `CallOptions` is accepted (a 2×2 matrix, with `Call`/`CallWithOptions` as the streaming pair already showing the same pattern one level up). Call-site count is small and all in-repo: `CallBlocking` × 4 (`session/headless/features.go`), `CallBlockingWithCost` × 1 (`session/review_gate.go`), `CallBlockingWithOptions` × 5 (`approval_handler.go`, `backlog_service_triage.go` ×2, `autonomous_driver.go`, `session_service.go`), `CallWithOptions` × 2. That's 12 call sites total — cheap enough to consolidate now, before a 5th variant becomes tempting later.
  **Remediation**: collapse to one blocking method taking `opts CallOptions` (zero value = today's `CallBlocking` behavior) and always returning cost (already parsed from the JSON result at zero extra cost when unused): `func (p *Pool) CallBlocking(ctx, key, systemPrompt, userPrompt string, opts CallOptions) (result string, costUSD float64, err error)`. All 4 existing blocking call sites become one-line updates (pass `CallOptions{}` where nothing is needed today, ignore the cost return with `_`), and the new empty-diff review call site is just another ordinary call — no `WithCostAndOptions` variant needed at all. This is a net simplification, not just a naming fix.

## Nitpicks

- **Plan sequencing**: Task 1.1.1b (Phase 1, Epic 1.1) explicitly notes it "depends on Story 2.1.1's `CallOptions` fields existing" (Phase 2). The dependency graph shows Epic 1.1 gating Epic 2.1/2.2 design, but 1.1.1b itself can't be *executed* until part of Phase 2 lands — the phase numbering implies an ordering that the task's own dependency note contradicts. Reorder 1.1.1b to run immediately after Story 2.1.1a, or renumber it into Phase 2, so the epic numbers don't overstate the intended execution order.
- **Log field naming**: Observability Plan says the completion log line gains `path=diff|codebase-read` — confirm this string is added consistently to *both* log lines flagged (`session/review_gate.go`'s "headless review complete" line and `backlog_service_triage.go`'s "headless re-review complete" line); the plan's Epic 2.5 stories already list both files, so this is just a reminder to keep the field name identical across both (`path=` not `mode=`/`source=`) since nothing enforces that at compile time.
- **`MergeLiveCriterionNotes` scope**: confirmed via `resolveACSnapshot` (server/services/backlog_service_triage.go:1078-1086) and `ReviewGateRunner.Run`'s snapshot deserialization (session/review_gate.go:237-240) that these are the only two snapshot-selection call sites in the reviewed code — the plan's Story 1.2.2/1.2.3 scope looks complete, no third call site was missed.
