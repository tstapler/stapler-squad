# Validation Plan: backlog-already-implemented

**Date**: 2026-07-14

## Happy Path Scenario
Given a backlog item whose acceptance criteria are already satisfied by existing code (Baseline: implementation agent finds nothing to change, diff is empty), when the implementation agent calls `request_review` with a `note`/`verification_notes` citing the exact file and function that already satisfies the criterion and the review gate runs `ReviewGateRunner.Run`, then the headless reviewer is granted bounded `Read,Grep,Glob` access to the item's worktree via `BuildReviewCallOptions`, independently locates and quotes its own evidence, populates a non-empty `tool_reads` list, and the item is graded `PASS` (logged `path=codebase-read-verified`) on the first review — never cycling through `AutoReopenAfterFailedReview`'s 3-iteration rework loop for a criterion that was never actually broken.

## Test Stack
- **Unit**: Go's built-in `testing` package + `testify/require` (`require.NoError`, `require.Contains`, `require.Equal`), matching this repo's existing convention in `session/backlog_review_test.go` / `session/review_gate_test.go`. Headless-call unit tests use the existing `FakeRunner` test double (`session/headless/*_test.go`) to capture subprocess args, system prompt, and context deadline without invoking a real `claude` process. Service-level unit tests use the existing fake/injected headless-pool pattern already present in `server/services/backlog_service_test.go`.
- **Integration**: Go `testing` with build tag `integration` (`//go:build integration`), run via `go test -race -tags integration ./session/... ./session/headless/...`, requiring a real `claude` binary in `PATH`. This is the only mechanism that exercises the actual anti-gaming guarantee end-to-end (Epic 2.3 and the two proposed adversarial fixtures) since a fake runner cannot authentically simulate an LLM choosing to lie, confabulate, or correctly refuse.

## Anti-Gaming Coverage Adequacy — Judgment

**Updated in the second repair pass** (pre-mortem + consistency-check resolution): the gaps flagged below were addressed in plan.md as follows — Pre-Mortem P1 #1 (item 2 below), Consistency-Check Blocker A (a new positive-case fixture, Story 2.3.2), and Pre-Mortem P1 #3 (a new fixture, Story 2.3.5, for the mixed-criteria-outside-empty-diff gaming pattern this section's original judgment didn't yet cover). The paragraphs below are kept largely as originally written, with resolution notes added inline, so the historical judgment and what changed both remain visible.

The plan's own adversarial-review.md already flags this precisely, and after mapping requirements to tests directly, I agree the mapping is thin relative to what requirements.md calls "the load-bearing guardrail" and "the core point of the feature":

1. **Single adversarial LLM fixture.** `TestReviewGateRunner_RealClaude_FalseAlreadyImplementedClaim_IsCaughtNotPassed` (Epic 2.3) is the *only* end-to-end, real-LLM test validating the anti-gaming success metric (REQ-2/SM2), and it covers exactly one lie shape: a citation to a file that does not exist at all. It does not cover a citation to a real file that exists but doesn't actually satisfy the criterion, an unstated-but-correct location the reviewer must find independently, a mixed review where some notes are true and one is subtly false, **or a mixed-*diff* review where the false claim sits on a criterion the diff itself never touches** — the first three of which adversarial-review.md names explicitly as uncovered, and the fourth of which Pre-Mortem Failure #3 separately identified as arguably the *most common* real-world gaming shape (a partial PR, not an empty one). I added two proposed integration tests above (`TestReviewGateRunner_RealClaude_CitesRealButIrrelevantFile_IsCaughtNotPassed`, `TestReviewGateRunner_RealClaude_MixedTrueAndFalseClaims_OnlyFalseCriterionDowngraded`) to close the two highest-value gaps; a third (unstated-correct-location) is lower priority since it tests the reviewer's positive search capability rather than its resistance to gaming, and is better owned by REQ-1's happy-path coverage than this section. **Resolution (second repair pass)**: both proposed tests are now referenced in plan.md as Stories 2.3.3/2.3.4; a positive-case sibling (`TestReviewGateRunner_RealClaude_TrueAlreadyImplementedClaim_IsVerifiedAsPass`, Story 2.3.2) was added to close Consistency-Check Blocker A (nothing previously proved the mechanism could reach PASS at all); and the fourth, mixed-*diff* gap is now closed by `TestReviewGateRunner_RealClaude_PartialDiffWithFalselyClaimedUnrelatedCriterion_NotCreditedAsPass` (Story 2.3.5), which also validates the new Story 2.2.5 evidentiary-weight prompt change. Anti-gaming LLM-fixture coverage is now five lie/truth shapes deep, not one.
2. **`tool_reads` self-attestation is not independently verifiable by any test in the suite.** `DegradeIfUnverified`'s unit tests (`TestDegradeIfUnverified_CodebaseReadPath_*`) only prove the Go-side downgrade logic is correct *given* a `tool_reads` value — they cannot and do not prove the LLM can't fabricate that value the same way it could fabricate the `evidence` field, because the heuristic is parsed out of the same JSON blob the model authors, with no cross-check against an independent signal (e.g., the CLI's own `--output-format stream-json` `tool_use` events). This is not fixable by adding more unit tests — it is a design-level gap the adversarial review already correctly logged as a tracked Concern rather than a Blocker, and no test in this validation plan (including my two proposed additions) closes it, since a confabulating model in the two new adversarial fixtures could in principle also fabricate a plausible `tool_reads` list. I recommend the plan explicitly record this in its Unresolved Questions section (currently it appears only in adversarial-review.md, not plan.md's own tracked-questions list) so it isn't lost once this validation phase ends. **Resolution (second repair pass, Pre-Mortem P1 #1)**: this gap is now *partially* closed, not fully. `verifyToolReadsExist` (plan.md Story 2.2.4, `os.Stat`-based, non-LLM) catches the cheapest and most mechanical half of this vector — a `tool_reads` entry pointing at a path that does not exist at all — via `TestDegradeIfUnverified_ToolReadsPathDoesNotExist_ForcesUnverifiable`. It deliberately does **not** and cannot close the harder half: a model that reads a *real* file and then fabricates or misremembers what's in it. That residual is now explicitly tracked in plan.md's Unresolved Questions (added in this repair pass) rather than living only in this document, per my original recommendation.

**Net judgment**: with the new adversarial fixtures (five real-LLM lie/truth shapes, up from one) and the `os.Stat` corroboration check (closing the "fabricated nonexistent path" half of the `tool_reads`-trust gap) both added in the second repair pass, requirement-to-test mapping for the anti-gaming metric is substantially stronger than the original judgment above found — adequate to ship against a "complexity 2" appetite. The narrower residual risk that remains genuinely undischargeable by testing — a model that reads a real file and lies about or misreads its contents — is now explicit in both this document and plan.md's own Unresolved Questions, rather than living only here.
