# Pre-mortem: backlog-already-implemented
**Date**: 2026-07-14

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | A confabulating reviewer model fabricates both `evidence` and a plausible-looking non-empty `tool_reads` list for a criterion that isn't actually implemented, so `DegradeIfUnverified` never fires and a false PASS is credited with zero human-visible signal (no PASS-path notification exists anywhere in this feature or its predecessors). | Weeks later, Tyler (or a downstream session/PR consumer) discovers a backlog item marked "done" doesn't actually work. Grepping logs afterward shows `path=codebase-read-verified` on that item — the degrade path never fired because `tool_reads` was non-empty, it just wasn't true. | Add a cheap, non-LLM-authored corroboration check now instead of deferring to future `stream-json` tool-event support: after the call returns, `os.Stat` each path in `tool_reads` against `codebaseWorkDir` in Go, and force `DegradeIfUnverified` to UNVERIFIABLE if any claimed path doesn't exist. Add as a task under Story 2.2.4 and a validation.md case: "tool_reads lists a nonexistent file." | P1 |
| 2 | Task 1.1.1b (confirming WorkDir tool access against the *production* systemd `claude` CLI/config, not just CI) is a manually-checked Post-Implementation-Checklist line with no automated enforcement, so it's skipped under normal solo-operator time pressure — and production's headless environment silently differs from CI's. | Tyler greps logs and finds `path=codebase-read-degraded` firing on effectively every empty-diff review in production (or notices items are still burning all 3 rework cycles exactly as before), even though every unit/integration test is green and the PR merged cleanly. | Convert Task 1.1.1b from a checklist line into an automated gate: have the running `stapler-squad` service perform a lightweight version of the WorkDir smoke test at startup (or on first empty-diff review) and log a WARNING (or refuse the codebase-read path, falling back to plain UNVERIFIABLE) if it fails — so the fact is verified on every deploy of the actual binary, not once by hand. | P1 |
| 3 | The codebase-read verification path only activates when the *whole* review's diff is empty (`diff == ""`). In the far more common case of a partial/mixed PR, an individual criterion's Note claiming "already implemented, unrelated to this diff" is rendered (Story 1.2.1, unconditional across all reviews) but never independently checked, because Story 2.2.1's falsification-framed prompt and tool access are diff-level, not criterion-level. | A PR merges where most acceptance criteria are genuinely satisfied by the diff, but one specific criterion was falsely marked satisfied via Note text alone with no tool-backed check. Nothing flags it at review time because the overall diff wasn't empty; it's discovered only later, disconnected in time from the original PR, when that specific behavior is exercised and found missing. | Add an explicit story addressing the mixed-criteria case before implementation begins: either run the codebase-read verification per-criterion whenever *any* criterion's Note claims "already implemented" regardless of overall diff emptiness, or explicitly downgrade such claims to "informational only, never sufficient for PASS" outside the `diff == ""` path — and document which choice was made. Add a fixture to validation.md: "partial diff + one falsely-claimed already-implemented criterion." | P1 |
| 4 | The `Pool.CallBlocking` consolidation (12 call sites spanning `approval_handler.go`, `session_service.go`, `autonomous_driver.go` — none related to backlog review) ships bundled in the same PR/pass as the anti-gaming fix. A subtle regression in one of those unrelated call sites (e.g. approval routing silently mishandling the new cost return, or autonomous-driver error-shape drift) ships alongside it. | An unrelated feature — session approvals, or autonomous-mode headless calls — starts behaving oddly within days of merge (e.g. approvals silently no-op, or an autonomous session stalls). Initial triage wastes time inside the backlog-review code because that's what the merged PR's title/diff summary emphasizes, when the actual regression lives in a call site the feature never intended to touch. | Split `Story 2.1.2` (the `Pool.CallBlocking` consolidation) into its own PR, merged and soaked separately from Epic 2.2's anti-gaming wiring, per the adversarial review's own recommendation — encode this as a plan.md sequencing change (two PRs, not one), not just a review comment that can be silently overridden during implementation. | P2 |
| 5 | `CodebaseReadCallTimeout` (150s) is a reasoned estimate, not data measured against this project's actual worktree sizes or AC wording. Broad or vaguely-worded criteria routinely need more than "a handful of Read/Grep/Glob round trips," so a meaningful fraction of genuinely-already-implemented reviews hit the timeout and degrade to UNVERIFIABLE — silently reproducing the original 3x-rework failure mode this feature exists to fix, just now labeled `codebase-read-degraded` instead of plain UNVERIFIABLE. | Tyler greps `path=codebase-read-degraded` a week or two in and finds it firing on a majority of empty-diff reviews rather than the rare case, while the rework-cycle rate barely moves versus pre-feature baseline. | Log call *duration* alongside `path=` (not just pass/fail) from day one, per Epic 2.5's Observability Plan, and run Epic 2.3's adversarial fixture plus a handful of real empty-diff items against representative worktree sizes before shipping, so 150s is validated against observed data instead of an estimate — add this as an explicit pre-ship task, not just a "tune later if needed" unresolved question. | P2 |

## P1 Items (address before implementation)
- [x] Failure #1 — Add an `os.Stat`-based existence check on every `tool_reads` path (Go-side, non-LLM) before trusting a codebase-read PASS/FAIL verdict; wire into `DegradeIfUnverified` (Story 2.2.4) and add a validation.md fixture for a fabricated-but-plausible `tool_reads` entry. **Resolved**: `verifyToolReadsExist` added to Story 2.2.4 (plan.md); `TestDegradeIfUnverified_ToolReadsPathDoesNotExist_ForcesUnverifiable` added to validation.md.
- [x] Failure #2 — Replace Task 1.1.1b's manual checklist verification with an automated startup/runtime check in the `stapler-squad` service itself (or a CI job that runs against the production `claude` binary/config directly, not a human-run checklist item), so a production tool-access gap fails loudly instead of silently degrading every empty-diff review. **Resolved**: new Story 2.2.6 adds a lazy, `sync.Once`-guarded `CodebaseReadCapabilitySelfCheck` that fires on the first empty-diff review after boot; Task 1.1.1b (manual pre-merge check) is kept alongside it, not replaced.
- [x] Failure #3 — Add a story to plan.md explicitly resolving the mixed-criteria (partial-diff, one falsely-claimed-already-implemented criterion) gap before implementation starts, plus a validation.md fixture covering it — currently unaddressed, not merely deferred. **Resolved**: new Story 2.2.5 downgrades an "already implemented" Note's evidentiary weight to informational-only whenever `diff != ""`; `TestReviewGateRunner_RealClaude_PartialDiffWithFalselyClaimedUnrelatedCriterion_NotCreditedAsPass` (Story 2.3.5) added as the regression fixture.
