# Research: Features / Edge Cases — per-call-site git CLI audit

**Scope**: non-test product code in `session/`, `server/`, `pkg/`, `testutil/`, `cmd/`, `github/`. Found by grep for `"git"` command construction (`safeexec.CommandContext`, `runner.Run(..., "git", ...)`, `runGit`, `runGitCommand`). Excludes `.claude/worktrees/*` copies.
**Evidence labels**: VERIFIED = opened go-git v5.19.2 source at `~/go/pkg/mod/github.com/go-git/go-git/v5@v5.19.2` or the repo file; INFERRED = from knowledge of go-git/git, not opened.

## Headline findings

1. **Native (in-process) worktree add/remove/list/prune/unlock already exist in product code** (`session/git/native_worktree_{add,remove,list,prune,common}.go`, `native_admin_writer.go`, plus a native merge in `native_merge*.go`, with OTel in `native_rollout.go`). They write the admin dir (`.git/worktrees/<name>/{gitdir,commondir,HEAD}`) and the worktree `.git` redirect file by hand and use go-git `Worktree.Checkout` for the files (VERIFIED: `native_worktree_add.go:67-214`, `worktree_ops.go:403-430`). The "go-git cannot create linked worktrees" premise in requirements.md is true of go-git's API, but this repo already works around it without a fork. The remaining worktree CLI calls are fallback/self-heal paths (`worktree_ops.go:214,217,291`) and the remote-host path (`remote_worktree.go:86,103`). The research question shifts from "can a fork add worktrees" to "what is left, and does a fork buy anything over the existing hand-rolled code".
2. go-git v5.19.2 has **linked-worktree read support** only: `PlainOpenOptions.EnableDotGitCommonDir` (`options.go:817`) and `dotGitCommonDirectory` (`repository.go:428`), and a `worktreesPath` constant in dotgit (`dotgit.go:44`). No `Worktree add/remove/list/prune/lock` API (grep of `worktree.go`/`repository.go` found none). VERIFIED.
3. go-git has **no credential-helper support** in `plumbing/transport/http` (only a test file mentions "credential"; VERIFIED by grep). SSH uses `kevinburke/ssh_config` and `SSH_AUTH_SOCK` (`transport/ssh/common.go:15,109`), so ssh-agent works but `url.<base>.insteadOf` rewrites and the HTTPS-to-SSH fallback wrapper do not. INFERRED for insteadOf (not grepped).
4. Network ops (push/fetch/clone, 12 sites) are the only group where go-git's API exists (`Repository.Fetch/Push/CloneContext`, VERIFIED `repository.go:1194,1223`) but behaviour parity is not.

## Edge-case matrix (CLI vs go-git semantics)

| Area | CLI behaviour | go-git v5.19.2 | Impact on this repo |
|---|---|---|---|

## User-visible edge cases the design must handle

| Scenario | Current handling (VERIFIED where cited) | Design requirement |
|---|---|---|
| **Concurrent sessions on one repo** | Per-repo mutex + Ground-Truth Re-Query loop: `branchExistsAfterAddFailure` retries on transient errors (`worktree_ops.go:92`), `nativeFindLiveWorktreeForBranch` retries listing (`worktree_ops.go:385`), `AllocateAdminDirName` race-safe via suffixing (`native_worktree_add.go:36`, concurrent test `native_worktree_add_test.go:82`) | Fork/native path must be linearizable against CLI path during rollout (index.lock, `worktrees/<name>` allocation, `refs/heads/*.lock`). |
| **Worktree path recycling** | `worktreeAlreadyRegisteredForBranch` compares `CanonicalizeWorktreePath(listed) != CanonicalizeWorktreePath(g.worktreePath)` (`worktree_ops.go:300`); path normalization for pre-normalization stored paths | Admin dir `worktrees/<name>` must not be re-used for a different path (`AllocateAdminDirName` suffixes); `gitdir` back-pointer must be verified against the recycled path; prune must treat a re-created dir at an old path as live only if `gitdir` matches. |
| **Branch deleted while worktree exists** | Worktree HEAD points to a missing ref; `branchExistsAfterAddFailure` and `findWorktreeForBranch` rely on re-query | `Head()` on that worktree errors `ErrReferenceNotFound`; status/diff callers (B2, B6) must degrade gracefully (the CLI says "ref: refs/heads/x" unborn). Never auto-create the branch silently. |
| **Pause deletes worktree, keeps branch** | `Cleanup()` deliberately does not delete the branch (comment `worktree_ops.go:434`); `nativeRemoveWorktree` never touches `refs/heads` (`native_worktree_remove.go:10-14`); this was a past regression ("stop_session silently deletes the git branch") | Resume path = D2 (add for existing branch): this is the one worktree-add variant still on the CLI. Keep the invariant with a regression test on the replacement. |
| **Worktree dir deleted externally (rm -rf)** | `nativeListWorktrees` marks prunable; `nativeRemoveWorktree` treats missing dir as logged no-op | Prune must run before add for the same branch; ensure admin-dir cleanup when dir missing. |
| **Locked/half-created worktree (crash between gitdir and commondir)** | `nativeUnlockWorktree` + prune tests (`native_worktree_add_test.go:192`) | Keep admin-file write order identical to git (gitdir, then commondir, HEAD) so real git can still prune it. |
| **Token-in-URL clone** | E1-E3: clone with token URL then `remote set-url` to the public URL | Must not leave tokens in `.git/config` on any error path; go-git `Clone` with `Auth` removes the need for the URL rewrite entirely (improvement). |
| **Remote (SSH) sessions** | D3/C5 run git on a remote host through `runner` | Out of scope for in-process replacement; the success metric needs "local" qualifier. |
| **Session on repo without `origin/HEAD`** | B12 and `ops.go:190-205` try candidate branches (main/master/develop/trunk) | Candidate loop must keep working when `refs/remotes/origin/HEAD` is absent. |
| **Cross-tool consistency** | Users run real `git`, IDEs, `gh` against the same worktrees | Everything the fork writes (admin files, index, packed-refs) must be readable by real git; the repo already tests this (`TestNativeSetupNewWorktree_WritesRealGitCompatibleAdminFiles`, `native_worktree_add_test.go:141`). |

## Implications for the design (for the architecture/plan phases)

- Remaining genuinely-CLI-only product operations after the existing native work: **existing-branch worktree add (D2), network ops with credential helpers (E1-E7), commit with hooks/signing (C3), index/worktree diff text (B4-B6), `status` rename/untracked-dir output (B1)**, plus remote-host git (D3, C5).
- Work that go-git alone covers with a thin adapter and no fork: A1-A15 (read-only introspection), B9-B13, C1-C2, C6, E3. Nothing in the audit requires a go-git *fork* for these.
- A fork is only justified by D2/D3-style worktree add (and only if the existing hand-rolled admin-file writer is judged less maintainable than a fork), and by credential-helper/insteadOf transport support (could be a wrapper `transport.Transport` registered via `client.InstallProtocol` without forking — INFERRED, go-git exposes this hook).
- The no-`-C` call sites (A13 x2, B3, B12) inherit the process CWD and are the cheapest to fix first.
- Open: `session/vcs/git.go` `GitClient` subcommand inventory not enumerated; `defaultPlainOpenOptions` content not opened (confirm `EnableDotGitCommonDir`).
