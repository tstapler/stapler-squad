## Blockers
- [ ] **Epics 1.1, 2.1, 2.2, 4.1 (Stories 1.1.2, 2.1.1, 2.1.2, 2.2.1, 4.1.1; package layout `session/git/backend{,/cli,/gogit}`)** — The package graph is undefined and, as written, cyclic or unbuildable. (a) The reusable native code the plan says the `gogit` backend wraps lives in `package git` (`session/git`) and is mostly unexported: `nativeListWorktrees`, `nativeRemoveWorktree`, `nativeUnlockWorktree`, `writeNativeWorktreeAdminFiles`, `checkoutNativeWorktree`, `worktreeIsDirtyFast`, `headTreeHashes`. Only `MergeBaseResolver`, `ListWorktrees`, `AllocateAdminDirName` and `NewAdminFileWriter` are exported. A sibling package `session/git/backend/gogit` cannot call the rest. (b) Story 2.1.2a makes `session/git/util.go` and `ops.go` callers of `Backend`, while `backend/gogit` must import `session/git`. If `session/git` has to build the routed backend, that is a cycle (`session/git` -> `backend/gogit` -> `session/git`). The plan never says who constructs the router (composition root). (c) `pkg/classifier` (currently depends only on `executor/safeexec`, `log`, `telemetry`) and `session/vcs` (does not import `session/git`) are migrated onto the interface (Story 2.1.2c). If the interface lives under `session/git/backend`, that drags `session/tmux` and `session/lifecycle` into `pkg/` (`go list -deps ./session/git` shows both). — **Remediation**: add a Story 1.1.0 "package topology" before 1.1.1, with these rules. (1) `session/git/backend` is a leaf: interface, typed results, errors, `Cohort`/`FallbackReason` and the `Router` take no import of `session/git`. (2) Move the reusable native on-disk code (admin writer, list/remove/unlock, dirty-fast, merge-base) into a lower package, e.g. `session/git/native`, exporting what `gogit` needs; `session/git` re-exports or wraps it so existing callers do not change. (3) `cli` and `gogit` depend on `backend` plus `native`, never on `session/git`. (4) Callers receive a `backend.Backend` by constructor injection from one composition root (server startup / `session` manager). `session/git`, `pkg/classifier` and `session/vcs` take it as an injected parameter and never construct it. (5) Add a depguard rule forbidding `backend/**` -> `session/git`. If `pkg/classifier` cannot take a dependency, define its one narrow port locally.
- [ ] **Stories 1.1.2, 2.1.2, 4.1.3 and ADR-003 carve-out (remote-host sessions); the existing `tmux.CommandRunner` seam** — The plan never mentions the existing exec seam, `session/git.GitWorktree.commandRunner()` (`session/git/worktree.go:392`, a `tmux.CommandRunner` that is `LocalRunner` or an SSH runner; `runGitCommand` at `worktree_git.go:160` calls `g.commandRunner().Run(ctx, path, "git", ...)`). `grep -rn "CommandRunner|LocalRunner"` over the plan directory returns nothing. Consequences: (a) `Backend` takes a local `RepoRoot`, so a remote session routed `refs=gogit` would open a local path that does not exist, or worse a different local repo at the same path, and silently return wrong answers. Nothing in the cohort router or capability preflight distinguishes local from remote. (b) The `cli` backend "by moving `safeexec` calls" (Task 1.1.2b) would bypass the runner and break remote sessions. (c) Story 4.1.3's claim that remote runs "never go through local `safeexec`" is unverified, and `LocalRunner` is a local-spawn path that the zero-spawn counter must see. (d) At least 8 `runGitCommand(` call sites plus every `commandRunner().Run(..., "git", ...)` site do not match the plan's `"git",` grep definition and are not covered by the `norawgitcli` analyzer, which only flags `safeexec.CommandContext`. — **Remediation**: (1) add a typed `RepoLocation` (sum type: `Local{RepoRoot}` / `Remote{Host, Path, Runner}`) to every `Backend` method receiver or constructor; `Router` sends `Remote` to the `cli` backend unconditionally and records reason `remote_host`, with no cohort override. (2) Make the `cli` backend execute through `tmux.CommandRunner` (or an equivalent port) rather than calling `safeexec` directly. (3) Extend the Story 0.1.1 audit script and the `norawgitcli` analyzer to cover `runner.Run(..., "git", ...)` and `commandRunner().Run`, and state the real site count under that definition. (4) Add an acceptance criterion: with `refs=gogit`, a remote-session `CurrentBranch` call never touches the local filesystem.
- [ ] **Stories 1.3.2, 4.1.3, 5.3.1 (zero-spawn counter and gate)** — The metric design is self-defeating once the seam exists. `git_cli_spawn_total{subcommand,callsite}` takes `callsite` from the `safeexec` constructor caller (`pkg/file.go:line`). After Epic 2 migrates callers, every remaining spawn originates inside the `cli` backend's one or two exec helpers, so `callsite` collapses to the same few values. The Story 5.3.1 gate ("fail if callsite or reason outside the allow-list") is then either vacuous (allow-list includes the `cli` helper) or always red. As a metric label `file:line` also changes on every edit. The plan's "`callsite` bounded by about 62 sites" no longer holds after migration. — **Remediation**: key the counter and the gate on the typed `OperationName` (Backend method) plus `FallbackReason`, passed from the router to the `cli` backend through the call, not through `runtime.Caller`. Keep a `safeexec` name=="git" counter as a backstop with no `callsite` label, to catch spawns that bypass the seam, and keep `file:line` only in the `SSQ_GIT_SPAWN_DUMP` test output. Rewrite Stories 1.3.2 and 5.3.1 acceptance criteria accordingly, and make `remote_host` an allow-list reason.

## Concerns
- [ ] **Story 0.2.4 / Story 2.3.1 / ADR-003 (CLI-compatible locking via a `Storer` decorator)** — The CLI holds `index.lock` from the index read through the rename. A decorator over `storage.Storer` sees `Index()` and `SetIndex()` as independent calls with no knowledge of the read-modify-write pairing. Taking the lock in `Index()` and releasing it in `SetIndex()` leaks a stale lock on any error path between them, and taking it only in `SetIndex()` still loses concurrent updates (read-before-lock). The S4 "wrapper works" outcome is therefore less likely than the plan expects, and the F1 fork patch may well be needed. — Make S4 explicitly test the read-to-write window (pair the lock at `Worktree.Add`/`Commit` level via an in-repo transaction helper rather than at `Storer` level), and add the stale-lock-on-error test case to Story 2.3.1. Treat "F1 needed" as the likely outcome in O-6 messaging.
- [ ] **Tech Debt Disposition, `session/vcs` vs `session/vc`** — "Isolate via seam: both route through `Backend`" keeps two parallel git abstractions (`vcs.GitClient.run`, `vc.GitProvider.runGit`; both confirmed as raw `safeexec` text-parsing layers, and they do have separate callers). Story 0.1.1 audits caller counts but no later story acts on the result. — Add a decision task after 0.1.1 (delete the dead layer, or name which one owns each operation) so Epic 2 does not implement each op twice.
- [ ] **Story 1.1.1 / `config` ownership of domain types** — `Cohort`, `BackendMode`, `ParseCohortMap` are defined in `config/git_backend.go`, while the router and `FallbackReason` live in `backend`. `config` already imports `executor/safeexec` (`go list -deps ./config`), so the dependency direction is fragile. — Define the sum types in `backend`, keep only the raw `map[string]string` field in `config`, and parse in the composition root. This also gives parse-at-boundary a single owner.
- [ ] **Story 1.1.2 (interface signatures)** — The plan says "typed results" but does not give signatures. The glossary's `RepoRoot`/`GitDir`/`CommonDir` newtypes and `OperationName` are not tied to method parameters. With about 25 methods taking `(string, string)` pairs (repo, branch/ref), the primitive-obsession advisory check configured in `.claude/inspect.json` will fire. — Add the interface sketch to Story 1.1.2 (with `RepoLocation`, `BranchName`, `RefName`, `CommitSHA` types) as an acceptance artifact.
- [ ] **Story 1.1.4 (norawgitcli baseline)** — "Baseline count equals 62 minus migrated" is wrong for an analyzer that flags only `safeexec.CommandContext(..., "git", ...)`. The plan's own audit gives 36 constructor sites, versus 62 `"git",` literal sites (the other 26 are runner calls, argument tables and test helpers). — State the analyzer's own baseline from the audit script's constructor-site count.
- [ ] **Epic 4.1 placement** — Story 4.1.1 adds `native_worktree_add_existing.go` to `session/git`, which already has 31 `native_*` files. Fold it into the `native` package from the blocker-1 remediation rather than growing `session/git`.
- [ ] **Status line / sequencing** — Plan says "Ready for implementation" while ADR-003 and ADR-006 are "NEEDS USER DECISION". The plan gates this at G7 and lets Epics 1.1 and 1.3 start earlier, which is acceptable, but Epic 1.1's `Router` design (cohorts, capability routing) bakes in ADR-006 defaults. State that explicitly in Epic 1.1.
- [ ] **Hotspot/ADR hygiene** — `docs/adr/` has no entry for the fork decision, and these ADRs live only under `project_plans/`. The repo's own ADR directory is where `prefer-go-git-over-subshells` policy would be looked up. Promote ADR-001/002/004 into `docs/adr/` when accepted.

## Re-review
**Date**: 2026-10-08
**Updated verdict**: BLOCKED (2 narrow blockers; the three original blockers A1, A2, A3 are resolved in principle)

Scope: only A1, A2, A3, against the revised `plan.md` (Story 1.1.0, interface sketch, Observability Plan) and ADR-004. Checked with `go list -deps`, `grep` and file reads on 2026-10-08. Concerns and nitpicks from the first review were not re-checked.

### A1 package topology / import cycle: resolved, one residual
Verified against the code:
- `go list -deps ./pkg/classifier`, `./session/vcs` and `./config` list only `config/workspacepath`, `log`, `telemetry`, `executor/safeexec` (plus `executor` for `config`). None imports `session/git`, `session/tmux` or `session/lifecycle`. `go list -deps ./session/git` does list `session/tmux`, `session/lifecycle` and `config`. So a leaf `backend` that imports none of those, and a `classifier.RefReader` port, keeps `pkg/` clean.
- The only package that imports `session/git` among the migration targets is `session/vc/types.go`, which sits above it, not below. With `session/git` taking an injected `backend.Backend` and `gitwiring` importing `backend`, `cli`, `gogit`, `native`, `config` and `tmux` but not `session/git`, no cycle follows. `session/tmux` does not import `session/git` (the dependency runs the other way).
- Rules 1-7 and the Task 1.1.0c depguard rule (`.golangci.yml` already enables depguard) are enough to hold this.

Residual (see B1): the `native` extraction is not yet implementable as specified.

### A2 remote host / `tmux.CommandRunner`: mostly resolved, one residual
Resolved: `RepoLocation` is the first parameter of every method; `Remote` routes to `cli` with reason `remote_host` and no override; the `cli` backend runs through a `Runner` port; `norawgitcli` now covers `runner.Run`, `commandRunner().Run` and `runGitCommand(`; the audit reports 25 runner sites; and Story 1.1.3 asserts no local filesystem access for a remote location.

Residual (see B2): the router cannot obtain the right runner for a `Remote`.

### A3 zero-spawn gate: resolved
The counter `git_backend_cli_spawn_total{operation,reason}` is keyed on the typed `OperationName` and `FallbackReason`, passed through the call, not `runtime.Caller`. The label-free backstop `git_cli_spawn_backstop_total{subcommand}` at `safeexec` (`name=="git"`) catches bypasses, `file:line` is test-dump only, and `remote_host` is an allow-listed reason. Both label sets are closed enums, so the gate is neither vacuous nor always red. Two concerns below (C2) tighten the matching rule.

### Remaining blockers
- **B1: Story 1.1.0 rule 2, Task 1.1.0a, ADR-004 decision 8.** Violation: `gogit` must open repos through `OpenRepo` (ADR-004 item 8; plan line 416, 697), but `OpenRepo` and `defaultPlainOpenOptions` live in `session/git/util.go:43`, and `native` and `gogit` may not import `session/git`. Task 1.1.0a's export list omits it. Also, `native_worktree_common.go:21` and `native_worktree_add.go:68` call `OpenRepo`, and `nativeSetupNewWorktree` is a method on `*GitWorktree`, so those files cannot move verbatim. Rule 2 says `native` imports "go-git, billy and the standard library only", but `native_rollout.go` (`withOperationSpan`, the `git_operation_duration_ms` histogram) imports `log` and `telemetry`, and Story 1.3.1b refactors it. Without a decision, implementers will either import `session/git` from `native` (cycle, depguard failure) or duplicate `OpenRepo` (bypassing `norawgitopen`). Remediation: add `OpenRepo` and its options to the Task 1.1.0a move list (`session/git/native/open.go`, `session/git.OpenRepo` becomes a one-line alias), move or exempt it in `tools/lint/norawgitopen`, convert `*GitWorktree` methods in the moved files into functions taking `repoPath`, and either put the span/metric helper in a tiny `session/git/native/obs` (or `backend`) package or amend rule 2 to allow `log` and `telemetry`. Add a Task 1.1.0a acceptance line: `go list -deps ./session/git/native ./session/git/backend/gogit` lists no `session/git`.
- **B2: Story 1.1.0 rule 5 (`NewRouter(cohorts, runner)`), interface sketch (`Remote{Host, Path}`), Stories 2.1.2, 4.1.3.** Violation: the router takes one `Runner`, and `Remote` carries no runner, yet the SSH runner is per target and per session (`tmux.NewSSHRunner(sshTarget, clientConfig, WithSSHClientPool(...))`, `server/services/remote_service.go:115`; the pool and host-key callback are server state). A `Host` string cannot reconstruct that runner, and `GitWorktree.commandRunner()` (`session/git/worktree.go:392`) is per instance. As written, the acceptance tests at plan lines 532, 548 and 965 can pass with fakes while no production wiring exists for remote sessions. Remediation: either restore the first review's shape (`Remote{Host, Path, Runner}`; the type lives in `backend`, which does not import `tmux`, so this is acyclic) or give `NewRouter` a `RunnerResolver func(RemoteHost) (Runner, error)` built in `gitwiring` from the session manager's SSH pool. Add an acceptance test that an unresolvable host returns a typed error and never falls through to `LocalRunner`.

### New concerns (not blocking)
- **C1: `Runner` signature mismatch.** Plan line 95, ADR-004 item 1 and rule 5 say `tmux.CommandRunner` "satisfies `backend.Runner` structurally". It does not. `tmux.CommandRunner.Run` returns `([]byte, error)` and the interface also has `Start` (`session/tmux/command_runner.go:52-60`), while the plan's port returns `(string, error)`. The adapter in `gitwiring` that rule 5 mentions is needed, so drop "structurally", or declare `Run` as `([]byte, error)` to match. Note that `Run` returns combined stdout and stderr, so `cli` result parsing for the typed methods must tolerate stderr noise as `runGitCommand` does today.
- **C2: Gate matching direction and remote spawns.** `LocalRunner` wraps `safeexec` (`command_runner.go:82`), so local runs reach the backstop. SSH runs do not, since no local `git` is spawned. State the invariant as `backstop(subcommand) <= sum(git_backend_cli_spawn_total over local reasons)`, not equality. Otherwise remote runs make the "unmatched increment" check misfire, or invite excluding `remote_host`.
- **C3: `classifier.RefReader` shape.** `pkg/classifier/classifier.go:713,721` run `rev-parse --show-toplevel` and `--git-dir` directly through `safeexec`. Story 2.1.2c should name the two port methods and take a plain path string, to keep `RepoLocation` out of `pkg/`.

### Summary
Resolved: A1 topology (acyclic by `go list -deps`), A3 gate design, and the bulk of A2. Open: B1 (`OpenRepo`/`native` extraction) and B2 (remote runner resolution); both are plan edits, not redesigns. Re-run this review after they land.
