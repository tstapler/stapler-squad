# Pre-mortem: go-git-fork-full-git-replacement
**Date**: 2026-10-08
**Inputs**: `implementation/plan.md` (Revision 5), `requirements.md`, `decisions/ADR-001` to `ADR-006`. Not re-run against source; every cited plan section was read, claims about go-git behaviour are INFERRED unless the plan marks them VERIFIED.

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | The plan has grown into a re-implementation of git's write path (own gitconfig tokenizer with `includeIf`/`hasconfig`, lock journal with xattr tokens and 5-condition stale-lock recovery, ref writer with git's lock order, reflog writer, fault-injection parity tests). One maintainer cannot finish it in 3 to 6 weeks. Seam work lands, `localwrite` and the resolver are half-built, and the appetite is blown (requirements: "cut scope, do not move the deadline"). | Week 3 checkpoint: Story 1.3.4 (resolver) and Story 0.2.4 (S4) are not both green; Epic 2.1 `refs` shadow has not started. Revision count keeps rising with each review (now 5) while shipped code is zero. | Make the resolver and `localwrite` cut by default, not by drop order. (a) Story 1.3.4: ship a **conservative resolver v1**: any `include`, `includeIf`, `core.hooksPath`, `GIT_CONFIG_*` env, or non-`.sample` hook routes the repo to CLI (`capability_detect_error`); the full git-compatible resolver is a later story only if the soak shows more than an agreed share of repos routed to CLI. (b) Move Epic 2.3 (all of `localwrite`) out of the 3 to 6 week appetite into a separate follow-up project with its own go/no-go; MVP in 0.3.1 already lists it second in drop order, promote it to "not in this project". (c) Add a written week-3 tripwire to `gates.md`: if S4 and the resolver are not green, freeze scope at seam + `refs` + test fixtures. | P1 |
| 2 | An in-process write corrupts or loses work in a worktree where an agent is running concurrently. Plan-specific hazards: deliberately reversed commit order (index renamed before refs, unlike git, ADR-003 point 2); no `reference-transaction` or other hooks fire; the lock-journal crash gap (`released` written, rename not done) leaves a lock nobody reports; go-git writes objects and indexes with its own semantics (dropped optional extensions). A lost commit or a staged-reversion state in an agent's worktree is user-visible data loss, and the agent is a CLI writer the server cannot control. | Agent session reports `index.lock exists`, an unexpected staged-reversion `git status`, or a commit missing from `git reflog`; `git_lock_contention_total` / `ErrLocked{Journaled:true}` non-zero in soak. | Restrict who may take the write path, not only how. (a) `localwrite=gogit` applies only when the session registry shows **no running (non-paused) session** in that repository (the plan already has this predicate for lock recovery, condition iv; reuse it as a routing precondition in `Router`, reason `live_session`, added to `FallbackReason`). (b) Keep `Commit`, `BranchRename`, ref deletes on `cli` permanently if the reflog and fault-injection parity tests are not green; the cohort never goes default-on, only opt-in per repo, for the entire first release. (c) Add the CLI-commit-in-the-gap test and the `pack-refs`/`branch -D` stress test (Story 2.3.1) as **required CI**, not soak-only. (d) Resolve the known crash gap by journaling `released` after the rename rather than before it, accepting a reported-never-deleted lock as the failure direction, or document it as a reason `localwrite` stays opt-in. | P1 |
| 3 | `diffstatus` on go-git answers "clean" for a worktree that the CLI says is dirty (gitignore/global excludes, autocrlf, symlinks, intent-to-add, assume-unchanged, submodules, rename detection: all INFERRED parity risks from features.md B1, not measured), and a destructive path (cleanup, pause, delete worktree, review gate "nothing to commit") trusts it. Uncommitted agent work is deleted. Shadow soak on one maintainer machine does not cover other repos. | An agent's changes vanish after pause/cleanup; `git_backend_shadow_mismatch_total` non-zero on any repo; reviewer sees an empty diff for a non-empty change. | Asymmetric trust. (a) Add a router rule: any dirty/clean/diff answer feeding a **destructive or irreversible decision** (worktree removal, cleanup, `pause_session` worktree delete, review gate pass) is computed by the CLI, or by gogit AND confirmed by the CLI when gogit says clean (gogit "dirty" may be trusted; gogit "clean" may not). Record the call-site list in Story 0.1.1. (b) Story 2.2.1 oracle corpus must include the fixtures above (CRLF with `core.autocrlf`, global excludesfile, symlink, intent-to-add, `assume-unchanged`/`skip-worktree`, submodule) and fail on any false-clean. (c) The `diffstatus` flip PR is blocked unless a false-clean count of zero is shown over the shadow window on at least the repos the maintainer actively manages, not one repo. | P1 |
| 4 | Success is claimed but the original pain (subprocess spawn cost dominating the `session` test package, requirements Baseline) barely moves: the server-side cohorts do not touch test fixtures, and the MVP cut drops Epic 5.1.2 "beyond the first batches" while `worktree add`, `checkout`, `clone` fixtures stay on the CLI. Weeks go to locking and config resolution, which do not reduce test spawns at all. | After week 4, `session` package wall time and spawn count (Story 0.1.2 baseline) are within noise of baseline. | Reorder so the cheap win is first: pull Epic 5.1 (in-process fixtures, which `b5af54fb8` already started) forward to week 1 to 2 and report spawn count and wall time against Story 0.1.2 at each weekly gate; make "spawns in `session` tests reduced by X%" an explicit G-gate before any Phase 2.3 or Phase 3 work starts. Also resolve O-1/O-9: restate the requirements metric to match ADR-003 tiers so nobody expects "zero git" while the plan carves out `gh`, remote hosts, agents, local transport, and worktree-writing ops. | P2 |
| 5 | The two-layer zero-spawn gate (PATH shim + counters, 20 `Setenv("PATH")` and 29 `LookPath("git")` sites, allow-list ratchet, skip-set ratchet, attribution by temp-dir name) is itself the largest piece of test infra in the plan. It either false-greens (a weakened test path) or false-fails on unrelated PRs, and gets disabled or allow-listed wholesale. | Gate red on a PR with no git change; allow-list file grows instead of shrinks; "report-only" mode never graduates to blocking. | Define the graduation rule in the plan: report-only for N consecutive green CI runs, then blocking; allow-list changes require a code-owner style check (ratchet test already planned) plus a PR-template line. Time-box Story 5.3.1 to the shim layer only; drop the backstop-vs-backend inequality (Layer 2) from the MVP if Layer 1 already catches every spawn. | P2 |
| 6 | Shadow soak evidence is unreliable, so the cohort-flip rule "block on any `shadow_mismatch_total > 0`" either never passes (mismatches are races between the CLI read and the in-process read while an agent mutates the repo) or gets waived by habit. | Mismatch counter non-zero in every window with no reproducible diff; flip PRs argue about "noise". | Define mismatch precisely before the soak: a shadow compare snapshots the ref/index state (or retries once when HEAD/index mtime changed between the two reads, the plan already treats the commit gap this way) and only counts a stable disagreement; each mismatch writes a redacted repro record the maintainer can triage. Specify the window size in operations (not only days) so an idle machine cannot pass vacuously. | P2 |
| 7 | The `replace` to a private `tstapler/go-git` fork (O-4 default private) breaks `go install`, Dependabot, forks' CI and release-please builds (secrets not exposed to fork PRs), while the fork ends up empty (plan's own most-likely end state). Maintenance burden with no benefit. Separately, go-git error strings embedding a token-bearing remote URL leak into logs or OTel before the Redactor covers every path. | CI red on an external PR or fresh clone with `410`/auth errors on module download; a token fragment shows up in a log line or span. | Decide O-6 and O-4 at G7a **before** Story 1.2.2 starts, with default "no `replace`, stock go-git v5" if S4/S6/S3 produce no fork-only failing test (flip the plan's stated default from "keep empty fork" to "drop it"); if kept, make the fork public. Gate Epic 3 on Story 1.3.1 (Redactor applied at `withOperationSpan` and all slog sinks) with a test that greps captured logs/spans for a canary token. | P3 |
