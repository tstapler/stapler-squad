# Fork-necessity decision record (Story 0.2.7)

Date: 2026-10-08. Inputs: `gates.md` and the spike files under `spikes/`. The fork-only test (plan section 0.3): a patch lands in the fork only if a spike shows, with a failing test, that no wrapper around public go-git API (custom `storage.Storer`, `billy.Filesystem`, `client.InstallProtocol` transport, or in-repo helper) can deliver it, or a measured G3 perf gap is fixable in under 200 lines.

## 1. Decision

**The fork ships as an empty pinned F0: zero patches.** No spike produced a failing test that a public-API wrapper cannot fix. This matches O-6 (Tyler: keep an empty pinned fork). One candidate (F4, status and diff performance) is **unresolved by the fork-only test**, not proven necessary, and the choice around it is a decision for Tyler (section 3, item 1).

## 3. New facts that change the plan

Numbered so the plan edits in section 4 can reference them.

1. **`diffstatus` conflicts with the end state (S3).** `Status` (240x slower, 896 vs 2 entries), `Patch.Stats`/`DiffTree` (3.6x to 9x) and `Log` fail G3. If they stay CLI, the server keeps spawning `git` for status lists, diff text, numstat and rev-list counts, which is a tier-3 carve-out under O-1/O-14 that the plan did not list. Three options, none evidence-backed yet: (a) keep CLI and add it to the O-14 list; (b) an in-repo status walker built on the index plus an ignore matcher, extending `worktree_dirty_fast.go` (unprototyped); (c) an F4 patch to `Worktree.Status` (unsized; S3 doubts the 200-line bound). `status` also gives wrong answers (896 entries), so any in-process status needs the oracle first; the Epic 2.2 destructive-intent fail-closed rule already assumes this.
2. **Retry bound (S6).** Retry at least 3 attempts, recommend 5 (observed max 3 in two modes), not "retry once"; unwrapped fresh opens still failed 15 times, so retry is necessary even with a fresh handle. Fresh opens cost about 15x read throughput (6.6k vs 97k reads per 60 s), so batch operations must open once per batch.
3. **`Reindex()` is banned on shared handles (S6).** Unlocked it panics (`loadIdxFile` nil map); locked it showed 0 failures and 0 retries, so it was not shown to help.
4. **Locking scope (S4).** `Checkout` and `Reset(Hard)` diverge from CLI semantics in stock go-git (T12), and `Reset(Hard)` deletes untracked files. `Remove`/`RemoveGlob`/`Move` write the worktree before the index. These stay `unsafe_worktree_write` CLI routes with measured, not assumed, reasons. `Commit(All+Amend)` is unsupported by go-git and needs an `AddWithOptions`+`Commit(Amend)` emulation (untested) or the CLI. `CommitOptions.Validate` mutates its argument, so options must be built per call. A product grep finds no go-git `Reset(Hard)` use today.
5. **Segfault, not corruption message (S4 T3b).** Apple Git 2.50.1 segfaults on a half-written index, so the scoped write is a correctness fix for any agent running `git status` while the server stages, not an optimisation.
6. **Credentials and transport (S5).** F1 same-hostname different-port redirect forwards `Authorization` on stock go-git/net/http; F2 transport-cache panic with a non-`*http.Transport` and a TLS option; F3 a `Match` block silently disables all ssh_config lookups for the file (preflight must route every SSH host to the CLI, not just the matched one); F4 `git-credential-osxkeychain` is not on PATH (search known libexec dirs, never spawn `git --exec-path`); F5 install protocols once; F6 resolver-based `insteadOf`; F7 `file://` spawns `git-upload-pack` or `git --exec-path`, so "zero git spawn" is false as written; an in-process `file` server is a candidate with unverified hooks/concurrency/shallow/v2 parity; F8 user-less `ssh://` uses the OS user. go-git ignores `User`, `StrictHostKeyChecking`, `IdentityFile`, `ProxyCommand` in ssh_config.
7. **`refs` (S7).** `ErrRefDangling` is required: when go-git returns a SHA whose object is missing, the CLI returns the same SHA (182, 428, 246 hits, 0 differences), so falling back to the CLI does not repair it; the CLI answer must be object-checked and a dangling result returned as a typed error. Class 1 (`EnableDotGitCommonDir` off) fails 100% of linked-worktree reads and is already fixed in-repo; the gogit backend must always set the flag. Soak ceiling 0.25% (an upper bound from a hostile stress rate).
8. **Rebase burden (S1).** 3 additive probe patches onto v5.19.3: 0 conflicts. Taking v5.19.3 also moves `go-billy/v5 v5.9.0 to v5.9.2`, `sha1cd v0.6.0 to v0.7.0`, `x/crypto v0.55.0 to v0.56.0` in the root `go.mod`; the real PR should expect those diffs. Not evidence for patches that edit upstream-touched lines.
9. **Independent data-loss risk (S0 audit).** `pauseLocked` (`session/instance.go:2278`, then `:2300-2303`) and the stop path (`:2467`, `:2485`) call `Remove()` and `Prune()` even when `IsDirty()` returns an error; only a commit failure returns early. This exists today with the CLI and becomes worse if the fork or router returns errors more often (fallback, capability routing). Recommend fixing in the existing code (fail closed on a dirty-check error) regardless of this project, as a standalone small change; plan Story 2.2.2c's `Intent=Destructive` rule should reference it. D8 (worktree removal) has no gate of its own.
10. **Baseline numbers (S0, S3).** 1,006 git spawns in `./session` tests (floor); `/usr/bin/git` `rev-parse HEAD` is 10.5 to 18 ms, not the plan's 39 to 52 ms; the dotfiles wrapper adds about 12 ms per spawn. The 30% and 60% spawn-reduction gates (GS-1, GS-2) can now be expressed as 704 and 402 spawns for the `session` package fixture suite, if Tyler keeps those thresholds (O-12).
11. **Library state (S2).** v6 remains beta; stay on v5. v6 migration would also touch `tools/lint/norawgitopen/analyzer.go:97`.
