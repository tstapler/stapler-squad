# ADR-004: Operation-level `GitBackend` seam with a cohort switch and CLI fallback

**Status**: Proposed
**Date**: 2026-10-08

## Context
- There is one exec seam (`executor/safeexec/safeexec.go:30`, lint-enforced by `tools/lint/norawexec`) and one open seam (`session/git/util.go:43` `OpenRepo`, `tools/lint/norawgitopen`), but no operation-level interface. Product CLI calls are scattered: 62 `"git",` construction sites in 29 files (see plan Story 0.1.1).
- `config.FeatureFlags` is `map[string]bool` (`config/config.go:359`), so it cannot carry a three-valued mode.
- `withOperationSpan` in `session/git/native_rollout.go:106` already labels spans and the `git_operation_duration_ms` histogram (`native_rollout.go:53`) with `operation` and `implementation`, but records `err.Error()` verbatim.
- Mixed backends on one repo multiply the test matrix and invite lock races (research/architecture.md 3).

## Decision
1. Add package `session/git/backend` with `type Backend interface` (one typed method per distinct operation: `ResolveRef`, `CurrentBranch`, `CommonDir`, `Diff...`, `Fetch`, `Push`, `Clone`, ...), typed results, no text parsing at callers. Every method takes a typed `RepoLocation` (`Local{RepoRoot}` or `Remote{Host, Path}`) first. **Package topology** (architecture review blocker, verified with `go list -deps`: `session/git` depends on `session/tmux` and `session/lifecycle`; the native worktree helpers are unexported): `session/git/backend` is a **leaf** (no import of `session/git`, `session/tmux`, `session/lifecycle`, `config`, or go-git types in its API); the reusable native on-disk code (including `OpenRepo`, which `native` and `gogit` must reach without importing `session/git`) moves to a lower package `session/git/native` with exported entry points; `native` may import only go-git, the standard library, OTel and the verified leaves `log`, `telemetry` and `session/git/redact` (the existing native files already use them; `go list -deps ./log ./telemetry` shows no `session/*`), enforced by a strict depguard allow-list; dependencies on the rest of `session/git` (`WithRepoWorktreeLock`, `getHeadCommitSHA` with its CLI fallback, and `FetchBranch`, a CLI spawn that must be routed and counted) are injected as function values, not imported, and the shared constant `IsDirtyCleanCacheTTL` moves into `native` and is aliased back; `session/git/backend/cli` and `session/git/backend/gogit` import `backend` (and `gogit` imports `native`) but never `session/git`; one **composition root**, `session/gitwiring`, builds the router and injects it into `session/git`, the `session` manager, `session/vcs` and (via a narrow local port, `classifier.RefReader`, two path-string methods `ShowToplevel` and `GitDir`) `pkg/classifier`. depguard enforces it. Implementations: `cli` (executes **through a `Runner` port** whose `Run` has the exact signature of `tmux.CommandRunner.Run` and returns `[]byte` of combined output, so a `tmux.CommandRunner` satisfies it with no adapter; never `safeexec` directly), `gogit`, and a `routed` implementation that picks per call.
   - **Remote hosts**: the router sends every `Remote` location to `cli` unconditionally, reason `remote_host`, regardless of cohort settings (a `gogit` backend would open a nonexistent or different local path and silently answer wrongly). `Remote` is `{Host, Path, Runner}`: the SSH runner is built per target from server state (key store, known hosts, client pool), and the one build that feeds git is `session_service_create.go:483` (reaching git through `RemoteExecutionTarget.Runner()`, `session/execution_target.go:119`, and the `git.WithCommandRunner` calls in `session/instance_worktree.go`; `remote_service.go:115` is a dial test and `:579` a health prober that runs `true`, neither runs git), so the caller passes it in through `backend.Locate`, which lives in `backend` and takes `Runner` plus `IsRemote() bool` (revision 4, architecture C3 and C5; `gitwiring` keeps only `NewRouter` and cohort parsing and no package under `session/git`, `session/vcs`, `session/vc` or `pkg/` may import it); `NewRouter` holds only the runner for `Local`. A `Remote` with a nil runner is `ErrNoRemoteRunner` and never runs locally.
2. Backend mode per **cohort**, not per operation: `refs`, `diffstatus`, `localwrite`, `network`, `worktree`. New config field `GitBackendCohorts map[string]string` (`json:"git_backend_cohorts"`), values `cli` (default), `gogit`, `shadow` (read-only **operations** only: run both, return CLI result, log mismatch classified `racy` or `real` after one pinned re-read; never shadow a write; in `network`, only `fetch`/`ls-remote`). Optional per-operation override key `<cohort>/<op>`. Cohorts flip in the order refs, diffstatus, localwrite, network, worktree.
3. Any in-process error classified as a named, retryable failure mode (torn read, `object not found` under repack) may fall back to CLI for that one call; every fallback increments `git_backend_fallback_total{operation,cohort,reason}`. Reasons are a closed enum.
4. The zero-spawn metric is keyed on **operation and fallback reason**, not call site: `git_backend_cli_spawn_total{operation,reason}` is counted once per `Runner.Run` of `git`, with operation and reason carried to the counting wrapper in the call's `context.Context`. A label-free backstop `git_cli_spawn_backstop_total{subcommand}` at the `safeexec` seam (`name == "git"`) catches spawns that bypass the seam. The gate is an inequality, `sum(backstop) <= sum(backend counter, reason != remote_host)`: `LocalRunner` wraps `safeexec` so local runs increment both, SSH runs increment only the backend counter, and a bypass makes the left side exceed the right. `file:line` appears only in the test dump. (A `callsite` label collapses to the `cli` helper after migration, making the gate vacuous or always red.) The gate is two-layer: a PATH `git` shim run (requirements' own definition) plus the counters.
5. A new analyzer `tools/lint/norawgitcli` forbids `safeexec.CommandContext(..., "git", ...)` and `Runner.Run(..., "git", ...)`/`commandRunner().Run`/`runGitCommand(` outside `session/git/backend/cli` and the sanctioned Runner in `session/gitwiring` (allow-list for the test oracle package). Its baseline is the audit's constructor-site plus runner-site count, not the 62 `"git",` literals.
6. One redaction function (`redact.Git`) strips URL userinfo, `Authorization`/token material and credential-helper stdout from every log line, span error and metric label; URLs never appear in labels.
7. Fallback has a lifetime: non-capability fallback branches and the cohort flag are removed one release cycle after the cohort default flips (requirements Risk Control). The `cli` backend itself is **permanent** for ADR-003/006 carve-outs (remote host, capability routes, `gh`, and the `torn_read`/`object_missing` route unless S7 removes the cause).
8. The `gogit` backend opens a fresh `*git.Repository` per call via `OpenRepo` and never caches one across calls (go-git caches pack indexes per storage and is not thread-safe).

## Consequences
- Callers migrate incrementally; each migration PR is one call site to one interface method.
- Cohort grouping keeps partial-migration states to five, not fifty.
- A new config field is additive and backward compatible (absent means all `cli`).

## Alternatives rejected
- **Per-operation boolean flags in `FeatureFlags`**: 50-plus independent flags, `map[string]bool` cannot express `shadow`, large mixed-state matrix.
- **Call-site-local `if flag {gogit} else {exec}`**: no shared counters, repeats the scatter problem.
- **Big-bang refactor**: sites average about 2 per file; nothing ships until all are done.
