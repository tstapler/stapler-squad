# Validation Plan: import-external-session

**Date**: 2026-07-16

## Happy Path Scenario
Given a running `ssq-mux`-wrapped Claude session at `~/proj/api` (PID 4821) that stapler-squad has already discovered but not yet managed, when the user clicks **Import** on that row, reviews a preview showing "Matched by process ID" with 42 turns, and clicks **Confirm Import**, then a new managed `Instance` appears in the session list with identical conversation history and the original external process is left untouched until the user separately confirms **End Session**.

## Migration Test

**`migration_should_be_reversible`**: N/A — the plan's Migration Plan section is explicit that there is **no ent schema change**. Imported sessions reuse the existing `SessionType` (`directory`) and existing `ConversationUUID`/`HistoryFilePath` columns; there is no new migration to run up/down. In place of a schema migration test, `TestEntRepository_Create_PersistsImportedSessionIndistinguishableFromManualCreate_When_SessionTypeIsDirectory` (Integration, listed in the requirement table above) verifies the behavioral claim the Migration Plan makes — that a row created via import is structurally indistinguishable from one created via `CreateSession` — by comparing column values between the two creation paths against the same ent test DB.

## Test Stack
- **Unit**: Go `testing` package + table-driven tests (repo convention, e.g. `session/*_test.go`, `server/services/*_test.go`); assertions via stdlib comparisons already used in this repo (no third-party assertion library observed as required).
- **Integration**: Go `testing` with the repo's existing ent test-DB fixtures (`session/ent_repository_test.go` pattern) and real/faked tmux subprocess calls where the existing test suite already exercises them (`session/pty_discovery.go`-adjacent tests); no test doubles beyond what the repo already uses for `procinfo.ProcessInspector` and `mux.Discovery`.
- **Frontend unit**: Jest + React Testing Library (`web-app/src/components/**/*.test.tsx`), `describe("<Component>", ...)` blocks with `ComponentName_should_<effect>_When_<condition>` test names, matching the existing `ApprovalAnalyticsPanel.test.tsx`/`ApprovalRulesPanel.test.tsx` convention.
- **E2E / UX**: Playwright specs under `tests/e2e/`, `data-testid`/ARIA locators only, no `waitForTimeout`, `// @feature session:import, session:import-kill` header per `.claude/rules/e2e-test-conventions.md`; manual checklist for focus-round-trip and keyboard-only walkthroughs that are impractical to assert reliably in Playwright.
