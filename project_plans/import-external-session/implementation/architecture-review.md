## Resolved (Iteration 1)

- [x] **Blocker 1 — `ConfirmKillExternalSession` depends on a `PIDIdentity` no earlier RPC returns.** RESOLVED. `PreviewImportExternalSessionResponse` now mints `pid_identity` (Story 1.1.3, Task 1.1.3a defines the shared `PIDIdentity` proto message; Task 1.1.3c sets it on every preview response "regardless of correlation outcome, since kill needs it even when correlation is Ambiguous/NotFound"). `CommitImportExternalSessionResponse` echoes a freshly-re-read `pid_identity` (Story 1.2.1, Task 1.2.1a). The frontend has an explicit task (Story 1.4.2, Task 1.4.2d) to thread `pid_identity` from preview into row state, pass it on commit, and overwrite row state with the commit-returned value for use by `ConfirmKillExternalSessionRequest` (Story 1.3.1, Task 1.3.1a takes `pid_identity` from the commit response, not preview — correctly using the freshest read). Verified against actual story/task text, not just the changelog summary — the plumbing is complete end-to-end (mint → commit echo → frontend row state → kill request).

- [x] **Blocker 2 — handler-to-handler RPC call (`ImportService` invoking `SessionService.CreateSession`'s connect handler).** RESOLVED. New Story 1.2.0a extracts `session.CreateManagedInstance(ctx, CreateManagedInstanceParams) (*Instance, error)` out of `SessionService.CreateSession`'s inline logic (Task 1.2.0a-1), explicitly taking "no `connect.Request`/`connect.Response` in its signature." Task 1.2.0a-2 rewires `SessionService.CreateSession`'s connect handler to unwrap into `CreateManagedInstanceParams` and call the shared function, leaving "no remaining inline creation logic in the handler." Story 1.2.1's Task 1.2.1b has `session.CommitImportExternalSession` call the same shared function directly, and the acceptance criteria explicitly asserts the dependency direction: `CommitImportExternalSession` "never imports `server/services` or references `SessionService`'s connect handler/`connect.Request` types." This is the correct fix — extraction into a plain domain function consumed by both handlers, not a handler calling a handler.

- [x] **Blocker 3 — Antigravity commit path reintroduces the synthetic-partial-`Instance` antipattern Story 1.1.4 eliminated.** RESOLVED. New Story 3.2.1b extracts `ReadCanonicalEntriesFromFile`/`ReadCanonicalEntriesFromStore(path string) ([]CanonicalTurn, error)` out of `AgyAdapter.Import`, explicitly mirroring the `ReadCanonicalTurnsFromFile` refactor, with acceptance criteria stating "no `*Instance` constructed anywhere in the call chain" and marked a hard prerequisite for Story 3.2.2 ("exactly as Story 1.1.4 was a hard prerequisite for Story 1.1.3"). Story 3.2.2's acceptance criteria was rewritten to call the bare-path reader directly and explicitly states "never `srcAdapter.Import(ctx, syntheticSourceInstance)`" and "never constructing a synthetic source `Instance`." Task 3.2.2b adds a test asserting the synthetic-`Instance` path is never exercised. Minor nitpick (not a new blocker): Story 3.2.2's acceptance criteria phrases the call as `srcAdapter.ReadCanonicalEntriesFromFile(...)` (method-call syntax), while Story 3.2.1b defines it as "a small, additive helper" / "package-level function," not a method added to the `HistoryAdapter` interface — worth tightening the wording so an implementer doesn't infer a new interface method is required, but this doesn't reintroduce the antipattern and isn't a structural blocker.

## Concerns

- [ ] **`CorrelationResult` / `ImportOutcome` / `KillOutcome` illegal states** — these are documented as "sum-type-shaped" but implemented as flat structs with all fields always present (`Kind`+`UUID`+`Confidence`+`Candidates` together; `Status`+`InstanceID`+`Error` together). Nothing prevents `CorrelationResult{Kind: NotFound, UUID: "abc"}` or `ImportOutcome{Status: Success, Error: ptr("x")}` from being constructed. **Recommendation**: add per-case constructor functions (`NewResolvedCorrelation`, `NewAmbiguousCorrelation`, `NewNotFoundCorrelation`, etc.) that zero out irrelevant fields, and assert the invariant in the table-driven tests already planned in Task 1.1.2d.

- [ ] **Story 1.2.1 Task 1.2.1b disambiguation bypass** — when `disambiguation_choice` is supplied, commit "skip[s] re-correlation and use[s] the chosen UUID directly," with no check that the choice was actually a member of the `Ambiguous` result's `Candidates` returned by the corresponding preview. A buggy or malicious client could supply an arbitrary path and commit would import an unrelated JSONL into a new managed `Instance` unchecked. **Recommendation**: always re-run `CorrelateCandidate`, assert `disambiguation_choice ∈ Candidates`, and return `CodeInvalidArgument` otherwise — never fully skip re-correlation.

- [ ] **No PID re-verification before commit** — Epic 1.3 wires the double-checked `PIDIdentity`/`procinfo.IsAlive` pattern into kill, but Epic 1.2's commit only re-runs `CorrelateCandidate` (a fresh path/PID *lookup*), not a create-time identity check that the process at that PID is still the one previewed. Between preview and commit (seconds to minutes, longer for Phase 3 batches) the PID could be reused by an unrelated process, and PID-first correlation would silently attach to it. **Recommendation**: capture `PIDIdentity` at preview time (see Blocker #1) and re-verify via `procinfo.ProcessInspector.IsAlive` at the top of `CommitImportExternalSession`, not only before kill.

- [ ] **`import_commit.go` responsibility creep** — across Stories 1.2.1/1.2.2/1.2.3 and Phase 3's 3.2.2, this file accumulates re-correlation, `CreateSession` delegation, `HistoryLinker.AddInstance`, compensating delete, *and* program-specific adapter Import/Export branching, apparently inside one function. This is the same "god-handler" risk the ADR calls out at the RPC-handler level, recurring one layer down. **Recommendation**: split into `commitViaResume` (Claude-like, delegates to session creation) vs. `commitViaAdapterTranscription` (Phase 3, direct `HistoryAdapter.Import`/`Export`) behind a thin dispatcher, mirroring the discipline already planned for `ConfirmKillExternalSession`'s `SourceKind` switch (Story 2.2.2).

- [ ] **`ImportOutcome.CandidateRef` is undefined** — referenced in the Domain Glossary and Story 3.1.1's acceptance criteria, but no story/task defines its type or contents, and it's unclear whether it's the same raw identity tuple sent to preview/commit or a distinct server-issued token. Given the TOCTOU window above, a short-lived server-issued token bound to a `PIDIdentity` snapshot would be the stronger design, but the plan doesn't decide either way. **Recommendation**: add a short story fixing `CandidateRef`'s shape before Story 1.1.3, since it's implicitly relied on starting there.

- [ ] **`AdapterFor(candidate.Program)` (Story 3.2.2) has no defining task** — grep of the repo shows no existing `AdapterFor` function; the plan uses it as if it already exists. **Recommendation**: add an explicit task creating `AdapterFor(program string) HistoryAdapter`, e.g. a small registry consulting the existing `HistoryAdapter.CanHandle` on `ClaudeAdapter`/`AgyAdapter`.

- [ ] **Unresolved Question #1 vs. Story 2.2.1 internal inconsistency** — the Unresolved Questions section defers the SIGHUP/signal-target choice for plain-tmux kill to "a spike... before writing `KillPlainTmuxPane`," but Story 2.2.1's acceptance criteria already commits to a specific mechanism (`tmux kill-session -t <paneTarget>`) as if the question were already resolved. **Recommendation**: either resolve the question now and delete it from Unresolved Questions, or make Story 2.2.1's acceptance criteria explicitly conditional on the spike's outcome.

## Nitpicks

- Story 1.1.2's `CorrelateCandidate` acceptance criteria covers Resolved/Ambiguous but doesn't spell out the "PID lookup fails and `DetectAllByPath` returns zero" branch explicitly (presumably `NotFound`) — worth stating for the implementer, since the other two branches get worked examples.
- `KillOutcome`/`ImportOutcome`'s `Error *string` is fine as a proto (`optional string`) shape but should be confirmed as *not* the internal Go domain type's shape — idiomatic Go would keep `error` (nil-checkable) internally and only marshal to `*string` at the proto boundary.
- Consider adding one sentence to ADR-001 (or a new Pattern Decisions row) memorializing that `AntigravityHistoryDetector` deliberately repeats the discriminant-over-interface choice (dispatch on `candidate.Program` string, no shared `Detector` interface) — otherwise a future contributor may "fix" the duplication with a speculative interface the checklist would flag.
