# Validation Plan: backlog-github-issue-link

**Date**: 2026-07-25

## Happy Path Scenario

Given a backlog item imported from GitHub with a linked issue URL, when an agent session is spawned for it, then the agent's prompt tells it the linked issue URL and the exact keyword (`Fixes`/`Related`) to reference in its PR.

This is proven end-to-end by `TestSpawnSessionFromItem_PromptContainsLinkedIssueSection` (Phase 5), which is the integration test closest to what an agent session actually sees; every other test below is a narrower slice (unit-level) of the same flow: plugin → repository → prompt renderer → service call site.

### Post-validation correction (sdd:4-validate pre-mortem, P1)

The pre-mortem pass found that the plan's original instruction-line design (`Fixes <full-url>`) does not match GitHub's documented closing-keyword syntax (only `#N`/`owner/repo#N` are recognized, confirmed by fetching GitHub's own docs). plan.md and ADR-001 were patched to add a `githubShortRefFor` helper and use its `owner/repo#N` output instead of the raw URL in the instruction line; the fact line is unaffected. All AC3/AC5/AC7 test expectations in the table above reflect the corrected design.

## Test Stack

- **Unit**: Go stdlib `testing` + `github.com/stretchr/testify` (`assert`/`require`), matching every existing test file in `session/` and `server/services/`.
- **Integration**: same stdlib/testify stack, exercised against a real (temp-file) SQLite database via the `createTestStorage(t)` helper (`session/storage_test.go`) or a directly-constructed `*EntRepository` (`NewEntRepository(WithDatabasePath(...))`) for tests that need `repo.client` access below the `Storage` abstraction; service-layer integration tests use the existing `mockSessionCreator` test double (`server/services/backlog_service_test.go`) so no real tmux/git process is spawned.
- **E2E / UX**: none — this is a pure backend/infra change with no user-facing surface (no `design/ux.md` for this project); the manual, non-unit-testable follow-up (confirming GitHub's live closing-keyword parser accepts a bare full URL) is called out in plan.md Phase 6 as a post-ship manual verification step, not part of this test suite.

## Migration Test Note

This repo uses ent's auto-migration (`client.Schema.Create(ctx)`, run at process startup — `session/ent_repository.go:86`) with no versioned up/down migration files, and ent does not generate down-migrations at all (plan.md's own Migration Plan section confirms this is irreversible by design, and states that's not a concern here since the added column is nullable with no default). A `migration_should_be_reversible` test as specified by the generic SDD template literally does not apply — there is no "down" to run. The adapted, meaningful migration-adjacent test is `TestGetBacklogItem_ExternalURL_ReadsEmptyStringForPreExistingRow` (AC2 part 2 above), which proves the actual risk that matters for an additive nullable-column auto-migration: that a row persisted before the column existed reads back a safe zero value (`""`) instead of panicking on a `sql.NullString` scan.
