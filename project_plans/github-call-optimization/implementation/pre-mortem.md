| 2 | `RateLimiterSnapshot` (`{Remaining, Limit int; ResetAt, RateLimitedUntil time.Time}` per the Domain Glossary) is a single flat struct with no `resource` dimension, exactly like today's `rateLimitedUntil` field — but `Update()` already parses a *different* `X-RateLimit-Resource` per response (core/search/graphql all share one token but have independent quotas, e.g. search is 30/hr vs core's 5000/hr). At minimum, add a Phase 3 test that interleaves a low-limit `search`-resource response with a healthy `core`-resource response and asserts `AdmitOrigin(OriginInteractive)` for a `core` call is unaffected by the `search` bucket's numbers. | P1 |

Update plan.md's Risk Control "Phase 5 caveat" to name `pr_event_webhooks` alongside `webhook_triggers`. | P2 |

## P1 Items (address before implementation)
- [x] #1 — **Resolved 2026-09-09**: Risk Control now states two concrete, dated triggers grounded
  in Phase 1's actual emitted metrics (weekly check of `github.rate_limit.remaining{resource="core"}`
  vs. nonzero background-origin call volume for the admission-control flag; a 2-week,
  parity-test-gated window for the GraphQL flag), replacing the indefinite "whenever Tyler gets to
  it" phrasing. See `implementation/plan.md`'s Risk Control section.
- [x] #2 — **Resolved 2026-09-09**: `RateLimiterSnapshot` redefined as
  `{Resources map[string]ResourceQuota; RateLimitedUntil time.Time}`; `AdmitOrigin` now takes an
  explicit `resource` parameter derived from the request inside `rateLimitTransport.RoundTrip`; a
  new mandatory Task 3.2.1c adds the interleaved-resource regression test (a low-limit `search`
  response must not affect a `core`-targeting admission decision, and vice versa) as a Phase 3
  merge gate alongside the existing `-race` test. See `implementation/plan.md`'s Domain Glossary,
  Story 3.1.1, and Story 3.2.1.

## Summary

2 P1, 2 P2, 1 P3. Top failure mode: `RateLimiterSnapshot`'s single flat `{Remaining, Limit}` struct conflates GitHub's independent per-resource quotas (core/search/graphql sharing one token but separate budgets) the same way today's `rateLimitedUntil` field already does in its warning log — except Phase 3 escalates that conflation from a merely-confusing log line into a live admission-control decision that can silently admit background traffic it should have rejected, defeating the project's primary success metric with no error signal anywhere.
