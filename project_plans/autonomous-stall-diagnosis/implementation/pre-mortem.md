## Detail

Each entry: likelihood (L) and impact (I) as H/M/L, evidence, then the concrete plan patch. Evidence labels VERIFIED/INFERRED.

### #1 a.mu locking (P1; L: M, I: H)

- VERIFIED the current shape: `SetLifecycleContext` is an unguarded write (`autonomous_orchestration_service.go:103-105`), `driverCtx()` is an unguarded read (`:133-138`), `registerDriver`/`stopAndDeregisterDriver` take `a.mu` (`:141-158`).
- VERIFIED what the plan prescribes: Task 3.1.3c "writes `lifecycleCtx` under `a.mu` (it is currently an unguarded write)"; Task 3.1.3a "register the recovery entry (ctx derived from `a.driverCtx()`...)" inside the `claimCompletion` hold; Glossary `startDriverIfAbsent` "checks, builds the driver, calls `Start` and registers it" under one `a.mu` hold; `restartAfterRecovery` "under one `a.mu` hold verifies ... `canRestart` ... then `startDriverIfAbsent`'s body" while `canRestart` is also "run immediately before the nudger is invoked".
- INFERRED failure: `go test -race` flags a locked write with an unlocked read, so the natural fix is to lock `driverCtx()`; `sync.Mutex` is not reentrant, so `claimCompletion` and `startDriver` then self-deadlock. A self-deadlock is likely to be caught by the first callback test, so the *shipping* likelihood is medium. The variants that fakes do not exercise are the lock-order ones: `startDriverIfAbsent` under `a.mu` calls `NewAutonomousDriver` (`inst.GetController()`), `withCostSink` (`a.storageGetter()` -> `SessionService.GetStorage()`, `session_service.go:1153`) and `driver.Start`; any request path that holds a SessionService or storage lock and then calls `stopAndDeregisterDriver` (`session_service_lifecycle.go:47,306`, `session_service_update.go:296`, `tools_backlog.go:1998`) can invert against it.
- Impact: every stop/delete/hibernate/toggle and `submit_review_verdict` blocks behind one mutex; the service looks alive but cannot stop an autonomous session.
- Patch: as in the P1 checklist above. Also add the rule to the plan's Glossary: "`a.mu` guards map membership only; no call to `driverCtx`, `NewAutonomousDriver`, `Start`, storage or instance methods while held".
