## Happy Path Scenario
Given the Next.js 15.3.2 static export of `web-app/` (production build 60.6 s warm, `make web-build` 54.0-88.5 s in development mode, 21.7 MB unminified JS, pnpm to Bun PR #1100 merged), when the owner runs `WEB_BUILD=bun make web-build` and starts a ManualInstance (`--remote-access`, ports 62871/62872) from the embedded binary, then `web-app/out/index.html` plus minified `/_next/static/**` assets (total JS <= 6,349,052 B) are produced in <= 10 s wall (<= 10.8 s end to end including the Go embed copy), all 42 routes render with their Next-baselined titles, deep links and query-string state, the unauthenticated `/login` page loads every asset with 200, and the full Playwright suite fails only on specs already `fail`/`flaky` in `next-e2e-baseline.json` or listed in `bun-expected-diff.json`.

## Conventions used below

- **Test IDs are descriptive names**, `methodName_should_Expected_When_Condition`. Jest/Playwright tests use the same string as the `it(...)`/`test(...)` title (snake form).
- **Story** in the Scenario column is the plan story/task that creates the test. **(+)** marks a test or assertion the validation adds beyond the plan's acceptance criteria (see "Gaps and plan amendments"; each is named A1-A12).
- Counts in the plan (42 routes, 337 `.css.ts`, 152 specs, 65 importers) are orientation only; every test derives the expected count from the filesystem (Plan decision 8).
- **No schema or data migration exists**; "Migration" rows below test the reversible mode flip (Step 5 analogue).

## Test Stack
