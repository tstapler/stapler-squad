# Architecture Review: web-app-bun-build
**Date**: 2026-10-19
**Verdict**: CONCERNS

Scope read: plan.md in full, `web-app/.eslintrc.json`, ADR-001/003/006, `research/architecture.md` (hotspot/debt sections), `server/middleware/static.go`, `auth.go` (`exemptPrefixes`), `Makefile` (`server/web/dist` rule), `web-app/next.config.ts`. No `ADR-000-architecture-constitution.md` exists, so there are no constitution violations. kibitzer checks were not run (review from plan text plus the files above).

Constitution Violations: none.

## Verified structure (no action)
- **Dependency direction of `src/lib/nav` holds against `.eslintrc.json`.** `lib` may import only `ui`, `sessions`, `gen` (`.eslintrc.json:105`); `app` may import `lib` (line 85). The plan keeps `RouteTable`, `RouteMeta`, `FeatureGuard`, `NotFound` and `RootShell` in `src/app/`, and `paths.ts`/`RoutePath` in `lib/nav`. The only edge is app -> lib, so no new boundary violation. `lib/lazy` -> `components/ui/ErrorBoundary` is lib -> ui, which is allowed.
- **Build-time alias is the right seam.** It gives dead-code elimination and a resolver-level ban on `next`, which beats runtime `if (isBun)` branching.
- **Tech Debt Disposition covers every hotspot** in `research/architecture.md`. Each "Isolate via seam" entry names a concrete task (Epic 2, Story 5.2).
- **Go coupling is handled soundly.** Characterisation tests land first (1.5), then the 404 for asset-prefix misses (1.6), then the built-asset-to-`isExempt` binding test (6.8). `make` wipes `server/web/dist` before copying (Makefile:232), so stale Next `rules/index.html` files cannot be served in Bun mode.

## Concerns
- [ ] **Story 4.4 (root `errorElement`)** — The plan renders `RootShell` as the root route element and puts `errorElement` on the same route. In React Router, an `errorElement` replaces that route's element, so a failed lazy import removes all providers and chrome (AuthProvider, CockpitShell, notification panel), and the ErrorBoundary UI renders outside them. Next's `layout.tsx` + `error.tsx` keeps the shell. Remediation: make the root route a pathless layout (`element=<RootShell><Outlet/></RootShell>`) and put `errorElement` on a pathless child route inside it. Add an AC: after a chunk-load failure the skip link and nav are still present.
- [ ] **Stories 1.2, 4.3 (three title sources)** — Titles live in `metadata` exports (Next), `RouteMeta` and `RouteDef.title` (`{load,title,guard?}`). The drift test only compares `RouteMeta` with `metadata`. Remediation: drop `title` and `guard` from `RouteDef`, and have `routes.tsx` look them up from `RouteMeta` by `RoutePath`. Add a 4.3 assertion that the key sets of `RoutePath`, `RouteMeta` and `routeTable` are equal.
- [ ] **Stories 1.4, 4.3 (duplicate guard logic)** — Three bespoke layouts (`backlog`, `settings/backlog-sources`, `changelog`) implement the flag guard. Story 4.3 adds a second implementation, `FeatureGuard`, "built on `RequireFeatureFlag` semantics", and the two are held in sync only by tests. Remediation (Refactor-first, per the skill's reuse check): introduce `FeatureGuard` in PR 1 or 2 and have the three Next layouts consume it. That leaves one guard implementation in both builds, and 4.3 only wires it into the table.
- [ ] **PR 2 size/decomposition** — PR 2 has 23 tasks: the facade, a codemod across 106 files, the lint ban, `LazyBoundary`, the `web-vitals` swap, the `ReplaceSearch` migration and the Storybook alias. AC 2.5 requires 2.3-2.5 and 2.7 to be complete before the `next/dynamic` ban reaches zero. The PR is revertible but not reviewable. Remediation: ship 2.7 (lazy) and 2.8 (web-vitals) as their own PRs, since they do not depend on the facade. Split the rest into 2a (2.1, 2.2, which add the facade and migrate the test mocks) and 2b (2.3-2.6, 2.9, the production migration plus the ban). Every split point stays green under Next.
- [ ] **PR 5 and PR 6 decomposition** — PR 5 has 27 tasks and PR 6 has 19, which makes PR 6 a bucket. The PR 6 rollback entry says "revert per workflow file", which is not a clean revert. ESLint flat-config conversion (6.1-6.3) is independent of the Bun build, high-risk (`boundaries` and the two `file:` plugins) and has its own rollback story. Remediation: split PR 5 into 5a (`build/` + Makefile seam + CI smoke) and 5b (dev server + dev-stack + Playwright dev-mode), and split PR 6 so that lint (6.1-6.3) is its own PR, with size-limit/CI/Storybook/docs/Go test in another. Also state that the Bun `web-build-smoke` cell is non-required (`continue-on-error`) until Story 8.1, as 7.10 already does for e2e.
- [ ] **Story 2.1 / ADR-001 item 3 (facade contents)** — ADR-001 says typed search-param helpers are written in the facade, but no story schedules them, and the exported names in 2.1 are exactly six. Decide whether they are in scope and add the task, or amend ADR-001. Separately, the glossary claim for `RoutePath` ("cannot navigate to a non-route") is overstated: `push`/`replace` must accept `string` because call sites append query strings and ids. State where `RoutePath` is actually enforced (the route table only) so reviewers do not expect more.
- [ ] **Story 2.1 / 4.2 (facade interface leaks)** — Two leaks, neither fatal.
  - `{ scroll: false }` is Next's option name, mapped to React Router's `preventScrollReset`. Consider a router-neutral name (for example `resetScroll: false`) in `impl.types.ts`, since the codemod already touches every call site.
  - `replaceHash` and `pushTrayEntry` are raw History operations, not navigation, and each impl must reconcile them with the router's ownership of `history.state` (`idx`/`key`). That risk is correctly held by S4 and Story 4.6; keep them in `impl.types.ts` so they cannot be called around the facade.
  - File naming: `impl.router.ts` and `impl.next.ts` export components (`Link`, `Redirect`) but are `.ts`, while 2.1/4.2 also list `Link.tsx` and `Redirect.tsx` as shared files. Say which components are impl members and which are shared, or rename to `.tsx`.
- [ ] **Story 2.9 / 4.7 (duplicate fakes, hollow contract case)** — There is an in-memory fake in `impl.storybook.ts`, another in `testing.tsx`, and a global jest stub. Reuse one in-memory impl for Storybook and Jest. The `impl.next.ts` NavContract case runs against a mocked `next/navigation`, so it proves the mock, not Next; real parity comes only from the Next-baselined e2e specs (7.1-7.4). Say so in 4.7.
- [ ] **Story 4.5 (announcer coupling)** — The announcer must read `document.title` (or take a `titleFor` prop from `app`), never import `route-meta`, or the lib -> app boundary breaks. Add that as an AC, and note the timing risk: the title must be set before the announcer reads it (S4 covers the `<title>` vs `useEffect` result).
- [ ] **Story 5.1 (VePlugin invalidation)**
  - Key the memo on content hash, or size + mtime in ns, rather than mtime alone (coarse granularity after checkout and CI restore).
  - A memo only makes a *re-requested* dependant correct. It does not make Bun re-request dependants of an edited token file, and Bun's `onLoad` has no `addWatchFile`. State the fallback if S2 shows dependants are not reloaded (full reload on `*.css.ts` change), instead of treating "memo mandatory" as the fix.
  - Bound the dev-side cache for the 1.5 GB RSS criterion.
- [ ] **Story 5.4 (FOUC generation)** — Three paths produce the theme script: Next `layout.tsx`, prod `html.ts`, and dev `theme-boot.ts` (a module script, so a flash is accepted and documented). Name the shared function's module and require it to be a pure string builder over a `ThemeMap` argument with no import of `theme.css.ts` (otherwise `build/` has to evaluate VE outside the plugin). Also: `index.html` placeholder is an HTML comment, `<!--THEME_BOOT-->`, and Bun's HTML minifier may strip comments before `html.ts` post-processes the output (UNVERIFIED). Use a non-comment placeholder such as `<script id="theme-boot"></script>`, and have S1 check it survives minification.
- [ ] **Epic 9 / Story 7.x (WEB_BUILD residue in tests)** — Section 7 has specs branch on `process.env.WEB_BUILD === "bun"` and record Next-baseline fixtures. Stories 9.2/9.3 delete `WEB_BUILD` from Makefile/CI, and 9.3's grep covers `CLAUDE.md docs .claude project_plans README.md` but not `tests/`. Add a task to remove the conditionals, convert fixtures to plain assertions, and extend the grep to `tests/`. Likewise `docs/how-to/web-dev-server.md` and the `process.env.WEB_BUILD` use in `test-server.ts`.
- [ ] **Story 8.2 (rollback claim)** — The "one-line flip" revert is true for the Makefile and workflow YAML, but the required-status-check names change with the matrix default, and branch-protection settings are not in git. Add the branch-protection edit to the 8.2 rollback steps.
- [ ] **Story 5.7 (tsc coverage)** — `tsconfig.json` aliases `@/lib/nav/impl` to `impl.next.ts` and `tsconfig.bun.json` aliases it to `impl.router.ts`, but each config must still include the non-selected impl so it is type-checked against `impl.types.ts`. Add an AC that `tsc -p` for each config also compiles the other impl (a `satisfies NavImpl` assertion in each impl file does this). Also say whether Jest needs a `moduleNameMapper` entry for `@/lib/nav/impl` (the global stub hides it for most tests, but the contract tests import impls directly).

## Nitpicks
- Story 3.3 says the shared-hash script keys on `bun.lock` while Story 4.1 and others depend on #1100's lockfile location, which is listed as an Unresolved Question. Make Story 3.3 depend on resolving it.
- `WebBuildMode` is a TypeScript union in `build/` but also lives as a Makefile variable and YAML matrix values; there is no single source. Acceptable for a bounded dual period, but have `launch.ts` and `test-server.ts` import one `WebBuildMode` parser.
- D1 (unknown path shows not-found instead of the sessions page) is a deliberate behaviour change; keep it excluded from the parity claim as written.
- Story 6.2 preserves the `boundaries` rules via a multiset diff; also assert the `lib` -> `app` disallow still fires on a fixture, since that is the rule this plan leans on.
