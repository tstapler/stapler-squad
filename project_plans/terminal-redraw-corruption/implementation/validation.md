## Test Stack

- **Unit**: Jest 29+ (`jest.useFakeTimers()` for throttle-window timing) with `@testing-library`-style assertions where applicable for the frontend (`web-app/src/lib/terminal/__tests__/TerminalStreamManager.test.ts`); Go's built-in `testing` package with table-driven subtests (`t.Run`) for the backend (`session/tmux/control_mode_dispatch_test.go`), using the existing `newDispatchTestSession` harness pattern. `test.failing(...)` (Jest's built-in inverted-expectation API) is used once, intentionally, for the Phase 1 pre-fix repro pin — not as a general pattern.
- **Integration**: Same two frameworks, exercising real data-flow boundaries within a single process rather than mocking across them — frontend: raw byte chunk → `isFullRedraw`/classifier → `summarizeEraseFootprint` → `isFootprintCovered` → `RedrawThrottler.process()`'s actual flush/coalesce branch → `onFlush` callback (the real callback passed to the throttler in tests, not a bypassed unit); backend: `broadcastControlModeUpdate` → real `chan []byte` subscriber channel → drain, including one genuine concurrent-goroutine race test (`go test -race`) rather than a single-threaded call-and-assert. No ConnectRPC/browser/xterm.js instance is spun up — "integration" here means "crosses an internal data-flow boundary inside the unit under test," not full end-to-end; a true end-to-end (server capture → wire → xterm.js render) check is out of scope for this plan and is instead covered by Task 1.3.1c's manual live-repro checkpoint.
- **API/E2E**: Not applicable to this plan. No new RPC surface or UI is added (Epic 1.2's counter accessor is test-visible only, not wired to a metrics/RPC surface per its own acceptance criteria). The manual live-repro checkpoint (Task 1.3.1c) is this plan's substitute for an automated E2E test, per the Success Metrics' explicit "reproducible manual verification procedure, if an automated repro proves impractical" allowance.

## Coverage Targets

- Unit test coverage: ≥80% (line) for the touched functions in `TerminalStreamManager.ts` (`isFullRedraw`, `summarizeEraseFootprint`, `isFootprintCovered`, `RedrawThrottler.process()`) and `control_mode.go` (`hasEraseSequence`, `controlModeEvictStaleEnabled`, the `broadcastControlModeUpdate` `default:` branch)
- All public service methods: happy path + error paths — covered above for `RedrawThrottler.process()` (flush-before-replace vs. coalesce-replace) and `broadcastControlModeUpdate` (evict-stale vs. refuse-to-evict-erase vs. revert-flag-disabled)
- All external integrations: unit mocked (pure-helper tests for `isFullRedraw`/`summarizeEraseFootprint`/`isFootprintCovered`/`hasEraseSequence` in isolation) + at least one integration test per boundary (the `RedrawThrottler.process()`→`onFlush` chain; the `broadcastControlModeUpdate`→channel→drain chain, including the `-race` concurrent test)
