# ADR-009: Expensive tests (Playwright e2e first) join the Bazel graph through observed-dependency slices, with selection on every PR and a full run as the safety net

**Date**: 2026-11-02
**Status**: Accepted 2026-11-05 with the "Full e2e run" outcome: spike S14 (Story 0.15) is `Fail` (selected-share median 1.00 at package, file and line granularity; S-e start-up 18.4 s against the 3.5 s limit; zero-miss claim not established; `implementation/spike-results.yaml`), and the owner chose "Full e2e run" (AskUserQuestion, 2026-11-05, recorded in `implementation/owner-attestations.yaml` as `adr_009_e2e`): e2e stays a full run in CI, with no e2e selection, so Epic 12 is not released and the selective-e2e parts of the Decision below are not adopted. The directive applies to the Go, Jest and integration layers. Original status: Proposed (owner directive 2026-11-02; was to become Accepted at Story 0.14 if spike S14, Story 0.15, passed). Amends ADR-005 (see "Amendment to ADR-005"; that amendment is not applied).
**Context**: Owner directive: "structure Bazel so that only the dependencies that update have to re-run their tests, helping us prevent running all of our really expensive tests for every change."

## Evidence

All numbers are recounted from the repo or the measured baselines; the commands are in `implementation/plan.md` Story 0.15.

- **The expensive suite is e2e.** `tools/bzl/baseline/measured.json` (worktree `bazel-epic0`, run 2026-11-02): CI time-to-green p50 2339 s; RA2 non-Go share of the critical path 0.987 (e2e median 1974 s, runner queue/setup 398 s, lint 0 s, other 34 s of a 2601 s median span). Two recent PR runs of `build.yml` (runs 41383118588 and 41386449418): five Playwright shards of 1030-1949 s each, about 6,800 shard-seconds (about 113 runner-minutes) per PR, against a partial-change PR class median of 184 runner-minutes (`partial_class.runner_min_p50`), so e2e is about 60% of the runner-minutes (INFERRED from two runs; Task 0.1i computes it properly).
- **Today every relevant PR runs everything.** `build.yml:97` runs the whole suite (193 spec files, three Playwright projects: `chromium`, `chromium-dom`, `mobile-chromium`; `tests/e2e/scripts/run-ci-shard.sh`, `E2E_SHARD_TOTAL: 5`, `E2E_WORKERS: 3`) whenever any `.go`, `web-app/src/`, `proto/` or `tests/e2e/` file changes. There is no per-spec selection.
- **E2E is not a strict gate today.** On PRs `e2e-bun` fails only on a crashed or empty shard; per-test failures are report-only, and on `main` the verdict is a comparator against `tests/e2e/baseline/next-e2e-baseline.json` (`build.yml` around the "Run the baseline comparator" step). That baseline records 357 failing and 78 flaky of 2,693 test instances (`meta.counts`). Any caching or selection scheme must be defined over the comparator verdict, not the raw exit code.
- **The binary embeds everything.** `tests/e2e/helpers/test-server.ts:63-77,126` takes the server from `TEST_SERVER_BINARY` or builds it with `make stapler-squad`; that binary links all ~3,700 Go files and `go:embed`s `server/web/dist`. If the binary were a declared input of an e2e test target, any Go or web change would change every target's cache key and `rdeps` would select every target. That is the core Bazel problem.
- **The existing feature registry cannot drive selection by itself (measured).** Using `// @feature` headers (188 specs) plus `FEATURE_CATALOG[...]` references (5 more) against `docs/registry/features/**`, `backend-features.json`, `frontend-features.json` and `web-app/src/lib/features/features/*.ts`:

| Measure (193 specs) | Count | Share |
|---|---|---|
| Specs carrying at least one feature id | 193 | 100% |
| Specs with at least one id that resolves in the registry or catalog | 119 | 61.7% |
| Specs whose every id resolves | 80 | 41.5% |
| Specs resolving to at least one source file that exists | 102 | 52.8% |
| Specs resolving to a Go file / to a web file | 55 / 68 | 28.5% / 35.2% |
| Distinct ids used / not resolvable | 238 / 106 | 44.5% unresolvable |

  Registry entries point at one handler or component file (a marker location), not at a dependency closure. Replayed over the last 100 first-parent commits on `main`: 66 touch non-test Go or web source, and only 5 of those have every changed prod file in a directory that some spec declares, so a registry-only selector would fall back to "run everything" for about 92% of code commits (61 of 66). 59 of the 66 (89%) touch `session/`, `server/` or `config/`, the packages most likely to sit in every spec's slice; whether they do is exactly what spike S14 measures. `tools/ci/detect-feature-changes.sh` is not a selector: it sets one boolean (`RECORD_FEATURES`) if any changed file carries a marker.

## Options

| Option | What it is | Soundness | Cost | Verdict |
|---|---|---|---|---|
| A. Bazel-native per-feature test targets with feature-scoped `data` | Each spec group is an `e2e_test` target whose declared inputs are a slice (Go packages, web files, protos); the binary arrives out of band (`--test_env`) so it does not enter the key | Sound only as far as the slice is complete; a dependency missing from the slice means a stale green | M to build the graph, but the slice source decides everything | Right structure, wrong slice source if the slice is the hand registry |
| B. Selection layer only | `bazel-diff`/`target-determinator` plus the registry computes affected specs; CI runs those; no Bazel cache for e2e | Same completeness question; no rerun reuse | S to M | Needs the same mapping as A; registry alone is about 90% fallback (measured) |
| C. Per-feature server binaries | Split the server into several binaries so each test depends on a small one | Sound by construction | Infeasible: one `main`, `server/server.go` wires every service, one `go:embed` of the whole web dist, out of scope by requirements ("no application rewrite") | Rejected |
| D. Hybrid | Bazel-native for fast layers (Go unit, Jest, axe) plus registry-driven selection for Playwright, periodic full run | Depends on the Playwright selector | S | Directionally right, still leaves the slice source open |
| **Recommended: D, with Playwright encoded as A-style slices generated from an observed-dependency manifest** | Instrument the server with `go build -cover` and the browser with V8/route capture, run each spec once, record the Go packages, web files, RPCs and routes it actually touched, generate `e2e_slice` targets from that manifest, select with `bazel query rdeps`, keep a full run on `main` and nightly | Sound for what a spec executed plus the static import closure of those packages plus a declared global-input list; unsound only for state outside the slice (see Residual risk), bounded by the nightly full run and an escape detector | M overall (Epic 12) | Recommended |

Why the observed manifest and not the registry: it is measured instead of hand-declared, it covers the startup path every spec shares (so the core packages appear in every slice automatically, which is correct), and the registry stays as the human-readable seed and a cross-check (declared handler packages must appear in the observed set).

## Decision

1. **Graph shape.** `tests/e2e/BUILD.bazel` (generated by `tools/bzl/e2e/gen-build.py` from `tests/e2e/slice-manifest.json`) declares one `e2e_test` target per spec group (grouped by filename family so one server boot is amortised across several specs; `backlog-*` has 29 specs, `session-*` 19, `scroll-*` 13). Each target depends on an `e2e_slice` made of: the observed `go_library` labels (their transitive deps come from Gazelle's graph, which gives the static import closure for free), the observed web source files, the proto files of the observed RPCs, the spec sources and helpers, and `//tests/e2e:global_inputs`. It does **not** depend on `//:stapler-squad`, `//server/web:dist` or the embed staging targets; a check (Task 12.3b) fails if `bazel query 'deps(//tests/e2e:all)'` contains them.
2. **Binary seam.** The server is built once by `bazel build //:stapler-squad` (same invocation, same commit) and handed to the tests as `--test_env=TEST_SERVER_BINARY=<abs path>` (the variable `test-server.ts` already honours). The path is constant so it does not change the key; the wrapper refuses to run if the binary's embedded git revision differs from `HEAD`. This is a deliberate, documented gap between the declared and the real dependencies; it is the one place the graph is told less than the truth, and the manifest plus the safety nets below carry the soundness burden.
3. **Selection.** On a PR, `tools/ci/affected-e2e.sh` maps the diff with `bazel query 'rdeps(//tests/e2e:all, set(<changed files>))'`. Any change to a `GlobalInputs` file (`go.mod`, `go.sum`, `MODULE.bazel*`, `.bazelrc*`, `proto/**` outside an observed RPC, `server/web/embed.go`, `tests/e2e/{playwright.config.ts,global-setup.ts,helpers/**,fixtures/**,bun.lock}`, build-tag config) selects every target. A spec with no manifest entry (new spec, not yet observed) is `unmanaged` and always runs. Selected targets are distributed over the existing five runners by recorded duration (bin packing), not by Playwright `--shard`.
4. **Cache.** Test results go through Bazel's normal test cache: only a passing result is reused (INFERRED, checked in Story 0.15), the PR jobs use the read-only endpoint of ADR-004 and never write, and the `main` push job writes. Because selection is done by `rdeps`, the cache serves reruns, retries and `main` re-runs of an unchanged slice; it is not what decides what runs on a PR.
5. **Verdict.** An `e2e_test` target passes iff the Playwright JSON report has no failure outside the baseline and expected-diff lists for the specs in that target (the existing comparator logic, `scripts/e2e-baseline-compare.ts`, run per target), so the Bazel verdict equals today's `main` verdict.
6. **Safety nets (required for the flip).** (a) Nightly full run on `main` with `--nocache_test_results`, in the existing `nightly.yml`; (b) an escape detector that, for every nightly or `main` e2e failure, checks whether the spec was selected on the PR that introduced it, files an issue naming the missing slice edge and widens the manifest; (c) the selective job is non-blocking and runs beside the full suite (shadow) until escapes are 0 over the soak window; (d) the full suite stays authoritative on `main` pushes.
7. **Other expensive suites** (Story 12.7): Jest, the Go integration/`mcp-integration` tests and the axe/Lighthouse jobs get the same treatment, but with the Bazel graph as the slice (they are Bazel-native tests in Epics 3-4, so no manifest is needed). Lint (`lint.yml`, p50 1033 s) stays outside under ADR-005.

## Bazel facts relied on

- VERIFIED-IN-DOCS (https://bazel.build/reference/be/common-definitions, "tags"): `external` "will force test to be unconditionally executed (regardless of `--cache_test_results` value)"; `no-cache` "results in the action or test never being cached (locally or remotely)"; `local` precludes remote caching, remote execution and sandboxing; `exclusive` runs a test alone after the build; `manual` excludes a target from `...` expansion; `requires-network` / `block-network` control sandbox network (loopback stays allowed with `block-network`).
- VERIFIED-BY-RUN (`research/bazel-docs-best-practices.md`, Bazel 9.3.1): `--cache_test_results` default `auto`; `--runs_per_test` disables result caching; `--flaky_test_attempts` marks multi-attempt passes FLAKY; sharding is the rule attribute `shard_count`.
- VERIFIED-BY-RUN (this host, `go help build`): `go build -cover` exists; `go doc cmd/covdata` documents the coverage-data tool for programs and integration tests. Go's documentation page for this feature is https://go.dev/doc/build-cover (not re-read in this pass; Story 0.15 exercises it on the real server).
- INFERRED, each with a check in Story 0.15: (i) a test target's cache key covers its runfiles, its `--test_env` values and its command line, so a source file in a declared `data`/`deps` slice changes the key and one outside it does not; (ii) a failed test result is not served from the cache on rerun (`auto` mode reruns failed tests) and is not uploaded to the remote cache; (iii) a constant `--test_env` path does not change the key when the file behind it changes; (iv) `bazel query rdeps` over source-file labels finds targets that list the file in `srcs`/`data` transitively through `go_library` deps; (v) per-target Playwright invocation overhead (server pool start, browser start) is at most 15% of the target's wall time.

## Soundness, flake and trust policy

- **What makes a selective result trustworthy**: slice completeness (observed manifest plus static closure plus global inputs), the nightly full run, the escape detector, and a CI check that every spec has a manifest entry (`unmanaged` specs always run and the list must be empty within one nightly cycle) and every `@feature` id resolves (advisory for the registry, blocking for manifest freshness of changed specs).
- **Residual risk (accepted, bounded)**: a dependency that the observed run did not exercise and the static closure does not include, for example behaviour reached only on a code path the spec did not hit this time, a runtime-read file outside the slice (config templates, `~/.stapler-squad` state), an environment variable, a tmux or git version, a Playwright browser update (browsers come from the pinned image tag, declared through `bun.lock`), or a new RPC wired through an unobserved handler. The nightly full run and the escape detector bound the exposure to one nightly cycle for `main`; PRs can merge a regression that the next nightly catches, which is the accepted tradeoff until the escape count over the soak window is zero.
- **Flakes**: the 78 flaky and 357 baseline-failing instances are handled by the comparator, not by retries in Bazel. A spec that fails twice in the last 10 `main` runs enters `tests/e2e/quarantine.json` (owner, issue, expiry of 30 days, checked by Task 12.5d): its target is tagged `no-cache` and its failure is report-only until fixed, matching repo policy to fix flakes. `flaky = True` and `--flaky_test_attempts` stay banned (pre-mortem #3 control, Task 4.2a). A cached pass of a spec that is merely lucky is possible; it is bounded by the nightly `--nocache_test_results --runs_per_test=3` job of Task 4.9c, which now includes the e2e targets.
- **Cache poisoning (ADR-004)**: e2e test results are cache entries like any other and follow ADR-004 unchanged: PR jobs hold only the read-only endpoint, so a PR key can never be written; the write path is `main` push only. Selection does not rely on the cache, so an unreachable cache degrades to "run the selected targets", not to "run nothing".
- **Pre-mortem #3 (false-green) and P1-P10**: the false-green controls are extended, not replaced, by the escape detector and the nightly. P7 (Playwright pass count against the Bazel binary equals the make binary) stays and now runs the full suite once through the Bazel targets (`--nocache_test_results`, all targets) as well as the legacy runner. P10 gains the T8 row (e2e work avoided); T8 includes `e2e_escapes = 0` over the soak window.

## Amendment to ADR-005

ADR-005 does not list Playwright in its exception table; the plan's actual position before this ADR was that e2e stays a separate CI job that consumes the Bazel binary (P7, Task 7.6b) and is outside the Bazel graph. This ADR changes that: **e2e execution and selection move into the graph** (Epic 12). What stays outside Bazel from ADR-005, unchanged: the otel variant, macOS codesign, diff/history gates, golangci-lint, release-please and deploy workflows, goreleaser/Formula, and the feature registry generator (`make registry-generate`, which now also serves as a cross-check input, not the slice source). What also stays outside Bazel for e2e: the Playwright browsers and OS libraries (the pinned container image, version taken from `tests/e2e/bun.lock`), `bun install` of `tests/e2e`, and the visual-regression/perf/secondary-browser projects that run only in `nightly.yml` (they remain full runs). Adding the Playwright image to the "tools Bazel does not track" list needs the image tag as a declared input, which Task 12.2b does.

## Consequences

- New Epic 12 (7 stories, 19 tasks) and spike Story 0.15 (S14, 4 tasks); Epics 1-11 are not renumbered. Epic 12 depends on Stories 3.1, 3.4, 4.1-4.2, 7.3, 7.4 and the P7 parity script (Task 7.5b); Story 12.6 (making selective e2e blocking) is gated by the Story 7.6 soak.
- Improvement target T8 (e2e runner-minutes per partial-change PR) is added; RA2/EG5 are re-expressed over the share that remains after e2e selection; the measured 0.987 is the reason for this ADR.
- If S14 fails (median selected share above 0.50, or any missed failure in the mutation backtest), the recorded fallback is a coarser slice (package prefix plus declared registry sources, expected to select more) or diff-line coverage selection (heuristic, tighter, needs a larger escape budget); the owner decides before Epic 12 is released. If both fail, the e2e suite stays a full run and the goal is met only for the Go, Jest and integration layers; this is the main way the directive could be unattainable.
- An ongoing cost: the manifest must be regenerated when specs or features change; the nightly regeneration job and the staleness check make that automatic, but it is a new piece of infrastructure to own.
- Package granularity (ADR-010, 2026-11-02): risk 1 (core packages in every slice) has a refactor mitigation, Epic 13, whose clusters are chosen by criterion SC5 from this ADR's manifest. Measured before S14 (INFERRED universal-slice proxy): 71% of recent Go production commits touch `session`, `server/services`, `server`, `config` or the root package, and the criteria-selected splits are predicted to lower that to 61% (last 100) and 58% (last 500). Epic 12 does not depend on Epic 13; the Story 12.4 replay is re-run at Story 13.7 to record the effect. An alternative with no code movement is a file-level slice (ADR-010 Decision 7).
