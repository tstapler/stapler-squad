# Pre-mortem: bazel-conversion
**Date**: 2026-11-01

Frame: it is three months after Story 8.6 (default flipped to Bazel). The migration "shipped" (parity P1-P10 passed, soak met) and is judged a failure. The plan already closes the review findings in its Review disposition table, so this list targets what survives: steady-state behaviour after the gates stop running, and assumptions the gates never test.

## Host facts used (VERIFIED by command on 2026-11-01)

- `hostname` prints `onyx`: the machine that will run `bazel-remote` is the same machine as the dev box, the live service (`:8543`, `:8444`), every agent worktree and the e2e runs. ADR-004 treats onyx as a separate "server"; operationally it is one host.
- `nproc` = 24; `free -g`: 61 GB total, 31 used, 8 free, 27 buff/cache; `uptime` load 2.95/3.91/6.68; `/tmp` is a 31 GB tmpfs (shares RAM); `/` is 1.9 TB, 67% used, 614 GB free (one filesystem for worktrees, `~/.stapler-squad` state and the future cache).
- `git worktree list | wc -l` = 107; `ls ~/.stapler-squad/workspaces/*/worktrees | wc -l` = 72.
- `git log --since='30 days ago' | wc -l` = 551 commits (about 18 per day) landing from agent PRs.
- Plan grep (no match) for `cache_test_results|no-cache|"external"|remote_download|toolchains_protoc|circuit_breaker|systemd-run|OOMScore|flock`: none of these appear in plan.md.

Verify: `bash tools/bzl/wrapper_test.sh` starts 6 invocations and asserts at most 2 run concurrently and that `systemctl --user show` reports the `MemoryMax`.
