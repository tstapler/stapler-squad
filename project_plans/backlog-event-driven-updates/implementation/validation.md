# Validation Plan: backlog-event-driven-updates

**Date**: 2026-07-21

## Happy Path Scenario

Given an operator has `/backlog` open showing an item in `in_progress` status (per requirements.md's Baseline), when the `ReconcilePRPending` reconciler calls `storage.TransitionBacklogItemStatus(ctx, itemID, "done", "in_progress")` directly (no RPC handler involved, simulating an autonomous merge-completion transition), then the open `/backlog` view's card for that item updates in place to show `done` within a few seconds — via a `BacklogItemStatusChangedEvent` pushed over the new `WatchBacklogItems` stream and applied by `upsertBacklogItem` — with no manual refresh, no page reload, and no row remount.

This scenario is the backbone for R4 (status-transition publish hook), R9 (handler live fan-out), R10 (reducer upsert), R12 (hook consumption), R13 (list-view wiring), and UX criteria #1, #6, #7.

## UX Acceptance Tests

Implementation model: the `ui-playwright` skill, following this repo's existing `tests/e2e/` conventions (`.claude/rules/e2e-test-conventions.md`) — `@feature`-mapped `FEATURE_CATALOG` import header, `test.describe`/`test` blocks with plain descriptive names (not the Go `should_When` convention — confirmed against `tests/e2e/backlog.spec.ts` and `tests/e2e/review-queue.spec.ts`), `data-testid`/ARIA-role locators only, no `waitForTimeout` (use `expect(locator).toHaveValue`/`toBeVisible`/`waitForSelector`), and new page-interaction helpers added to `tests/e2e/pages/` (e.g. extend `BacklogPage`, add a `SessionDetailPage` helper if none exists for Surface 4).

All new specs need a `docs/registry/features/frontend/*.json` entry per `.claude/rules/feature-registry.md` once implemented — not designed here, tracked as a Phase 8 governance item (see Coverage Targets).

## Test Stack

- **Unit (Go)**: standard `testing` package + table-driven style already used throughout `session/*_test.go` and `server/services/*_test.go`; in-process `*events.EventBus` instances (no mocking framework needed — the bus is already dependency-free per its design). Naming convention: `TestXxx_should_<expectedBehavior>_When_<condition>`, confirmed against existing house style (`session/backlog_remediation_test.go`, `session/backlog_stuck_migration_test.go`).
- **Unit (TypeScript/Jest)**: Jest + React Testing Library, following `web-app/src/lib/store/__tests__/reviewQueueSlice.test.ts`'s `describe`/`it` plain-English convention (not the Go should/when convention — frontend tests in this repo do not use it). Redux slice tests use a real `configureStore` instance (not a mocked reducer), mirroring `reviewQueueSlice.test.ts`'s `makeStore()` helper.
- **Integration**: Go tests that exercise a real ent-backed repository + a real `*events.EventBus` together (no mocked bus/DB in these); TypeScript tests that combine the hook + reducer + a mocked transport layer (mocked at the network boundary, not at the Redux/hook boundary) — mirrors the existing `useReviewQueue.test.ts` pattern.
- **E2E / UX**: Playwright, per `tests/e2e/` conventions (`.claude/rules/e2e-test-conventions.md`) — `@feature`-mapped `FEATURE_CATALOG` header, `test.describe`/`test` blocks, `data-testid`/ARIA locators only, no `waitForTimeout`, new page helpers added under `tests/e2e/pages/`. New spec files: `backlog-live-updates.spec.ts`, `backlog-board-live-updates.spec.ts`, `backlog-detail-live-updates.spec.ts`, `session-detail-backlog-panel.spec.ts`, `backlog-connection-indicator.spec.ts`, `backlog-edit-buffering.spec.ts`; extend existing `accessibility.spec.ts` for the 4 cross-cutting a11y criteria (#4, #5, #12, #26, #29–33) rather than duplicating an a11y suite per surface.
