## Decision

1. **One choke point; six raw writers closed; two exempt classes.** `Storage.GatedTransition(ctx, TransitionRequest)` (package `session`, new file `session/transition_gate.go`) is the only code that may call a raw status writer.
   - **Naming and compile guarantee, stated accurately.** (a) The five `EntRepository` writers (`TransitionBacklogItemStatus`, `ArchiveBacklogItem`, `UnarchiveBacklogItem`, `TransitionBacklogItemStatusWithPRFields`, and the write half of `ReconcileStuckItems`) are **unexported** (`rawTransitionBacklogItemStatus`, `rawArchiveBacklogItem`, `rawUnarchiveBacklogItem`, `rawTransitionBacklogItemStatusWithPRFields`; `ReconcileStuckItems` is split into an exported read-only `FindStuckInProgressCandidates` plus per-item writes through `rawTransitionBacklogItemStatus`). Non-test callers are only `storage.go` and `backlog_lifecycle.go:1256` (VERIFIED by `git grep`); the test callers are 28 calls in 7 files in package `session` plus one in another package, `server/services/backlog_item_event_publisher_test.go:258` (`repoA.TransitionBacklogItemStatus` on an `*EntRepository`), which Task 1.5.4e rewrites to go through a `Storage`. After the change a call from `server/*` is a compiler error, and the `server/services` import of `*session.EntRepository` (`session_service.go:1190`) cannot reach them. (b) The `Storage` wrappers are renamed `RawTransitionBacklogItemStatus`, `RawArchiveBacklogItem`, `RawUnarchiveBacklogItem` and `RawSetBacklogItemPRAndTransition` and **stay exported** until the last test outside package `session` stops needing them; that is why, for the `Storage` layer, the guarantee is "every old name fails to compile, so each caller is edited deliberately" plus the strict guard in Decision 9, not a compiler wall. (c) `Gated*` entry points: `GatedTransition`, `GatedArchive`, `GatedUnarchive`, `GatedSetPRAndTransition`, `GatedReconcileStuck`, all delegating to one decision function.
   - **Exempt entry points (counted, never engine-checked)**: `Rollback` (restores a prior status after a failed multi-step operation; requires `ExpectedStatus`; `caller` class `rollback`), `DebugForce` (debug mutate handler; operator-only endpoint; `caller` class `debug`), and the exempt class `create` below.
   - **Exempt class `create`.** `CreateBacklogItem` has no `from` status and no edge, so it is not a transition and the engine has nothing to decide. It is exempt but constrained: (i) the constraint is static, not a runtime rejection: a runtime check in `Storage.CreateBacklogItem` was rejected because about 300 test fixtures in 93 test files (`git grep -A6 'CreateBacklogItem(ctx, ' -- '*_test.go'` with a non-idea `Status:`) create items at `review`, `done` and so on. Instead the strict inventory test (Decision 9) asserts that every non-test `CreateBacklogItem` call either sets no `Status`, sets `BacklogStatusIdea` (an entry stage, `builtInEntryStages`, `session/workflow_stage_seed.go:49`), or sits on the allow-list; the seven production creators pass `idea` or nothing (VERIFIED above), so behavior is unchanged in every mode and no agent or RPC input can choose a creation status; (ii) the debug seed and mutate handlers use a named `Storage.CreateBacklogItemForDebug` (any status, counted as `workflow_engine_bypass_total{caller=debug_create}`, operator-only like the rest of the debug surface); (iii) the inventory lists all creators as `create` or `exempt: debug` with a reason. Exempt is safe because the only non-entry creations are the operator-only debug endpoints, and everything created afterwards can move only through the gate.
   - The exempt set is therefore: 3 rollbacks plus 2 debug transition sites (`backlog_debug_mutate_handler.go:172,253`) = 5 exempt transition sites, plus the `create` class. Say it this way everywhere.
2. **Caller registry.** Every call into the gate names a `TransitionCaller` registered in a closed table (`session/transition_callers.go`): `{name, class, legacy, guards, edges, forwarding}`.
   - `class`: `operator` (a human acting through UI/RPC), `agent` (an AI session acting through MCP), `system` (reconciliation, lifecycle, pollers, sync, auto-reopen/respawn, triage pipeline, autonomous completion).
   - `legacy`: `Engine` (the path asks the engine today; Off and Shadow reproduce the Default engine's answer for the methods it calls today) or `Unchecked` (a bare storage write today; Off and Shadow reproduce "allow").
   - `guards`: `BuiltIn` (Default `TransitionGuard` applies) or `None`.
   - `edges`: the `(from,to)` pairs the caller can request. `to=archived` callers declare the wildcard `*->archived`.
   - `forwarding`: true only for a caller that forwards an edge somebody else requested instead of a fixed edge of its own. Exactly one entry is `forwarding` (`mcp_transition_delegate`, the generic MCP `transition_backlog_item_status`, which delegates to the handler with actor `agent`, `tools_backlog_dependencies.go:163`); a test pins that the set of `forwarding` entries is that single name, so a second generic forwarder needs a deliberate registry change. **How a shared-handler request becomes class `agent` (round 5, ADV-N2)**: the delegate calls the same `BacklogService.TransitionBacklogItemStatus` handler as the UI, and the handler is the only `GatedTransition` call site for that RPC. The handler resolves the registry caller from `transitionActorFromContext(ctx)` (`backlog_service_lifecycle.go:838`; the context key is an unexported type set only in-process by `WithTransitionActor`, so a request cannot choose its own class): actor `agent` gives `mcp_transition_delegate` (class `agent`), the default `user` gives `operator_transition_rpc` (class `operator`), any other value fails closed to the `agent` class, which ignores `override_reason`. The `forwarding` entry is exempt from the "every registry entry has a call site" rule because the delegate itself makes no `Gated*` call; its coverage is a handler caller-resolution test plus `TestMcpTransitionDelegate_UsesAgentClassAndGraph_WhenActorAgentAndEdgeDisabled`.
3. **Class semantics (what the enforced answer is).**

| | graph | Default built-in guards | Configured operator gates | `override_reason` | on denial |
|---|---|---|---|---|---|
| `operator` | Configured graph UNION `SystemRequiredEdges()` | yes | yes | Default guards get the input unchanged (their own, narrower override semantics preserved); a non-empty reason additionally bypasses Configured operator gates, never the graph and never a Default guard that ignores override (ADR-001, W0 errata) | error to the human; no stuck reason |
| `agent` | same | yes | yes | ignored (an agent must not bypass a `human_approval` gate) | error to the agent with a next-step hint, plus reporter call |
| `system` | same | per caller registry (`BuiltIn` only where the path asks for guards today: `transitionWithGuard` callers, `AttachSessionToItem`; otherwise `None`) | yes | none exists | reporter call; the caller's own handling still runs |

   Why `system` evaluates operator gates: a `human_approval` or `automated_review` gate on `pr_pending->done` is exactly the lever an operator uses to stop automation from shipping unreviewed work. If automation ignored gates, editing a gate would change nothing for the most important caller class and Metric 1 would again be partly fiction. The cost is that a gate the operator forgot to satisfy denies the automated transition; that is surfaced, not swallowed (Decision 5). Why `system` skips Default built-in guards by default: those guards (AC present, plan approved, PASS verdict, code on main, no blockers) encode preconditions for a human-initiated move with `override_reason` as the escape hatch; a PR-merge reconciler has no human to override and already carries its own preconditions through CAS and site logic. Applying them would change shipped pipeline behavior beyond what the owner asked to make configurable. The pre-existing "autonomous completion skips the AC gate" gap stays recorded, not widened.
4. **System-required edges: fixed callers only; forwarders are governed like the operator.** An edge is system-required (cannot be disabled; unioned into the enforced graph) iff some registry entry with class `agent` or `system` and `forwarding=false` declares it. Consequences, decided explicitly:
   - **The generic MCP transition delegate (`forwarding=true`) is EXEMPT from this rule.** It forwards whatever valid edge the agent requests, so declaring "every edge" would make every edge un-disableable and the editor would reject all edits. It is governed like `operator` for the graph (a disabled edge denies it), with class `agent` for guards, gates and `override_reason`. Only the purpose-specific agent tools register fixed edges: `request_review`, `report_blocked`, `resume_work`, `report_duplicate`, `report_pr_created` (exact edges fixed by Task 1.5.1a against each tool). This keeps the Story 1.5.1b edge audit non-vacuous: it asserts every non-forwarding `agent` or `system` entry has a non-empty edge set that is a subset of `SystemRequiredEdges()`, and separately that the forwarding set is the pinned singleton.
   - **Archive edges.** Because every archive caller archives from any status, `*->archived` is declared by system and agent callers (`archiveStaleDoneItems`, `SyncLoop`, `reportDuplicate`) and by operator callers (the Archive RPC). `SystemRequiredEdges()` therefore returns `X->archived` for every built-in status X, and `IsSystemRequired(from,to)` also answers true for `to=archived` from any enabled custom stage slug and for `archived->archived` (the idempotent re-archive that `reportDuplicate` can hit). This is the single storage-direct group; the table `validTransitions` is **not** changed (Decision 7). Gates on archive edges stay editable and denials surface; only the graph edge itself cannot be disabled. Caveat (round 5, ADV-N4): four of these edges (`in_progress|review|pr_pending->archived` and `archived->archived`, plus custom-slug `to=archived`) have no row in the stage tables, so the Stages editor cannot show them or attach a gate to them; the owner decided on 2026-10-17 (option A) that archive-from-active is documented as UI-ungateable (an operator who needs a gate there attaches it to `done->archived`); virtual editor rows are not built. **Fallback path (round 5, ADV-N1)**: when `Configured` is nil, its cache is empty or the load failed, the enforced graph is Default UNION `SystemRequiredEdges()`, never plain Default, because plain Default lacks the four archive edges and Enforce would otherwise deny archive of an `in_progress`, `review` or `pr_pending` item (and `archived->archived`) on exactly the path meant to fail open. `SystemRequiredEdges()` and `IsSystemRequired` do not exist in the tree today (`git grep` returns zero hits); Task 1.1.2b creates the set and the union, and Task 1.5.1c adds the archive group.
   - Editing such an edge is a defined, visible rejection (Story 1.2.1), not a silent no-op, and gates on those edges remain fully editable. This is the one explicit carve-out of Metric 1; the plan lists it once in Unresolved Questions, and the PR template records the carve-out list generated from `SystemRequiredEdges()` (no hand-written copy).
5. **A denial is never swallowed.** On a denial for class `agent` or `system` the gate calls `TransitionDeniedReporter.Report(item, from, to, reason)` before returning the error. The interface lives in `session`; `server/services` supplies the implementation by adapting `transitionOrNotify` (Story 1.2.2). Reporting is idempotent per `(item, caller, from, to, reason)` (round 5, ARCH-C4: the caller name is part of the recorded denial and the key, so two different sources of one edge, for example `autonomous_complete` and `maybe_trigger_triage` on `idea->ready`, do not collapse into one report; the reporter signature is `Report(item, caller, from, to, reason)`): stuck reason `transition_denied` (structured `caller`, `from`, `to`, `denied_reason`), one progress comment, one `notify()`. A denial must also not cause *other* automation to churn: Decision 12.
   - **Reporting is guaranteed by a gate test, not by a lint rule (round 5, ARCH-C1).** The guarantee that no `agent`/`system` denial is swallowed is `TestGatedTransition_EveryAgentOrSystemDenial_ReachesReporter`: every denial source (`config_graph`, `default_guard`, `operator_gate`, `target_stage_removed`) crossed with every non-`operator` class records exactly one `Report` before the gate returns and writes nothing. A call-site lint cannot add to that, because the gate itself calls the reporter and the caller of an `agent`/`system` `Gated*` method has nothing left to surface; an earlier design that counted a selector containing `Report` as "surfacing" matched a call the caller never makes (it would flag about 40 migrated sites or be vacuous).
   - **The `silenttransition` analyzer still goes dark on rename unless extended, but only where a caller must handle the error.** `tools/lint/silenttransition/analyzer.go:63` keys on the method names `TransitionBacklogItemStatus` and `UpdateItemSessionEnded` (resolved to package `session` by type info, `analyzer.go:67-71,156-157`); after the rename no call carries the old name. Task 1.5.4f extends its target set to (a) the `Raw*` names (kept until the last caller moves; no reporter exists on that path) and (b) `Gated*` calls whose `Caller` resolves to an `operator`-class registry constant, or is not a constant (those callers return the error to a human and could drop or only log it), and does NOT apply it to `agent`/`system` `Gated*` calls. A test pins the analyzer's operator caller-name set to the registry. It moves the testdata fixtures (`testdata/src/github.com/tstapler/stapler-squad/session/storage.go`, `a.go`), adds a failing-then-passing operator-class fixture plus a log-only agent-class fixture that is intentionally not flagged, and re-checks the 8 `//nolint:silenttransition` annotations that sit on status-write calls (19 in total; 11 are on `UpdateItemSessionEnded` and are unaffected) as each migration story moves the call. Acceptance includes `make lint-custom`.
6. **CAS semantics: the gate carries the whole `BacklogItemPrecondition`.** `TransitionRequest` has `Precondition *BacklogItemPrecondition` (`ExpectedStatus`, `ExpectedUpdatedAt`, `Note` all preserved and passed through to the raw writer) and `TriggeredBy`. The gate decides on one observed `from`:
   - A caller that supplies `Observed *BacklogItemData` avoids a re-read; otherwise the gate reads once.
   - `ExpectedStatus` is derived as `from` when empty; a caller-supplied `ExpectedStatus` that differs from the observed status returns `ErrPreconditionFailed` without writing and without an engine call.
   - A caller-supplied `ExpectedUpdatedAt` is passed through unchanged (the handler sets it, `backlog_service_lifecycle.go:940-948`; `SetBacklogItemPRAndTransition` derives it from `observed.UpdatedAt`, `storage.go:1210`). When the request carries prebuilt `Guard` input read from item fields (Default built-in guards apply) and no `ExpectedUpdatedAt` was supplied, the gate sets `ExpectedUpdatedAt = Observed.UpdatedAt` so a status-only CAS does not leave the guard input stale; a mismatch is `ErrPreconditionFailed`. Callers with `guards=None` get the status-only CAS, which avoids spurious failures from unrelated `updated_at` bumps.
   - A caller that passed a nil precondition today (at least seven: `AttachSessionToItem` `:158`, `spawnSessionAfterGates` `:1268`, `forceResetItem` `:1324`, `autoReopenForPRFix` rollback `:2471`, `pushAndCreatePR` `:601`, `SyncLoop` `:450`, the debug handler `:172`) now gets `ExpectedStatus = from` derived. This adds one failure mode, `ErrPreconditionFailed`, to those sites; each has a test that a concurrent mover is treated as skip or retry, not an error log.
   - A request marked `Unconditional` (for example `forceResetItem`) re-reads and re-decides at most twice on `ErrPreconditionFailed`, so the engine decision and the written `from` always match.
   - Config edits are not serialized with in-flight transitions: a transition legal at check time may land just after an operator disables the edge. Same as today's handler; accepted.
   - `BeforeCommit func(ctx) error` runs after the engine allows and before the CAS, so the handler's push-branches-before-done step and the Archive RPC's push-before-archive keep their order; its error aborts the write. Post-write side effects (worktree cleanup after archive) run only after a successful write, never after a denial.
7. **Off-graph edges are decided, not assumed; the table is not changed.** Task 1.5.1b diffs every registry edge against `ValidTransitions()`. Resolution for a legitimate edge the table lacks (known: `in_progress|review|pr_pending->archived`, `archived->archived`) is to declare it in `SystemRequiredEdges()` (Decision 4), **not** to edit `validTransitions` or the seed. Why (all VERIFIED): (i) editing the table changes the Default engine, which every Off and Shadow path asks, so "all four flags off equals today" (Migration Plan, D11) would be false, and `session/workflow_engine_test.go:22` pins the opposite; (ii) `DefaultWorkflowEngine.AllowedTransitions` feeds the UI's `allowed_transitions` (`server/services/backlog_service.go:1048,1102-1109`), so Archive would appear on in-progress, review and PR-pending items on deploy; (iii) the seed is create-if-count-zero and never re-run (`workflow_stage_seed.go` header), so a table or seed edit would not reach the live database, and under operator Enforce the human Archive RPC on an in-progress item would be denied there. Unioning system-required edges at read time works on the live database as it is. A stale-seed test (live database without the archive edges still archives under every class's Enforce) pins it, and an empty-cache variant pins the fallback path (Decision 4: the fallback graph is Default UNION `SystemRequiredEdges()`). If the owner would rather have the table changed, that is Unresolved Question 1's alternative, not the default. A registry edge that is a caller bug is fixed in the caller.
8. **Rollout per caller class through the same selector.** Flags (live, bool, no env vars): `backlog:workflow-engine-shadow` (global, default on), `backlog:workflow-engine-enforce` (class `operator`), `backlog:workflow-engine-enforce-agent`, `backlog:workflow-engine-enforce-system` (all default off). `ModeFor(class)` = enforce flag for the class if on, else Shadow if the shadow flag is on, else Off. Why per class: the risk is asymmetric (operator moves have an `override_reason` escape hatch and a human watching; agent moves have no human; system moves can strand the autonomous pipeline), the sample volume and expected-edge lists differ, and each class needs an independent revert; the flag RPC is bool-only and the scope vocabulary is unverified for class keys (Task 0.1.1b). Recommended flip order: operator, agent, system. **Hazards are controlled by when the flag is registered, not by a runtime degrade clause (round 5, ARCH-C3)**: an earlier design degraded an `agent`/`system` class to Shadow when the reporter was unwired, and the `system` class when a process-wide `RecoveryReady()` atomic was false, with a metric label, a `recovery_wired` proto field and a global read inside the pure selector. That added a silent third state for a hazard that wave order already controls: the system flag defaults off and every flip is owner-gated after soak. So (a) `-enforce-agent` is registered in Task 1.5.3c, the same task that wires the reporter, and (b) `-enforce-system` is registered in Task 1.5.8g, after the spawn-point guards, detector-local guards and re-drive sweep of Story 1.5.8 exist. A class whose flag is not registered yet resolves from the shadow flag alone and cannot enforce. The dependency is a runbook statement for Story 1.4.1: the system-class step requires the Story 1.5.8 completeness test green on the deployed binary.
9. **The inventory test becomes the guard.** `workflow_bypass_inventory_test.go` (Story 1.2.3b) walks the module with `go/parser`. It starts with a ratcheted `pending` list of the 40 + 5 sites (green every wave; the list can only shrink, and a stale pending entry fails). When Story 1.5.9a lands the list is empty and the test fails on (a) any call, on **any receiver**, whose selector name is one of the six old names (`TransitionBacklogItemStatus`, `ArchiveBacklogItem`, `UnarchiveBacklogItem`, `SetBacklogItemPRAndTransition`, `ReconcileStuckItems`, `TransitionBacklogItemStatusWithPRFields`) or its `Raw*` / `raw*` form, outside the allow-list; (b) any `Gated*`, `Rollback` or `DebugForce` call whose caller name is not in the registry; (c) any non-`forwarding` registry entry with no call site (the `forwarding` `mcp_transition_delegate` is exempt, Decision 2); (d) any `.SetStatus(` call on a `BacklogItem` ent builder in package `session` outside the allow-listed writer functions (the five transition writers, the `ReconcileStuckItems` per-item write and the creator, each with a reason), which closes the name-matching gap that let the sixth writer go unnoticed twice. Matching for (a)-(c) is by name, so the allow-list names the legitimate same-named non-storage declarations: the `BacklogService` RPC handlers and their one non-test caller, the MCP delegate. The allow-list is exactly: the gate file; the `Storage` wrapper bodies in `storage*.go` (each by function); the MCP delegate (`tools_backlog_dependencies.go:163`, reason: forwards to the handler, which calls the gate); the 3 `Rollback` sites; the 2 debug `DebugForce` sites; and, for creation, the `create` and `exempt: debug` creators, each with a reason. Test files are exempt from (a). The `julesPollerStorage` interface (`jules_session_poller.go:86-87`) and its fakes (`session/jules_session_poller_test.go:178,185`, `server/services/jules_config_service_test.go:78,82`) are method declarations, not call sites: the interface is re-pointed in Task 1.5.4e then moved to `Gated*` in Task 1.5.7c, and the fakes follow each time. The existing `workflow_engine_bypass_total{caller}` counter keeps its name and now also counts `rollback`, `debug` and `debug_create`; per-class gate counters are added (`workflow_engine_gate_calls_total{class,caller,mode}`).
10. **Hot-path latency.** The gate adds one map lookup (graph), one atomic mode read, and for Enforce the operator-gate evaluation already bounded by Task 1.1.2e; the extra DB read happens only when the caller has no `Observed` item. Transition volume is tens per day, not per request; the budget is "no measurable regression on `BenchmarkTransition*` and gate overhead under 50 microseconds per call excluding I/O" (Task 1.5.3d, INFERRED target, owner can adjust). `recover()` wraps the Shadow branch so a Shadow defect never fails a transition.
11. **Live-service hazard.** Nothing in this decision needs a restart: enforce flips are flags. Deploying the new binary does restart the service; the owner's deploy first confirms `--tmux-keep-server` in the unit (`docs/explanation/tmux-keep-server-on-restart.md`) and no worker runs `make install-service` (plan "Worker brief standard block").
12. **One shared denial predicate; every detector enumerated.** `RemediationBlocked(item, reason)` (`session/backlog_remediation.go:332`) gates only the caller's own reason's row, so an open `transition_denied` row does not stop any other detector. The gate therefore exposes one predicate, `Storage.HasOpenTransitionDenied(ctx, itemID, status)`, true iff an open `transition_denied` row exists whose recorded `from` equals the item's current status (a stale row for another status does not block). Every spawn point (a method that respawns, reopens or nudges) and every detector that acts without going through one calls it first and does nothing (no respawn, no nudge, no triage start) when it is true. **Where the guard lives (round 5, ARCH-C2, VERIFIED in code)**: `runStuckDetector` (`session/backlog_lifecycle.go:1236`) is a name-and-closure panic wrapper with no item in scope, and `remediationActionByReason` (`server/services/backlog_service_stuck.go:353`) is only the operator "Retry now" map; neither hosts a single guard. They do, however, converge on six `BacklogService` methods (`AutoReopenAfterFailedReview`, `AutoRespawnReview`, `AutoRespawnAutonomousWork`, `RemediateStaleWorkSession`, `AutoRespawnTriage`, `AutoReopenForPRFix`), which the periodic sweep also reaches through interfaces wired at `server/dependencies.go:1524-1605`. The guard therefore lives once in each spawn point (plus `MaybeTriggerTriage` and `DequeueNextQueuedItems`), covering periodic and "Retry now" callers together; per-detector guards remain only for the inline `FindReviewItemsWithoutGate` respawn and the `orphaned_triage` shape-2 marker, and detectors that only `MarkStuck` (idempotent per row) or only resolve stay as they are. The real stranding path (VERIFIED in code, not the earlier assumed role mapping): `onAutonomousDriverComplete` makes exactly one status write, triage-role `idea->ready` (`autonomous_orchestration_service.go:453`, applied at `:584-586`); the work role deliberately does not transition (`:455-499`) and the review role (`:505-575`) only closes an `autonomous_stuck` row or ends the `ItemSession`; the `toStatus == BacklogStatusReview` branch at `:604` is dead code. If an operator gate denies `idea->ready`, triage has ended, the item stays `idea`, and `reconcileOrphanedTriageItems` shape 2 ("ended, item still in idea", `session/backlog_lifecycle_triage.go:374`) marks it `orphaned_triage`, which `reconcileOrphanedTriageRemediation` (`:445`) retries through `AutoRespawnTriage` to `respawnTriage` (`backlog_service_triage.go:2608`) on every backoff tick; the graceful-shutdown branch (`:352-366`) respawns with no backoff at all. The full table (24 `runStuckDetector` names, 7 remediation reasons, with each one's status scope and guard kind) is in plan Story 1.5.8; a completeness test fails when a `runStuckDetector` name or a `remediationActionByReason` action is in neither the guarded list nor an explicit "not applicable: <reason>" list.

## Alternatives rejected

- **Gate inside the repository primitive.** The repository cannot see guard input (git-based shipped-code check, blockers) and would need the whole engine and reporter; the `Storage` layer is the narrowest place every caller already passes through.
- **Lint analyzer instead of rename plus inventory test.** Lexical, name-matched (`research/build-vs-buy.md` E2); the compile error from the unexport/rename is stronger and free where it applies (repo level, old names). The `silenttransition` analyzer is kept as an additional rung and extended (Decision 5), not replaced.
- **A single class and a single enforce flag.** One flip would change operator, agent and automation behavior at once with no way to revert one class.
- **Apply Default built-in guards to system callers.** Would block PR-merged items that lack a PASS verdict (human-merged PRs) and change pipeline behavior no operator can configure.
- **Fail-closed when the gate is not wired.** A forgotten injection (the `dependencies.go:678` bug class) would stop every transition. Chosen: an unwired gate behaves as Off, loudly (`gate_unwired_total`, startup WARN, `GetWorkflowEngineStatus.gate_wired=false` makes the banner Unknown, wiring test).
- **Add the archive edges to `validTransitions` and the seed.** Rejected in Decision 7 (breaks Off equals today, leaks to the UI's `allowed_transitions`, does not reach the live database).
- **Declare every edge for the generic MCP delegate.** Rejected in Decision 4 (makes every edge un-disableable).
- **Runtime degrade clauses (`RecoveryReady()`, reporter-unwired).** Rejected in Decision 8 (round 5): redundant with registering each flag in the task that closes its hazard.
- **A `Report`-selector rule in `silenttransition` for `Gated*` calls.** Rejected in Decision 5: the gate reports, so callers have nothing to surface.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| A stricter graph or an operator gate strands the autonomous pipeline. The real mapping: `onAutonomousDriverComplete` writes only triage-role `idea->ready` (work and review roles do not transition); `ReconcileStuck` `in_progress->review`; the PR paths (`review->pr_pending`, `pr_pending->done`, `done->archived`) | Every edge a fixed `system` caller can request is system-required (cannot be disabled, Decision 4); the only new denial source is an operator gate or a stage deleted under a live item; both go to the reporter and are recorded as `transition_denied` with `from`/`to`; every spawn point and detector-local site that can act on that `from` status is guarded by `HasOpenTransitionDenied` (Decision 12) and a re-drive sweep retries when the gate state changes (Story 1.5.8); the `-enforce-system` flag is not registered until that recovery ships (Decision 8); Shadow per class measures it before enforce; `--config-diff` and the live-database replay preview stranded items (Tasks 1.1.3f, 1.5.9d) |
| Operator gate on an automated edge causes a denial loop or respawn churn (`orphaned_triage`, `respawnTriage`, `stale_work`, `abandoned_review`, bouncing, others) | Decision 12: one predicate, one required test per detector, a completeness test over `runStuckDetector` and `remediationActionByReason` |
| CAS and TOCTOU: nil-precondition sites gain `ErrPreconditionFailed`; guard input read from item fields goes stale | Decision 6: whole precondition carried, `ExpectedUpdatedAt` set when guard input is supplied; per-site concurrent-mover tests; bounded retry only for `Unconditional` |
| An off-graph edge missing from the table (archive from `in_progress`) | Decision 7: system-required union, table untouched; registry edge-audit test; stale-seed test |
| Raw writer left reachable (unexported repo writers, the missed `TransitionBacklogItemStatusWithPRFields`, `ReconcileStuckItems`, `CreateBacklogItem`) | Decision 1: unexport at repo level; old and new names on any receiver in the strict guard; `create` constrained to entry stages |
| Static analyzer rung goes dark after the rename | Decision 5: Task 1.5.4f extends `silenttransition`; `make lint-custom` in acceptance |
| Behavior change for `agent` class from Default guards (for example `resume_work` to `in_progress` needs an approved plan) | Shadow class `guard_new` counts these before enforce; each distinct `(caller, from, to)` must be owner-acknowledged in the runbook before the agent flag flips |
| Hot-path latency or Shadow panic | Decision 10 |
| Live-service restart | Decision 11 |
| Dual-flag misconfiguration (enforce on, shadow off); system flag flipped before recovery ships | Mode truth table covers the first (enforce wins); the second cannot happen because the flag is registered only after the recovery guards (Decision 8) |
| Soak sample thresholds unreachable at the live volume (about 21 items) | The runbook defines READY for low-volume edges by owner acknowledgement of four artifacts, not by sample counts (plan Risk Control; Task 1.5.9d replay) |

## Consequences

- Success Metric 1 is met per class when that class's enforce flag is on, and for every status-write path once all three are on, except the one explicit carve-out (system-required edges cannot be disabled; their gates are editable). Before that, the Stages banner states which classes are enforced.
- ADR-001 is amended: the handler IS edited, minimally (Story 1.5.5a replaces its three engine/storage calls with one gate call after an Extract-first commit that lowers its complexity); modes are per class.
- ADR-002 Decision 1 is superseded; its Decisions 2-5 apply with the registry replacing the bare caller-name list.
- The Stages page note "automated lifecycle edges are fixed" becomes "automation edges are fixed, automation gates are editable".
- The estimate grows by Epic 1.5 (see plan "Effort estimate"); this is full scope by owner instruction, with no cut line. The reviewers' simplification alternative (one enforce flag plus a per-caller revert list) is not adopted and is no longer carried as an open question; it remains described in `implementation/architecture-review.md` and `implementation/adversarial-review.md` and would be considered only if the owner asks.
