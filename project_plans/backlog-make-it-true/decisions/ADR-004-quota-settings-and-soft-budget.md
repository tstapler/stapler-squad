# ADR-004: Quota settings via a Get/UpdateQuotaConfig RPC; soft budget gets a global default plus the existing per-item edit

**Status**: Accepted (planning; amended 2026-10-17 by pre-mortem #3: `FeatureFlagService` writes move onto `config.UpdateConfig`)
**Date**: 2026-10-17
**Project**: backlog-make-it-true, workstream B

## Context

`QuotaConfig` (`config/types.go:743-770`) is read live every tick through a closure (`dependencies.go:1429-1436`), so the gate needs only a write path. The feature-flag RPC is boolean-shaped (`feature_flag_service.go:172-180`), so thresholds cannot ride it. The "soft budget" is a per-item `cost_budget_threshold_usd` (`backlog.proto:289-294`) consumed by pure `EvaluateBudgetThreshold` (`session/budget_warning.go:10`) at `backlog_service.go:1460,1482`; there is no global value. Edge cases (VERIFIED, `research/features.md` quota section): disabling the gate while it paused backlog leaves backlog paused (`quota_gate.go:201-204`); `PauseBelowHeadroomPct + ResumeMarginPct` must be at most 100 or resume never triggers (`:287`); zero is silently replaced by defaults in `QuotaConfigOrDefault`; `AssumedWindowTokenBudget=0` disables the proactive signal.

## Decision

1. **New RPC pair** `GetQuotaConfig` / `UpdateQuotaConfig` in a new `proto/session/v1/quota.proto` (copy the `unfinished.proto` / `llm_backend.proto` pattern), handler `server/services/quota_settings_service.go`, read-modify-write through a new package-level helper `config.UpdateConfig(fn func(*Config) error) error` that holds a separate outer mutex, keyed per config path like the existing one, across `LoadConfig`, `fn` and `SaveConfig`. It must NOT reuse the `saveConfigLockFor` mutex (`config/config.go:1475-1482`): `SaveConfig` already takes that lock (`:1502`) and `sync.Mutex` is not reentrant, so reuse would self-deadlock. That inner lock serializes only the file write, so two read-modify-write callers can still lose an update without the outer one. `SaveConfig` itself is already atomic (unique temp file in the same directory, chmod, write, close, `os.Rename`, VERIFIED `config/config.go:1514-1555`); Task 2.1.1d adds `tmpFile.Sync()` before the rename so a power loss cannot leave a zero-length file. `FeatureFlagService` (VERIFIED: it loads via `config.LoadConfig()` at `feature_flag_service.go:453,549,574`) owns the two-plus-three engine mode flags and the three autonomy flags, so Task 2.1.1d moves its writes onto `config.UpdateConfig` and adds a flag-flip versus `UpdateQuotaConfig` race test under `-race`. Residual risk narrows to the other `config.SaveConfig` callers (`defaults_service.go`, `jules_config_service.go`, `remote_service.go`, the `Config` setters at `config/config.go:593-702`), which still do unlocked read-modify-write and can race with a quota save or a flag flip; moving them is a follow-up outside this project and is listed in Unresolved Questions. `GetQuotaConfig` returns stored values, the **effective** values after defaulting, a derived read-only `mode` (`disabled` / `reactive_only` / `proactive`), and gate runtime state (`paused_by_quota`). The UI shows effective values from the read-back, never local state. Round 7: the response also carries `quota_source` (`NOT_CONFIGURED` or `CONFIGURED`) so the page can tell "never configured" from "configured with default-equal values"; it must be derived from the stored value BEFORE `QuotaConfigOrDefault()` runs (`config/config.go:823,1673`), because `Quota` is a non-pointer struct (`config/config.go:390`) and the loaded value cannot distinguish the two; `NOT_CONFIGURED` is the zero stored value, and the page always saves non-zero pause and resume, so a page save is `CONFIGURED`.
2. **Validation lives server-side** and is mirrored in the UI: reject `PauseBelowHeadroomPct + ResumeMarginPct > 100`; reject zero/negative for fields where zero is silently defaulted: `PauseBelowHeadroomPct` (default 20), `ResumeMarginPct` (default 15), tick counts, window minutes, grace minutes and throttle seconds, VERIFIED `config/types.go:777-800` (error names the constraint; the UI never offers 0 as "off"); `AssumedWindowTokenBudget` zero is allowed and means reactive-only, but the RPC response and UI show a persistent warning when `enabled && budget == 0` ("Gate is on but no budget is set, so the proactive signal never fires"). Q4 (derive the budget) is accepted as an Unresolved Question; the UI shows an observed-usage figure as read-only context only if cheap.
3. **Disabling while paused**: `QuotaGate.Reconcile` on `Enabled=false` with `pausedByQuota=true` resumes backlog once (clears provenance, calls `BacklogController.Enable`) and logs it. The UI save response states "Backlog resumed" when it happens. Never trust persisted "paused for quota" across restart (existing pitfall).
4. **Soft budget = both**: add global default `Quota`-adjacent config field `DefaultCostBudgetThresholdUSD *float64` (the single Go name used everywhere in this project; JSON `default_cost_budget_threshold_usd`) (nil = off, so a stored `0.0` stays a valid threshold, matching the proto comment) applied where `EvaluateBudgetThreshold` receives a nil per-item threshold; keep the existing per-item `cost_budget_threshold_usd` edit as the override. Settings page exposes the global default; per-item stays where it is. Rejected: per-item-only (leaves requirement 2 unmet: operator cannot set a budget from settings), global-only (removes an existing capability).
5. **Placement**: new route `web-app/src/app/settings/backlog-quota/`, linked from the Features page (the Features page is already a special-case pile, `page.tsx:165-183`). Single Save plus Revert, cross-field validation once, "Applied" only after read-back matches.
6. `ForegroundThrottleDelaySeconds` is gated by `Enabled` (`dependencies.go:1514-1516`); the page states that enabling also throttles foreground dispatch.

## Alternatives rejected

- Env vars (standing preference: live-settable); viper/koanf (second config source of truth); feature-flag `statusDetail` text as the only surface (read-only).

## Consequences

- Toggling the gate from the UI counts as a manual override to the gate (`quota_gate.go:~215-229`) and may suppress notifications for the grace window; documented in the page help text, not changed.
- `SaveConfig` locking is decided (the `UpdateConfig` helper above with its own outer per-path mutex, Task 2.1.1c, with a concurrent lost-update test; flag service writes migrated in Task 2.1.1d), not spiked. A hand edit of `config.json` by a human while the server runs remains last-writer-wins and is documented.
- `DefaultCostBudgetThresholdUSD` rejects negative, `NaN` and `Inf`; `0.0` is valid; the resolved default is applied at both evaluation sites (`backlog_service.go:1457-1460` and `:1482`) through one service-layer helper.
- The `[BudgetWarning]` crossing is a log line only (`backlog_service.go:1467,1489`); the UI copy says so. Routing to a notification is an open owner decision (plan Unresolved Questions).
