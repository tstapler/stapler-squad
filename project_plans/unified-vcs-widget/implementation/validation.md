# Validation Plan: unified-vcs-widget

**Date**: 2026-07-18

## Happy Path Scenario
Given a backlog item whose worktree has been cleaned up and whose `ReconcilePRPending` reconciler
already ran `CaptureShipSnapshot` at merge time (Baseline + Phase 3), when the user opens that
item's detail page, then the Backlog item detail's Version Control section renders `VcsWidget
mode="full"` fed by `fromShipStatus(shipStatus)` showing the `"shipped"` `MergeabilityPill`, the
durable GitHub PR/CI/review badges, the per-file diff stats, and the commit list — all without a
live worktree, live session, or new RPC call beyond the existing `GetBacklogItemShipStatus`.

## Migration Test (Story 3.1.2 — additive ent schema fields)

Per Step 5: this repo's ent migrations are additive/optional-field, applied via ent's
auto-migration at startup (no traditional up/down SQL migration with data transformation — see
`plan.md`'s "Migration Plan" section). The canonical "reversible migration" test is adapted to
verify the additive-field contract instead of an actual rollback.

**File**: `session/ent_repository_backlog_test.go`
**Test name**: `TestMigrationShouldBeReversible_WhenBacklogItemGainsOptionalShipSnapshotFields`
(the literal phrase `migration_should_be_reversible` from the template, wrapped in this repo's Go
`TestX_ShouldY_WhenZ` convention)

**Assertions** (integration test against a real ent-backed test `Storage`, not a fake):
1. **Pre-migration row, post-migration read** — a `BacklogItem` created via the existing
   `CreateBacklogItem` path (before this story's schema edit lands, simulated by not setting any
   of the 6 new fields on creation) is read back via `GetBacklogItem` after the client opens
   against the migrated schema: `ShippedCheckConclusion == ""`, `ShippedApprovedCount == 0`,
   `ShippedChangesReqCount == 0`, `ShippedSnapshotAt == nil`, `ShippedFileStats == ""`,
   `ShippedSnapshotCaptureFailed == false` — all 6 fields at their nil/zero-value default, matching
   `plan.md`'s "existing 'done' items... simply have all 6 fields at their zero-value/nil" claim.
2. **Round-trip write via the upsert path** — `UpdateBacklogItem` (the same call
   `CaptureShipSnapshot` uses, generated with `--feature sql/upsert` per
   `.claude/rules/ent-schema-generation.md`) sets `ShippedSnapshotAt`, `ShippedApprovedCount`, and
   `ShippedSnapshotCaptureFailed` on that same pre-existing row; a subsequent `GetBacklogItem`
   returns the newly set values, and every field that existed on the row *before* this migration
   (e.g. `PrNumber`, `Status`, `Shipped`) is unchanged — confirming the additive column add did not
   disturb existing data.
3. **No NOT NULL constraint introduced** — a second, brand-new `BacklogItem` created with none of
   the 6 fields explicitly set persists successfully with no constraint-violation error, confirming
   `Optional()` is honored end-to-end through the generated client, not just in the schema source.

This is the ent-based equivalent of migration reversibility: since there is no down-migration to
execute, "reversible" is verified as "old rows are unaffected and new/optional columns default
safely," which is exactly what `git revert` + regenerate (`plan.md`'s documented rollback
procedure) depends on being true.

## Test Stack
- **Unit (TypeScript/frontend)**: Jest + React Testing Library (`@testing-library/react`), `jest-dom` matchers. Pure-function adapters/mergeability tested with plain Jest (no RTL needed). Type-level tests (`VcsWidgetData`'s discriminated-union guarantees, `MergeabilityPill`'s exhaustive switch) verified via `cd web-app && npx tsc --noEmit`, with illegal shapes marked `// @ts-expect-error`.
- **Unit (Go)**: Go's standard `testing` package, table-driven tests per this repo's existing style (`session/git/ops_test.go`, `session/backlog_lifecycle_test.go`). No new assertion library — matches existing convention.
- **Integration**: 
  - Frontend: RTL rendering the real hook/context (`useSessionVcsContext`, `useBacklogItemShipStatus`, `WatchUnfinishedWork` stream) against a mocked ConnectRPC transport (`createRouterTransport` or equivalent), not a stubbed adapter function — validates hook→adapter→component wiring end-to-end.
  - Backend: real ent-backed `Storage` (SQLite in-memory or the project's existing ent test-DB helper) exercising `UpdateBacklogItem`/`GetBacklogItem`/`GetBacklogItemShipStatus` against actual generated ent code, and `FileStatsBetween` against a real temporary git repository constructed via go-git (init/commit/rename), per `.claude/rules/prefer-go-git-over-subshells.md`.
- **E2E / UX**: Playwright against the test server (`http://localhost:8544`), page-helper class `tests/e2e/pages/VcsWidgetPage.ts`, `data-testid`/ARIA-role locators only, no `waitForTimeout` — per `.claude/rules/e2e-test-conventions.md`.
- **Accessibility**: Project's existing Axe Core CI gate (blocks on WCAG AA violations) for automatable D-series criteria; manual screen-reader verification (VoiceOver/NVDA) for `aria-live` announcement behavior (D6) that Playwright cannot assert directly.
