# Validation Plan: stapler-squad-website

**Date**: 2026-10-14

## Happy Path Scenario
Given the current broken-Pages baseline (`https://tstapler.github.io/stapler-squad/` returns `404`), when `deploy-website.yml` ships and a prospective user visits that URL, then the page returns `200` and renders the hero (value prop + install CTA), the demo video, the `FeatureCard` grid, and a reachable `HelpSection` docs nav — proving the site's core promise (landing → install → self-serve docs, no source-reading required) end-to-end. *(Anchor for all test design below; error paths and edge cases in `design/ux.md` §1.4/§2.5/§4 are variations on this scenario, not equal-priority items.)*

## Test Stack
- **Unit**: Vitest + `node:assert`/Vitest's built-in `expect` — idiomatic for an Astro project (Astro's own docs recommend Vitest), and `website/` is a standalone package with no reason to inherit `web-app/`'s Jest setup. Covers `.mjs` scripts (`sync-content.mjs`, `transform-markdown.mjs`, `check-asset-health.mjs`, `check-internal-links.mjs`), the `release-asset.ts` helper, and Astro component rendering via Astro's container API (`experimental_AstroContainer`).
- **Integration**: same Vitest runner, but tests marked `*.integration.test.ts` and excluded from the default fast run — they touch the real filesystem (`docs/how-to/`, real `README.md`/`docs/features.md`), invoke real external tools (`ffmpeg`, Lighthouse CI, `gh` CLI), or make real network calls (HEAD requests to `github.com/.../releases/download/...`). No test doubles for the external-call integration tests — that's the point of distinguishing them from the mocked unit tests above.
- **E2E / UX**: Playwright, modeled on `tests/e2e/`'s existing conventions (`@feature`-annotated spec headers adapted to this project's own feature set, `data-testid`/ARIA-only locators, no `waitForTimeout`, page objects under `website/tests/e2e/pages/`) but in a separate `website/tests/e2e/` suite — `website/` is a standalone package, not a `web-app/` addition. Accessibility scans reuse `@axe-core/playwright` (same library as `tests/e2e/accessibility.spec.ts`), per `research/ux.md` §3's explicit "reuse the same library" instruction.
