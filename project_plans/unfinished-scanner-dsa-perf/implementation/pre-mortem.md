# Pre-mortem: unfinished-scanner-dsa-perf
**Date**: 2026-10-15

Frame: some weeks after shipping, the project failed or caused harm. Sources: `plan.md` (including Repair logs 1-3), `requirements.md`, ADR-001..009. Labels: VERIFIED = read in the cited plan/ADR line; INFERRED = my reasoning about filesystem or runtime behaviour, not run (analysis-only task, no builds or tests). Line numbers refer to `implementation/plan.md` unless prefixed.

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | **Stale ahead/behind from a long-lived `RefSnapshot`.** Story 4.1.1 says the snapshot is "dropped on `.git` events" (plan:964), and Story 4.1.2 then reuses committed-state fields "beyond `diffStatCacheTTL`" when `(HEAD, base, ShallowStamp)` is unchanged (plan:983). The plan never bounds the snapshot's age. Tier A watches only `.git/worktrees/<name>/` (ADR-006), and kqueue directory watches are non-recursive (ADR-006 context, INFERRED). Ref moves that touch no watched file are therefore invisible: `reset --soft`, `update-ref`, `branch -f`, a push or fetch that rewrites `refs/remotes/...` or `refs/heads/...` in the common dir (INFERRED: a linked-worktree HEAD file keeps `ref: refs/heads/x` while the branch file changes). Today every 5-minute tick re-resolves refs, so this would be a new regression: a worktree shows the old ahead/behind and old `AheadMessages` until some unrelated event. | A user resets or pushes a branch and the Unfinished/Up Next UI keeps the old "N ahead" for much longer than 5 min. Metric: tick-initiated scans with `refsnapshot_reused=true` and a hash that differs from a fresh resolve. | Define `RefSnapshot` lifetime as **one Burst only**: it is never reused across Bursts, and every tick-initiated Burst builds a fresh one (ref resolution is a handful of stats and file reads, so there is nothing worth caching across Bursts). Add to Story 4.1.1 an AC and a test: "move a branch ref through the go-git storer with no fsnotify event, run a tick-initiated Burst, and assert the new hashes and the new ahead/behind." Add to Story 4.1.2 a rule that signature reuse never outlives one 5-minute tick. | **P1** |
| 2 | **Pressure/over-cap fallback points at code that Story 5.3.1 deletes.** Stories 2.1.2 (plan:661), 2.1.3 (plan:684-685) and 4.1.1 (plan:966) all say `ErrPressure`/`ErrGraphFull`/severe pressure make the caller "use the legacy walk". Story 5.3.1 (plan:1273) deletes "`parentMemo`-only walk selection" and keeps the legacy implementations "only as `_test.go` oracles". After retirement the fallback has no production implementation. Under severe memory pressure (the load-110+ machine) scans would return errors, hang on fill, or silently serve stale data. Every pre-5.3.1 test of the fallback exercises code that is about to disappear. | After retirement, `ErrPressure` or `ErrGraphFull` surfaces as scan errors (`ScanResult.ErrorMsg`), or a compile failure appears when 5.3.1 removes the symbol. Metric: `graph_full_fallbacks_total` increases and worktrees show errors. | Amend Story 5.3.1: the lockstep walk with the per-call `parentMemo` from Story 0.0.1 stays in production as the named `plainWalk` fallback. Only the path-keyed caches, the flag branches and the `lcsLength` production use are deleted. Add ACs: "after retirement, a test with `MaxGraphCommits` lowered and a test with `PressureFunc` true return results identical to the lockstep oracle", and "5.3.1 must keep `plainWalk` reachable from the `ErrPressure`/`ErrGraphFull` branches (AST or grep test)". | **P1** |
| 3 | **Dormant migration: flags stay off, legacy never removed, `gogit_vcs_reader*.go` carries two implementations.** Defaults are "off until Story 5.2.1 soak" (plan:120-125), but the soak is Wave H, after 45 stories and ~16.5M CU (plan:1367), and it needs a manual A/B, an owner go-ahead for a live deploy, and a 24 h watch before 5.3.1 (Wave I). Any stall (owner decision, S1-profile gate closing stories, fork CI) leaves six flags and doubled call sites in the 2,311-line hotspot that Story 0.0.2 only split. | Weeks after Wave D merge, `UnfinishedCaches` is still all-false in the live config. Pyroscope shows no change, while `gogit_vcs_reader*.go` line count and cache-field count are higher than at Story 0.0.2's end. | (a) Make rollout **per rollback unit, not one Wave H**: `diff_counter` (independent, small) and the first `scan_skip` items run their own manual A/B and flip default in the same wave they land. Add a per-unit "A/B then flip" task right after 3.2.2/3.2.3, instead of a single Story 5.2.2 at the end. (b) Add a **flag-expiry test**: every flag in `EffectiveFlags` declares `RemoveBy` (a date or release); a `go test` fails after it passes, so a stalled flag turns into a red `make ready`. (c) State in Story 0.0.2 the invariant "no call site is switched to a new path in a wave unless that wave's rollback unit has a scheduled A/B", so a half-migrated file cannot be left at a wave boundary. | **P1** |
| 4 | **Wrong 'clean'/'ahead/behind' from shared state goes unnoticed on the live process.** Correctness evidence is corpus-bound: oracles, differential tests and a scripted A/B on a byte-copied corpus (plan:1222; ADR-008). Real histories have shapes and event orderings the corpus lacks (octopus merges, deepen-in-place, worktrees pruned mid-walk, `pruneRepoCache` closing a storer mid-walk, id-relative products read across a `Generation` swap). Nothing in the plan compares candidate verdicts to the legacy path on live data, so a wrong shared-cache verdict looks like a normal number. | Silent: numbers differ from the user's own `git log` counts, or a worktree with real work shows "clean". No metric would fire. | Add a **shadow-verify mode** to Story 5.1.1 and the 5.2.x flip criteria: `shadow_verify_rate` (default 1/50 scans, sampled at random, never on severe pressure) runs the oracle path (`plainWalk` + legacy `HasUncommitted`) beside the new one and increments `unfinished_repostate_parity_mismatch_total{field}` with a debug log of both values. Flip criterion in 5.2.1/5.2.2: mismatch counter is exactly 0 across the manual soak and the 24 h live watch; any non-zero value is `HOLD`. Fits ADR-008's "gates compare against retained oracles" and costs bounded CPU only on sampled scans. | **P1** |
| 5 | **Lockstep commit (Story 0.0.1) silently changes ahead/behind on real criss-cross histories.** ADR-003 records that lockstep is not git's best merge base, and the golden divergence set is "to be filled" (ADR-003). AI-session workflows merge `main` into feature branches routinely, which is the criss-cross shape. The plan commits the lockstep regardless and "reports" the divergence. | After deploy, ahead/behind numbers differ from the previous binary for branches that merged main. | In Task 0.0.1a, run the differential over the owner's **real worktrees** (read-only via go-git), not only synthetic DAGs, and record counts old vs lockstep vs `object.Commit.MergeBase`. Make the golden file a blocking artifact: if more than a stated share of real worktrees diverge, stop and ask the owner before committing. | P2 |
| 6 | **Long-running memory growth beyond the accounted budget.** `RepoState` lives as long as its store is referenced, and pinned/registered repos keep it referenced indefinitely (the store's idle TTL only helps for zero-refcount stores). `Bytes()` is an estimate. `xsync.Map` and the interner are pointer-bearing, and the overhead per entry is easy to undercount. The only `inuse_space <= budget + 10%` check is in the 30-min A/B on a session-less instance (plan:1224). A process that stays up for weeks adds GC mark work (already ~28% of CPU, requirements.md:12), the opposite of the goal. | Process RSS or `inuse_space` trends upward over days; `unfinished_repostate_bytes` stays flat while `inuse_space` grows (the estimate is wrong); GC share rises. | Add a **calibration gate**: in the Story 2.1.1/3.1.1 tests, assert `Bytes()` is within +/-25% of a measured `runtime.ReadMemStats` delta for a built graph and tree map (not just a ceiling). Add a Story 5.2.2 check: `unfinished_repostate_bytes / inuse_space_delta` ratio logged daily over the 24 h watch, with an alarm-less debug log when drift exceeds 30%. Extend 5.2.1 to a 24 h run on one instance, not 30 min. | P2 |
| 7 | **Deploy kills live tmux sessions.** `make install-service` restarts the service and kills the tmux server unless the deployed unit passes `--tmux-keep-server` (CLAUDE.md WARNING). Plan says "verify first" (plan:130, 1234) but the check is an instruction, so a missed check ends every running agent session, including the ones doing this work. | After the deploy, every session shows "tmux session missing" and agents die. | Add Task 5.2.2a step 0: a scripted preflight that reads the installed launchd plist/systemd unit and fails the deploy task unless `--tmux-keep-server` is present in `ExecStart`. Do the live deploy only when the owner confirms no unsaved agent work, per the plan's existing go-ahead. | P2 |
| 8 | **Gates pass, owner's metric is missed.** Every hard gate is a deterministic count (ADR-008), CI benchstat is advisory (`|| true`, plan:ADR-008 context), and the A/B runs on a session-less instance where the stat-bound bucket (`syscall.rawsyscalln` 32%) is mostly "accepted" (Stories 4.2.4, 0.1.1d). Result: all gates green, live scanner share still well above 15%, found only at Story 5.2.2, the last measurement step. | Story 5.2.2 shows share of process CPU unchanged; per-scan CPU falls but scan count rises. | Move a **live read-only measurement forward**: Task 0.1.1a captures the live Pyroscope owner share now, and each flip-per-unit (see #3) re-reads it, so a missed target is found per unit, not at the end. Add an early "stat-bucket reality check" task to Wave A that estimates the ceiling from the S1 profile; if the ceiling is above 15%, ask the owner to restate the target at Wave A exit (the plan already lists this as Q1; make it blocking for Wave B and record the answer). | P2 |
| 9 | **Waiter spin loses under load and decode amplification returns.** ADR-009 item 3: a loser of the `Filling` claim waits a bounded number of `runtime.Gosched` rounds, then decodes itself. At load 110-160 a claim holder blocked in storer IO (file IO under `SharedObjectStore.mu`, ADR-001) is descheduled far longer than a few `Gosched` rounds, so W workers all decode the same commits again. The deterministic gates (G2, G2b) pass because they use a yield hook, not real load. | `fill_lost_decode_total` grows with `fill_lost_cas_total`; decodes per scan match pre-change numbers on the live process. | Replace spin-then-decode with a **per-row wait on a `chan struct{}` or `sync.Cond` created by the claim holder** (closed on publish or rollback), with a ctx deadline, instead of `Gosched` rounds. Add an alert-free metric ratio `fill_lost_decode_total / fill_lost_cas_total` and make Story 5.2.1's pass clause require it below 0.2. | P2 |
| 10 | **Loss of real-git interop coverage in `gogitstore`.** Task 0.0.3d rewrites mmap/real-repo/soak tests on go-git-written packs (Q13 default if silent: accept the loss). A bug in the mmap pack/index reader that only shows on git-written packs (different delta ordering, `gc --aggressive` output, v2 index quirks) would ship. | Pack read errors or `object not found` on a git-gc'd repo in the live process. | Keep `mmap_realrepo_test.go`-style coverage by opening the owner's **existing** repos read-only through go-git (no exec, no fixtures to generate), skipped when the repo path is absent. Alternatively commit binary pack fixtures as data, as Q13 allows. | P2 |
| 11 | **Per-directory untracked pruning false clean.** The model oracle (Story 4.2.3) covers the modeled operations only; the stated worst case is a 5-minute false-clean window for changes that leave every key unchanged (ADR-006). Candidates the generator may not model: mtime-preserving moves (`rsync -a`, `tar x`) into a directory, network or case-insensitive filesystems, a nested repo or symlinked directory appearing. | A newly arrived untracked file is not shown for up to 5 min, or a worktree stays "clean" while holding a file copied in by `rsync -a`. | Add `rsync -a`-style (mtime-preserving create), symlink-directory and nested-repo operations to the Story 4.2.3 generator; cap the pruning window below the tick (e.g. 2 min) while engagement is below 10% anyway (the plan already counts such engagement as 0 in the projection, plan:991, ADR-006). | P2 |
| 12 | **Planning artifacts lost.** `project_plans/unfinished-scanner-dsa-perf/` is untracked (git status) in a worktree under `~/.stapler-squad/workspaces/...`. Cleanup of worktrees (`worktree-disk-cleanup`) or a reset would lose a 215 KB plan, nine ADRs and both reviews, and Story 0.0.1 stages by explicit paths so it will not pick these up. | The worktree is removed or reset and the plan directory is gone. | Commit the planning artifacts at Phase 4 exit as a `docs:` commit (`docs/how-to/commit-sdd-planning-artifacts.md`). | P2 |
| 13 | **Fork tag mutation breaks rollback.** If `-ssq.2` is cut and later re-pointed, `go.sum` mismatches and the rollback runbook (network `go get` of upstream v5.19.3, no upstream entries in `go.sum`) fails mid-incident. | `verifying module: checksum mismatch` on build or rollback. | Add to Story 1.2.3a: tags are immutable by policy; a fix is a new `-ssq.N`; the rehearsal in Task 1.2.3c also runs with `GOFLAGS=-mod=mod GONOSUMDB`-free settings. Only reachable if the Story 1.2.2 local gate passes. | P3 |
| 14 | **Subtle race in the lock-free arena ships.** Cost of getting a CAS state machine slightly wrong is a wrong verdict across all worktrees of a repo. Mitigated by Story 2.1.4 (histories, `-race`, stress, `goleak`) and S1 scheduling gates, which may defer the whole arena. | Intermittent flaky failures in `make test -race` that get re-run until green. | Treat any intermittent failure in the 2.1.4 suite as a stop (per `fix-flaky-tests-dont-defer`); shadow-verify (#4) catches it live. | P3 |
| 15 | **Tier B exhausts file descriptors.** Off by default (ADR-006), but if enabled, one kqueue fd per directory could starve tmux/pty fds for the whole process. | `too many open files` in unrelated components. | Hard fd budget enforced in code with a refusal to arm above it (already an AC, plan:1141); add a test that arming stops at the budget. Keep flag owner-only. | P3 |

## P1 Items (address before implementation)
- [x] #1 (applied in the Phase 4 patch) Stale ahead/behind from long-lived `RefSnapshot`: patch Story 4.1.1 so the snapshot lives for one Burst only and every tick-initiated Burst re-resolves refs; add the "branch ref moved with no fsnotify event" test to 4.1.1 and a "reuse never outlives one tick" rule to 4.1.2.
- [x] #2 (applied in the Phase 4 patch) Fallback targets deleted code: patch Story 5.3.1 to keep the lockstep `plainWalk` in production as the `ErrPressure`/`ErrGraphFull`/severe-pressure fallback, and add post-retirement tests for both triggers; fix the "legacy walk" wording in 2.1.2, 2.1.3 and 4.1.1 to name `plainWalk`.
- [x] #3 (applied in the Phase 4 patch) Dormant migration: replace the single end-of-plan Wave H flip with a per-rollback-unit A/B-then-flip task after each unit lands; add a `RemoveBy` flag-expiry test to Story 1.1.3c; add the "no switched call site without a scheduled A/B" invariant to Story 0.0.2.
- [x] #4 (applied in the Phase 4 patch) No live parity detection: add `shadow_verify_rate` and `parity_mismatch_total` to Story 5.1.1, and make "zero mismatches over the manual soak and the 24 h live watch" a flip criterion in Stories 5.2.1 and 5.2.2.
