# ADR-006: Dirty tracking — Tier A default (never skips the stat pass), Tier B opt-in off, asymmetric-safety fallback

**Status**: Accepted for Tier A and the fallback policy (amended in repair iteration 1 and the Phase 4 patch: `RefSnapshot` and `ScanSignature` reuse never outlive one 5-minute tick, because a branch-ref move in the common dir can produce no watched event); Tier B build pending owner decision and a kqueue spike · **Plan**: Epics 4.2, 4.3

## Context
A false "clean" hides unfinished work; a false "dirty" costs one extra scan. Today only `<repo>/.git` is watched (`scanner.go:495-509`), linked-worktree gitdirs are not, `w.Errors` is only logged (`S:564-569`), `Rename` is dropped (`S:542`). fsnotify v1.10.1 (`go.mod:28`) on darwin uses kqueue (one fd per watch; directory watches do not report in-place file writes — INFERRED, UNVERIFIED for this version). **Tier A watches only `.git/worktrees/<name>/` (HEAD, index): editing a tracked file in place never produces an event there.**

## Decision
- **Hard rule**: `DirtyGen` (Tier A) may gate only (a) the parsed-index cache and (b) reuse of committed-state fields. **Skipping the tracked-file stat pass requires Tier B armed and healthy** (off by default), so by default `HasUncommitted` runs its stat pass on every scan. The clause "an armed healthy watcher with no loss since the last full pass" applies to Tier B only. Test: Tier A armed, edit a tracked file in place, the next scan reports dirty.
- **Tier A (default, rollback unit `watch_worktree_gitdirs`)**: watch `.git/worktrees/<name>/`, handle `Errors`/overflow/`Rename`/pointer-file repos, bump `DirtyGen`.
- **Tier B (`dirty_watch_tierb`, default off, hot worktrees only, fd-budgeted)**: built only after a spike measures fd cost and in-place-edit visibility; never enabled by default; owner decision required.
- **Fallback (`FullWalkFallback`)**: a full walk is forced on: not armed, overflow/error, directory create/rename/remove, or >= 5 minutes since the last full walk. A watcher hit may return dirty immediately.
- **Untracked per-dir pruning (Story 4.2.3)** keys each directory verdict on `(dir mtime, ctime, matcher identity, exclude fingerprint, tracked-set generation)`: the stat signatures of every consulted `.gitignore`, of `.git/info/exclude` and the global excludes file, and the index signature + entry count. `.gitignore` edits, exclude edits and `git rm --cached`-style index changes (go-git storer equivalent in tests) therefore invalidate; a seeded model-based oracle with random event drops compares skip-enabled verdicts with a full walk.
- Index-signature skip and untracked pruning carry a racy-timestamp guard (mtime within 2 s of store time is untrusted), as in git.
- Worst-case false-clean window per mechanism is stated in the plan (5 minutes, equal to the backstop tick `S:253`, versus today's 30 s `diffStatCacheTTL`); engagement of the skip is measured, and counted as 0 in the CPU projection if < 10%.

## Consequences
Worst-case staleness of a missed event is bounded by 5 minutes for changes that leave every cache key unchanged; the stat-bound CPU bucket is owned by the single-stat-pass work (Story 4.2.4) or recorded as accepted, not by the watcher; Tier B may deliver little on macOS and is allowed to end as "untracked-set only".

## Addendum: Story 4.2.1 spike (2026-10-16), go-git-written indexes only

Experiments: `session/unfinished/index_spike_test.go` (go-git `Worktree.Add` + `Commit` only; no native git).

1. **Cache-tree: go-git writes none.** `index.Encoder.encode` (fork `plumbing/format/index/encoder.go`, "TODO: support extensions") emits header, entries and checksum only. After `Add`+`Commit`, and again after a staged change, `index.Decode` returns `Index.Cache == nil` and the raw bytes contain no `TREE` signature (`TestIndexSpike_ShouldHaveNoCacheTree_WhenIndexWrittenByGoGit`). So there is no root hash to compare with HEAD's tree for go-git-written indexes.
2. **Decoder tolerance holds both ways.** An index without extensions decodes cleanly; a handcrafted `TREE` extension (the layout git writes, with a recomputed SHA-1 trailer) parses into `index.Tree` with the expected root hash, entry count and subtree count (`TestIndexSpike_ShouldParseTreeExtension_WhenPresentAndTolerateAbsence`). The handcrafted bytes prove the parser, not what native git writes; whether a native-git-written index carries the extension is not testable under the go-git-only policy.
3. **Q5 verdict: the staged-vs-HEAD shortcut (Story 4.2.2) is NOT built from cache-tree.** The plan's condition ("built only if the go-git-written case is valid AND the decoder tolerates an absent extension") fails on the first clause: the go-git-written case has no cache-tree. `TestStagedVsHead_ShouldBeO1_WhenGoGitWrittenCacheTreeValidAndAbsentToleranceHolds` is therefore not written. Staged-vs-HEAD stays the existing O(n) entry-vs-HEAD-tree compare, and the decode-skip by `IndexStatSig` (Story 4.2.2 main path) is unaffected.
4. **Stat signature.** go-git rewrites `.git/index` in place (`DotGit.IndexWriter` is `fs.Create`, which truncates), so the inode stays the same across rewrites (logged by the test: same inode before and after), and the inode adds no discrimination. A same-length content change keeps `size` equal, and restoring mtime (`os.Chtimes`, or a coarse-timestamp filesystem) makes `(mtime ns, size, inode)` fully equal for different content: false-equal is possible (`TestIndexSpike_ShouldShowFalseEqualSignature_WhenRewriteRestoresMtimeAndKeepsSize`). Recommendation: keep the racy guard, i.e. an equal signature is trusted only when the index mtime is more than 2 s older than the parse time; the spike models it as `racyIndexSigTrusted`.

## Addendum: Wave D4 implementation notes (2026-10-16)

- **DirtyGen gates caches, never the stat pass.** `scanSkipDecision` (`session/unfinished/scanskip_decision.go`) forces a re-parse of the index and a fresh untracked walk on any `FullWalkFallback` reason; the tracked-file lstat pass runs on every scan (`TestDirtyGenIntegration_ShouldRunStatPassEveryScan_WhenTierAArmedAndCachesHit`).
- **A hint is not a dirty verdict.** The Story 4.3.2 criterion "a watcher event on a tracked path returns `dirty=true` without a full walk" is not implemented: HEAD and index events also fire for commits and checkouts that leave the tree clean, so `dirty=true` would be a false positive. A hint forces one index re-parse (`DirtyGen.AckHint` clears it afterwards) and the verdict still comes from the stat pass.
- **Cache keys.** Index cache: `IndexStatSig` (mtime ns, ctime ns, size, inode) plus HEAD tree hash, trusted only when the newest timestamp is more than 2 s older than the observation time and the entry is under 5 min old. Untracked directory verdicts: directory signature (ctime exposes mtime-preserving creates), own and ancestor `.gitignore` markers, matcher identity, excludes fingerprint, tracked-set generation (index signature observed before the index read, plus entry count).
- **go-git `ReadPatterns` is non-local.** It appends to a shared slice while recursing, so sibling directories can overwrite each other's pattern domains and one `.gitignore` edit can change classification in unrelated directories. The cache is safe against this because a rebuilt matcher has a new identity (whole cache resets). The model-based oracle therefore builds its matcher with a locality-correct reader.
- **Sparse checkout.** Under `scan_skip` an absent skip-worktree entry is not reported deleted (deliberate fix; legacy still reports it, characterized in `TestEdgeCase_SparseCheckout_SkipWorktreeAbsentFile_ShouldReportDirtyToday`).

## Addendum: staleness bound is a multiple of the scan tick (2026-10-16, S2 A/B round 1 finding)

**Root cause (MEASURED in the S2 A/B, CONFIRMED by test).** `fullWalkMaxAge` and `scanSkipMaxAge` were 5 minutes, equal to the backstop scan tick, so a scheduled scan always arrived at or past the age limit and was forced to a full walk: index-cache hits 0/234, signature skips 2/234, untracked dirs skipped 2.7%, `dirty_full_walk_total` age 157. `TestDirtyGenPolicy_ShouldServeFromCache_WhenScansSpacedAtScanInterval` and `TestDirtyGenIntegration_ShouldHitCaches_WhenScansSpacedAtScanInterval` fail with a one-tick bound and pass with three.

**Decision.** The bound is `scanSkipAgeTicks * defaultScanTickInterval` = 3 x 5 min = **15 minutes**, used by `FullWalkFallback` (`fullWalkMaxAge`), the parsed-index cache and the untracked-dir verdict cache (`scanSkipMaxAge`). Two ticks is the smallest multiple that serves any scheduled scan from cache under tick jitter; three gives two cached scans per forced walk (about 2/3 engagement on a quiet worktree) while keeping the worst case short. Worst-case false-clean window of a missed event that leaves every cache key equal (for example a dropped directory create/rename the watcher never delivered) is now 15 minutes instead of 5, still bounded and corrected by the next forced full walk. It stays well above the legacy 30 s `diffStatCacheTTL` only in the sense that the legacy path rescanned; events, overflow, error, dir events and the stat signature keys still invalidate immediately. Unchanged hard rule: the tracked-file stat pass is never skipped; only the parsed-index cache, committed-state reuse and untracked per-dir pruning use the hint. `RefSnapshot`/`ScanSignature` reuse keeps its own one-tick bound (it is not governed by this constant).

**Second finding: spurious `unarmed` walks.** `DirtyGen.Arm` reset `lastFullWalk` on every call, and `watchRepo` (hence `Arm`) runs on every `AddRepo` and on each all-worktrees ref event, so an unbroken watch looked freshly armed and the next scan was an `unarmed` full walk (76 of about 233 scans in the A/B; the earlier INFERRED explanation "main repos have no working-tree watch" was incomplete). `Arm` is now idempotent while armed; a real `Disarm` then `Arm` still forces a fresh walk (`TestDirtyGenPolicy_ShouldNotRefireUnarmed_WhenArmedAgainAfterFirstWalk`). A worktree that is dirty by its tracked files or staged changes returns before the untracked walk, so it never completes a full walk and keeps re-forcing; that is deliberate (the caches were not refreshed) and costs little because those scans exit early.
