# ADR-008: Four rollback-unit flags with a normalizer, relative deterministic gates, A/B that exercises the new path

**Status**: Accepted (plan phase; amended in repair iterations 1-3 and the Phase 4 patch: per-unit A/B-then-flip triggers T1-T4, `RemoveBy` flag expiry, shadow-verify flip criterion, third Wave-0 instance, 30 s G10 deadline) · **Plan**: Risk Control, Story 0.1.2, Epics 5.2-5.3

## Context
Machine load is 110-160, so wall-clock is meaningless. `benchmark.yml:120` runs benchstat with `|| true`; the PR comment step is `continue-on-error: true` (`benchmark.yml:140`); `hasGoTier1Regression` (`tools/ci-gates/benchmark-regression.js`, called at `benchmark.yml:132`) only drives a comment. Thirteen independent booleans (plus two more elsewhere) had undeclared dependencies and no retirement story (architecture-review C9; adversarial-review C4). A default-off deploy measures the legacy path (adversarial-review B4).

## Decision
- **Four flags** (rollback units; amended 2026-10-16: `dirty_watch_tierb` dropped because Tier B is skipped (Q2), `best_merge_base` dropped because paint-down is the only walk (Q3)): `shared_commit_state` (graph, reach, ab/behind/messages, tree maps; they share ids/epochs), `diff_counter` (Myers + memo), `scan_skip` (prelude, signature, index cache, untracked pruning, single stat pass, matcher memo; sub-option `pool`), `watch_worktree_gitdirs` (Tier A). Sub-options `graph_base`, `pool` have no independent key. Requirement "flag per shared cache" (requirements.md:84) is met at rollback-unit granularity; the deviation is deliberate because id-sharing caches cannot revert independently.
- An `EffectiveFlags()` normalizer forces dependents off when a dependency is off (WARN once); a table test runs the parity suite over the full **legal** combination set. Flags are read once at startup into an `atomic.Pointer` snapshot (config struct `UnfinishedCaches` on `config.Config`, `config/config.go:196`); reload is restart-only, matching the runbook. After the soak, Story 5.3.1 deletes the path-keyed legacy caches and the flag branches of every flag that defaults on; the lockstep `plainWalk` stays as the production fallback. Every flag declares a `RemoveBy` date enforced by a `go test`, so a stalled migration turns `make ready` red (pre-mortem P1 #3).
- **Gates** are `go test` assertions comparing the new path with a retained oracle (committed-old walk, lockstep, `lcsLength`, `map` reach set) on `DecodeCount`, `StatCount`, `testing.AllocsPerRun` (non-race build only, never behind `-short`) and `B/op`/`allocs/op` ceilings; benchmarks use `-benchtime=Nx`. The benchstat PR comment stays advisory (CI baseline is cache-restored and noisy). Every metric in requirements.md maps to owning stories and a gate that can fail (plan Verification Matrix); Story 0.1.1d's projection gate can block Wave B.
- **Rollout / A/B**: flags default off in code until **each rollback unit's own A/B** passes at its trigger (T1 `diff_counter`, T2 `watch_worktree_gitdirs`, T3 `shared_commit_state`, T4 `scan_skip`; Story 5.2.1), then flip in their own commits; there is no single end-of-plan flip. A flip requires exactly 0 `parity_mismatch_total` from the shadow-verify sampler over the soak and the 24 h live watch (pre-mortem P1 #4). The comparison never measures a default-off deploy: Story 5.2.1 runs the **same binary** on manual instances (flags off = N-off, on = N-on) plus a third instance running the retained Wave-0 binary (W0 = S1; ports 62871-62876, private tmux sockets), the headline ratio being N-on/W0, and Story 5.2.2's live deploy (after a scripted `--tmux-keep-server` preflight) carries a config with the flags on. Headline metric is the owner's share of process CPU; per-scan CPU is a diagnostic. Fail-and-hold: a missed target means defaults are not flipped and the owner decides. Baseline states: S0 live `39fa33a11` (attribution only), S1 control = HEAD after Wave 0 (lockstep committed; the flags do not exist yet, so its behaviour is the legacy path), S2 candidate. **Every target, projection and gate is measured and stated relative to S1**, never S0 (adversarial-review N1: Story 0.0.1 already removes most of the S0 `DecodeCommit` bucket). The S1 profile is taken on the manual control instance under the scripted Story 0.1.5 workload. The A/B gate is the S2/S1 ratio of scanner CPU-seconds and allocations under that identical workload; the absolute scanner share of process CPU (<= 15%) is judged only at the live Story 5.2.2, because a session-less manual instance has a different denominator. Flags are set per instance in that instance's `config.json` (`UnfinishedCaches`, under `STAPLER_SQUAD_INSTANCE`'s config dir) and take effect on restart only. Owner confirmation of the S1-relative targets is a gate before Wave B. No deploy of this branch before `baseline.md` exists.

## Consequences
CI will not block on benchmark regressions; the hard gates are deterministic tests in `make ready`. Fewer, dependency-aware flags are testable; legacy code and flags are removed after the soak instead of lingering.

**Status update 2026-10-16 (flips, no live watch).** Per-unit defaults flip in `config.DefaultUnfinishedCaches` after the manual A/B recorded in `baseline.md` "S2 A/B"; the config key stays the off-switch (absent keeps the default, explicit `false` disables). Flipped so far: `diff_counter`, `watch_worktree_gitdirs`. The 24 h live watch of Story 5.2.2 did not happen (owner answer Q4/Q11: no live deploy), so each flip commit states that and the live watch remains the Story 5.3.1 precondition.
