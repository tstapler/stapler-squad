# ADR-001: Persist PRs as a `PullRequestState` fact entity plus `SessionPR` link rows

**Status**: Accepted (planning, 2026-11-03); revised after architecture and adversarial review (same day); iteration 2 added canonical lowercase identity and the no-marker backfill; iteration 3 (simplification) DELETED `origin_session_uuid`, `abandoned` and mirror links and made `PullRequestState` single-writer; Phase 4 patch (2026-11-03) gated the boot maintenance by `BuildOptions.RunPRMaintenance` and made transient maintenance errors non-fatal — **Project**: session-multi-pr-tracking

## Context
A session stores one PR in `github_pr_url` / `github_pr_number` (`session/ent/schema/session.go:136-143`); a backlog item stores another pair (`backlog_item.go:98-101`). Poller, retention sweeper, backlog gate and search all need cross-session queries over PRs, and per-PR state (open/merged/closed/unknown, draft, CI, terminal).

The first draft used one `SessionPR` entity with a `""` sentinel in a six-column unique index. Review found that the same PR then exists as several rows (session link, item link, Jules link), each carrying its own copy of `state` and `terminal`, so rows can diverge, the item verdict can count one PR several times, and item-only rows are never polled (architecture B3, adversarial B3).

## Decision
- Two ent entities, plus a tombstone table, all hand-written in `session/ent/schema/`; generated code is not committed.
  - `PullRequestState`: the facts about one PR. Unique on `(host, owner, repo, number)`. Holds state (`open|closed|merged|unknown`), draft, checks, approvals, terminal, timestamps and poll bookkeeping (`last_polled_at`, `poll_fail_count`, `poll_error`, `rate_limit_reset_at`). Polled once per tick, so there is no fan-out and no divergence.
  - `SessionPR`: a link from exactly ONE owner, a session (`session_uuid`) or a backlog item (`backlog_item_id`), to a `PullRequestState` (ent validator: exactly one non-empty). Loose string FKs (default `""`) like `ItemSession`, so history survives session deletion and Jules/item-only PRs need no session. Unique on `(pull_request_state_id, session_uuid, backlog_item_id)`. Holds role, pin, attach source, attach time and nothing else: no `abandoned` flag, no origin column. Nothing is copied from a session link to an item link.
  - `SessionPRTombstone`: `(session_uuid XOR backlog_item_id, canonical PRRef)` written in the same transaction as a detach that deletes that owner's link; backfill, discovery, scan and Jules never recreate a tombstoned owner link; for an item owner it also filters the derived item PR set; collected with its owner.
- Identity is `PRRef{host, owner, repo, number}`, never the number alone, and it is CANONICAL: `NewPRRef` lowercases host, owner and repo (the `RepoRef.repoKey()` rule, `github/repo_ref.go:57-59`; GitHub treats all three as case-insensitive). `NewRepoRefWithHost` keeps owner/repo verbatim (`repo_ref.go:27-37`), so without this the case-sensitive unique index would hold `Acme/App#12` and `acme/app#12` as two state rows. Columns, tombstones, lookups and filters all use the canonical form; display case lives only in `url`.
- Many-to-many falls out of the split: a rework session and its original are two links to one state row.
- Item PR set (membership) is DERIVED at read time and never stored: distinct `PullRequestState` ids from links carrying the item's `backlog_item_id`, UNION the links of the item's current round (its latest `work`-role `ItemSession` by `created_at`, tie-break `id`, falling back to an earlier work session only while the later one has never linked (no link and no session tombstone); `ended_at` and the nullable `started_at` are not read), MINUS states tombstoned for the ITEM (a session tombstone only records that session's own, already deleted, link and does not hide a PR another live contributor holds; the backfill candidate rule, the legacy fallback and the `pr_number` recompute use the wider item-or-any-session `PRCoveredByTombstone` test). A superseded round's session keeps its links and its states keep being polled, but they leave the item's verdict. Detach and item tombstones remove exactly the link they name. A manual attach on a session unrelated to the item does not feed the item.
- Single writer (invariant I1): after insert, `PullRequestState` columns change only through `UpdatePullRequestState`, called only from the poll fetch core (plus one boot-only named exception in the same repository file, `ResetVerifyCounters`, run by `Storage.RunPRStartupMaintenance` from the service bootstrap call sites (`BuildCoreDepsWithOptions` only when `BuildOptions.RunPRMaintenance` is true; the stdio MCP fallback `buildMCPDeps` leaves it false), never from `NewEntRepository`, before any poller exists). Attach, backfill and full saves use insert-if-absent (`EnsureState`), so a stale snapshot can never overwrite a fresher poll result. `UpdatePullRequestState` is monotonic: compare-and-set on `observed_at`, merged/closed sticky with a stated transition table (closed to merged allowed; closed to open only on a webhook-proven reopen; an unverified-terminal row resolves to any real state), and a direct ent write to the entity outside the repository file fails a Makefile ratchet.
- Pin is a boolean on the link (at most one per session), not a Session column. At most one `role=primary` link per session.
- Link, state and the legacy mirror columns are written in one ent transaction.
- Orphan links are removed with their session and by a nightly delete-only GC (owner gone AND older than 24h; states via one conditional statement); search filters orphans.
- Cap of 50 links per session in the attach path.

## Alternatives rejected
- One `SessionPR` entity with a `""` sentinel (first draft): divergent copies of state, double counting, unpolled item rows.
- Single table plus a `distinctByPRRef` step with a precedence rule (`merged > closed > open`): works but leaves divergence possible in storage and needs the poller to fan out; the split removes the cause instead.
- JSON array on the session row: no cross-session query, whole-blob rewrite per state tick, read-modify-write race between poller and `report_pr_created`.
- Item-only PR table: sessions without a backlog item get nothing; breaks when the item/session link is lost mid-review.
- `PreviousPRs []string`: no per-PR state.
- Ent edge `session -> pull_requests`: cascades with session deletion; a `session_uuid IN (...)` query gives the same no-N+1 property.

## Consequences
Bounded bulk load (at most 2 statements per list page: links, then states by id). Idempotent backfill, constructive-only and non-resurrecting (per-boot top-up of legacy numbers that no link represents, run from the service bootstrap only (hook, CLI and MCP-fallback processes never run it; transient errors are retried in-process and then boot continues on the fail-closed rules, re-tried on a 5-minute ticker), with no run-once marker, so a revert and re-deploy self-heals before instances load; tombstones). Backfill never guesses an outcome: terminal legacy rows seed as `unknown` + `terminal` ("unverified terminal", no separate column), merged across candidates with non-terminal winning, and verified by the poller. Cost: two tables instead of one and a join in the load path; a state row with no links is garbage-collected. The poller's unit of work is the non-terminal `PullRequestState`, which also covers item-only PRs.
