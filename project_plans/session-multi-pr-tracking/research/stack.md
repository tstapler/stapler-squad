# Stack research: multiple PRs per session

Method: static reading via grep/sed on 2026-11-03; nothing was run. All claims below are VERIFIED by opening the cited file unless marked INFERRED.

## 1. Ent schema conventions

- Schemas are hand-written in `session/ent/schema/*.go`; generated output (`session/ent/*.go`, subdirs) is gitignored. Only `schema/` is committed (CLAUDE.md "Modifying the ent ORM Schema"). `make ent-gen` runs from a stamp file (`ENT_STAMP := .ent-gen.stamp`, Makefile:52) and `build`/`test`/`lint` depend on it. Generate command must include `--feature sql/upsert`.
- Single-PR data lives as scalar columns on `Session` (`session/ent/schema/session.go:136-155`): `github_pr_url`, `github_pr_number` (Int, default 0), `github_pr_status_terminal` (Bool), `github_owner`, `github_repo`, `github_host`. A second blob, `session_artifacts` (JSON `SessionArtifactsBlob`, field at session.go ~157), already stores `PRURLs []string` (`session/artifacts/types.go:7`): a partial, unqueryable PR history. Research for Phase 2: who writes it, and is it a usable migration source.
- `BacklogItem` has its own `pr_url` / `pr_number` (`session/ent/schema/backlog_item.go:98-102`), also single-valued. `FindPRPendingItems` filters on `PrNumberGT(0)` (comment at `session/backlog_lifecycle_pr.go:167`); `reconcilePRPendingWithoutPRItems` treats `pr_number == 0` as stuck (lines 185-195). Multi-PR items need these reworked too.
- Edge conventions in `Session.Edges()` (session.go:189-217): `edge.To("shells", Shell.Type)` is the existing one-to-many; `edge.From("backlog_items", BacklogItem.Type).Ref("sessions")` is many-to-many. A `SessionPR` entity would add `edge.To("pull_requests", SessionPR.Type)` on Session and `edge.From("session", Session.Type).Ref("pull_requests").Unique()` on SessionPR.
- Loose-FK alternative: `ItemSession` stores `session_uuid` as a plain string, "Loose FK to Session; not an ent edge" (`item_session.go`), so rows outlive the session. Relevant because PR history may need to outlive a deleted session (retention sweeper). Tradeoff: ent edge gives eager loading (`WithPullRequests()`, no N+1) and cascade options; loose FK survives session deletion.
- Composite unique index precedent: `BacklogItemDependency` uses `index.Fields("blocker_id","blocked_id").Unique()` (`backlog_item_dependency.go:58`) together with `OnConflictColumns(...)` upsert in `session/ent_repository_backlog.go:633`. Same shape fits `SessionPR` with unique `(session_id, host, owner, repo, number)`, which satisfies the requirement that the key not be the number alone. Also `OnConflictColumns(...).Update(func(u *ent.BacklogStuckStateUpsert){...})` at `ent_repository_backlog.go:2366` is the template for an idempotent "attach PR" write (needs `--feature sql/upsert`).
- Index discipline: recent commit 35c9687b7 ("index item_sessions by backlog item; drop 4 unused classification_analytics indexes") shows indexes are added deliberately and unused ones dropped, so add only the indexes with a real query (session_id for list load; state for the poller's "open PRs" scan).
- Schema tests: `session/ent/schema/migration_test.go` is the pattern: in-memory SQLite round trip proving new fields exist and old rows load at zero values; there is no SQL migration file.

## 2. Migrations

- DDL: `client.Schema.Create()` in `NewEntRepository` (`session/ent_repository.go:237`), serialized by `EntSchemaCreateMu` (line 40). ent auto-migration adds tables/columns/indexes additively; it does not drop columns, so legacy `github_pr_*` columns stay (matches the "legacy fields stay readable" constraint).
- Data migrations: `session/ent_repository_migrations.go`. Add `func runXBackfill(ctx, er *EntRepository) error` plus a test, append `funcMigration{"name", fn}` to `startupMigrations` (list at end of file). Must be idempotent, run on every startup, and be best-effort per row (log and continue). Current order is non-load-bearing; `github pr url backfill` is entry 4. Pre-schema checks (like `workflowEnabledColumnPreexisted`) are the only exception and are not needed here.
- Backfill template, `session/github_pr_url_backfill.go`: query rows with `session.GithubPrNumberGT(0)` and empty URL, build a `github.NewRepoRef(owner, repo)`, recover host with `hostFromClonedPath(path, ref)` (`session/repo_path.go`) and skip, never guess, when host is unrecoverable (guessing github.com would corrupt GHE rows), then `UpdateOneID(...).Save`. Returns nil if the table is missing. Counts migrated/skipped and logs with `log.InfoLog()`/`WarningLog()` using a `[Migration] ...` prefix. A new "legacy PR fields -> SessionPR rows" migration follows this shape; idempotency comes from the unique index plus upsert/`OnConflictColumns...DoNothing`, and it runs after `github pr url backfill` so URLs are populated first. It satisfies the requirements' observability item ("log when migration backfills legacy fields"). Note the host quirk: `github_host` exists on Session, so for rows that have it, no path recovery is needed.
- The backfill gives the legacy dual-write path a parallel: during rollout legacy columns keep being written (requirements "Risk Control"), so the write path (ent_repository.go create ~406-422 and update ~752-768, plus `UpdateGitHubPRNumber` at 1136 and `UpdateGitHubPRStatusTerminal` at 1156) needs both legacy and relation writes. Caution: update path only sets fields when non-zero (`if data.GitHubPRNumber > 0`), so clearing/switching the legacy field is not expressible through the existing update; the relation must be the source of truth for "current PR" when the flag is on.

## 4. Proto conventions for the change

- Add, never renumber or remove: new `message SessionPullRequest { host, owner, repo, number, url, state (string "open|closed|merged"), is_draft, role, created_at, merged_at/closed_at, is_active }` and `repeated SessionPullRequest pull_requests = <next free number>` on `Session` (check the max field number first; 35 is used, but `reserved` ranges are unchecked). Keep fields 25/26/33-35 populated from the active PR so older clients (mobile app) work, which matches the legacy-readable constraint. Status values use plain strings today (`"open" / "closed" / "merged" / ""`, line 1706), so follow that rather than introducing an enum unless planning wants one (enum + `buf-breaking` would then need care; `make proto-breaking` exists).
- A new RPC (e.g. set active PR, list PRs) needs proto in `proto/session/v1/session.proto`, `make proto-gen`, handler in `server/services/`, registration in `server/server.go`, `make registry-generate`, a `// +api:` marker, and RPC read/write classification (see memory entry on new-RPC CI gates: sinkguard tag, hand-set `tested`).
- Direct Connect calls use the `/api` prefix (`docs/reference/backlog-dependencies.md`); not needed for this feature unless MCP tools are added.

## 6. Data-model options mapped to this stack

| Option | Stack fit | Verdict (INFERRED) |
|---|---|---|
| New ent entity `SessionPR` + edge | Matches `Shell`/`BacklogItemDependency` precedents; unique composite index and `OnConflictColumns` upsert exist in repo; `WithPullRequests()` avoids N+1; additive DDL via `Schema.Create` | Best fit; requires snapshot slice + dual-write |
| JSON array column on Session | Precedent: `session_artifacts` JSON blob; no new table; but state updates rewrite whole blob and the poller/gate can't query "open PRs" across sessions | Weak for polling and backlog gate |
| `PreviousPRs []string` | Trivial, but no per-PR state | Fails success metric 1 |
| Derive from GitHub on demand | Costs rate limit; conflicts with ETag-saving rule | Reject |

Suggested key: unique `(session_id, host, owner, repo, number)`; `host` empty = github.com, matching `github_host` semantics (session.go:153-155).
