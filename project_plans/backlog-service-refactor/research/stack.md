## ent ORM

**entgo.io/ent v0.14.5** with the `--feature sql/upsert` flag required for regeneration.

### Column-level projection (critical for P4 BacklogItemSummary)

`BacklogItemQuery.Select(fields ...string) *BacklogItemSelect` exists and is functional — confirmed in `session/ent/backlogitem_query.go` line 441. The generated `BacklogItemSelect` supports scanning into custom structs via `.Scan()`.

Usage pattern for a summary projection:
```go
var summaries []BacklogItemSummary
err := client.BacklogItem.Query().
    Select(backlogitem.FieldID, backlogitem.FieldTitle, backlogitem.FieldStatus, backlogitem.FieldPriority, backlogitem.FieldUpdatedAt).
    Scan(ctx, &summaries)
```

This means P4 can use ent's own Select/Scan without raw SQL, staying fully within the ORM.

### ent type leakage into domain model (P6)

`BacklogItemData` in `session/repository.go` (line 283–286) already leaks ent types:
```go
ItemSessions  []*ent.ItemSession         // ent type in domain model
StatusEvents  []*ent.BacklogStatusEvent  // ent type in domain model
```
The P6 audit starts here — these fields are the known violations. The Storage interface methods (`CreateBacklogItem`, `GetBacklogItem`, `ListBacklogItems`, etc.) in `session/repository.go` lines 160–172 all return `*BacklogItemData` or `[]BacklogItemData`, which means ent only leaks through these two eager-load fields, not through the interface contract itself.

## Build Constraints and Code Generation

Steps that must be preserved after any package reorganization:

| Step | Command | Trigger |
|---|---|---|
| Proto bindings | `buf generate proto` via `make proto-gen` | Any `.proto` change; auto-stamps `.proto-gen.stamp` |
| ent ORM | `go run -mod=mod entgo.io/ent/cmd/ent generate --feature sql/upsert ./session/ent/schema` | Any schema file change |
| Feature registry | `make registry-generate` | Any new RPC or React component |
| Web assets | `make web-build` | Frontend changes only |

**Critical**: The `--feature sql/upsert` flag is mandatory for ent generation (see `session/ent/generate.go`). Omitting it silently breaks `UpsertRule` methods.

Package reorganization (P5 `session/domain`) requires no code-generation changes — only import path updates in files that reference the moved types.

## Linter Configuration (golangci-lint v2)

Active linters: `depguard`, `exhaustive`, `forbidigo`, `gochecknoglobals`, `ineffassign`, `nilnil`, `prealloc`, `staticcheck`, `govet`, `unused`.

### Critical rules for this refactor

**`depguard` — `no_server_in_core` rule** (`.golangci.yml` lines 26–35):
- Applies to: `**/session/**/*.go`, `**/config/**/*.go`, `**/log/**/*.go` (excluding test files)
- Denies imports of: `github.com/tstapler/stapler-squad/server` and `server/**`
- Impact on P5: A new `session/domain` package is covered by this rule. It must NOT import anything from `server/`. This is already the correct design — pure domain types have no reason to import server code.

**`gochecknoglobals`**:
- Suppressed for `^session/` path — the existing glob covers `session/domain/` too. New package inherits the suppression.
- New packages in `pkg/` (e.g., `pkg/warren`, `pkg/events`) are NOT suppressed — unrelated to this refactor.

**`forbidigo`** — log pattern suppressed for `^session/` — `session/domain/` inherits suppression.

**`exhaustive`** — suppressed for all `session/` paths except `session/detection/`. Moving `BacklogStatus` to `session/domain` poses no exhaustive-switch risk since the linter is already suppressed there.

**`unused`** — after splitting `backlog_service.go` (P1), unexported helpers that are only referenced within the same file must remain in the same package (they can move to a new file within `server/services/`). Moving them to a new package would require exporting them, which may be intentional or an export-pollution issue to watch.

## Summary

- **Go 1.25.0** — full modern stdlib; no constraints on sub-package creation.
- **ent v0.14.5** — `BacklogItemQuery.Select(fields...)` confirmed available for P4 `BacklogItemSummary` column projection without raw SQL; known ent-type leaks in `BacklogItemData.ItemSessions` / `.StatusEvents` are the P6 starting point.
- **depguard `no_server_in_core`** is the key lint constraint for P5 `session/domain`: the new package is automatically covered and must stay free of server imports (which is the correct architecture anyway). `gochecknoglobals` and `forbidigo` suppressions for `^session/` extend to sub-packages.
