## P1 Items (address before implementation)

- [ ] **Failure #1 — schema mismatch in second-phase query**: Before writing a single line of Story 5.1.2, query the actual `item_sessions` columns from the schema (`session/ent/schema/item_session.go`). The plan's proposed SELECT list (`status`, `triage_result_summary`, `overall_outcome`) references three non-existent columns. The correct approach: select `id`, `backlog_item_id` (via edge FK), `session_role`, `triage_result` (full JSON), `ended_at`; extract `triage_result.summary` by parsing the JSON in Go; add a third query (or a LEFT JOIN) on `review_verdicts` keyed on `item_session_id` to populate `overall_outcome` for the board view's gate verdict indicator. Update the `ItemSessionSummary` struct definition in Story 4.1.1 to add `Status` (actually `EndedAt *time.Time` is what the board view uses — see `mapBacklogItem`), `OverallOutcome string`, and use `TriageResultSummary string` populated by parsing `TriageResult` JSON. Revise Story 5.1.2's task list before any implementation begins.

- [ ] **Failure #2 — missing struct tags**: Add `json:"<column_name>"` tags to every field in `BacklogItemSummary` before writing the `Select().Scan()` query. Required tags (from ent `BacklogItem` generated struct as reference): `ID \`json:"id"\``, `ExternalID \`json:"external_id"\``, `Title \`json:"title"\``, `Status \`json:"status"\``, `Priority \`json:"priority"\``, `RepoPath \`json:"repo_path"\``, `AcceptanceCriteria \`json:"acceptance_criteria"\``, `Notes \`json:"notes"\``, `PrURL \`json:"pr_url"\``, `PrNumber \`json:"pr_number"\``, `CreatedAt \`json:"created_at"\``, `UpdatedAt \`json:"updated_at"\``, `ArchivedAt \`json:"archived_at"\``. Omitting any tag causes `ScanSlice` to return a hard error (not a silent zero value) because `columnName()` in ent's scan.go uses `strings.ToLower(fieldName)` without underscores when no tag is present.
