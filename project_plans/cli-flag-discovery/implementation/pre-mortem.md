# Pre-mortem: cli-flag-discovery
**Date**: 2026-09-21

Inputs: `implementation/plan.md` (662 lines, read in full) and `requirements.md`. Claims about plan content cite plan sections; claims about the world outside the plan (CLI startup times, script behavior) are INFERRED and marked as such.

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | The fixed 3s timeout (AC3, `DefaultLimits`) is too short for the CLIs this feature exists for. Node and Python CLIs such as claude, gemini and especially aider often need multi-second cold starts (INFERRED, never measured; plan Task 1.1.3a captures fixtures but records no timings). Flags come back as `TIMEOUT` with zero flags, so autocomplete and warnings never appear for the main targets. `TIMEOUT` is cached only 30s, so each re-probe repeats the slow run. | Program Config shows "Timed out checking flags (3s)" for `aider`/`claude` on first blur, on a busy laptop, or after a reboot when the page cache is cold. The AC1 aider fixture test passes because `run` is faked. | Add a gating step to Task 1.1.3a: record cold and warm `--help` wall time for claude, aider, gemini, agy and gh, and write the numbers into the plan. If any target exceeds about 1.5s cold, amend AC3 (with the user's sign-off) or make the probe async. Async means the RPC returns quickly with a `PENDING` status, the flight continues under `WithoutCancel`, and the client re-polls. Also: raise the `TIMEOUT` TTL, or cache partial output up to the timeout and parse it. Add one real-binary smoke test (skipped when the binary is absent) that asserts `FOUND_PARSED` for whichever of claude/aider is installed. | P1 |
| 2 | Probing runs `<path> --help` on any executable the user types or has saved, including custom shell scripts. Many scripts ignore arguments and run their body, for example wrapper or launcher scripts in `~/bin` (the repo has `proxy-claude` style wrappers, plan Flagged Choice 10). Wrapper detection covers only a fixed list (`env`, `sudo`, `npx`, ...). In session creation the probe fires on picker selection with no explicit user action (Task 2.3.2a effect), and Program Config fires on blur/Enter. So merely selecting a program executes it. | A stray process, daemon, network call or file write appears after the user tabs out of the command field or opens the omnibar Advanced section. The audit log shows a `program_probe` line, but only after execution. | Do not execute unknown scripts implicitly. In `Prober.Probe`, read the first bytes of the resolved file; if it has a `#!` shebang (script, not a native binary), return a `NEEDS_CONFIRM` status and run only after an explicit Check click (`prog-command-check`) that sends a `confirmed=true` field. In the session picker, never auto-probe; probe only cache hits or saved programs already verified through Program Config. Add tests: a script whose body touches a marker file is not run on blur or selection, and is run after an explicit Check. Get ADR-001 sign-off on this explicitly, since AC8 in `requirements.md` says probing is "only allowed for the command the user is configuring". | P1 |
| 3 | `ProbeGuard` (Host and Origin allow-list on `Start()`'s chain, `authMiddleware == nil`) 403s the real access path. Unresolved Q #7 leaves the bound-address accessor unverified, and the guard treats a non-loopback bind as "block always". If the service is reached through a LAN or Tailscale name on `:8543`, a reverse proxy, or a listen address other than `localhost`, every probe returns 403. The UI maps that to "Couldn't check" for good. | The badge always reads "Couldn't check" in the deployed systemd instance while unit tests, e2e (`Host: localhost:<port>`) and manual `localhost` runs all pass. | Before merge, hit the deployed instance's real URL(s) and record which Host values the guard sees. Add a Task 1.2.3d live check against a manual instance with `STAPLER_SQUAD_INSTANCE`. Make the guard log the rejecting reason and Host at Warn (already partly planned) and surface a specific `transportError` hint naming "Host not allowed" rather than generic copy. Resolve Unresolved Q #7 in the first task of Story 1.2.3, not at implementation time. | P2 |
| 4 | Login-shell PATH derivation (Task 1.1.4d) sources the user's `~/.zshrc` from a goroutine started in `NewDefaultsService()`. That constructor is called across many `server/services` tests, so every test process spawns a real shell that reads the developer's or CI runner's real rc file (slow, non-hermetic, goleak-visible). Separately, rc output on stdout (p10k instant prompt, `echo`, nvm banners) is concatenated into the captured `$PATH`, yielding garbage directories and a false NOT_FOUND. | Flaky or slower `server/services` tests and leaked-goroutine failures in CI. On the dev machine, `NOT_FOUND` for a binary that is on PATH. | Do not start the goroutine in `NewDefaultsService()`. Start it in the production wiring point (`main`/`BuildDependencies`) via an explicit `prober.StartLoginPathDerivation()`, so tests default to server PATH plus fallback dirs. Print the PATH between unique sentinel markers (`__PATH_START__...__PATH_END__`) and parse only that span; discard the result if the markers are missing. Add tests for polluted rc output and for a test-constructed `DefaultsService` spawning no process. | P2 |
| 5 | The precision-first parser (8 fixtures, heuristic per-format line handlers) misses or mangles flags on real help output (multi-line groups, hidden or undocumented flags, subcommand-only flags, version drift). `validateFlags` then warns on valid flags, or autocomplete lists a partial set. Users learn to ignore or distrust the warnings, which is the opposite of the goal. The zero-flags and wrapper suppressions do not cover a partially parsed table. | The user reports a warning on a flag that works (for example a claude flag missing from `--help`). Field usage shows Save clicked with warnings present every time. | Add a per-program sample check to the fixture task: for claude, aider, gemini, agy, run the parser on current real output and compare the flag count against a hand-counted list. Add a low-coverage guard: if fewer than N candidate `-`-lines parsed relative to the count of `-`-leading lines in the text (say under 60%), treat as `FOUND_NO_FLAGS` and suppress warnings. Keep the "may still work" wording (already planned) and add a per-program "dismiss" for warnings if noise shows up. | P2 |

## P1 Items (address before implementation)
- [ ] Failure #1 (3s timeout too short for target CLIs) — add a measured cold/warm `--help` timing step to Task 1.1.3a as a go/no-go; if a target exceeds about 1.5s cold, amend AC3 or make the probe async with a `PENDING` status; raise/reshape the `TIMEOUT` cache; add a skip-if-absent real-binary smoke test.
- [ ] Failure #2 (implicit execution of arbitrary scripts on blur or picker selection) — add shebang detection and a `NEEDS_CONFIRM` status in `Prober.Probe`, require an explicit Check click to run scripts, remove auto-probe on picker selection in `ProgramProbeSection` for unverified programs, add tests that a marker-writing script is not run implicitly, and record the AC8 interpretation in ADR-001 sign-off.
