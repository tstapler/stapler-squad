## Blockers
- [ ] Task 1.1.4a/1.1.4b (Prober, singleflight, cache) + Task 2.1.1a (hook aborts on every command change) — the singleflight leader runs `run` with the caller's request context, and the hook aborts the previous request each time the command changes or the component unmounts. A cancelled leader (a) fails every follower sharing the flight, and (b) makes `Run` return partial output with `TimedOut=false` (only `DeadlineExceeded` sets it; "ignore exit error unless start failed"), which maps to `FOUND_NO_FLAGS` and is cached for 10 min. That is a sticky wrong result triggered by the plan's own client design. — Run the flight body on `context.WithoutCancel(ctx)` (the 3s `WithTimeout` inside `Run` still bounds it) and let each caller wait on `DoChan` or `ctx.Done()`; treat `ctx.Err()==Canceled` as `ERROR` and never cache it; add a test that cancels the caller mid-probe then re-probes and asserts a real result. Add this to Story 1.1.4 acceptance criteria.

## Concerns
- [ ] Task 1.1.4a (semaphore) + 1.1.4b (cache TTL) — semaphore-saturated rejection returns `ERROR` and the cache stores `ERROR` for 30s, so transient load becomes a 30s sticky failure for that binary — Return a distinct non-cached outcome (e.g. `ERROR` with `cacheable=false`, or the UI retries), or cache only `TIMEOUT` and run-start `ERROR`.
- [ ] Unresolved Questions #1 / Task 1.1.4a (LookPath-only resolution) — the repo itself resolves programs through the interactive shell (`config/config.go:1215-1262`, `GetClaudeCommand` sources `~/.zshrc` and reads `alias`; `GetAvailablePrograms` at `:1286` uses `which` via the shell), and the candidate list includes `proxy-claude`. A pure `exec.LookPath` on server PATH will report "not found" for alias-only programs that do launch. The plan only frames this as a PATH mismatch. — Record in the plan that alias/function-defined commands are reported not-found, keep the "server's PATH" wording, and make the not-found copy softer ("not found as an executable on the server's PATH; shell aliases are not checked"). Do not upgrade to shell resolution (it would break ADR-001's no-shell envelope).
- [ ] ADR-001 / Story 1.2.2 — the `:8543` listener is unauthenticated (ADR cites `main.go:1538`; `SetupAuth` is `server.go:1267`, remote server only), and the RPC now executes an arbitrary caller-chosen absolute path with `--help`. The ADR reasons "same user can already launch it", but an unauthenticated local or browser-driven caller (CSRF/DNS rebinding against localhost) is not that user. Sign-off is still open in Unresolved Questions. — Before merge, confirm the existing Connect handler rejects non-JSON/cross-origin POSTs and Host-header mismatches for this RPC (add one handler-level test), and note in ADR-001 that escalation to option B is additive. Requirement AC8 ("only the command the user is configuring") is met only by shaping, not verification; say so in `docs/reference/program-probe.md`.
- [ ] Tech Debt Disposition, `OmnibarCreationPanel.tsx` row — the row promises "one hook call and one badge element", but Tasks 2.3.2a and 4.1.2b add command resolution from `pickerPrograms`, a selection-change effect, `validateFlags` computation, a warning element, and rework of `isProgramRecognized` in a 1040-line file with 36 commits. That deepens the hotspot, contrary to the "Isolate via seam" claim. — Name the seam as a task: a `ProgramProbeSection` component (props: selected `ProgramOption`, `extraFlags`) owning hook, badge and warning, so the panel gains a single JSX element and no state. Sequence it before 2.3.2a/4.1.2b.
- [ ] Domain Glossary `RunFunc` vs Task 1.1.2b `Run(ctx, path, lim Limits)` — the injected `RunFunc(ctx, path)` has no `Limits`, yet `WithLimits` and `Run` take them; the two never meet in the design, so tests using `WithRun` cannot exercise limit plumbing, and production wiring is unspecified. — Make production `run` a closure `func(ctx, p) { return Run(ctx, p, limits) }` built in `NewProber`, and state it in Task 1.1.4a.
- [ ] Proto (Task 1.2.1a) — `found` and `probe_status` are two encodings of one fact and can disagree (`found=true`, `NOT_FOUND`). — Keep `found` for AC1, but derive it solely in `probeResultToProto` from the status (found iff status in {FOUND_PARSED, FOUND_NO_FLAGS, TIMEOUT}) and add a table test asserting the invariant. Also define what `found` means for `ERROR` (semaphore rejection is neither found nor not-found) so the badge does not claim "not found" on a resource-limit error.
- [ ] Story 4.1.2 / AC7 — `extraFlags` from alias metadata is validated only "if already plumbed to the panel" (`Omnibar.tsx:1485` is a different component from the panel), so AC7's second half may silently not ship. — Decide now: pass `extraFlags` as a prop (small task) or explicitly narrow AC7 in requirements and record it in Flagged Choice 2 as a scope reduction.
- [ ] Flagged Choice 5 (new `FlagCombobox`) — a second combobox alongside `AutocompleteInput` and `HistorySearchInput` (`components/history/`) creates three overlapping combobox implementations. Not a blocker given the five `AutocompleteInput` consumers and jscpd margin, but the "shared pure helpers" mitigation is not a task. — Add a task to extract the listbox key handling shared with `HistorySearchInput` (or record a follow-up issue) so the duplication is a known, tracked cost.
- [ ] Task 1.1.1a — `Resolve(command, home) (Target, ResolveReason)` allows a populated `Target` with a non-`OK` reason. — Return `(Target, ok)` with a reason only on failure, or make `Target` unconstructible except via a successful resolve (parse-at-boundary; keep `ResolvedPath` only from `lookPath`).

## Re-review (2026-09-21)
**Scope**: only the prior BLOCKER (singleflight leader on caller ctx / cancelled probe cached as `FOUND_NO_FLAGS`), checked against `plan.md` Tasks 1.1.4a-c, Story 1.1.4 ACs, the "Review repair log" (`plan.md:600-612`) and `decisions/ADR-002-*.md`.
**Verdict**: CONCERNS (prior blocker resolved; no new blocker)

### Prior blocker: resolved
- Flight isolation: `plan.md:277` runs the flight body on `context.WithoutCancel(ctx)` with `DoChan`; each caller selects on the channel or its own `ctx.Done()`. Concrete, and a follower no longer inherits a leader's cancellation.
- Never cached: cancelled caller returns `ERROR`; `ERROR`, `BUSY`, `NOT_FOUND` are never stored (`plan.md:276`); `Canceled` cannot set `TimedOut` (`plan.md:277`, ADR-002 decision list).
- Tests specified: Story 1.1.4 "Cancellation safety" AC (`plan.md:262-263`) covers cancel mid-probe, prompt `ERROR`, re-probe returns the real result, and a follower gets the real result; Task 1.1.4c lists cancel-then-reprobe and follower-of-cancelled-leader; runner test asserts cancelled ctx returns an error.

### New-issue check
- Goroutine leak on `DoChan` when all callers cancel: not a leak. The flight goroutine is bounded by `Limits.Timeout` (3s) plus `WaitDelay` 200ms, and the `DoChan` channel is buffered, so it finishes and caches for the next caller. Server shutdown no longer cancels an in-flight probe, but the same 3s bound applies.
- `ProbeGuard` placement: wraps the handler at the mount point (`server.go:414`), applies only to the `ProbeProgram` path, POST-only then Host/Origin; consistent with the verified middleware chain. No issue.

### Concerns (non-blocking, fix in the plan before implementing)
- [ ] Task 1.1.4a semaphore ordering: the slot is taken per caller before the flight (`cache lookup -> semaphore -> flight`). Followers of one flight each consume a slot, so concurrent duplicate probes of one binary can return `BUSY` instead of sharing the result, and a cancelled caller frees its slot while its flight keeps running, so more than 2 processes can run at once. Acquire the non-blocking slot inside the flight body (leader only), release when the flight ends, and return `BUSY` through the flight result. Add a test: 10 concurrent same-binary probes all get the real result, and a cancelled caller does not free the slot early.
- [ ] Repair log cites ADR-002 for the fix, but ADR-002 records no `WithoutCancel`/singleflight decision. Add one line to ADR-002 or drop the citation.
- [ ] Add a `goleak`/`Eventually` assertion that the flight goroutine exits after all callers cancel and the fake is released (cheap, and it proves the no-leak claim above).
