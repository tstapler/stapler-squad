# Pre-mortem: scrolling
**Date**: 2026-10-01

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | Routing ships on the default rows (`alternate`+any -> `tui-pgkeys`, `tracking != none` -> `tui-pgkeys`, `normal`+`none` -> `xterm-local`) unverified because the Phase 0 device spike is device-gated and may be skipped (decision 2026-10-01: ship unverified, user-accepted). Sessions run inside tmux, so a plain shell reports the alternate screen: its drag sends PgUp to tmux, which enters copy-mode and scrolls tmux history (INFERRED from tmux defaults; bash ignores the key), and a stale copy-mode can swallow keystrokes. Claude Code may sit in the normal buffer with tracking `none`, where local scroll does nothing for the app. | First device run: drag in a tmux shell or Claude Code moves the wrong layer or only one direction; typing seems ignored after a drag in a tmux shell. | **Resolved by decision, not by a gate**: the Routing Verification Statement (a PR-body statement, not a mechanical block) states the risk; the persisted `auto \| local \| tui` override, the always-visible effective-mode chip, the first-use hint (PgDn to the bottom exits tmux copy-mode; no Esc/`q` offered) and the route-aware toolbar keys are the mitigations; the spike's mode matrix (week-1 device pass) corrects the rows afterwards; tmux copy-mode cannot be detected from the client (design/ux.md S6). The per-session `'tui'` default for tmux sessions suggested earlier is not adopted (decision). Jest fixtures pin the default rows. | P1 (mitigated) |
| 2 | The black-screen fix targets the wrong cause. The plan assumes the container resizes on keyboard open and a sampler or repaint step is missing. But the Q3 branch table admits the container may not resize (only `visualViewport` shrinks), and the log at `XtermTerminal.tsx:~606` says WebGL2 may be unavailable on Android, so the WebGL branches (`clearTextureAtlas`, `onContextLoss`) may never run on the target device. All unit tests pass (mocked terminal) while the 50-cycle metric still fails. | Device checklist D7 still shows blank terminals after a few cycles; `dump()` shows `refit()` fired with an at-rest repaint but the canvas stays black. | Capture the Q3 verdict (container size vs `visualViewport`, active renderer) before Story 2.1.2 wiring, and branch on it explicitly. Add a fallback path that does not depend on RO: the settle signal also sets `--viewport-height` consumers and forces a container reflow check. State in the PR that D7 is unproven if no device run happened. | P1 |
| 3 | Deleting TerminalOutput's `onVpResize`/`isFittingRef` pipeline and bypassing the 150 ms RO debounce causes regressions: a SIGWINCH burst to tmux while the keyboard animates (`refit()` per settle, plus URL-bar jitter hitting the 600 ms max-wait), or an iOS-style resize loop that `isFittingRef` was guarding (`TerminalOutput.tsx:1171`). Settle (3 frames, up to 600 ms) can also be slower than today's 400 ms path, so the blank window grows. | Terminal reflows repeatedly or flickers when the keyboard opens; tmux panes redraw twice; `__termDebug` shows multiple `refit()` calls per open. | Add a test that N rapid `vv` resize events yield exactly one `refit()`, and a loop guard in `refit()` (ignore a request when dims are unchanged and a repaint already ran this frame). Measure the settle latency in the Phase 0 log and tune `stableFrames`/`maxWaitMs` against 400 ms. | P2 |
| 4 | The TUI path is page-stepped and non-1:1 (one `\x1b[5~` per half page of post-slop travel, capped at 5 pages per fling, 100 ms rate limit), yet an early success metric said "1:1 with finger movement ... including Claude Code". Users see page jumps or a stalled fling and judge the feature not done. | User feedback on the first device run: "scrolls in big jumps" or "fling stops after a few pages". | **Resolved**: requirements.md Success Metrics carves out TUI mode (decision 2026-10-01); half-page steps and the first-use hint (design/ux.md S1, S6) reduce the dead-drag problem; D9 tunes the step. | P2 (mitigated) |
| 5 | The COASTING / `consumedByCoast` state machine leaks. A `touchcancel` (Chrome taking over the gesture), a momentum end racing a `touchstart`, or a lost `touchend` leaves the flag stale, so the next real tap does not focus (or a touch-to-stop opens the keyboard). | Tap-to-focus intermittently fails after a fling, or the keyboard pops up when stopping a fling. | Add tests for `touchcancel` during COASTING, `touchstart` on the exact frame momentum ends, and a flag timeout reset (clear on any new touchstart that is not the coast-stop). Include in device checklist D3/D5. | P3 |
| 6 | Route-aware toolbar PgUp/PgDn (Story 1.2.9) change a proven path: in `auto`, a normal-buffer Claude Code that routes local now scrolls xterm history from the toolbar instead of reaching the app. | D5: toolbar PgUp in Claude Code no longer moves the app's scrollback. | Edge fall-through to bytes in `auto`; App pages override; D5 records which case occurs; PR states the residual risk. | P2 |
| 7 | TalkBack: `preventDefault` over the canvas breaks explore-by-touch or activation, and page JavaScript cannot detect TalkBack. | D8 with TalkBack on. | Gesture scrolling Off setting (manual switch) restores native gestures and `touch-action`; D8 verifies Off and On; screen-reader access to content is out of scope. | P2 |

## P1 Items (all resolved 2026-10-01, round 2)
- [x] Failure #1: resolved by the user decision to ship unverified. The Q2 mode matrix is not a merge gate; see the Routing Verification Statement (plan.md), the override, chip and hint (design/ux.md S6) and Story 1.2.9, and the week-1 device pass (plan.md Schedule) that corrects the rows early.
- [x] Failure #2: the Q3 verdict (container resize, renderer) is recorded in the week-1 device pass (Task 0.1.2d) before Story 2.1.2 is wired; Story 2.1.2 is built for every outcome with a non-RO trigger (`refit()` reads container vs `visualViewport`); the 50-cycle metric is never claimed without a device run and a measured baseline (requirements.md rule `N = ceil(3 / baseline)`; no-device path in Task 0.1.2d).
