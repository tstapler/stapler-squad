# Validation Plan: scrolling

**Date**: 2026-10-01

All paths are under `web-app/src/` unless stated. Type names follow the plan.md Domain Glossary. All new jest tests use fake timers / injected clock and rAF (no real sleeps).

## Happy Path Scenario
Given the Baseline (Android Chrome, drag up scrolls partially, drag down does nothing, blank terminal after keyboard open), when the user drags a finger down then up in a normal-buffer terminal and in a Claude Code session and then opens and closes the soft keyboard, then content moves in both directions (1:1 in `xterm-local`; page-stepped, capped and rate-limited via `\x1b[5~`/`\x1b[6~` in TUI mode, reached through the default routing rows, unverified until the spike, or the S6 override), no keyboard opens from the drag, and the terminal repaints with content visible within plan.md's repaint timing budget after the viewport settles.
