# Validation Plan: linear-jira-integration

**Date**: 2026-08-21

## Happy Path Scenario

Given a `LinearPlugin`-backed `ItemSource` is configured with a valid API key in the OS keychain, when the polling sync loop calls `LinearPlugin.Fetch` and finds a new Linear issue, then a new `BacklogItemData` is created, mapped with the issue's title/priority/labels/external URL, rendered in the web UI with a "Linear" source badge, and visible when the backlog board is filtered to `source_plugin_filter: ["linear"]`.

## Test Stack

- **Unit**: Go's standard `testing` package + table-driven tests, matching `session/backlog_plugin_github_test.go`'s existing style. `httptest.Server` for stubbing Linear's GraphQL endpoint and JIRA's REST endpoints at the HTTP boundary (kept as "unit" when the assertion is about a single function's decoding/mapping logic; promoted to "integration" below when the assertion is about the full request/response round trip or cross-package wiring). `99designs/keyring`'s `keyring.MockInit()` for keychain package tests (mirrors `github/main_test.go`).
- **Integration**: Same Go `testing` package, but exercising real cross-component wiring — an actual ent-backed test database (`session/ent_repository_backlog_test.go`'s existing harness) for repository/filter tests, the real `EventBus` + subscriber wiring for forward-sync tests (`server/services/backlog_forward_sync_test.go`), and the hand-rolled JIRA client against an `httptest.Server` for JIRA plugin tests.
- **E2E / UX**: Playwright against the isolated per-run test server (`tests/e2e/global-setup.ts`), per `.claude/rules/e2e-test-conventions.md` — `@feature` annotation header, no `waitForTimeout`, `data-testid`/ARIA locators only, reusable page helpers in `tests/e2e/pages/`.

## Coverage Targets and How to Measure

| Stack | Coverage command | Target |
|---|---|---|
| Go | `go test ./... -coverprofile=coverage.out && go tool cover -func=coverage.out` | ≥80% line |
| TypeScript/Jest | `npx jest --coverage --coverageThreshold='{"global":{"lines":80}}'` | ≥80% line |

- All public service methods: happy path + error paths covered (`LinearPlugin`/`JiraPlugin`'s `Fetch`, `MapToBacklogItem`, `UpdateIssueState`/`TransitionIssue`, `PostIssueComment`; `linear`/`jira` keychain packages; `jira.ADFToPlainText`/`PlainTextToADF`).
- All external integrations: unit mocked (`httptest.Server` stubs for Linear GraphQL and JIRA REST) + at least one integration test exercising the real HTTP round trip and.
- UX acceptance criteria: each of the three Phase 4 criteria (source badge, filter-by-source, JIRA credentials form) has a corresponding Playwright spec — see UX Acceptance Tests table above; no manual-only steps remain unautomated.
- Migration: **N/A** — plan.md's Migration Plan section confirms no ent schema migration (ADR-001 reuses `GitHubSyncedIssueUpdatedAt` as-is); only additive, non-breaking proto field changes (`BacklogItem.plugin_id`, two `source_plugin_filter` fields) requiring `make proto-gen` but no up/down migration test.
