# ADR-001: Single host consumer, event-free steer text, dedicated poll ticker, actor gate, fail-closed login, exported signature

**Status**: Proposed (2026-10-22). Needs the owner's sign-off on the ticker exception (decision 3) and on the open human-feedback residual risk (decision 4). Decisions 4-6 were added after the triad review and are part of the same proposal; decision 4 was reworked in repair pass 3.

## Context

Squad will poll the gh-signal inbox (`docs/agent-inbox.md` in `tstapler/gh-signal`) and steer sessions whose PRs get activity. PR text is attacker-controlled; the inbox has no push API, cannot list consumers and never prunes pending items for active subscriptions; `server/wakes` ADR-006 rule 6 says no new tickers.

## Decisions

1. **One consumer, `squad:<hostname>`.** Meets the one-events-request-per-tick requirement; lets Squad diff its own `GET /v1/subscriptions` (about every 60 s) to remove orphans. Cost: acks cover all targeted sessions, so Squad tracks per-event delivery in memory. A hostname change orphans the subscriptions under the old consumer ID; the operator doc gives the cleanup commands.
2. **The steer text contains no event-derived free text** (no actor, action, summary or body). Only an enum kind (`review`, `comment`, `inline comment`, `CI failure`; mixed kinds in one coalescing window render as a fixed enum list such as "review, CI failure"), a PR number, a validated `owner/name`, fixed per-kind instructions (`gh pr view <n> --repo <owner>/<repo> --comments`, `gh api repos/<owner>/<repo>/pulls/<n>/comments` for inline review comments, `gh pr checks <n> --repo <owner>/<repo>`), the sentence that genuine Squad notices appear only in the terminal and never inside PR text, and the fixed provenance prefix `[stapler-squad automated notice]`. Rationale: a legal GitHub login or an `action` string can carry instruction-like text, and the pane is a prompt; the "only in the terminal" sentence is the defence against a PR comment that imitates the prefix. The `gh api` pointer exists because `gh pr view --comments` may omit inline review threads (INFERRED; checked in plan task 6.5).
3. **A dedicated short-interval poll loop**, as an explicit exception to ADR-006 rule 6, because it is loopback-only and makes no GitHub API call. Bound with the exception: poll interval plus request timeout (5s + 2s = 7s). Fallback if rejected: use the existing 60s ticker; the bound becomes about 62s. (Owner: Tyler. This ADR stays Proposed until he signs off. The requirements "Decisions awaiting owner" section lists this item.)
4. **Actor gate: collaborator check REJECTED for v1; `human_feedback_mode` plus self and bot filters ADOPTED.** The pre-mortem (P1 #1) suggested gating on the repo's collaborators via a `gh api` call. Rejected because it adds a network call per unseen actor, on the event path, and a new failure mode (rate limit, auth, GHE) there, on a path that must stay loopback-only. Adopted instead:
   - Unconditional self-event and `[bot]` filters (`ignore_bot_actors`, default on, with `bot_actor_allowlist` so `copilot[bot]` can be kept).
   - A config key `human_feedback_mode` in {`all`, `allowlist`, `off`}. `all` (proposed default, pending sign-off): any non-self, non-dropped-bot actor steers. `allowlist`: only logins in `actor_allowlist` (and bots in `bot_actor_allowlist`) steer; an empty list behaves as `off` and warns at load. `off`: no comment or review steers; CI failure events, which do not depend on the actor, still steer.
   - **Working fallback if the owner rejects `all`:** the shipped default becomes `allowlist` with an empty list (so `off` in effect) until the operator names **other** trusted logins (teammates, review bots). The operator's own login is never useful in the list, because self events are always dropped (a warning says so). A solo operator with no other logins is on **CI-only steering**; human-feedback steers stay off until an allowlist is set.
   - **Measurement without logging identities.** Actor logins and text are never logged, counted or shown. Each human-feedback event gets an `actor_class` in {`self`, `bot`, `allowlisted`, `other`} (precedence in that order; a missing actor is `other`), logged and counted per repo. **Pause threshold:** more than 3 `other`-class steers on one repo in a rolling 7 days raises one `StrangerActivity` operator notification suggesting `human_feedback_mode = allowlist`. **Kill threshold** (requirements criterion 5): more than 10 in a rolling 7 days on any repo while the mode is still `all`.
   - Residual risk with `all`, stated plainly: any account that can comment on a watched public PR can wake the agent once per `min_steer_interval` (default 5 min) per session and PR. The steer text carries nothing from the commenter, but the woken agent then reads PR text through `gh`. Mitigations are the flag defaulting off, the coalescing window, the mode and the thresholds above. Revisit with a collaborator check only if the kill criteria in `requirements.md` show a noise problem. **Owner sign-off on this residual risk is pending** (requirements "Decisions awaiting owner" item 2).
5. **Self-login resolution fails closed, and is a different kind of network call from the rejected collaborator check.** The plan does call the network for the operator's own login (`github.GetCurrentUserLogin`, `github/client.go:273`), which looks inconsistent with decision 4. The difference: it happens once per process and the result is cached for the process lifetime, rather than once per unseen actor; it runs off the event path (a background resolver with backoff, not inside event handling); it needs no per-repo permission; and it fails closed, so a failure holds events instead of letting them through. `GetCurrentUserLogin` returns `("", nil)` when unauthenticated and an error when rate limited. Until a non-empty login resolves, comment and review events are held (not steered, not acked), because we cannot tell the agent's own comments from a stranger's; CI events are unaffected because they do not depend on the actor. Retry with backoff (5s doubling to 5 min); raise one operator notification if still unresolved after 10 minutes. Failing open would risk the comment-steer-comment self-echo loop (pre-mortem P1 #3).
6. **Export a small guard-signature helper from `server/services`, with the enum split at the layer boundary.** `guardSignature` and `reasonSetSignature` are unexported (`server/services/session_nudge_guard.go:46,62`), and the nudge guard is reachable only through `SteerSessionGuarded`. Add `server/services/prwatch_signature.go` with a **services-level enum** `PRWatchKind` (`PRWatchKindCI`, `PRWatchKindComment`, `PRWatchKindReview`) and `PRWatchGuardSignature(pr githubpkg.LinkKey, kinds ...PRWatchKind) string`, which maps the kinds onto the canonical reason names the manual nudge and #645 already use (`FAILING_CHECKS`, `UNRESOLVED_THREADS`, `CHANGES_REQUESTED`; `server/services/github_user_nudge.go:443-448` and `backlog_service_pr_fix_steer.go:63-72`) and calls `guardSignature`. **`server/prwatch` keeps its own `Kind` enum** (it may not import `server/services`); the **server adapter** (`server/prwatch_adapters.go`) maps prwatch kinds onto `services.PRWatchKind` (`review_comment`, rendered `inline comment`, maps to `PRWatchKindComment`). Rejected alternative: re-deriving the string in `server/` (silent drift from the real format). Accepted side effect: a prwatch steer inside the guard's 60s window suppresses an identical manual nudge for the same PR, which is the intended dedup. The adapter calls `IsHiddenSession` and then `SteerSessionGuarded`; it does not pre-check `IsReadyForSteer`, because `SteerInstanceGuarded` applies readiness itself.

## Consequences

- A stranger can still wake an agent on a public PR when `human_feedback_mode = all`; coalescing, the mode, the `actor_class` thresholds and a feature flag bound the effect. This is documented and measured, not solved.
- Squad depends on gh-signal's HTTP schema; a contract fixture test guards drift.
- `server/services` gains one exported function and one small enum; `pinnedCallers` (`server/services/terminal_write_pins_test.go:19`) gains one row for the new steer adapter.
- For the in-scope cohort nothing else steers: `PRStatusPoller` does not (VERIFIED by grep), and the backlog paths cover only sessions whose newest linked item is in `pr_pending`. Events lost before subscription have no backstop beyond the catch-up read and the operator; events inside a coalescing window are held and folded, not dropped.
