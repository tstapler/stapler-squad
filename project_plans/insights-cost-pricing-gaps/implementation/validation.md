# Validation Plan: insights-cost-pricing-gaps
**Date**: 2026-07-27

## Happy Path Scenario
Given a session's JSONL transcript contains usage for `claude-sonnet-5-20250929` and `DefaultPricingTable()` has been updated with a verified `claude-sonnet-5` entry, when a user loads the Insights page, then the Total Cost tile, the `ModelBreakdownChart` bar/legend, and the `SessionsTable` cost cell all show a real, non-zero, non-flagged dollar figure for that session — no `(pricing unavailable)` badge, no `unpriced` badge, no "excludes N unpriced model(s)" footnote — because the model is now priced.

*(Corollary/negative happy path, since this project's real value is in the failure case: given a session uses a model family with no `DefaultPricingTable()` entry, when the Insights page loads, then every surface that would otherwise show a bare `$0.0000`/invisible bar instead visibly labels that figure as "pricing unavailable"/"unpriced"/"excludes N unpriced model(s)", so the user can never mistake missing pricing for genuinely-free usage.)*

## Test Stack
- **Unit**: Go `testing` + `testify/assert` (backend, `session/tokens/`, `server/services/`); Jest + React Testing Library (frontend component tests)
- **Integration**: Go `testing` against `InsightsService` with in-memory fixture stores (`server/services/insights_service_test.go`'s existing `newInsightsFixture`/`newResult` helper pattern) — full RPC-shaped request/response round trips within the service layer, no real network/DB boundary crossed
- **E2E / UX**: None warranted for this feature — see the UX Acceptance Tests table's opening note. All UX criteria are static, fixture-driven rendering checks (Jest/RTL), not multi-step flows; UX-AC-13 and part of UX-AC-3/7/11 are manual/PR-review checklist items instead of automated tests, called out explicitly in the table above where that's the case
- **Manual**: AC-4's server-startup wiring (no `server/dependencies_test.go` by explicit plan decision) and UX-AC-13's whole-diff negative check, both verified per `CLAUDE.md`'s "Manual/interactive testing without touching the live deployed instance" convention (a second `PORT=8999 STAPLER_SQUAD_INSTANCE=claude-manual-test` instance, never `make install-service` against the live one)
