## Blockers

- [ ] **Stories 2.1.2 / 1.2.3 / 4.1.1b: the recorder is not one chokepoint, and it is flag-gated and also drives an ungated feature.**
  - Violation 1: the glossary and ADR-004 call `SessionEventRecorder` "the single chokepoint". Task 2.1.2b wires it from four independent sites: the poller decision result, `transitionTo`, `Instance` lifecycle events, and the ack handler. Story 3.1.1 adds a fifth write path, `HandleStop` in `server/`, which writes `TurnEnded` outside the poller. Story 2.1.2's "no double count across paths" test is a dedup patch over a topology that is not single-path. The poller skips Hidden sessions (`shouldSkipSession`), yet AC "Hidden sessions are logged, not surfaced" requires a `TurnEnded` row for a Hidden session. The plan does not say which writer produces that row.
  - Violation 2: Story 4.1.1b advances `LastMeaningfulChangeAt` "at the recorder chokepoint", but the recorder is a no-op when `session_event_log` is off. Risk Control says `LastMeaningfulChangeAt` "needs no flag". Both cannot hold. With the flag off, the card timer never advances, which defeats the timer fix.
  - Remediation: split the recorder into two collaborators.
    - (a) A domain-level `SessionActivity` port, always on and in-memory/snapshot only. It takes meaningful-change signals and advances `LastMeaningfulChangeAt` via an actor setter.
    - (b) A flag-gated `SessionEventRecorder` that persists events.
    - Name the single owner of each event kind in a table: `TurnEnded` is written only by the code path that sets the `TurnEnded` snapshot field (Hidden sessions included, since the setter is not behind `shouldSkipSession`). `Attention*` is written only by the queue observer. `Status*` is written only by `transitionTo`. `Acknowledged` is written only by the ack handler.
    - Make Story 1.2.3's interface list these methods explicitly.

- [ ] **Story 3.2.2 / ADR-006: the acknowledged episode has no persistence path, and `TurnEnded` has none either.**
  - Violation: `LastAcknowledged` is persisted today (`session/ent_repository.go:340,580`). Plan 3.2.2a stores `AckedEpisodeID` in `session/review_state.go` with no ent column, no `InstanceData` field and no restore step. The Migration Plan lists exactly one ent change on `session.go` (`last_meaningful_change_at`). After a restart the ack is lost, and the dedup key `EpisodeID` is lost too. That resurrects acked prose questions, which is the very failure ADR-006 exists to prevent. Because `ToInstanceData` rebuilds state on every save, an unpersisted field is also easy to drop silently.
  - Remediation: decide explicitly. Either persist `acked_episode_id` and the latest `TurnEnded` (episode, kind) as nullable columns, added to the Migration Plan and to Story 4.1.1a's persist/restore scope. Or state in ADR-006 that restart re-derives them, and add a test showing that behaviour is safe. The test must cover an acked question surviving a restart without re-raising a notification. The persisted option is recommended.

- [ ] **Stories 1.1.2 / 1.4.1 / 3.2.1b: flag access inside `Determine` is unspecified.**
  - Violation: `Determine` is documented as "a pure function — no queue operations" (`review_queue_determiner.go:46-47`). It takes `inst, content, statusInfo, detector` and holds only `config ReviewQueuePollerConfig`. The plan adds three flag-dependent behaviours inside it: `attention_idle_clock_output`, `attention_prose_question_detection`, and the TurnEnded stage. Reading live-settable flags from a global resolver in a pure determiner makes golden tests non-hermetic. It also makes the "flag off is byte-identical" AC (3.2.1) depend on process state.
  - Remediation: add a Task before 1.4.1a that injects a small immutable `DeterminerOptions{IdleClockOutput, ProseQuestion bool}`. The poller reads the flags once per poll cycle and passes the options through `ReviewQueuePollerConfig` or a field on `statusInfo`. Golden tests then parameterize on the options. Name this as a concrete seam task.
