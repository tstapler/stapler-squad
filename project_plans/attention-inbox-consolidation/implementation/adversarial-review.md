## Blockers

- [ ] **The timer fix silently depends on a default-off flag.** Plan Risk Control says `LastMeaningfulChangeAt` "needs no flag", but Task 4.1.1b advances it "at the recorder chokepoint", and the recorder is a no-op "when `session_event_log` is off" (Glossary, `SessionEventRecorder`; Task 2.1.2a "behind `session_event_log`"). The dependency graph also orders 4.1.1 after 2.2. With the flag off (its default and the first rollout state) the persisted field never advances past its backfill, so Story 4.2.2's "identical before/after reload and restart" holds only because it is frozen, and requirement "Timer correctness" is not met. The "TurnEnded at 15:30 advances it" AC in 4.1.1 also depends on the flag-gated TurnEnded stage. — Decide where the advance lives. Put it in an always-on actor setter (output, transition, input, TurnEnded) that does not go through the recorder, and have the recorder only mirror it. Add a flag-off AC to 4.1.1.
- [ ] **The new prose-question item does not survive a server restart, and episode acks are not persisted.** `TurnEnded` is only "stored on Instance, published in `InstanceSnapshot`" (Glossary; Task 3.1.1a: "types, actor setter, snapshot field"). The migration plan lists only two additive ent changes (`session_events` table and `last_meaningful_change_at`). The review queue is in-memory and rebuilt after restart (`session/review_queue_poller.go` spam-prevention comment: "After a server restart the queue is empty"), and `Determine` is the only producer. So after a restart `Determine` sees no `TurnEnded`, and the prose question or awaiting-direction item vanishes. That is the requirement's "durability: an item stays visible until acknowledged" and "missed notification is recoverable" failure, reintroduced by the fix. `AckedEpisodeID` (Task 3.2.2a, `session/review_state.go`) has the same gap: `LastAcknowledged` is persisted through ent (`session/instance_serialization.go:134,327`, `session/ent_repository.go:340`), but nothing persists the episode id, so after a restart an ack is lost or inverted. — Add persisted `TurnEnded` (kind, episode, excerpt, source, at) and `AckedEpisodeID` columns (or rehydrate `TurnEnded` from the newest `TurnEnded` event, which would make `session_event_log` a hard prerequisite). Update the Migration Plan, the Story 4.1.1-style restore AC, and add a "restart with an open ProseQuestion item" test.

## Concerns

- [ ] **`NeedsHumanClass` already exists, and the delivery class is keyed by `NotificationType`, not by attention reason.** The plan lists it as "New class in `server/deliverygate/policy.go`" (Glossary, Story 3.2.3). `ClassNeedsHuman` is already defined at `server/deliverygate/policy.go:50`, and class is looked up from the `typeClass` map keyed by the proto `NotificationType` (`policy.go:130-140`). Task 3.2.3a says "no proto enum change unless Spike shows required", but a ProseQuestion can only get `ClassNeedsHuman` by being emitted as `INPUT_REQUIRED` or `CONFIRMATION_NEEDED`, or by adding a `NotificationType`. Both choices have downstream effects (web tiers, push, Slack copy, `TestConfigSurfaceProof`, exhaustiveness test). — Fix the glossary, pick the type mapping in the plan, and state which sinks react to it.
- [ ] **The 2-minute re-add limiter contradicts Story 3.2.2.** AC "E2 creates a new item" conflicts with `session/review_queue_poller.go` spam prevention (`minReAddInterval := 2 * time.Minute`): if E1's item is still queued and E2 has the same priority, `checkSession` returns before the update, so the excerpt and episode are stale. The grace rule (`priority == PriorityLow || !IsControllerActive`) also removes a Low AwaitingDirection item for 5 minutes after any ack, even when a new episode arrives. — `suppressionPolicy` (Story 1.2.1) must treat a new `EpisodeID` as an escalation for the limiter and the grace rule; add table rows for it.
- [ ] **Ack-bypass fix is gated off while the prose-question flag ships first.** ADR-006 and Story 1.2.2 put the bypass behind `attention_ack_bypass_fix`, and the flip order in Story 7.3.2 turns it on after `attention_prose_question_detection`. Prose questions are Medium, so for the whole interval they are the snoozable class (`:901`): any acknowledgement followed by output buries them. The episode-keyed ack in 3.2.2 is not flagged, so behavior in that interval is ambiguous. — Either make `ProseQuestion` use the episode rule unconditionally, or flip the bypass flag first (or together).
- [ ] **HookReceiver has no path to an `Instance`.** `HookReceiver` (`server/services/hook_receivers.go:15-60`) holds only drift state and an optional `PostToolUseObserver`; session identity is the title in `X-CS-Session-ID`. Story 3.1.1 AC asserts `inst.Snapshot().TurnEnded` after `HandleStop`, but no task wires an instance resolver into the receiver, constructs it in `server/server.go`, or handles unknown/archived titles. — Add a task for an observer/resolver injection (the `SetPostToolUseObserver` pattern fits) and cover unknown session and archived session (`noarchivedrevival` spirit: record, never revive).
- [ ] **Hook double-emission analysis is shaky.** The injected Stop hook already points at `/api/hooks/stop` (`server/services/hook_injector.go:118`), while `scripts/ssq-hook-handler stop` (`:448-463`) is a separate path that emits `Task Complete`. The plan says the script "additionally POSTs to `/api/hooks/stop` (or defers to it)", which could produce two stop deliveries per turn and relies on `HookDeduper` keyed by an episode that is itself derived from the delivery. — Specify which path owns the notification and what the dedup key is before 3.1.1c; Spike 0.1.4 should record which of the two hooks is active per creation path.
- [ ] **Hidden-session ACs are unreachable as written.** `shouldSkipSession` skips `Hidden` sessions before any evaluation (`session/review_queue_poller.go:828`). Story 3.2.3 ("a Hidden session raising `AwaitingDirection`... the gate suppresses it") can never occur through the poller, and Story 2.1.2's "TurnEnded row exists for Hidden" works only from the hook path. — Reword the ACs to the real paths (hook-side recording for hidden sessions; gate test through the bus directly).
- [ ] **Two Low "finished" reasons collide.** `StatusSuccess` already yields `ReasonTaskComplete` Low (`session/review_queue_determiner.go:~166`), and the new `ReasonAwaitingDirection` is also Low for a finished turn. The queue holds one item per session, but the plan states precedence only against `approval_pending`. — Define precedence and mapping (does `AwaitingDirection` replace `TaskComplete`, or is `TaskComplete` folded in under the flag?) and add it to the goldens.
- [ ] **Duplicate hook for relative time.** `web-app/src/lib/hooks/useNowTicker.ts` already exists as a single-interval `Date.now()` hook (documented "One call per panel = one shared ticker"), and `web-app/src/lib/unfinished/relativeTime.ts` already has `formatRelativeTime(thenMs, nowMs)` with a different signature than Story 4.2.1's `(then, now)`. Only one local `useNow` copy was found by grep (`StuckItemDetail.tsx:83`), not three. — Reconcile with `useNowTicker` (extend it with the visibility pause rather than adding `useNow`), correct the "three copies" claim, and note that `SessionCard`'s local `formatTimeAgo` takes a protobuf timestamp and returns `"Never"`.
- [ ] **Wrong file location for the actuator.** Plan puts the endpoint in `server/actuator/attention_coverage.go`; there is no `server/actuator` package. Actuator endpoints live in `server/actuator.go` (with `server/actuator_test.go` and registration in `server/server.go`). — Fix Task 7.1.1a's file list.
- [ ] **Coverage gauge definition is under-specified.** `AttentionCoverageGap` is "sessions in needs-operator states with no open item", but hidden/suspended/archived sessions are excluded from evaluation by design (`:828`) and the Determine result is what defines "needs operator", so the gauge risks measuring the poller against itself. The requirement's metric is against operator-labelled ground truth. — State the independent source of truth for "needs operator" (e.g. detector status plus TurnEnded fact versus queue membership) and count intentionally skipped sessions separately.
- [ ] **Scope drift risk in Epic 5.2.** Story 5.2.1 bundles eight behaviors (grouping at scale, sticky oldest-waiting callout, Quiet/Finished chips, live-region debounce, disconnect banner, no-reorder-under-focus, Paused group, Done/Seen) that are mostly UX-research additions, not requirements; only Done/Seen, reasons and recoverability trace to requirements. They share the `ReviewQueuePanel.tsx` serialization point and the jscpd 0.14% ratchet (CLAUDE.md notes margin is already thin). — Mark which are requirement-traced versus polish and sequence the polish after the coverage soak; keep them behind the panel's existing flag if one is available.
- [ ] **Precision gate lacks a data source for non-Claude programs.** Story 3.1.2's >=40 message corpus is Claude-only, while Story 3.1.3 accepts aider's screen fallback with "the same fixture-corpus precision gate", for which no corpus is planned (Task 1.1.1a captures terminal tails, not labelled prose). — Add a labelled per-program corpus requirement or state that non-Claude programs ship as `Finished` only until measured.
- [ ] **Retention and privacy tests are thin.** Scrubbing is tested with one `API_KEY=` pattern (Story 2.1.2). Excerpts of agent prose can hold tokens, URLs with credentials and file contents. — Add a corpus of secret shapes (bearer, `ghp_`, `sk-`, JWT, URL userinfo) and test that both the event-log excerpt and the notification message pass through the same scrubber.

### New findings from the repair edits

- [ ] **N1 (BLOCKER): persistence wiring targets the full-save path, but the hot paths use narrow UPDATEs that the plan does not extend.** Story 3.1.4/Task 3.1.4a and Task 4.1.1a wire the new columns only through `ToInstanceData`/`FromInstanceData` and the full create/update setters (`ent_repository.go:340,580`). In the code, the two writes these features depend on bypass that path:

SET last_acknowledged` (`session/ent_repository.go:1220-1225`). Nothing in the plan makes the episode ack write `acked_episode_id` here, so an ack is only durable after the next full save. Crash or restart in that window re-raises an acked episode, the exact "ack inverted after restart" failure B2 named.

Note `UpdateTimestamps` also sets `updated_at` (`:1163`); keep `UpdatedAt` untouched semantics from Story 4.1.1 in mind.

- [ ] **N2 (CONCERN): `Touch` on every output event may add write amplification and a second lock acquisition on a hot path.** `UpdateTimestamps` runs per terminal output event and `Instance.UpdateTimestamps` (`session/instance_approval.go:108`) already holds `i.mu` and republishes the snapshot. Task 1.2.3b should say `Touch` is applied inside that existing critical section (only when `changed` is true, as `:100` does) rather than as a separate setter call that locks and rebuilds the snapshot twice. Also state that `Touch` is called only from the meaningful-output branch, not from every frame.

- [ ] **N3 (CONCERN): `DeterminerOptions` changes the `Determine` signature at an interface boundary.** Story 1.1.3 shows `Determine(inst, content, statusInfo, detector, opts)`, but `Determine` is a method on `DefaultStatusDeterminer` (`session/review_queue_determiner.go:114`) and presumably satisfies a `StatusDeterminer` interface used by tests and the poller. Task 1.1.3a should list the interface and all implementers/fakes it touches, or inject `DeterminerOptions` via the determiner's constructor and a per-cycle `WithOptions` copy. Minor today, a compile-wide change if missed.

- [ ] **N4 (CONCERN): `Instance.RecordTurnEnd` does synchronous persistence and a recorder call inside an actor setter.** The ownership table has the setter set the snapshot, persist, `Touch`, then `RecordTurnEnded`. A DB write under `i.mu` (lock-free-read rule, `.claude/rules/instance-lock-free-reads.md`) risks stalling readers if the ent call blocks. State that the persist and recorder calls run after the lock is released (snapshot published first), and that persist failure is logged and does not drop the in-memory fact.
