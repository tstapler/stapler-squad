# Pre-mortem: attention-inbox-consolidation
**Date**: 2026-10-23

Frame: it is 2027-01 and this shipped and failed. Inputs: `plan.md` (887 lines, 93 tasks, ~17M CU), `research/pitfalls.md`, ADR-001..006, and the repo memory index (flakes, CI gates, review-repair overbuilding, parallel workers in one worktree). Confidence: INFERRED from the plan text and memory entries; no code was run for this document.

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | The whole prose-question feature rests on one unverified premise: the Stop hook fires for the sessions the operator actually runs (manually created Claude sessions, non-Claude programs) and carries or points to the last assistant text. Spikes 0.1.1/0.1.4 may come back "no" for most sessions, leaving the screen fallback as `Finished`-only. The feature ships "working" but surfaces only `awaiting_direction` (Low, silent), so the operator's original complaint (missed questions) is not fixed. | Soak report shows `turn_end_classified_total{source="hook"}` near 0 for manually created or non-Claude sessions; `attention_prose_question` creation count stays flat while the operator still finds unanswered questions by hand. | Make Phase 0 a hard go/no-go gate in plan.md: write the explicit exit criterion "Stop fires for >= X% of the operator's real session-creation paths" and a named fallback (idle-for-N + transcript-tail poll for Claude, no Question kind elsewhere) decided BEFORE Phase 3 starts. Add a soak metric, hook-coverage ratio per program, as a flip precondition in Story 7.3.2. | P1 |
| 2 | Scope and review-repair overbuild (repo memory `feedback_review_repair_loops_overbuilding`). The plan is already 3 repair iterations deep, 93 tasks, ~17M CU, with 6 flags, 3 new persistence paths (event table, 6 session columns, 2 narrow writers), proto changes, and a UI consolidation. Each review round found new BLOCKERS in the same subsystem (persistence/locking), which is the stated "simplify, don't patch" signal. Implementation stalls mid-Phase 3 or ships with a half-wired flag matrix. | Phase 1 or 3 overrun checkpoint trips (>25%); a third or fourth verify round on `RecordTurnEnd`/ack persistence still yields new BLOCKERs; PRs grow past reviewable size. | Add an explicit stop rule to plan.md: max 2 verify rounds per story; a repeat BLOCKER in the persistence/locking subsystem triggers a re-scope to the minimum (episode ack + TurnEnded persisted via full-save only, defer narrow writers) rather than another patch. Ship as 4 independently mergeable PRs in this order: (a) Phase 1 refactor + flags, (b) Phase 3 detection+reasons, (c) Phase 2+4+5 log/timer/drawer, (d) Phase 6. Do not start (c)/(d) until (b) has soaked. | P1 |
| 3 | Prose-question precision collapses in production. The >= 0.90 precision bar is measured on a >= 40-message fixture corpus that the same author labels; real agent closers ("Want me to also add tests?") are far more varied, and the Medium-priority `INPUT_REQUIRED` toast/push/Slack path interrupts for each false positive. The operator turns the flag off in a week and stops trusting the list (the exact original failure). | `attention_prose_question_dismissed_total` ("Not a question") / `attention_items_created_total{reason="prose_question"}` > 20% in the first week; operator toasts dismissed unread. | (1) Corpus must be built from real last-messages harvested from `~/.claude` transcripts across at least 10 repos, labelled by Tyler (not the implementer), >= 100 items. (2) First live week: `ProseQuestion` delivers inbox-row + tray only (no toast/push/Slack); promote delivery class only after the dismiss rate is < 10% over 100 items. Put that staging in Story 3.2.3 and the 7.3.2 runbook. | P2 |
| 4 | Persistence and locking regressions in the session hot path. The plan adds `touchLocked` inside `Instance.UpdateTimestamps`, `transitionTo`, a new setter that persists after unlock, and narrow SQL writers by title. Likely bugs: a lost-update when the narrow `UpdateTurnEnded` races a concurrent full `UpdateInstance` (SELECT-then-rewrite overwrites the new columns with stale values); a data race in the poller test package (repo memory: "many unrelated parallel failures = one DATA RACE"); crash-window loss of `last_meaningful_change_at` making the card timer regress after a non-graceful restart. | `go test -race ./session ./server/...` flakes across unrelated tests; after a systemd restart, a just-acked question reappears or `AckedEpisodeID` is empty; timer on the card jumps backwards after a crash. | Add an AC (Story 3.1.4) for the interleaving: concurrent `UpdateInstance` full save and `UpdateTurnEnded`/`UpdateAckedEpisode` on the same title, assert the narrow-written columns survive (or make the full-save setters skip these columns when the in-memory value is stale/zero). Run the new session tests with `-race -count=20` in the 7.3.1 sweep. State the "crash loses timer" decision to Tyler once in ADR-005 so it is accepted, not discovered. | P2 |
| 5 | Notification flood or silent burial after flag flips. Flip order interacts: `attention_idle_clock_output` (changes when `ReasonIdle` fires, already hidden) plus `awaiting_direction` replacing `task_complete` for every finished turn can produce one Low row per turn per session with no cap, and Done/Seen semantics (Seen does not remove) make the list grow without bound; conversely episode-ack plus the 5-min grace/2-min limiter changes can bury a legitimate repeat. | Items/hour/session > 6 in the soak flood check; ReviewQueue badge count in the tens within a day; nav badge permanently non-zero so the operator ignores it. | Add auto-expiry to the plan for `AwaitingDirection` Low rows (e.g. drop when the operator sends input to the session or after N hours) and a hard per-session cap (1 open item per session already stated; add a global cap with a "show N more" fallback tested at 55 items). Make the soak flood threshold (<= 6/h/session) a blocking flip criterion, not just a report line; test the flip-order matrix (all 2^n combinations of the 4 attention flags is too many; test the 4 documented orders plus each flag alone) in Story 1.3.1. | P2 |
| 6 | CI-gate whack-a-mole at ship time. Known repo gates (memory: `instinct_new_rpc_ci_gates`, `instinct_pr_ci_gates_lint_routes_config_surface`, `fix_flaky_tests_dont_defer`): jscpd absolute 0.14% with a margin already at ~0.10%, gocognit/dupl new-from-rev on `Determine`/`checkSession`, sinkguard RPC classification, hand-set registry `tested`, `TestConfigSurfaceProof` for 6 flags, "gate" in a test filename (BUG-087, and this project has files named `*_suppression*`/rule "gate" wording), zero-warning eslint, route-meta 3-file tables. Pre-reserve jscpd budget: put the drawer/panel tests under shared fixture helpers from the start and check `bun run lint:duplicates` after each UI story, since 5.1/5.2/6.1 add three heavily mocked test files into a ratchet with ~0.04% headroom. Name new Go tests without the word "gate". | P2 |
| 7 | Parallel workers collide on the serialized shared files. The plan names ~6 serialization points (determiner, poller, `session.proto`, `ent/schema/session.go` + `ent_repository.go` + `storage.go`, `SessionCard.tsx`) but waves W3/W4/W7 schedule 5-8 workers concurrently. Also generated `gen/` and `session/ent/*` are gitignored, so fresh worktrees fail until `make build`. | A worker's commit contains another worker's hunks; `make build` fails in a worker worktree on missing generated code; disk full from multiple go caches. | In the Phase 5 briefing: one worktree per worker cut from the feature branch, explicit file-ownership list per task (stage only named files, never `git add -A`), `make build` as the first step in every fresh worktree, `unset npm_config_user_agent` before web builds, `uptime` check before spawn, and a hard cap of 2 concurrent workers on the serialized Go files (the remaining parallelism goes to web tasks 4.2.1/5.x). | 8 | Consolidation flag flip (Epic 6) breaks entry points the plan only partially enumerates: Slack/callback deep links, push notification click targets (`review-queue-tier1-*` ids), PWA/mobile app (memory: `project_mobile_app_server`) and the omnibar. Add hook-coverage-per-program to the flip preconditions in Story 7.3.2.
- [ ] #2 Overbuild/review-repair loop — add a stop rule (max 2 verify rounds per story; repeat persistence/locking BLOCKER triggers re-scope to full-save-only) and restructure delivery into 4 independently mergeable, independently soaked PRs with Epic 6 explicitly deferred behind the Phase 3 soak.

## Top risk
#1: the plan's value depends on a Stop-hook turn-end signal that is still UNVERIFIED for most real session types; if the spikes disappoint, ~60% of the plan's scope (Phases 3, 5.2 grouping) delivers little, and the plan has no pre-agreed fallback or go/no-go gate.
