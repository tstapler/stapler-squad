# UX design: /tours section, entry points and media states

Sources: `requirements.md`, `research/ux.md` (s1-s9), plan.md Epics 3.1-3.3. Deliverable structure follows the five deliverables in `~/.claude/commands/ux/design.md` (the named `sdd/ux-design-prompt.md` does not exist on this machine). Public copy calls the theme only "Grimdark".

UX readiness gate: [x] user flows mapped, [x] key states identified, [x] accessibility requirements noted.

## 1. Users and jobs

| User | Job | Entry | Success |
|---|---|---|---|
| Evaluator | Decide in under 2 minutes if this helps run several agents without babysitting | README link, landing hero, features grid | Reaches a tour, sees real-looking data, finds Install |
| Existing user | Learn or recall a feature flow | Tours index, search, in-app `/help` | Follows steps, jumps to the help page |

## 2. Information architecture

```
Landing (index.mdx)  --hero "See the tours"-->  /tours/ (index)  -->  /tours/<id>/ (tour page)
Features grid card   --"See the tour: <title>"-->  /tours/<id>/
README "Tours" link  ------------------------>  /tours/
Tour page  --"Read the help page"--> /help/<slug>/     --"Install"--> landing install block
Tour page  --prev/next--> adjacent tour        --"All tours"--> /tours/
```

URL scheme: `/stapler-squad/tours/` and `/stapler-squad/tours/<tour-id>/` (Starlight docs entries per ADR-001, so sidebar, search and skip-links come free). Sidebar group "Tours" is autogenerated.

## 3. Flow A: /tours index

**Layout (top to bottom)**
1. `h1` "Tours" plus one-line promise: "Short, recorded walkthroughs of real Grimdark-themed sessions. Each takes about a minute." (Clips are capped at 60 s and tours at 3-6 steps, enforced in CI.)
2. "Start here" ordered strip of 3 cards, tours with `tour.order` 1-3: `dashboard-lifecycle`, `approval-review`, `organise-at-scale`; numbered 1-3, each links to its tour. Order is by evaluator value and comes from frontmatter, not hard-coded.
3. Grouped grids, one `h2` per the 5 README categories, each card reusing `FeatureCard` tokens: poster, title, outcome line, duration ("Watch 0:45", from the clip; at most 1:00), "Tour" link. Same `minmax(260px,1fr)` grid; 1 column at <=480px.
4. Build stamp footer: "Recorded <date> (build <sha>)" read from `media-manifest.json`, date first and the sha in `<small>`; plus the line "Recorded with sample data, not a real team's work."

**Entry points**: sidebar, landing hero link, grid card links, README, search.
**Exit paths**: any card to a tour; header nav to Docs/Install; "Back to home" breadcrumb; browser back. No dead end, no modal.

**States**
| State | Behavior |
|---|---|
| Normal | All 8 tours listed with posters |
| Fewer than 3 recorded Start-here tours (smoke) | The strip shows only the recorded subset of `order` 1-3, with no empty card or gap; at 0 recorded it is omitted. A category with zero recorded tours renders no `h2` |
| Smoke build contents | The smoke build always includes the `dashboard-lifecycle` tour, so `/tours/` is never empty in smoke. AC: the smoke build builds at least one tour (asserted in `tours.spec.ts`, plan Task 3.1.1d); zero built tours is a build failure, not an empty page |
| Tour excluded (clip unrecorded) | PR smoke builds only (`TOURS_MEDIA_MODE=smoke`): the tour is not built at all, so it has no index card, sidebar entry, search hit, prev/next link, landing card link or README link; never a "coming soon" card. In deploy mode the build fails (ADR-003) |
| Poster image fails to load | Card keeps title, outcome and link; image box collapses to the card's dark background, text stays readable (alt text shown) |
| JS disabled | Index is static HTML; fully usable |
| Empty index (zero tours; build misconfig) | Build fails; never ships an empty page |
| Slow network | Posters `loading="lazy"` with explicit width/height (no layout shift) |

## 4. Flow B: tour page

**Order of content**
Owning components (plan Story 3.1.1): `TourHeader` (items 1-2), `TourClip` (item 3 incl. the Install link), `TourSteps` (items 4-5), `TourShot` (figures), `TourFooter` (items 6-7), `BuildStamp` (item 8).
1. Breadcrumb: Tours > Title. `h1` (Cinzel by the existing rule) and one-sentence outcome.
2. Meta row: audience tag (`tour.audience`), "Watch M:SS" (clip length from `media-manifest.json`, at most 1:00; the label is omitted if the manifest has no duration) and "Read N min" (`tour.durationMin`, steps only; the two are never merged into one ambiguous "min"), prerequisites or feature-flag note (`tour.flagNote`, e.g. backlog: "enabled in this recording"). Step fields: `caption` is the figcaption, optional `why` is the "Why it matters" line; `tour.phoneFigure` names the phone-framed mobile shot.
3. Clip: `<video controls muted loop playsinline preload="none" poster>` via `reduced-motion-video.ts`; `aria-label="<title> demo: <alt>"`; caption line below; inner fallback "Your browser cannot play this clip. Download it" plus poster. **The inner fallback renders only when the browser supports none of the `<source>` types; a network or decode failure after load leaves the native player's error state with the poster, and the steps and transcript carry the page (no error-event handler is built).** Encoding: `<source>` WebM (VP9) first, H.264 MP4 second, so Safari and older iOS play it; both are required by the freshness check. An "Install" link sits directly after the clip block, before the transcript (a second one follows in "Try it").
4. `<details><summary>Transcript</summary>` listing, per step in time order, the `narration` (what happens on screen: "The approval prompt for `git push` appears; focus moves to Allow; the session resumes") and the caption timeline. Narration describes the action, not only the imperative step text (WCAG 1.2.1 and 1.2.3); a step whose narration equals its text fails the build.
5. Numbered steps, `<ol>`: imperative sentence, `<figure>` with annotated screenshot and `<figcaption>` restating what the numbered gold markers mean, optional "Why it matters" line. Text is complete without the media.
6. "Try it" block: Install command (`InstallCommand.astro`) and a help link (`helpDoc`). Label is "Read the help page" only for a topical page; when `helpDoc` is the generic `help/getting-started` the label is "Getting started guide".
7. Prev / next tour links and "All tours". Order is ascending `tour.order` (unique integers 1..N), skipping tours absent from the manifest in smoke builds (those are not built at all). Prev, next and "See the tour" links show their full label as visible text ("Previous tour: <title>", "Next tour: <title>", "See the tour: <title>") and have no `aria-label`, so the accessible name equals the visible text (WCAG 2.5.3) and same-target duplicates are still distinguishable.
8. Build stamp: "Recorded 2026-11-10 (build <small>a1b2c3d</small>)" and "Recorded with sample data, not a real team's work."

**Interaction**: no autoplay below the fold; play is user-initiated via native controls. No lightbox (images are full content width and readable without zoom).
**Exit paths**: Install, help page, prev/next, All tours, breadcrumb, header nav, browser back. Last tour's "next" becomes "Back to all tours"; first tour's "prev" is omitted.

**States**
| State | Behavior |
|---|---|
| Normal | As above |
| Clip failed to record | Deploy mode: build fails (freshness check). PR smoke mode: the tour is not built (no page, sidebar entry or links); for a built tour, any unrecorded step figure is omitted from the HTML (not linked), with a build-time note in CI logs only; no public "missing" placeholder |
| Step screenshot missing at build | Deploy mode: build fails (file-existence check); never a broken `<img>`. Smoke mode: the step figure is omitted from the HTML, with a CI-log note only |
| Step or phone screenshot fails at runtime (network, decode) | The `figure` keeps its reserved width and height (explicit `width`/`height` plus `aspect-ratio`), the `alt` text shows in place of the image, caption and steps unchanged; no collapsed or empty box |
| Video unsupported by the browser (no `<source>` type playable) | Inner fallback text with download link plus poster; steps intact |
| Video network or decode failure after load | Native player error state with the poster; steps and transcript carry the page (no custom error handler) |
| `helpDoc` target missing | Build fails (Task 3.1.1e): `helpDoc` is a website docs collection id such as `help/getting-started`; no dead "Read the help page" link ships |
| JS disabled | `<noscript>` poster image; controls remain; no autoplay; transcript works (native `<details>`) |
| Reduced motion | See s6 |
| Print | Steps and figures print; clip hidden |
| 404 on tour URL | Starlight 404 page; its search and home link are the exit |

## 5. Flow C: landing and README entry points

**Landing**: hero `<video>` source is the CI clip `dashboard-lifecycle.webm` (same reduced-motion handling), poster visible immediately. Directly under the hero CTAs add a secondary link "See the tours" to `/tours/`. Features grid: cards with a tour show a second link "See the tour: <title>" next to the existing media; cards without a tour are unchanged. Card count text is derived, not hard-coded.
- Error/fallback: if the hero clip is missing the build fails; at runtime, poster plus fallback link (HeroVideo pattern). Exit: Install block, Docs, tours.
- Hero edge cases: JavaScript disabled shows the poster with native `controls` and no autoplay (no Pause button is rendered because nothing plays); if the browser blocks autoplay (`play()` rejects) the hero starts paused, the button reads "Play" (`aria-pressed="false"`) and starts it on activation; with `prefers-reduced-motion: reduce` the hero shows native `controls` only, with no autoplay and no custom Pause/Play button.
- Smoke builds: "See the tour: <title>" card links and the README tour links exist only for tours that are built (the PR smoke build contains `dashboard-lifecycle` only); `/tours/` always resolves.

**README**: no binary embeds. A "Tours" section with 3 text links (Start-here tours) and one link to `/tours/`, each with a one-line outcome. Link text describes the destination ("Tour: approving agent actions"). Error state: link check in CI covers README URLs; a broken base URL fails. Exit: links open the site; README remains complete (install, quick start) without media.

## 6. Missing-clip and reduced-motion states (consolidated)

| Condition | Page behavior | CI behavior |
|---|---|---|
| Clip recorded | Video + poster + transcript | pass |
| Clip missing, any environment | Never an empty box. Deploy mode never ships it (build fails); in a PR smoke build the tour is simply not built, and a built tour's unrecorded step shots are omitted from the HTML | deploy mode fails (fail loud); PR smoke mode excludes the tour, so no allow-list is needed |
| Hero: JS disabled / autoplay blocked / reduced motion | Poster plus native controls, no autoplay / paused with a "Play" button / native controls only (no custom button) | Playwright (JS-disabled context, stubbed `play()` rejection, emulation) |
| Poster missing | Build/link check fails | fail |
| `prefers-reduced-motion: reduce` | `preload="none"`, poster shown, `controls`, no autoplay, no loop start until user plays; CSS transitions/parallax disabled on tour pages | Playwright emulation test asserts attributes (plan 3.1.1) |
| No reduced-motion preference | Autoplay only for the above-fold hero, muted, deferred to idle; tour clips below the fold stay click-to-play | n/a |
| Data-saver / slow connection | `preload="none"`; poster only until play | n/a |

## 7. Mobile (390 px class and up)

- Single column under 1024 px; steps: text first, then screenshot. At >=1024 px, two-column step rows (text left, image right); clip full content width at 16:9.
- Clips are desktop-recorded only; they scale to width and carry `playsinline`. Four tours carry one phone-framed figure each from the 390x844 shot set (`tour.phoneFigure`): `dashboard-lifecycle` -> `terminal-mobile`, `organise-at-scale` -> `dashboard-mobile`, `approval-review` -> `review-queue-mobile`, `backlog-pipeline` -> `backlog-mobile`; the other four tours have none. Each figure has alt and a figcaption; the figure is wrapped in a link to the full-size shot (tap-to-open, `aria-label="Open full-size screenshot: <alt>"`, >=44x44 px) so small text is readable on a phone.
- Touch targets >=44x44 px for card links, prev/next, transcript summary, video controls (native). Cards are whole-tile links with adequate spacing.
- No horizontal scroll at 320-390 px: fix the cause rather than rely on `overflow-x: hidden`; a tour page is added to the mobile overflow check.
- Sticky chrome: Starlight header only; no extra fixed bars that cover content.
- Landscape and 200% zoom: text reflows; step text duplicates image information (1.4.10).

## 8. Accessibility requirements (WCAG 2.2 AA)

- Keyboard: skip link; logical tab order (breadcrumb, video, Install link after the clip, transcript summary, steps links, "Try it" Install link, help link, prev/next, "All tours"); visible gold focus ring with >=3:1 contrast on `#0c0a08`; native `<video controls>` and `<details>` only, no click-to-play wrappers.
- Screen reader: one `h1`, steps as `ol` with `h2` for the sections; `figure`/`figcaption`; video `aria-label`; alt describes the point ("Approval prompt for `git push` with Allow and Deny buttons; Allow focused"), 1-2 sentences, never pixels; markers explained in figcaption; "Grimdark" described as "dark parchment-and-gold interface" where visual description helps.
- Alternatives for time-based media: transcript on every tour (1.2.1); burned-in captions are a convenience only; `.vtt` tracks are a follow-up.
- Pause/stop (2.2.2): native controls on tour clips (click-to-play, no autoplay). The landing hero clip auto-plays muted for users without a reduced-motion preference, so it has a visible, focusable Pause/Play button (`aria-pressed`) before the video in tab order.
- Contrast (1.4.3, 1.4.11): annotation badges use theme tokens (text >=4.5:1, shape >=3:1), checked automatically on the token pairs (unit test) and, on the rendered pixels over screenshots, by an owner manual check in 6-verify; axe and Lighthouse cover `/tours/` and a tour page.
- Screen reader: a manual VoiceOver or NVDA pass over `/tours/` and one tour page is an owner check recorded in 6-verify. Forced-colors and print emulation tests are deferred to 6-verify as owner-run checks (explicit deferral, tracked in plan Task 3.1.1i).
- Names: link text unique and descriptive ("See the tour: Approval review"), not "click here"; links that share a target (prev/next, card links) are told apart by their visible text, which is also their accessible name (no `aria-label`, so Label in Name 2.5.3 holds by construction); only the image-only phone-figure link uses `aria-label`.
- WCAG 2.2 additions: Focus Not Obscured (2.4.11): the tour layout sets `scroll-padding-top` from the sticky header height so a focused link is never hidden under it (Playwright check); Text Spacing (1.4.12): a Playwright check injects the spacing override on `/tours/` and a tour page at 390 px and asserts no clipping or overflow; Captions for prerecorded audio (1.2.2): **not applicable**, clips have no audio track (the post-process passes `-an`) and the transcript covers the visual content; Target Size (2.5.8) is met by the 44x44 px rule in s7.

## 10. Heuristic checks and friction points

- Visibility of status: build stamp and duration shown. Match with real world: outcome-first titles. User control: native video controls, no autoplay. Consistency: shared card component. Error prevention: missing media fails the build rather than reaching users. Recognition: numbered markers match step numbers.
- Friction: long tours (cap at <=6 steps, <=60 s clip); screenshots with unreadable text (essential info repeated in step text); flag-gated features confusing viewers (state "flag enabled in this recording"); Cinzel not loaded at capture (recorder waits for `document.fonts.ready`).
