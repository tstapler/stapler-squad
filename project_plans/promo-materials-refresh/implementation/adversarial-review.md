## BLOCKERs

### B1. The media-commit guard (and termcheck) will not run on the PRs it exists to stop (R1, R15)
Tasks 1.1.4b and 2.1.1b wire `mediaguard` and `termcheck` as steps in `.github/workflows/lint.yml`. That workflow's `paths:` filter (`lint.yml:1-40`) lists `**.go`, `Makefile`, `proto/**`, `web-app/**`, `tests/e2e/**`, `**.sh`, and nothing else. A PR that only adds `website/public/clips/x.webm`, `assets/demo.gif`, a README embed, or a `docs/**` image touches none of those paths, so no `Lint` check is created and the guard never executes. The same hole lets a trademarked term land in `website/src/content/**`, `docs/**` or `README.md` unscanned. Story 2.1.1's AC (PR adds `website/public/clips/new.webm` -> exit 1) is unsatisfiable as wired.
`docs/reference/ci-job-budget.md` also says to prefer a step in an existing job and not to filter out cheap guards; it names `backlog-scaffolding-guard.yml` as "the one check a docs-only PR gets" (runs on every PR).
**Fix**: put both checkers in an always-on workflow/job (`backlog-scaffolding-guard.yml` `pr-diff-guards`, or a new path-filter-free job) and add a workflow-yaml test asserting the trigger has no `paths:` filter for that job. Record the choice in the ADR-003/ADR-004 consequences.

### B2. New `tools/promo` and `tools/docscoverage` Go code shelling out to `git` conflicts with the repo's blocking custom linter; the plan defers the decision (R11)
Plan Unresolved Question 11 treats "shell out to git vs go-git" as an implementer note ("check skill scope"). It is not optional: `make lint-custom` runs `$(LINTER_BIN) ./...` over the root module (`Makefile:946-950`), and `tools/lint/norawgitcli/analyzer.go` forbids new non-test `exec.Command("git", ...)` sites outside `session/git/backend/cli` and `session/gitwiring`. `make lint` is "REQUIRED; make build fails if this fails" (CLAUDE.md). The plan's shared `gitbase` helper (Task 2.1.1a: `A`/`M` vs `origin/main...HEAD`; 4.1.2a: `git show origin/main:<path>`, rename detection; 1.1.4a: `git ls-files`) is exactly that pattern, and `go.mod`/module placement of `tools/promo` is never stated (a separate `go.mod` like `tools/lint` would escape the linter but also the `make test`/`dupl` gates).
Because Stories 2.1.1, 1.1.4, 4.1.2 and everything downstream import `gitbase`, a wrong guess invalidates three epics.
**Fix**: decide now in the plan: either implement `gitbase` with the sanctioned go-git fork (`github.com/tstapler/go-git`; tree-diff against `origin/main` is supported) or give `tools/promo` its own `go.mod` and state how it is built, tested and linted in CI (`make test` does not cover nested modules). Add a task for the module/lint wiring.

### B3. The trademark scanner's `\b`-bounded regexes will not match the identifiers that need renaming, so the R15 gate cannot catch regressions (R15)
ADR-004 and Task 1.1.4a specify `\b`-bounded case-insensitive terms. In this repo the legacy id mostly appears glued to other word characters: `git grep -i -o 'wh40k[A-Za-z_-]*'` gives `wh40kTheme` (11), `wh40kStart` (3), `wh40kBlock` (2) besides 41 bare `wh40k`, 9 `WH40K`, 2 `wh40k-theme`. `\bwh40k\b` does not match `wh40kTheme`, `wh40kStart` or `wh40kBlock` (a letter follows, no word boundary), nor would it match `Warhammer40k` or `isWH40K`. After the rename, a stray `wh40kTheme` (16 current occurrences, `ThemeContext.tsx`, `theme.css.ts`, ...) passes the gate silently. The plan's own AC only tests a space-separated `WH40K theme`.
**Fix**: match the substring case-insensitively for the distinctive fragments (`wh40k`, `warhammer`), use `\b` only for short/ambiguous terms (`40k`), and add table tests for `wh40kTheme`, `Warhammer40K`, `WH-40K`, `wh_40k`. Also list the actual banned term set in the plan (currently "built from fragments" with no list; see C6).

## CONCERNs

### C1. Story 1.1.1's acceptance criteria cannot pass before Story 1.1.3 lands (ordering)
The dependency graph runs 1.1.1 -> 1.1.3. But 1.1.1's AC expects `localStorage['stapler-theme']='wh40k'` to produce the Grimdark class and write back `grimdark`; `grimdark` is not in `THEME_NAMES` (`web-app/src/styles/theme-boot-script.ts:3`) or `ThemeName` (`ThemeContext.tsx:24`) until 1.1.3a renames the id. Shipped in that intermediate state, the alias would write an id the boot script maps to `clean`, so users lose their theme (the exact failure ADR-004 exists to prevent). Both 1.1.1b and 1.1.3a edit `ThemeContext.tsx`; the plan separates them only to get three commits.
**Fix**: make 1.1.1 and the id switch in 1.1.3a one atomic change (keep the separate `git mv` commit), or move the AC to 1.1.3 and say 1.1.1 only introduces dead code.

### C2. Existing website tests and e2e are pinned to the structures the plan rewrites; none are in any task's Files

### C3. Fixed browser clock vs seeded server timestamps (R6, R9, determinism)
Task 2.3.1d freezes the browser with `page.clock.setFixedTime(...)` (no value given), while Story 2.2.2 seeds timestamps as offsets from the server's wall-clock "now" (`-3m`, `-47m`; today's `mockSessions()` uses `time.Now()` at `tests/demo/helpers.go:~150`). If the fixed browser time differs from seed time, relative labels render "in 2 days"/"3 months ago", and live-updating fields (uptime, last-activity) diverge. Backend timers (poller, escape analytics rollups) keep real time.
**Fix**: specify that the harness passes the seed's reference instant to both the seeder and `setFixedTime`, add an AC that asserts a rendered relative-time string, and mention that server-computed "ago"/spend windows (insights, analytics) are not frozen.

### C4. Seeding feasibility is unproven and there is no fallback (R2, R6)
Spike 0.1.1d decides whether approvals, backlog items, notifications and canned terminal output can be seeded at all; `tests/demo/helpers.go:152-155` documents that only Paused/Active statuses survive the review-queue poller without tmux. Three of the eight tours (approval-review, attention-notifications, dashboard-lifecycle's "live terminal") depend on states the harness presently cannot produce. If 0.1.1d says "no", Stories 2.2.2/3.2.x have no alternative (mock the RPC at the Playwright route layer? cut the tour?), yet R2 fixes N=8. Also every seeding path must stay public-safe: the default scenario already carries `/Users/dev/services/...` paths (`helpers.go`) while the leak pattern set lists `/home/` but not `/Users/`.
**Fix**: add a fallback branch to Story 0.1.1 (route-level fixtures via `page.route` or a smaller tour set decided with Tyler) and add `/Users/` to `LeakPattern` (or state default-scenario paths are accepted as obviously fake).

### C5. Docs-coverage "changed feature" predicate fires on test additions and ignores grandfathered-on-change semantics (R4)
ADR-005 drops `lastModified`, `handlerFile`, `markerLine`, `testIds` but not `tested`, `name`, `description`. The README process (`docs/registry/README.md:80-95`) says "Existing feature now has tests: set `tested: true`, append `testIds`, update `lastModified`". That flips `tested` and is treated as a meaningful change, contradicting the plan's stated goal ("refactors and test additions must not fire the gate", Pattern Decisions). Also unspecified: does *changing* a grandfathered feature fail (forcing docs) or pass? Story 4.1.2 only covers new ids and shrink. The two readings make the ratchet either toothless or a tax on every touched baseline feature.
**Fix**: add `tested` (and probably `description`) to the ignored set or define "changed" as semantic fields (`id`, `component`, `path`/`filePath`); state the grandfathered-and-modified rule with an AC.

### C6. Trademark term set, scan scope and imagery are underspecified (R15)
(a) The plan never lists the banned terms; "Warhammer, 40K, WH40K, other trademarked names" needs a reviewed list (e.g. Games Workshop, Space Marine, Adeptus, Mechanicus, Imperium, Astartes, Citadel, Black Library) with a rationale per term, because the allow-list is the only escape. (b) Skip rule `project_plans/` as a path prefix misses `docs/project_plans/**` (VERIFIED: that directory exists; 3 files hit broader fantasy terms like "emperor/heresy" which may or may not be intended) and any worktree copies; specify "path component" matching. (c) `dist` mode scans text, file names and search index but not `<title>`/OG metadata images, `sitemap`, `robots`, or video/PNG pixels (OCR of captured frames is the only machine check; plan accepts a manual residual). (d) Scenario fixtures (`tests/demo/scenario`), generated `expected-media.json`, and git branch/PR names are not covered by any mode. (e) The e2e `baseline/next-e2e-baseline.json` (6 hits) is a generated artifact; renaming by codemod may desync it from `parity-collect.ts` output.
**Fix**: add the term list, define skip by path component, add a task to scan fixture strings via the existing leak test, and call out OCR on one keyframe per clip as an optional gate or explicit owner check.

### C7. Sidecar identity: registry ids are not filenames (R4)
ADR-005 stores sidecars at `docs/registry/docs-coverage/<feature-id>.json`. VERIFIED by script: of 85 frontend and 12 root JSON files, 12 and 4 have `id` != filename and 11 + 3 ids contain `:` (for example `alias.json` has id `alias:invoke`); one root file is a JSON array (multiple entries per file). Backend ids (default `userFacing=false`) are nested under `features/backend/<group>/`, so "349 backend + 148 frontend + 13 root files" in ADR-005's Context is wrong: counts are 102 backend entries, 87 frontend entries, 13 root files (one array) from `ls`. A colon in a filename breaks checkout on Windows and `git`-on-NTFS contributors. Story 4.1.3's "87 frontend entries" (correct) contradicts ADR-005's 148.
**Fix**: key sidecars by a sanitized filename and carry the true `id` inside, define handling of array files and nested backend directories, correct the ADR counts, and add a uniqueness test.

### C8. Two doc universes and a heavy per-feature burden (R4, scope)
"Help" means in-app `web-app/public/docs` + `DOC_FILES` (11 docs); "website" means `website/src/content/docs/**`, whose `help/` pages are *generated from `docs/how-to/*`* via `content-manifest.json` and `sync-content` (VERIFIED: 13 files in `help/`, mostly how-tos, not in-app doc counterparts). The gate demands both `help` and `website` for every new/changed frontend feature. A new small UI element (e.g. `approval-rule-min-session-idle-minutes`) therefore needs a new in-app doc *and* a website page, or an `exempt` reason. The plan does not say whether one existing page may cover many features, how anchor validation works against Starlight-generated slugs (`github-slugger` vs the checker's own parsing), nor how a website page whose source is `docs/how-to/x.md` is attributed (edit source + regenerate). Expect widespread `exempt` use (gate hollowed) or contributor pain.
**Fix**: define allowed many-to-one mapping and an `exempt` policy; use the same slug algorithm as Starlight in the anchor check; add a worked example for a sync-generated page.

### C9. PR smoke recording in `website-ci` is expensive and its Lighthouse run lacks the media (R7, R8, R12)

Meanwhile the Lighthouse/axe steps in that job run against a build where all tour media except the smoke subset is absent; 404'd posters/videos hurt Lighthouse best-practices (console errors) and can trip the 0.90 error threshold; Task 2.4.1c only fixes the *link check*.
**Fix**: state per-shard and PR-smoke runtime targets and cap them; reuse a binary artifact from `build.yml` rather than rebuild; exclude tour pages from PR Lighthouse or serve placeholder media; keep Lighthouse on tours for the deploy job only and say so.
