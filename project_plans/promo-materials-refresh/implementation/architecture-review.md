## Blockers
- [ ] **Task 2.1.1a, Story 4.1.2, Task 2.2.2d (shared Go code placement)** — The plan puts the shared diff helper at `tools/promo/internal/gitbase/diff.go` and has `tools/docscoverage/internal/changed` reuse it (Story 4.1.2 Files: "`tools/promo/internal/gitbase/diff.go` (reused)"). `tests/demo/scenario/leak_test.go` is also meant to run the leak pattern set that lives in `tools/promo/internal/termscan`. Go's `internal/` rule only lets code rooted at `tools/promo/` import those packages, so `tools/docscoverage` and `tests/demo/scenario` cannot compile against them. VERIFIED: `tools/promo` and `tools/docscoverage` do not exist yet; the rule is a language guarantee. Remediation: put shared code in a package both can import, e.g. `tools/internal/gitbase` and `tools/internal/termscan` (importable by everything under `tools/`), or non-internal `tools/promokit/...`. For `tests/demo/scenario`, either exec the `termcheck` CLI from the test (state that in 2.2.2d) or export the leak pattern set from a non-internal package. Update the Files lists of 2.1.1a, 4.1.2, 1.1.4a/c and 2.2.2d.
- [ ] **Task 2.1.1a, Story 4.1.2, Unresolved Question "Shelling out to git"** — The plan treats "git CLI vs go-git" as an open, non-blocking implementer choice, but the repo already decides it. `make lint` runs `lint-custom`, which runs `$(LINTER_BIN) ./...` (Makefile:946-950) with the `norawgitcli` analyzer (`tools/lint/norawgitcli/analyzer.go`). It forbids `exec`/`safeexec` "git" call sites outside `session/git/backend/cli`, `session/gitwiring`, `testutil/gitfixture` and `session/git/internal/gittest`. `tools/promo` and `tools/docscoverage` would sit in the root module (`go.mod` module `github.com/tstapler/stapler-squad`; only `tools/lint` and `tools/scanner` are separate modules), so a `git diff --name-status origin/main...HEAD` and `git show origin/main:<path>` helper fails `make lint`, which "make build fails if this fails" per `CLAUDE.md`. Remediation: decide now, as a task before 2.1.1a. Options: (a) implement the diff and base-blob reads with go-git (`session/git` policy; note rename detection and merge-base are weaker, so state how `A`/`M` classification and `origin/main...HEAD` are done); (b) route through `session/git/backend`; (c) make the tools separate Go modules like `tools/lint` and `tools/scanner` (then `./...` does not scan them; state this and its cost for shared code, see blocker 1); or (d) add `//nolint:norawgitcli <reason>` at the single `gitbase` call site and document it. Close the Unresolved Question accordingly and remove "blocks 2.1.1a, 4.1.2".

## Concerns

- [ ] **Tasks 4.1.1a/b, Story 4.1.3 (registry shape assumptions)** — Registry files are not uniformly one object per file. - [ ] **Story 2.2.1 / Task 2.2.1a (Scenario lifecycle)** — `Scenario{SeedFiles(dir); SeedRPC(ctx, client)}` mixes pre-boot file seeding and post-boot RPC seeding in one interface, but the CLI `go run ./tests/demo/seed --scenario ...` is documented as working "without a running server" (`tests/demo/helpers.go` `SeedDirectory`). ### Blocker 1 (Go `internal/` visibility): RESOLVED
- Plan now places shared code in non-internal `tools/promolib/{gitbase,termscan}`; single-consumer code stays in `tools/promo/internal/...` and `tools/docscoverage/internal/...`. Task Files lists (1.1.4a/c, 2.1.1a, 2.2.2d, 4.1.1, 4.1.2) and ADR-002/004/005 now agree (grep of plan.md and ADRs shows no remaining shared `internal/` path).
- Compile check by rule (the packages do not exist yet, so nothing was built): a non-internal package is importable by any package in the same module. Importers `tools/promo/cmd/*`, `tools/docscoverage` and `tests/demo/scenario` are all in the root module (VERIFIED: `find tools tests -name go.mod` returns only `tools/lint` and `tools/scanner`; root `go.mod` module `github.com/tstapler/stapler-squad`). `tests/demo` (package `demo`, plus `seed/`) has no `tools/` ancestor, which is why the old `tools/promo/internal` placement failed and the new one does not.
- `tests/demo/scenario/leak_test.go` importing `termscan` directly is sound; no CLI exec needed.

### Blocker 2 (git CLI vs norawgitcli): RESOLVED
- `make lint-custom` runs `$(LINTER_BIN) ./...` over the root module (Makefile:946-950) and the `norawgitcli` analyzer flags only `exec`/`safeexec` "git" constructors and `Run(..., "git", ...)` (`tools/lint/norawgitcli/analyzer.go:13-15`, sanctioned package list at `:47`). A go-git implementation contains none of these, so it passes without an exemption. `git fetch --depth=2` lives in workflow YAML, which the analyzer does not scan.
- `session/git.OpenRepo(path string) (*git.Repository, error)` exists at `session/git/util.go:34` (confirmed by `go doc ./session/git OpenRepo`), delegating to `native.OpenRepo`. Using it satisfies `norawgitopen` (which forbids raw `PlainOpen`; `tools/lint/norawgitopen/analyzer.go`). The `go.mod` `replace github.com/go-git/go-git/v5 => github.com/tstapler/go-git/v5 v5.19.3-ssq.5` is present (go.mod:232).
- go-git approach is sound: the fork provides `object.DiffTree` (`plumbing/object/difftree.go:15`), `Commit.Parent(i)`/`NumParents` and `Commit.MergeBase` (`merge_base.go:17`), all of which the plan needs. A `pull_request` checkout is GitHub's merge commit with the base as first parent, so after `git fetch --depth=2` both parents and their trees are present and `-base HEAD^1` diffs exactly the PR changes; go-git resolves `HEAD^1` and reads shallow repos. Tree diff gives Insert/Modify/Delete only (rename = delete + add), which the plan correctly states is fine for the media guard. Local default via `MergeBase` needs history that a normal clone has.
- Closed Unresolved Question and the claim "no new task needed" hold; gitbase is within 2.1.1a.

### New concerns introduced by the repairs (none block)
- [ ] **gochecknoglobals on new packages.** `.golangci.yml` enables `gochecknoglobals` and only exempts listed legacy paths (session/, server/, cmd/, etc.); `tools/promolib/**` and `tests/demo/scenario` are not exempt. `termscan.LeakPatterns` and the `BannedTermSet` are described as values. Make them functions (`LeakPatterns() []Pattern`) or compile in a func, otherwise `make lint` fails. Add this to Tasks 1.1.4a and 2.2.2d.
- [ ] **Merge-commit assumption.** `-base HEAD^1` is right only for the `pull_request` merge ref; on `push` or a re-run on a head SHA it is the wrong base. Have `gitbase` fail loudly if HEAD has fewer than two parents and `-base` is the default `HEAD^1`, and have `pr-diff-guards` pass `github.event.pull_request.base.sha` after the depth-2 fetch as an alternative (note base.sha may be older than the merge parent if main moved; HEAD^1 is more accurate).
- [ ] **Workflow cost.** `pr-diff-guards` currently has no checkout deliberately (16 GB pack; comment at `backlog-scaffolding-guard.yml:41-45`). The plan adds a shallow checkout + depth-2 fetch; state in the task that `fetch-depth: 2` is used from the start (not `1` then deepen) and measure it once, since a `setup-go` + build of `session/git` dependencies also adds job time.
- [ ] **Heavy dependency edge.** `tools/promolib/gitbase` importing `session/git` pulls the session/git dependency graph into three small tools (build time only). Acceptable; if build time matters, `session/git/native.OpenRepo` is the lighter alias.

### Final verdict: CONCERNS
Both original blockers are resolved and verified; no new blockers. Remaining items are fixable in-task and do not need another plan round.
