# ADR-005: Docs-coverage gate uses per-feature sidecar files and a diff-aware, per-feature ratchet

**Status**: Accepted (owner-decided input on blocking-for-new + per-feature baseline; sidecar location is this ADR's choice) | **Date**: 2026-11-10

## Context
Registry entries (`docs/registry/features/**`; counted with `find ... -name '*.json' | wc -l`: 349 backend files, 148 frontend files, 13 root files holding 15 entries; one root file is a JSON array; one id, `launcher_presets:get`, is declared in two backend files; 322 ids contain `:`) track tests only. Scanners rewrite those files, so hand-written fields are at risk (`proto_scanner.go` has 50 touches since 2026-08-01). A single baseline file conflicts on every concurrent PR. `docs/registry/README.md:90` states the gap rule only in prose.

## Decision
1. **Sidecar per feature**: `docs/registry/docs-coverage/<encoded-id>.json` where `%`, `:` and `/` in the id are percent-encoded (`alias:invoke` -> `alias%3Ainvoke.json`; safe on NTFS, injective), the true `id` is stored inside, never inside scanner-owned files (Isolate via seam). Shape: `{ "id": "<feature-id>", "userFacing": bool, "help": "<DOC_FILES slug>[#anchor]", "website": "<docs collection id>[#anchor]", "tour": "<id>", "exempt": "<reason>", "status": "grandfathered" }`. `exempt` and `help`/`website` are mutually exclusive; `exempt` requires a reason.
2. **Universe**: frontend and root registry entries (163 ids) default `userFacing=true`; backend entries default false unless a sidecar says true (so no backend sidecars at baseline). The loader reads array-shaped files and nested backend dirs and keys by `id`; a duplicated id collapses to one record with a warning; a sidecar whose id is in no registry file fails (orphan). One website/help page may cover many features; `exempt` needs a reason and the exempt count is reported with a ceiling. Registry JSON is authoritative; the typed `web-app` catalog is out of scope.
3. **Checker in Go** (`tools/docscoverage`, root module; git base reads via go-git through `tools/promolib/gitbase`, never the CLI), reading JSON, `DOC_FILES` from `web-app/src/lib/docs/docLoader.ts` (array literal parsed, compared with `web-app/public/docs/*.md`), website ids from `website/src/content/docs/**` frontmatter and filenames, and tour files bidirectionally (`tour.features` must list the registry id). No Next or Astro build needed.
4. **Changed feature** = a new `id`, or an existing id whose `name`, `description` or `userFacing` differs from the base; `component` and `path`/`filePath` changes alone (moves and renames) and every other field (`tested`, `testIds`, `lastModified`, `handlerFile`, `markerLine`, and any future scanner field) are ignored. A new id is new regardless of filename. A grandfathered id that is changed passes (reported as "changed, still grandfathered").
5. **Ratchet is per feature**: `status: "grandfathered"` is valid only if that id exists on `origin/main` and was already a gap there; a grandfathered feature that gains docs must drop the status (checker fails otherwise); a new id can never be grandfathered. `make docs-coverage-baseline` generates the initial sidecars.
6. Base resolution: `HEAD^1` on `pull_request`, `github.event.before` on `push`; when the base cannot be resolved (dispatch, merge queue, zero `before`, single parent) the checker is report-only and exits 0, even when blocking. `exempt` sidecars name an approver, sit under a CODEOWNERS entry, and a PR may raise the exempt count by at most 5.
7. Rollout: report-only (job summary table with per-feature missing field and count), then blocking via `docsCoverageEnforce` in the checked-in `.github/promo-flags.json` (reviewable flip, works for fork PRs); blocking covers new and changed features only, per requirements, and only after at least 30 merged PRs or 4 weeks of report-only runs with a would-have-failed rate under 3% (each false positive triaged; numbers recorded in the flip PR).

## Alternatives rejected
Single `docs-coverage-baseline.json` (merge conflicts, two-place drift); docs fields inside scanner output (clobbered on regenerate; would force edits to the high-churn scanner); JS checker (repo convention is Go for new scripts); name-matching of ids to help slugs (naming drift).

## Consequences
~hundreds of small files possible for the baseline, but each PR touches only the ids it fixes. A generator round-trip test is unnecessary because scanners never read the sidecars.
