# ADR-004: Rename the theme to "Grimdark" everywhere, with a one-way legacy alias and a trademark-term check

**Status**: Accepted (owner-decided input) | **Date**: 2026-11-10

## Context
The theme id `wh40k` and picker label "WH40K" appear in web-app, website, e2e, server and snapshots (`research/architecture.md` s6). The raw id is stored in `localStorage['stapler-theme']`; the FOUC boot script maps unknown ids to `clean`, so a bare rename silently drops existing users' theme. User theme files may declare `"base": "wh40k"`.

## Decision
1. New id `grimdark`, label "Grimdark", `grimdark.css`, `grimdarkTheme`, project `visual-grimdark`.
2. **One-way alias** `LEGACY_THEME_IDS = { wh40k: 'grimdark' }` in a single module `web-app/src/lib/theme/legacy-theme-ids.ts`, imported by `ThemeContext.tsx` (read, map, write back the new id), `theme-boot-script.ts` (alias before the class lookup, so first paint is correct), and `CommandDetector.ts` (`>theme <legacy>` resolves through the alias; no visible legacy command). The `stapler-theme-custom` cache key is versioned so a cached old class name cannot paint unstyled.
3. Server: `server/user_themes.go` accepts the legacy `base`, normalizes to `grimdark` on load, logs a deprecation; files on disk are not rewritten.
4. The alias module, the server compat constant, their tests, the legacy-id test cases (ThemeContext, boot script, FOUC e2e, `CommandDetector`), the `add-user-themes` how-to and its website copy, and `CHANGELOG.md` are the only allow-listed places for the legacy string; the plan's Task 1.1.4a enumerates them (fixture-only tests) and Task 1.1.4b, which runs after the rename, tests the list equals the actual set. The alias is kept for at least two releases, with the removal date in the module header and a tracking issue; removal is never in the same PR.
5. **Trademark check** (Go CLI `tools/promo/cmd/termcheck`; scanner in non-internal `tools/promolib/termscan` so `tools/docscoverage` and `tests/demo/scenario` can import it; git file listing via go-git): distinctive fragments (`wh40k`, `warhammer`, `wh-40k`, `wh_40k`, `wh 40k`, plus the owner-reviewed names in plan Task 1.1.4a) match as case-insensitive **substrings**, so glued identifiers such as `wh40kTheme`, `wh40kStart`, `isWH40K`, `Warhammer40K` are caught; only the short term `40k` is `\b`-bounded. Terms are assembled from fragments so the tool does not trip itself. Modes `source` (git-tracked text, skipping lockfiles, binaries, build output, and any path component named `project_plans`), `dist` (built website text, search index, file and media names), `media-text` (DOM text dumped by the recorder at capture time). Allow-list is a checked-in `path:reason` file; an entry that matches nothing fails (cannot rot). `source` runs in the path-filter-free `pr-diff-guards` job (or `promo-guards`, per the Task 1.1.4b0 measurement; ADR-003) of `backlog-scaffolding-guard.yml`, not `lint.yml`, wired only after the rename and after `.github/CODEOWNERS` and branch protection are in place (ADR-003), so website/docs/README-only PRs are scanned. Text rendered in screenshots is machine-checked by an OCR step in the record job (plus `media-text` DOM dumps) that blocks the Pages upload; logos and decorative imagery cannot be read by OCR and remain an owner review item, backed by a CODEOWNERS sign-off on theme files (`web-app/src/styles/theme*`, `grimdark.css`, fonts). `40k` is `\b`-bounded and applied only under published paths (`website/`, `web-app/src/`, `README.md`, `assets/`, `docs/`) with a benign-string golden test.
6. Order of operations, one PR, separate commits: (1) alias module (dead code), (2) id switch + alias wiring (the boot script and `ThemeName` must know `grimdark` before the alias writes it, or users fall to `clean`), (3) `git mv` of the snapshot directory as a 100%-rename. No release between commits.

## Alternatives rejected
Keep the id and relabel only (leaves the term in source; owner scoped the rename to code); permanent dual ids (alias forever); inline `git grep` step (poor allow-list, cannot scan built output or DOM text).

## Consequences
Existing users land on Grimdark. Visual-regression snapshot bytes stay identical. First post-merge deploy needs the e2e theme-fouc legacy case green.
