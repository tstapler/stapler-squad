# Validation Plan: worktree-envvars-hijack

**Date**: 2026-09-24

## Happy Path Scenario
Given a repo at `repoDir` with a live `SessionTypeDirectory` session already running there, when a caller invokes `CreateSession` with `SessionType: SESSION_TYPE_NEW_WORKTREE`, `Branch: "<new-branch>"`, `Program: "claude"`, and `EnvVars: {"ANTHROPIC_BASE_URL": "..."}`, then the new session reaches `status: Active` with `Workspace().ActiveDir` a genuinely distinct, freshly-created worktree path (never `repoDir`), `EnvVars` applied, and its `ConversationUUID`/`HistoryFilePath` disjoint from the pre-existing session's — proving isolation holds end to end for the exact request shape the original bug report used. *(This is Epic 4.1's `ModeIsNewWorktree` subtest — the anchor all other test design below is a variation of: error paths are "the same scenario, but the worktree/guard fails instead of succeeding.")*

## Test Stack
- **Unit**: Go's standard `testing` package + `github.com/stretchr/testify` (`assert`/`require`), run via `gotestsum` (`make test`/`make quick-check`) for readable pass/fail output; one-off runs use plain `go test -run <name> ./<pkg>`.
- **Integration**: Same stack, `server/services`-level tests exercising real `CreateSession`/`runBackgroundResolutionPipeline` calls against real git repo fixtures (`initGitRepoWithCommit`, `git_fixture_test.go`) and a real tmux server socket (`fix.svc.testTmuxServerSocket`) — per `research/build-vs-buy.md`'s recommendation to test at this level rather than E2E, since the bug is async server-side state with no UI decision point. `go test -race` is required for the snapshot-republish test (Story 3.2.2).
- **E2E / UX**: N/A.
