# Validation Plan: pr-fix-steering

**Date**: 2026-08-26

## Happy Path Scenario

Given a `pr_pending` backlog item with an active work session and a PR whose `GetPRStatus` now reports `CIFailing=true`, when `AutoReopenForPRFix` runs its reconcile tick and calls `steerActiveSessionForPRFix`, then the active session receives a PTY-injected steer message (fix-context + `/github:pr-ship` for a Claude Code session) via `SessionSteerer.SteerActiveSession`, `steerDedup` records the delivered `reasonSignature`, and a `NOTIFICATION_TYPE_INFO` event is published — with no `TransitionBacklogItemStatus` call.

Note on file targets below: `server/services/backlog_service_triage_test.go` is already 4,931 lines — over the plan's own "~3000 lines" split threshold (Task 5.3.1b) — so every Epic 5.3 integration test in this table targets the new file `server/services/backlog_service_pr_fix_steer_integration_test.go`, not the existing triage test file.

## Coverage Gaps (requirements plan.md's named tests don't fully cover)

- **`SessionSteerer`'s own method bodies (`SessionProgram`, `SteerActiveSession` on `*SessionService`)** — Story 1.2.1's acceptance criteria give three Given/When/Then examples (not-live → `("", false)`; live → `(program, true)`; missing UUID → error, no panic), but Tasks 1.2.1a–d name no `Test...` function for them — only a compile-time interface assertion (`var _ SessionSteerer = (*SessionService)(nil)`) and `go build`. The behavior is exercised indirectly through `mockSessionSteerer` in Epic 5.3's integration tests, but the *real* `SessionService` implementation of these two methods has no direct unit test in the plan. Recommend adding `TestSessionService_SessionProgram_ReturnsProgramForLiveInstance`/`_ReturnsNotOkForUnknownUUID` and `TestSessionService_SteerActiveSession_ReturnsErrorForUnknownUUID` during implementation, even though the plan doesn't name them.
- ~~**`SetSessionSteerer` DI wiring in `dependencies.go`**~~ — **Closed** (pre-mortem.md P2 #5): plan.md's Task 1.2.2d adds `BacklogService.GetSessionSteerer()`/`GetSessionStopper()` getters and `TestBuildRuntimeDeps_should_WireSessionSteererAndSessionStopper_When_ServerBoots` (`server/dependencies_test.go`), asserting both are non-nil and identity-correct after `BuildDependencies()` — the first such wiring-assertion test for either setter (confirmed no prior precedent existed for `SetSessionStopper` either).
- **No new user-facing configuration surface** and **program-gating exact-match rationale (ADR-001)** are architectural/negative constraints not independently testable by a unit or integration test; verified by code review against the diff (no new proto field, no new settings key, no `strings.Contains`/`ToLower` substring match introduced).
