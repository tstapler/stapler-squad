# Validation Plan: subagent-spawn-tracking
**Date**: 2026-08-01

## Happy Path Scenario
Given a session whose terminal tail contains `"✻ Waiting for 2 background agents to finish"`, when the poller calls `GetStatusAndIdleInfo` → `InstanceStatusManager.GetStatus` → `InstanceToProto` and pushes a `WatchSessions` update, then the session's card in the web UI renders the `SubStatusChip` reading `"⏳ Waiting for 2 Agents"` (not the generic un-numbered chip), and the count returns to the plain `"⏳ Waiting for Agents"` chip on the next turn once the tail no longer matches a `WaitingForAgent` pattern.

## UX Acceptance Tests

**Tool decision:** Jest/RTL component tests, not Playwright. `SubStatusChip` already has an established Jest/RTL test file (`__tests__/SubStatusChip.test.tsx`) using `describe`/`it` with `@testing-library/react` — no existing Playwright spec or `data-testid` targets this chip, and `tests/e2e/*.spec.ts` has no precedent for a single-badge assertion (its specs cover full session-lifecycle flows). Per `.claude/rules/e2e-test-conventions.md`, a new Playwright spec would need its own `@feature` annotation and page-object plumbing for a check that RTL can make directly against rendered DOM/attributes — disproportionate for a passive, non-interactive status chip. One criterion (UX-2, layout/jank) is not meaningfully assertable in jsdom (no real layout engine) and is called out as a manual browser check instead.

| UX Criterion | Test File | Test Name | Tool | Steps |
|---|---|---|---|---|
| UX-1: Singular/plural correctness (no orphaned "s") | `SubStatusChip.test.tsx` | `"renders singular Agent for subagentCount === 1"` | Jest/RTL | Render with `subagentCount={1}`, assert `screen.getByText(/1 Agent\b/)` and assert the string does **not** match `/1 Agents/`; render with `subagentCount={2}`, assert `screen.getByText(/2 Agents/)` |
| UX-2: No layout shift/jank as digit count grows | n/a | Manual visual check | Manual (browser) | Run `make install-service`-free manual instance (`PORT=8999 ... /tmp/ssq-manual-test &`), populate a session list with mixed counts (1, 2, 3, and a synthetic 2-digit count e.g. 12 via a fixture/mock), resize to a narrow column, and visually confirm: row `minHeight: 38px` unchanged, chip never wraps (`whiteSpace: nowrap` holds), growing width is absorbed by the already-ellipsizing path text, not by the chip/GitHub badge/action buttons shifting position |

## Test Stack

- **Unit**: Go `testing` package (table-driven where the existing file already uses that style, e.g. `pattern_set_test.go`'s `should_..._When_...` convention) for `session/detection`, `session/claude_controller.go` (via `session` package tests), `session/instance_status.go`, and `server/adapters`. Jest + `@testing-library/react` for `SubStatusChip.tsx`, following the existing plain-English `describe("SubStatusChip", () => { it("...") })` convention already in `__tests__/SubStatusChip.test.tsx` — new frontend tests match that existing convention rather than the Go `should_When` style, per this repo's own precedent.
- **Integration**: Go tests that exercise more than one package-boundary layer in the same test — `session/claude_controller_test.go`'s cache-coherence test (`detection` results flowing through the shared `atomic.Pointer[statusCacheEntry]` cache into both `GetCurrentStatus` and `GetStatusAndIdleInfo`), and a new `session/instance_status_test.go` test crossing `claude_controller` → `instance_status`. On the frontend, a new `SessionRow.test.tsx` crossing the `SessionRow` → `SubStatusChip` prop boundary plays the same role (no data store exists in this feature to integration-test against).
- **E2E / UX**: None (Playwright). Jest/RTL component tests against `SubStatusChip` cover all UX acceptance criteria that are DOM-assertable; one criterion (layout/jank, UX-2) is a manual browser verification step since jsdom has no real layout engine to assert against.
