# Architecture Review: backlog-item-detail-ux
**Date**: 2026-07-21
**Verdict**: CONCERNS

## Blockers
- [ ] None — see prior finding, resolved: Task 3.1.2d now adds an explicit `showPrLink?: boolean` prop (default `true`) threaded through `VcsWidget`/`VcsWidgetGithubRow`, with only `BacklogItemDetail`'s new `VersionControlSection` call site passing `false`, `VcsPanel.tsx` and `UnfinishedItemDetail.tsx` are explicitly named in the task text as unmodified/unaffected (keeping the default `true`), and a regression test on `UnfinishedItemDetail.test.tsx` is required — the opt-out-prop scoping mechanism the original blocker asked for is present and correctly targeted at the single new call site.

## Concerns
- [ ] Story 1.1.3 / Epic 4 (`classifySessionKind`, `SessionDiagnosticPanel`) — `LinkedSession.reviewVerdict`/`triageResult` remain independent optional fields on the wire type (`useBacklogService.ts:65-70`), and Task 4.1.2d's dispatch is an if/else‑if chain with no documented branch for a `headless_diagnostic`-kind session where neither field is populated. **Remediation**: add an explicit fallback branch in `SessionDiagnosticPanel` (reuse the `BlockedNotice` treatment with a "No diagnostic data recorded" message).
- [ ] Story 4.1.2 (`readOnly` prop on `TriageReviewPanel`/`GateVerdictBox`) — required write-mode callbacks force read-only consumers to fabricate no-op callbacks; a discriminated union would rule this out at compile time. **Remediation**: split props into a union.
- [ ] Story 3.1.3 (`ActionsSection` extraction, Task 3.1.3b) — moves ~290 lines verbatim rather than decomposing via the kind-based-dispatch precedent already established elsewhere in the plan. **Remediation**: decompose into per-status components, can be a follow-up task.
- [ ] Story 2.1.1 (`StageTracker`) — `modifier?: string` is a raw string even though only 2 literal values are ever produced. **Remediation**: type as a closed union.
- [ ] Story 1.1.3 / Story 4.1.4 (`classifySessionKind` call sites) — classifier invoked independently at multiple render-time call sites instead of computed once and carried on the session object. **Recommendation**: compute `kind` once via `useMemo` where the list is first consumed.
- [ ] plan.md line 72's citation of "requirements.md's RESEARCH FINDINGS section" is a stale/incorrect cross-reference (that content lives in research/ files, not requirements.md itself). Minor documentation-hygiene issue.
- [ ] **(New, found in this re-review)** Story 3.1.2 / Task 3.1.2d — the regression-test target described for check (d) is factually inaccurate given the component's actual current structure. `UnfinishedItemDetail.tsx` renders `<VcsWidget data={...} mode="compact" />` (`UnfinishedItemDetail.tsx:91`), and `VcsWidgetGithubRow` — the component that renders the `PR #{prNumber}` link and will gain the `showPrLink` gate — is only rendered when `mode === "full"` (`VcsWidget.tsx:92-96`, `<VcsWidgetGithubRow data={data} />` wrapped in `{mode === "full" && (...)}`). So `UnfinishedItemDetail`'s `VcsWidget` never rendered a PR link before this change and won't after it either way — the visible PR reference on that page instead comes from a separate `GitHubBadge` component (`web-app/src/components/sessions/GitHubBadge.tsx`, rendered as `#{prNumber}`, not `PR #{prNumber}`). This doesn't weaken the scoping fix — the compact-mode call site is inherently unreachable by `showPrLink` regardless of its value — but Task 3.1.2d's literal instruction ("confirming its rendered `VcsWidget` still shows the `PR #<n>` link text") describes content that doesn't exist in `UnfinishedItemDetail`'s current render tree, so the regression test as specified can't be written as described. **Remediation**: correct Task 3.1.2d's test description — drop the `UnfinishedItemDetail.test.tsx` "VcsWidget still shows PR link" assertion (there's nothing there to regress), and instead add the real `VcsWidgetGithubRow`-level regression coverage to `VcsPanel.test.tsx`, which does use `mode="full"` and is the actual consumer of the code path `showPrLink` changes.

- `LinkedSession.role` is a raw string, not a closed union — out of scope to fix as part of this project (proto-level change), worth a follow-up ticket.
- `SessionDiagnosticPanel`'s kind-based switch dispatch is appropriately simple for a closed set of 5 values — no Strategy/Visitor abstraction needed.
- Confirmed no drift between the plan's chosen approaches and build-vs-buy.md's recommendations.
- Story 3.1.1's `key={selectedItemId}` remount fix is a clean, minimal, idiomatic React fix — no notes.
- The extraction approach (Approach A, props-down/callbacks-up, no shared Context) is well-justified against `.claude/rules/interface-pollution-checklist.md`.
