# Pre-mortem: terminal-resize-fit-loop
**Date**: 2026-07-24

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | Real-world WebGL glyph-mismatch magnitude (especially under common fractional OS display scaling — Windows 125%/150%, macOS non-integer zoom) doesn't match the synthetic `MISMATCH_TOLERANCE_PX=1`/`MISMATCH_THRESHOLD=3` constants, which were only validated against invented numeric fixtures, not measured real mismatch data. Either the fallback never trips (bug persists as repeated bounded ~1s give-up/restart CPU bursts) or it trips broadly (irreversible, unwanted downgrade to Canvas for a large fraction of ordinary users on common scale factors). | Support/bug reports within days of ship: either "terminal still spikes CPU on resize" on fractional-scaling machines, or "my terminal looks/feels different now" as Canvas silently, permanently replaces WebGL for many sessions. | Before implementation, empirically measure actual px/col mismatch magnitude in a real browser (not jsdom) across Windows 125%/150% and macOS non-integer zoom, and tune the tolerance/threshold constants against that data. Add a manual-verification sub-step that specifically forces and observes a WebGL→Canvas trip on a real fractionally-scaled display. | P1 |
| 2 | jsdom's hand-triggered mock `ResizeObserver` validates the pure `shouldScheduleFit`/sampler decision logic but cannot reproduce real browsers' batched-after-layout delivery timing or true multi-instance layout cascade (Task 4.1.6 fakes sibling perturbation with one mocked `getBoundingClientRect` side effect, not a real cascading reflow). Tests can be fully green while, under real GPU contention with several WebGL terminals, the decoupled 50ms sampler repeatedly exhausts its `MAX_SAMPLES=20` (~1s) budget back-to-back because layout genuinely hasn't settled — reproducing visible, if bounded, CPU churn and console warning spam. | `[XtermTerminal] Resize did not converge... giving up` fires repeatedly, several times in a row, on real hardware with multiple terminals open — despite 100% green Jest suite. | Add a real-browser smoke test (Playwright) or an explicit manual-verification step that opens N terminals under artificial CPU/GPU throttling and watches for repeated give-up cycles, not just a single resize/background-resume check. | P2 |
| 3 | Epic 5 Task 5.2 (AC7 manual verification) has no enforcement mechanism beyond "record pass/fail in the PR description or a backlog comment" — nothing blocks merge or the SDD `/backlog/done-N` criteria from being marked complete without it actually being executed. Once Epic 4's automated suite is green, this is the easiest step to skip or rubber-stamp, silently leaving the one scenario automated tests admittedly cannot cover (real browser, real WebGL, real concurrent mounts) unverified. | PR merges with an absent or copy-pasted "looks fine" manual-verification note, no captured console log or screenshot; the original CPU-pegged/frozen-input bug resurfaces in production weeks later because the real-browser path was never actually exercised. | Make Task 5.2 a hard gate: require the PR description to include actual evidence (console log excerpt or screenshot from steps 2-3), and have the ship/review step explicitly check for that evidence before the AC7 criterion can be marked done — not a self-reported checkbox. | P1 |
| 4 | `@xterm/addon-canvas`'s actual visual/functional rendering correctness (fonts, cursor, selection, themes) is never verified anywhere in the plan — Epic 4 only asserts trigger/dispose call counts against a mocked addon surface (jsdom can't meaningfully run WebGL or Canvas 2D), and Task 5.2's manual checklist never forces or observes a live fallback trip. A real rendering regression in the Canvas tier would only surface for the subset of real users whose mismatch heuristic fires in production, with zero verification path before then. | A user whose terminal silently and permanently (one-directional latch) switched to Canvas reports garbled glyphs, wrong colors, or a broken cursor — undiagnosable to them since the trigger is invisible and irreversible for that session. | Add a dev-only forced-fallback trigger (debug-menu toggle or env var calling `triggerCanvasFallback()` directly) so Task 5.2 can visually inspect the real Canvas-rendered terminal in a browser before shipping, instead of relying on the heuristic firing naturally during manual testing. | P3 |
| 5 | The decoupled sampler's mandatory 2-tick Reading-A confirmation (min. ~50-100ms) sits on top of, not in place of, the retained "ultra-fast" 10ms-for-first-3-resizes adaptive debounce. Genuine initial-sizing resizes (not just jitter) now incur added confirmation latency they didn't before — most visible under AC1's own concurrent-mount scenario (3+ terminals mounting together) — and this is never measured against the "feels instantaneous" threshold ADR-002 only justifies for a single generic steady-state settle. | Users opening a new multi-terminal session see each terminal visibly "pop" to correct size ~50-100ms later than before, or a brief flash of default 80x24 sizing, especially noticeable when several terminals open at once. | Add an explicit before/after latency measurement for initial-mount sizing (not just steady-state resize) to the test/manual-verification strategy; consider special-casing the very first RO delivery after mount (when nothing has been applied yet) to skip the 2-tick gate, mirroring how the double-RAF init path already bypasses it. | P2 |

## P1 Items (address before implementation)
- [x] #1 — Mitigated, not fully eliminated (real-display measurement genuinely requires a physical fractionally-scaled machine, unavailable during planning): Task 3.2.1 now documents the constants as provisional with a pointer to validation; Task 3.2.1a adds a dev-only forced-fallback trigger so `CanvasAddon` rendering correctness can be verified regardless of whether the heuristic fires naturally; Task 5.2 step 7 adds a real-display comparison step that surfaces a retuning follow-up if measured mismatch diverges from the constant. Plan's Unresolved Questions §5 documents this as an accepted residual risk, not a silent gap — the loop-prevention mechanism (Epic 1) does not depend on these constants being perfectly tuned.
- [x] #3 — Task 5.2 rewritten: requires pasted console log excerpts + a screenshot in the PR description as a hard prerequisite before the AC7 `/backlog/done-N` criterion can be marked complete; a self-reported "LGTM" without evidence explicitly does not satisfy the task.
