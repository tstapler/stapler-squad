## Verified facts that hold
- `localChainWith` order is stamp -> Logging -> CORS -> Compress -> HostGuard -> (auth | `LocalWriteGuard`) -> mux (`server/guarded_procedures.go:103-115`). `remoteChain` has no HostGuard (`server/server.go:1941-1948`). `stampRequest` builds the `RequestRecord` from `r.Host`, `Origin` and proxy headers per request (`server/services/capture_tap_service.go:62-79`), so copying upgrade headers onto a synthesized request does give matching verdicts. Re-entry is the right mechanism.
- The existing stream bridge builds a fresh POST with only Authorization/Cookie/Connect-Protocol-Version (`ws_stream_bridge.go:81-97`) and calls the raw handler, so it is not a precedent (plan is right).
- `createConnectTransport` non-test files: 37 (recounted, matches plan).
- `useWatchBacklogItems` is the existing data owner; `backlogItemsSlice` holds proto items. Plan direction (no parallel layer) is right in principle; blockers below are about its assumptions.
- Window keydown at `SessionDetailView.tsx:665-676` is ungated (effect deps have no `isActive`); `useShortcut(..., isActive)` at `:634`; `PaneSplitRenderer.tsx:395` passes `isActive={isFocused}`. `shortcutRegistry.ts:95-100` overwrite-and-delete bug is real.

## Blockers
- [ ] **Story 6.1.1 AC1-2 / Story 6.1.2 (backlog store hydration)** — The plan states `/backlog` issues no `listBacklog` unary and the REST path is "not called while the stream is live". The hook does the opposite by design: `useWatchBacklogItems.ts:178-208` runs `listBacklogItems` on every mount "alongside (not gated behind)" the stream (pitfalls #1) and again on gap/reconnect. Second, `refresh()` and the stream only `upsertItem`; nothing prunes. `snapshotComplete` is sent only when the snapshot is otherwise empty (comment at `useWatchBacklogItems.ts:318-326`), so the stream has no end-of-snapshot marker when items exist. A persisted-hydrated item deleted/archived server-side would therefore live forever as a ghost: "stream snapshot is the revalidation" cannot work as written. Third, `isSnapshot=false` only drives `liveVersion` bookkeeping (`backlogItemsSlice.ts:43-50`), not reconciliation. — Remediation: rewrite 6.1.1 AC to state the truth (one REST refresh per mount + one stream subscribe, counted and tested), and make the REST `listBacklogItems` response the authoritative reconcile in 6.1.2: record hydrated ids, and after the first successful REST refresh `removeItem` ids absent from it (respecting `statusFilter` and in-flight local mutations). Add this as its own task with a test for "hydrated item deleted server-side disappears".
- [ ] **Story 5.2.1 / ADR-001 REQUEST `meta.headers`** — The plan promises every REQUEST behaves like HTTP, but ADR-001 lets the client put arbitrary `headers` in meta. If the bridge copies them onto the synthesized request after the upgrade headers, page JS can set `Host`, `Origin`, `X-Forwarded-*`, `Cookie` or `Authorization` per call and change the HostGuard/`LocalWriteGuard`/auth verdict that Story 5.2.1d claims is identical. — Remediation: meta headers are an explicit allowlist (e.g. `Connect-Protocol-Version`, app-specific custom headers named in a list); `Host`, `Origin`, `Cookie`, `Authorization`, `X-Forwarded-*`, `Forwarded`, `Content-*`, `Connect-Timeout-Ms`, `Accept-Encoding` always come from the upgrade request or bridge. Add a chain-parity test in 5.2.1d: meta carrying `Origin: http://evil.example` is ignored/rejected.
- [ ] **Story 5.2.1 / 5.3.1 acceptance criteria (wire parity)** — "RESPONSE bytes equal the HTTP call's" is unsatisfiable: the HTTP transport has no `useBinaryFormat` (`web-app/src/lib/api/transport.ts:34-38`, default JSON), while the bridge uses `application/proto`. Separately, 5.3.1 AC says "headers/trailers surface" but ADR-001 RESPONSE/ERROR carry no meta (`totalLen | fin | bytes`; ERROR JSON only `{code,message,details}`), and connect-go unary trailers travel as `Trailer-` response headers. — Remediation: change the AC to "decoded message equals HTTP's decoded message" (Jest uses the real schema both ways); extend RESPONSE and ERROR with `u16 metaLen | meta JSON {headers, trailers}` (include in 5.1.1b vectors), or state explicitly that headers/trailers are dropped and delete that AC. Also note JSON vs proto changes the 256 KiB request budget (`guarded_procedures.go:67-72` sizes are base64-JSON) so size the cap from proto bytes.

## Concerns
- [ ] **Story 5.2.1b/5.1.1 chain re-entry plumbing** — `localChain()`/`remoteChain()` return one composed handler; "minus Compress/Logging" needs those functions refactored to expose the inner stamp->guard->auth composition (and the Compress-free CORS decision). `server/guarded_procedures.go` is not in 5.2.1's Files list; add it and a named task. Also the dispatcher is per listener but the mux (hence the bridge) is shared: define the injection (map listener name -> inner handler, set in `Start()`/`StartRemote()`), and make an unset dispatcher fail closed (`unavailable`), not fall back to `s.mux`.
- [ ] **Story 5.2.1 remote listener origin** — `isAllowedOrigin` accepts any HTTPS origin (`connectrpc_websocket.go:104-122`) and the remote chain has no HostGuard; the plan relies on `SameSite=Strict`. The client disables WS on `:8444` but the server route is still reachable there. Either do not register the route on the remote chain until measured, or enforce the same origin rule as `server/auth/handlers.go:407-420` (primary domain) at upgrade. Add a test: cross-origin HTTPS upgrade to the remote listener -> 403.
- [ ] **Story 5.2.1 auth expiry on long sockets** — synthesized responses drop `Set-Cookie`, so a sliding-session cookie would not be refreshed by WS-only traffic (INFERRED; `server/middleware/auth.go` and `server/auth/localtoken.go:142` not traced). Verify whether auth extends sessions on use; if so the user gets `unauthenticated` while active. Add to spike 5.1.1.
- [ ] **Task 5.4.1c / ADR-003 250 ms rule** — "not OPEN within 250 ms -> HTTP" is per call; calls starting later while the socket is still CONNECTING behind saturated slots should go to HTTP immediately (decide once per connect attempt), not each pay 250 ms. Specify state: CONNECTING-for->250 ms means "HTTP until open".
- [ ] **Story 4.1.3e / `TerminalPool` + `webglBudget`** — `TerminalPool.dock` is keyed by sessionId with a single anchor (`TerminalPool.tsx:296-307`) and eviction skips `docked` entries (`:251`). With K=3 retained windows (a) the same session in two windows would move one host element between anchors, (b) hidden-window terminals stay `docked`, so the pool can exceed `maxSize` and nothing can be reclaimed. Decide in 4.1.2 whether hidden windows undock (DOM moves to graveyard, refit on show) or stay docked, and forbid or handle a session mounted in two retained windows. Also `webglBudget` says an evicted pane "stays on that renderer for its lifetime" (`:3-4`): a retained window evicted from WebGL never regains it; record as accepted or add re-claim on activation. The AC "WebGL contexts <= 8" needs the slot's `isVisible()` wired to `windowActive`.
- [ ] **Story 4.1.5 hoist** — Underscoped. The window model lives in `app/page.tsx` (`useWindowShortcuts` at `:180`, `useWindowUrlSync`, `paneDispatch`, `sessionDetailRef`, external assign); moving the host into the layout means moving per-window state, URL sync and the tab strip contract, and the host must render in the same DOM position/geometry as the page slot (portal or sibling inside `<main>`, `RootShell.tsx:25-30`), which the plan does not specify. Also 4.1.2b integrates into `page.tsx` and 4.1.5 then moves it again. Recommend: build a `WindowsProvider` at layout level first (4.1.2 targets it directly), name the portal/sibling strategy, and split 4.1.5 into at least three tasks (state move, geometry, off-route gating).
- [ ] **Story 2.1.0b "no behavior change"** — today the window keydown is ungated by focus, so every mounted `SessionDetailView` handles Shift+Arrow. `keysEnabled = windowActive && isFocused` with defaults silences unfocused panes: a behavior change (arguably a fix for double `onNext`). Either pass `keysEnabled=true` in 2.1.0 and flip in 4.1.3b, or reword the AC and add a test for the unfocused-pane case.
- [ ] **Story 6.1.3 warm-up** — "start the Backlog watch subscription on hover" has no owner: the hook owns the stream lifecycle (AbortController per effect, `useWatchBacklogItems.ts` header) and unmounting `/backlog` ends it, so the store goes stale while on `/` and a hover-started subscription would be a second, parallel subscriber. Warm-up should be only chunk prefetch plus hydration from persisted data, or the stream moves to a store-level singleton (explicit refactor story); otherwise "return navigation renders from the warm store" shows items that went stale while away until the mount REST refresh lands.
- [ ] **Shared-file serialization beyond `SessionDetailView.tsx`** — only that file has a fixed order. `components/sessions/SessionDetail.tsx` (2.1.0a, 2.1.6a, 4.1.3b), `TerminalOutput.tsx` (2.1.3b, 3.1.1b), `lib/hooks/useSessionVcs.ts` (2.1.6a, 4.1.3c) and `PaneSplitRenderer.tsx` (2.1.0a, 4.1.3b) are edited by stories in parallel waves. Add them to the "Fixed edit order" note.

## Nitpicks
- ADR-001 "odd ids" has no stated purpose (no server-initiated ids exist); drop it or say it reserves even ids for server push.
- CANCEL after the RESPONSE head has been sent should say the server stops queued CHUNKs for that id.
- Hidden-window terminals keep consuming streams and writing to xterm (decided in 4.1.3); say that parse/write CPU is accepted, not just fit/rAF.
- Epic 7.1.1's `no-restricted-syntax` for dynamic import: name the AST selector so the rule is testable.

## Answers to the requested lenses
1. **Bridge**: chain re-entry preserves HostGuard/`LocalWriteGuard`/auth/Origin/body limits on both listeners provided meta headers are allowlisted (blocker 2) and the dispatcher plumbing is built (concern 1); body limit works because each synthesized request carries `ContentLength` and `withFileBodyLimits` sits around the session handler (`guarded_procedures.go:78-88`). Deny-by-default allowlist is workable and the "no `guardedProcedures` key in `wsUnaryAllowed`" test is the right guard. ADR-001 is coherent for unary without an envelope, with the metadata gap (blocker 3). Bootstrap with a persisted flag is sound; the 250 ms rule needs per-attempt semantics.
2. **Keep-alive**: the `isFocused`/`windowActive` split is correct and the single combining hook is a good seam. `TerminalPool`/`webglBudget` integration and the route-boundary hoist are underspecified (concerns 5, 6).
3. **Backlog**: right layer choice, but its premises conflict with `useWatchBacklogItems` (blocker 1, concern 8).
4. **SessionDetailView ordering/seam**: sound for that file; extend the ordering note to the other shared files (concern 9) and fix the 2.1.0b wording (concern 7).
