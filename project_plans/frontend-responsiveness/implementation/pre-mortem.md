# Pre-mortem: frontend-responsiveness
**Date**: 2026-10-26

Scenario: three months after shipping, the work failed or caused harm. Labels: VERIFIED = opened in this worktree (path:line given); INFERRED = reasoned, not run.

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | The ~30 s stalls are not (only) the browser's 6-connection cap. Server handlers contend with each other, so Epic 5 multiplexes 6 slots into 32 in-flight calls and makes the server worse, not better. Evidence: `ListShells` is an in-memory lookup but calls `s.storage.ListInstanceData()` (a full session-list read) on every call (`server/services/session_service_shells.go:62-73,210-232`), yet the HAR shows 4-6 s of server wait for it. A cheap handler with a multi-second wait points at lock/DB/exec-gate contention, not queueing in the browser. The 161 status-0 / `blocked ~30000` entries also match the client's own `DEFAULT_RPC_TIMEOUT_MS = 30_000` abort (`web-app/src/lib/api/transport.ts:19`), which fires for any request that waits 30 s anywhere, not only in the browser queue. | Arm C (WS on) shows `queuedOver1s == 0` but `rpc:*` latencies unchanged or worse, and `ws_unary_inflight` pinned at the cap of 32. Perf spec shows the stall moved from "blocked" to "waiting". | Add a server-side phase to Story 1.1.4 and the 5.1.2 gate (see P1 list). Start the bridge in-flight cap at 6, not 32, until Story 5.5.1 proves a higher value helps. | P1 |
| 2 | A hidden or zero-size terminal sends 0x0 (or tiny) dimensions in the stream handshake, and the server resizes the real tmux window to it. Keep-alive makes hidden terminals routine (`display:none`/`inert`, remount on reactivation). The plan guards only the client `resizeSession` RPC (plan.md:498). The server's handshake paths check only for nil: `performInitialResizeNudge` (`connectrpc_websocket.go:1165-1180`) and the capture-pane nudge (`:3237-3262`) pass `targetCols/targetRows` straight to `ResizePTY` -> `SetWindowSize` (`session/instance_tmux.go:1285-1292`) with no `<= 0` check. Only `handleCurrentPaneRequest` rejects `<= 0` (`:2558`). `resize.WithForcedRedraw` skips the nudge only for `cols > 1`, then still calls the real size. | An agent's TUI in a live session collapses or garbles after a window switch; tmux pane reports 1x1/0xN; `[streamViaControlMode] handshake dimensions ... cols=0` in `staplersquad.log`. Damage persists in the tmux session after the flag is flipped back. | Add the server-side guard and handshake guard (see P1 list). | P1 |
| 3 | A half-open WebSocket (laptop sleep/wake, VPN or proxy drop, tab throttling) hangs every WS unary call for the full 30 s, recreating the original symptom on the new transport, and the breaker never trips. ADR-002 item 8 gives the ping/pong deadline to the server only. Story 5.3.1's ACs (plan.md:611-629) define reconnect on a close event and a send-queue bound, but no client liveness probe; calls only fail at the 30 s local timeout, and timeouts are not "socket failures" for the breaker. | After wake, window switch and Backlog load hang 30 s then fail `DeadlineExceeded`, only while `unary_over_ws` is ON; force-HTTP override fixes it instantly. | Add a client liveness rule (see P1 list). | P1 |
| 4 | Keep-alive exhausts resources. 3 windows x 4 panes = 12 docked terminals; `TerminalPool` never evicts docked entries and `DEFAULT_TERMINAL_POOL_MAX_SIZE = 8` (`TerminalPool.tsx:83,254`); WebGL cap is 8 (`webglBudget.ts:7`), and an evicted pane never regains WebGL. Hidden terminals keep consuming 12 streams and parsing output (plan.md:756 accepts this). | Heap growth over a workday, blank/canvas-fallback panes in retained windows, fan noise, typing lag in the active window, more tmux control-mode work server-side. | 4.1.6 criterion 6 is "recorded and accepted by the owner" with no number. Add a numeric ceiling (heap after 30 min / N switches, stream count) and a hidden-window stream-pause or throttle option (flag-ON only). | P2 |
| 5 | Coalescer hands the same decoded protobuf message object to every subscriber of a shared flight (14 `getFeatureFlags`, N `getFileContent`). protobuf-es messages are mutable; one consumer's mutation or `toBinary`-then-edit corrupts the others. | Intermittent wrong values in one component that vanish on reload; only reproduces with concurrent callers. | In Task 2.1.2b, resolve each subscriber with `clone(schema, msg)` (or freeze) and add a test that mutating one result leaves the other unchanged. | P2 |
| 6 | Chrome serializes WebSocket handshakes to one host (one connection in CONNECTING state per endpoint, RFC 6455 section 4.1; INFERRED, not tested here), so the boot-time unary socket queues behind the ~20 existing Watch/terminal stream sockets (HAR: 20 x status 101). The 250 ms rule then sends everything over HTTP and WS silently provides no benefit while the flag reads ON. | Fallback rate > 1% (criterion 4) in arm C; `ws_unary_calls_total` near zero despite the flag ON. | Story 1.1.4 already records the handshake-under-saturation result; add "WS handshake queued behind other WS handshakes" as an explicit probe (open unary socket while 14 stream sockets are CONNECTING) and make the early-open ordering in Task 5.4.1c depend on it. | P2 |
| 7 | CI perf budget flakes and gets disabled or ignored. The "deterministic" blocking subset (plan.md:975) includes `long-task max` and `peak in-flight`, which are timing-dependent on shared runners; the fixture needs 20 real tmux sessions in CI (plan.md:199 calls this "unpriced"). | Blocking job red on unrelated PRs; owner adds a skip or reverts 7.1.3b. | Block only on count assertions (RPC counts per method, `GetFeatureFlags <= 1`, status-0 == 0, `createConnectTransport` ESLint ban). Keep long-task max and `peak in-flight` advisory with a 3-run median. | P2 |
| 8 | Reconnect/replay ordering: a read replayed over HTTP after socket close can finish before the original's late reply, or the original arrives after a newer call. Hooks that `setState` from each response last-write-wins with stale data. The write-generation guard covers mutations, not WS/HTTP reordering. | Panel briefly shows older VCS status after a reconnect; self-corrects on next poll. | Late replies for an id already settled or replayed are dropped in `UnaryWsTransport` (assert in 5.3.1c). | P2 |
| 9 | Guard bypass through the new entry point. Design is sound on paper (chain re-entry, deny-by-default table, remote listener refused, `guardedProcedures` keys rejected, `localChainWith` at `server/guarded_procedures.go:100-113`), so the risk is drift: a later "widening PR" adds a method with side effects, or a refactor of `localChainWith` leaves the dispatcher on a stale composition. | A guarded RPC succeeds over `/api/ws/unary` on an unauthenticated local listener; or a cross-origin upgrade is accepted. | Keep the existing build-time test (no `guardedProcedures` key in `wsUnaryAllowed`) and add a CODEOWNERS-style comment plus a test that every `wsUnaryAllowed` method has `idempotent` read semantics listed in `idempotentMethods.ts` (already planned). No new plan work required beyond holding that line. | P3 |
| 10 | Mutation loss or duplication on reconnect. Structurally prevented now: only 9 read methods are `wsEligible`, mutations are never replayed (ADR-002 items 2, 5). Becomes real only when a later PR widens the table to a mutation. | Duplicate `CreateSession`/`WriteFile` after a socket drop. | Add to the flip guide (Task 5.5.2a) a rule: no non-`coalescible` method is added to `wsUnaryAllowed` without an idempotency key in the proto. | P3 |
| 11 | Flag bootstrap deadlock. Not reachable by design: `GetFeatureFlags` is never `wsEligible`, pre-load default is persisted-or-OFF, and a 401 upgrade does not count toward the breaker (plan.md:94,670). Residual: a stale persisted `ssq:flag:unary_over_ws=true` after the server flag was reset keeps opening the socket at boot until a flag response arrives. | Socket opens at boot despite the server flag being OFF, for as long as `GetFeatureFlags` is stalled. | None beyond the existing 250 ms rule and force-HTTP override. | P3 |

## P1 Items (address before implementation)
- [ ] Failure #1 (root cause may be server-side) — patch plan.md as follows:
  - Story 1.1.4: add a third deliverable, "server-phase capture": during the stall reproduction, record per-RPC server handler duration (`rpc` timing on the Go side, or `slog` start/end with request id) and the number of in-flight handlers, and compare with the browser-side `requestStart - fetchStart`. Record, for `ListShells` specifically, how much of its wait is `ListInstanceData` (profile or temporary timing log). Output goes in `research/slot-holders.md`.
  - Story 5.1.2 table: add a row "server handler wait p95 > 1 s with fewer than 6 concurrent handlers" -> the stall is server-side: `unary_over_ws` stays OFF, the bridge in-flight cap stays at 6, and a follow-up (cache `ListInstanceData` result for `resolveSessionTitle`, or look up by UUID in memory) is added to Epic 2 scope as an in-scope backend change (today Out of Scope, requirements.md section "Out of Scope").
  - ADR-002 item 8 / Task 5.2.1c: set the default per-socket in-flight cap to 6 (a constant); raising it requires Story 5.5.1 evidence that server latency does not grow with the cap.
  - Story 5.5.1: add criterion 6, "server handler p95 for `GetVCSStatus`/`ListShells` in arm C is within +10% of arm B".
  - Unresolved Questions: change the "What held the other connection slots" entry to also name the server-side contention hypothesis, with `ListInstanceData` as the first suspect.
- [ ] Failure #2 (0x0 resize reaching tmux) — patch plan.md as follows:
  - New Task 3.1.2c (S), or fold into Task 4.1.3e: in `performInitialResizeNudge` (`connectrpc_websocket.go:1165`) and the capture-pane nudge (`:3237`), reject non-positive and implausibly small dimensions (`cols < 2 || rows < 1`) with the same early return used for nil, plus a Go test per path (0x0, 0xN, 1x1 leave `ResizePTY` uncalled).
  - Client: the stream handshake in `TerminalOutput.tsx`/`XtermTerminal.tsx` must not send `targetCols/targetRows` from a container with zero `clientWidth/clientHeight`; defer the handshake until `fitOnShow` reports a real size. Add a Jest test with `isVisible=false` that asserts the handshake is not sent at 0x0 (extends the existing AC at plan.md:498, which covers only `resizeSession`).
  - Story 4.1.4c Playwright spec: after each switch assert tmux pane dimensions via `GetPaneDimensions` equal the pre-switch dimensions.
- [ ] Failure #3 (half-open socket recreates the 30 s stall) — patch plan.md as follows:
  - Story 5.3.1: add an AC and a Task 5.3.1c line: the client sends PING every 10 s while any call is in flight (or on `visibilitychange`/`online`/wake), and treats a missing PONG within 5 s as a socket failure: close, reject in-flight calls with `Unavailable` (replayable reads then replay over HTTP), and count it toward the circuit breaker. Test with a fake socket that never answers.
  - ADR-002 item 8: state that the liveness deadline is symmetric (server and client), with the 10 s / 5 s values.
  - Story 5.4.1: a per-call WS timeout shorter than the 30 s default (for example 8 s) before replaying a `replayable` read over HTTP, so a silent socket costs at most that, not 30 s.
