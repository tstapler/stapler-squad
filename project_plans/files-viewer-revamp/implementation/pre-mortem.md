**Date**: 2026-10-16

## Notes for the plan owner
- **Top risk**: #2 (a dirty edit applied to, or lost with, the wrong session's checkout) because it is the one data-integrity path the server-side token cannot fully protect, and the existing code already shows `FilesTab` is reused across sessions.
- **Claims checked in code** (all VERIFIED unless stated): `guardedProcedures` set and `localChainWith` (`server/server.go:1879-1915` (map 1879-1888, `localChainWith` 1901-1915)); WS bridge registration only for `Watch*` (`server/server.go:499-509`) and its source-check test; `createSessionWatchTransport` native-streaming gate (`watch-ws-transport.ts:223-230`); `collectAllGitignorePatterns` pre-pass (`file_service.go:597-636`); `hardSkipDirs` applies at any depth (`file_service.go:606`); `resolveAndValidatePath` lexical-only (`file_service.go:106-116`); `Workspace` field semantics (`session/types.go:317-355`) support the plan's `ActiveDir == ExistingDir` write gate; `FeatureFlagsContext` single fetch (`FeatureFlagsContext.tsx:72-96`); funlen/gocognit limits (`.golangci.yml:38-43`); Go 1.26.6 (`go.mod`) so `os.Root` is available. Auth invites only enrol another device for the same user (`server/auth/invite.go`), which supports the plan's "single-user, no per-owner model" statement.
- **Not verified**: CodeMirror's default content attributes (no `node_modules` here); Connect `ReadMaxBytes` (no `WithReadMaxBytes` option found in `server/*.go`, which suggests no explicit cap, but Task 0.1.3b should confirm); real WebKit-in-CI behaviour; any measured search timing.
