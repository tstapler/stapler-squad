# Validation Plan: files-viewer-revamp

**Date**: 2026-10-16

Inputs: `requirements.md`, `implementation/plan.md` (Phase 3, post-repair, plus the ADR-036 integration), `design/ux.md` (criteria `U-*`, section 18), `decisions/ADR-030..036`. Type names follow the plan's Domain Glossary (`FileRef`, `ResolvedPath`, `WorktreeRoot`, `FileVersionToken`, `ReadOnlyReason`, `SearchOptions`, `SearchKey`, `SearchRegistry`, `Buffer`, `OpenBuffers`, `NavEntry`, `SaveOutcome`, `TheirsVersion`, `MergeBase`, `MergeResult`, `Draft`, `InputProfile`, `FileWriter`).

## Happy Path Scenario
Given a running session whose worktree contains `pkg/a.go` (CRLF + BOM, `needle_fn` on line 12) with `files:viewer-v2` on and the global `files:editing` flag on, when the user opens Search, types `needle_fn`, activates the hit, edits line 12 and presses Ctrl+S, then the editor opens `pkg/a.go` at line 12 in <= 3 interactions, `WriteFile` returns `Saved` with a new `FileVersionToken`, the file on disk equals the edit byte-for-byte with CRLF and BOM preserved, the tab's unsaved dot clears, and the git-status badge updates; and if an agent rewrote the file before the save, the save is blocked, nothing is written, and the "File changed on disk" dialog opens instead. *(Every row below is a variation on this flow: error paths, other form factors, other file states.)*

## Test Stack
- **Unit (Go)**: stdlib `testing` with table tests, `t.Parallel()` and `t.TempDir()`, testify `require`/`assert`, `goleak` for goroutine leaks, `-race` on every concurrency test. Time and filesystem effects are injected (clock, pre-rename hook, `os.Chtimes`), not slept on (`deterministic-fast-tests`); no `t.Setenv` fixtures; fixtures built under `b.TempDir()`/`t.TempDir()` from seed `42`; fuzz targets for `file_codec.go`.
