# Pitfalls and Risks: files-viewer-revamp

**Date**: 2026-10-16. Labels: VERIFIED = checked in this repo this session; KNOWN = established behavior from general knowledge, not re-tested here (no web search run); each KNOWN item needs a spike or test in implementation.

## 0. Verified facts about the current server (drive the design)

- V1 VERIFIED. `GetFileContent` truncates at 1 MB: `truncateSize = 1MB`, reads `readLimit` bytes, sets `is_truncated` (`server/services/file_service.go:32`, `:365-420`). Files over 10 MB are rejected with `FailedPrecondition` (`:28`, `:360`). The response `content` is the first 1 MB only; `size` is the full on-disk size.
- V2 VERIFIED. Truncation is a raw byte cut then `string(buf)`. It can split a multi-byte UTF-8 rune. `encoding` is hardcoded `"utf-8"`; no decoding/BOM/CRLF handling exists. proto3 `string` must be valid UTF-8, so non-UTF-8 text (latin-1, UTF-16) or a split rune risks a marshal error or replacement characters. The proto field is `string content = 1` (`proto/session/v1/session.proto:2319`).
- V3 VERIFIED. `resolveAndValidatePath` (`file_service.go:106`) is purely lexical (`Clean` + `HasPrefix`). It never calls `EvalSymlinks`. `GetFileContent` then does `os.Lstat` (does not follow) followed by `os.Open` (follows). A symlink inside the worktree pointing to `/etc/passwd` or `~/.ssh/id_rsa` passes validation and is READ today. For a write RPC the same function would let `O_WRONLY` follow a symlink out of the worktree. This is an existing read-side hole and must be fixed in a shared helper before the write RPC exists.
- V4 VERIFIED. `Lstat` on a symlink reports the link's size and `IsDir()==false`, so `size`/binary decisions can describe the link, not the target.
- V5 VERIFIED. Base dir is `ws.ExistingDir`, which falls back to the repo root when a worktree dir is gone (see `.claude/rules/instance-lock-free-reads.md`). A write RPC resolved against `ExistingDir` could write into the MAIN repo checkout of a paused/cleaned session. Writes must require `WorktreeDir`/`ActiveDir` to exist, else fail precondition.
- V6 VERIFIED. `SearchFiles` already uses `filepath.WalkDir` with `ctx.Err()` checks (`:516-519`), `hardSkipDirs` (`.git`, `node_modules`, `vendor`, `dist`, `build`, `target`...), a gitignore matcher with a cache, and a 500 cap. Reusable skeleton for content search, but note `hardSkipDirs` hides `build/`, `dist/`, `vendor/` from search entirely.
- V7 VERIFIED. `rg` exists on this host (`/home/linuxbrew/.linuxbrew/bin/rg`) but is a Linuxbrew install, not guaranteed on PATH of the systemd service or other hosts (mac work machine).
- V8 VERIFIED. Existing viewport infra: `--viewport-height` / `100dvh` in `SessionDetail.css.ts:18,25`, `visualViewport` use in `XtermTerminal.tsx:588,1343`, `createViewportSettle` in `TerminalOutput.tsx:1532` (ADR-002 notes a direct fit off visualViewport raced the sampler). Reuse, do not reinvent.
- V9 VERIFIED. `web-app/package.json` has `@codemirror/{commands,search,state,view,language}` and language packs, but NO `@replit/codemirror-vim` / vim package. Vim mode is a new dependency (bundle size, must be lazy-loaded).

## 1. Write RPC: data-loss and security pitfalls (design against all)

| # | Pitfall | Design response |
|---|---|---|
| W1 | **Saving a truncated buffer overwrites the full file** (V1). Editor loads first 1 MB; user saves; file silently loses everything past 1 MB. Highest-severity risk. | Server: reject writes unless the request carries the base version token of a FULL read; additionally refuse any write where the client's `base_size`/hash corresponds to a truncated read. Client: truncated files open read-only (no edit affordance); a "load full" path (<=10 MB) or partial/range edit is a separate, explicit design. Add a Go test: write with truncated-read token is rejected. Never infer "truncated" from client alone. |
| W2 | **Symlink escape on write** (V3). | New shared `resolveInWorktree` doing `EvalSymlinks` on the parent dir, re-check prefix against `EvalSymlinks(base)`, and `Lstat` the leaf: reject if leaf is a symlink (or write the link-target only if it also resolves inside). Use `O_NOFOLLOW` (`syscall.O_NOFOLLOW`) on open where available. Apply the same helper to reads (fixes V3 read hole). Test with symlink-to-outside for file and for parent directory. |
| W3 | **TOCTOU** between validate and open (symlink swapped by an agent). | Resolve then open with `O_NOFOLLOW`; for atomic replace, `rename` over the leaf (rename does not follow a leaf symlink, it replaces it). Residual race on parent-dir swap accepted for single-user; note it. Go 1.24 `os.Root` (`os.OpenRoot`) gives kernel-enforced confinement: check go.mod Go version and prefer it if available (KNOWN API; verify). |
| W4 | **Non-atomic write** (truncate-then-write; crash/OOM mid-write leaves empty or partial file; agents reading mid-write see torn content). | Write temp file in the SAME directory, `fsync`, `chmod` to original mode, `rename` over target, fsync dir. Same-dir is required so rename is atomic (not cross-device). Cost: breaks hard links and changes inode (watchers, `tail -f`); acceptable, document. |
| W5 | **File mode / ownership loss** (temp file is 0600/0644: loses `+x` on scripts). | `Stat` original, apply `Mode().Perm()` plus setuid-irrelevant bits to temp before rename. Preserve exec bit explicitly with a test. |
| W6 | **Lost update vs concurrent agent writes** (requirement: never silently overwrite). mtime+size alone is racy (same-second edits, coarse FS mtime, `git checkout` restoring mtime). | Token = content hash (sha256 of full bytes) returned by read and echoed on write; server re-hashes the current file and compares inside the same critical section as the rename. A per-path mutex in-process closes the check/rename window against other stapler-squad writers; external writers (agent processes) can still race between compare and rename: accept, narrow window, and re-verify mtime/hash immediately before rename. Return `ABORTED`/`FailedPrecondition` with current content + hash so the client can render the diff. Hash only for files <=10 MB (existing cap). |
| W7 | **CRLF corruption.** CodeMirror normalizes line breaks to `\n` internally (KNOWN); saving `doc.toString()` converts a CRLF file to LF, a whole-file diff in git. | Detect dominant EOL on load (server or client), keep it in metadata, re-apply on save (`state.lineBreak` / `EditorState.lineSeparator` facet, or convert on serialize). Mixed-EOL files: preserve by refusing to normalize (open read-only or warn) rather than guess. Test with CRLF and mixed fixtures. |
| W8 | **BOM loss/duplication.** UTF-8 BOM is currently passed through as U+FEFF in `content` (V2, no stripping); CM shows it as an invisible char. UTF-16 files are mis-sniffed. | Detect BOM, strip for editing, re-emit on save. Non-UTF-8 (invalid sequences, UTF-16): open read-only, do not transcode on save. Round-trip test: write(read(f)) == f byte-for-byte for BOM/CRLF/no-trailing-newline fixtures; this is the single most valuable test. |
| W9 | **Trailing newline** added or removed by editor/serializer. | Preserve exactly: CM does not add one; do not "fix" it server-side. Part of the byte-identical round-trip test. Offer an opt-in "ensure final newline" only if wanted. |
| W10 | **Binary / huge / sniff-misclassified files** become editable. `isText` is extension-driven, so a `.txt` containing NULs skips binary detection (V: `isText` bypasses Layers 2-3). | Write path re-runs a strict check (NUL scan + utf8.Valid) on the incoming bytes and on the on-disk file; reject binary targets; cap request size (<= maxFileSize; also check Connect max message size config, default 4 MB reads for ConnectRPC handlers: KNOWN, verify the server's `WithReadMaxBytes`). |
| W11 | **Write to protected paths**: `.git/` internals, `.git` file in a worktree, `.claude/`, hooks. Writing `.git/hooks/*` = code execution. | Deny list for any path component `.git`; consider denying git hooks and the worktree `.git` pointer file. Reads of `.git` are already hidden in listings (`hardSkipDirs`) but `GetFileContent` does not enforce that for direct paths: add. |
| W12 | **Authz / ownership**: requirement says "respect session ownership". Existing `GetWorkspace(session_id)` only maps id to dir. Remote-access (mobile over Tailscale/TLS) makes write RPC a remote-code-write primitive (writing `.git/hooks`, `Makefile`, agent config that the agent then runs). | Gate on `files_editing` flag AND verify auth path used by remote access applies to this RPC (check the middleware, `/api` prefix routing). Treat write RPC like other privileged RPCs; consider a confirm/CSRF-style header. Audit log line (requirements Observability): session, path, bytes, outcome; no contents. |
| W13 | **git interaction**: write while a rebase/merge is in progress; editor saves a file git has locked (`.git/index.lock` is separate). Agents' own `git add -A` will pick up user edits (intended but surprising). | No index writes from the save path. Surface a notice if the session has an in-progress git operation (read-only check). Do not run `git` from save. |
| W14 | **Path edge cases**: absolute `rel` (`filepath.Join` makes it relative: OK), NUL byte in path, case-insensitive FS on macOS (work machine) where `a.go` vs `A.go` collide, Windows separators N/A, very long paths, unicode normalization (macOS NFD vs NFC mismatches between client path and disk). | Reject NUL and `..` components pre-join, canonicalize on server, return the canonical path in the response, and key client buffers by the server-canonical path, not user-typed. |
| W15 | **Disk full / ENOSPC / quota** leave stray temp files. | Always `defer os.Remove(tmp)` on failure; name temps `.<name>.ssq-tmp-<rand>` and exclude them from tree/search/git-status noise; sweep stale temps at startup is optional. |

## 2. CodeMirror 6 on mobile

KNOWN issues (verify on a real iOS device; owner real-device check is already a wall-clock blocker):

- M1 **iOS Safari keyboard / visual viewport.** The on-screen keyboard shrinks the VISUAL viewport but not the layout viewport; `100vh`/`position: fixed` bottoms sit behind the keyboard, and Safari scrolls the page to the focused caret, shoving the app header off screen. Design: sizing from `visualViewport` (`resize`+`scroll`), reuse `--viewport-height` plumbing (V8) rather than a second copy; settle-then-act (ADR-002 lesson: raw visualViewport reads race the sampler). Keep the toolbar/save bar anchored to `visualViewport.offsetTop + height`. Inputs/contentEditable with font-size < 16px trigger iOS auto-zoom: set editor font >= 16px on touch devices. Test with Playwright WebKit mobile emulation, but emulation does NOT reproduce the real keyboard: do not claim keyboard behavior verified from emulation.
- M2 **Caret scroll-into-view fights.** CM's `scrollIntoView` plus iOS' own scroll plus a resizing container cause jitter/jumps. Design: only one scroller (the CM scroller), `overscroll-behavior: contain`, avoid nesting scroll containers, avoid animating height during keyboard open.
- M3 **IME composition (CJK, iOS predictive text, Android Gboard).** Rewriting the doc or re-creating the view during composition cancels it and duplicates text. Design: never replace the whole document from a React prop on each render; keep the `EditorView` imperative and stable per buffer, apply external changes as transactions, never dispatch while `view.composing`; defer remote-change reloads until composition ends. Android Gboard autocorrect/ "composing region" bugs are mostly handled by CM6's DOM observer but break with custom keymaps that intercept Backspace/Enter: avoid binding plain Backspace/Enter/Space.
- M4 **Vim mode on soft keyboards.** Soft keyboards have no Esc, no Ctrl; modal editing relies on them. `@replit/codemirror-vim` (not in deps: V9) handles key events, but on Android many soft keys send `keyCode 229` (composition), so vim sees nothing; iOS lacks Esc. Design: vim OFF by default on touch; if enabled on touch, mandatory on-screen Esc / Ctrl-[ button and a mode indicator; test only on desktop automation; label mobile vim as best-effort. Lazy-load the vim extension (bundle). Vim `:w` must route through the same conflict-checked save path, never a second save implementation.
- M5 **Memory and large docs.** CM6 virtualizes rendering, but the document tree, syntax tree, and the 1-10 MB string copies (proto string, JS string, `doc`, undo history, plus Lezer parse) multiply: a 10 MB file may use >100 MB on a phone and iOS kills the tab (white page, no error). Mitigations: read-only + no parse/no highlight above a threshold (suggest > 1 MB, which coincides with the existing truncation), disable `lineWrapping` and expensive extensions (bracket matching, `highlightActiveLine`, search match highlighting, `foldGutter`) on large docs, cap undo history depth, extremely long single lines (minified JS) are the real killer: cap rendered line length or fall back to a plain `<pre>`/read-only viewer. Never keep every open tab's `EditorView` alive: keep `EditorState` per tab, mount one view.
- M6 **Multi-tab state.** Preserve scroll/cursor by serializing `EditorState` selection + `scrollTop` per buffer (requirement: not lose position). Do not persist unsaved edits to localStorage without size caps (quota errors throw: wrap in try/catch per the Artifact/web storage norm), and do not restore a draft over a file that changed on disk without a conflict prompt.
- M7 **Touch targets / gestures**: long-press and drag selection handles are native on iOS; custom gestures on the CM surface (swipe-to-switch-tab) conflict with selection and scroll. Put gestures on the tab bar only. 44px minimum targets (requirement); `touch-action` choices must not disable native selection.
- M8 **Pane switching bugs already known** (`project_plans/mobile-ux-improvements/`, `better-file-tree/research/pitfalls.md` P1: pointer capture for drags, `pointercancel` handling). Reuse the pointer-capture pattern for any new draggable splitter; mobile has no split view, so collapse it.
- M9 **Selection of long-press vs. context menu / `contextmenu` event** and `user-select` on the tree; keep text selectable in the editor.
- M10 **Back button**: mobile browser back should step through file navigation history or the pane, not leave the session. Mirror `history.pushState` for open-file/back-forward carefully (race with existing router).

## 3. Content search

| # | Pitfall | Design response |
|---|---|---|
| S1 | **ReDoS.** Go's `regexp` is RE2 (linear time, no backtracking): safe for pattern-eval time. ripgrep default engine is also automaton-based (PCRE2 only with `-P`). | Never enable PCRE2/lookaround; reject `-P`-style options; document "RE2 syntax". Still cap pattern length (e.g. 1 KB) and compile errors return `InvalidArgument` with a message. Do not build the regex via string concat with user flags beyond `(?i)`. |
| S2 | **Command injection if shelling out to rg.** Query starting with `-` is parsed as a flag (e.g. `--pre=cmd` executes an arbitrary binary: real rg footgun). | If rg is used: `exec.CommandContext` with args array (no shell), pass `-e <pattern>` and `--` before paths, never pass user glob/option strings through unvalidated, reject `--pre`/`--hostname-bin`/config via `RIPGREP_CONFIG_PATH=` unset and `--no-config`. Repo convention prefers go-git over subshells (`prefer-go-git-over-subshells` skill; applies to git, but same spirit): decide in-process vs rg in architecture. In-process needs its own binary skip, gitignore (reuse V6 matcher), and is slower on 50k files; rg `--json` gives speed and ignore semantics. Recommend: in-process baseline that is always correct, rg as optional accelerator behind detection (V7: not guaranteed present), identical result contract. |
| S3 | **Huge outputs.** One minified-JS line can be MBs; a common token returns 100k hits. | Hard caps: max matches (e.g. 1000 total, 50 per file), max bytes per matched line (truncate with `...` and column offsets of the match clamped), max files, `truncated` flag on response. Stream results (server-stream RPC) or paginate; never buffer an unbounded `[]Match`. Count only after the cap for "N+ matches". |
| S4 | **node_modules/.git traversal cost.** Walking unignored huge trees dominates latency (the 2 s SLO). | Prune dirs at `SkipDir` (not per-file filtering), reuse `hardSkipDirs` and gitignore cache (V6). Caveat: `hardSkipDirs` includes `build`, `dist`, `vendor` which users sometimes want to search: offer an "include ignored" toggle consistent with `SearchFiles.IncludeIgnored`, but `.git` stays hard-denied always. Do not follow symlinked directories (loop + escape; `WalkDir` doesn't follow but a symlinked FILE read must use the W2 helper). |
| S5 | **Binary hits** (matching NUL-containing files, lockfiles, minified bundles). | Per-file: sniff the first 8 KB for NUL (as `GetFileContent` does), skip; skip files > size cap (e.g. 2 MB for search); skip known-binary extensions; skip huge lockfiles by default. |
| S6 | **Cancellation.** Typing fires overlapping searches; abandoned walks burn CPU and disk. | Server: honor `ctx` in the walk AND in per-file scanning loops (V6 only checks per entry; a 2 MB file scan needs periodic checks), kill rg subprocess on ctx cancel (`CommandContext`, wait to avoid zombies). Client: abort the in-flight request (AbortController/`signal`) plus the `searchRequestIdRef` stale-response guard from P5a; debounce 300 ms; min query length. Concurrency cap: one active search per session, newest wins (also guards WIP/OOM concerns). |
| S7 | **Encoding**: non-UTF-8 files yield garbage or panics when slicing; column offsets in bytes vs UTF-16 code units (CM positions are UTF-16): a byte offset from Go lands at the wrong column for non-ASCII lines. | Return line number + the line text + match ranges in UTF-16 code units (or character index), computed server-side; client jumps by line, then column. |
| S8 | **Result staleness**: agents edit files during/after search so hit line numbers drift. | Jump-to-line must tolerate out-of-range line (clamp), show the matched text in results, and ideally re-highlight the query in the opened buffer instead of trusting the number. |
| S9 | **Sensitive output**: search over worktree surfaces `.env`/secrets in a UI and logs. | Log only query length, duration, counts (as the observability requirement states); never log query text at info. |
| S10 | **Worktree vs main repo**: searching `ExistingDir` of a paused session searches the main checkout (V5). | Same precondition as writes; show which root is searched. |

## 4. Repo conventions that will bite (VERIFIED from `CLAUDE.md` unless noted)

- C1 **Proto/codegen.** Edit `proto/session/v1/session.proto` then `make proto-gen`; `gen/` output is gitignored: commit only the `.proto`. Fresh worktrees need `make build` before Go compiles (memory: proto gen + CI gotchas). New RPCs also require registration in `server/server.go` and `make registry-generate` committed (`docs/registry/features/*.json`, `// +api:` / `// +feature:` markers); CI fails on stale registry (memory: PR #905).
- C2 **ConnectRPC `/api` prefix** for direct Connect calls (`docs/reference/backlog-dependencies.md`): any raw `fetch` path in tests/e2e must use `/api/<package.Service>/<Method>`; use the existing generated client in the web app, not hand-rolled fetch. Message size: ConnectRPC default read limits may reject large WriteFile bodies; check handler options.
- C3 **Complexity gates**: golangci `gocognit`/`gocyclo`/`funlen` run new-code-only (`--new-from-rev=origin/main`), and (memory) apply to MODIFIED existing functions too. `GetFileContent` is already ~140 lines; do NOT bolt the symlink/encoding logic into it. Extract helpers (`resolveInWorktree`, `detectTextEncoding`, `atomicWrite`, `searchWorktree`) into a new file with small functions. Same for the 700-line `file_service.go`: put write and search in new files (`file_write.go`, `content_search.go`).
- C4 **Duplication gates**: Go `dupl` new-code-only (do not copy-paste the validate/stat boilerplate from `GetFileContent`/`ListFiles`: three handlers repeat the same session_id/path/workspace preamble, extract once). web-app `jscpd` is an absolute ratchet at 0.14% (memory: margin ~0.10% after PR #815): new heavily-mocked test files add irreducible `jest.mock(...)` baseline. Keep new jest files few, share fixtures/test helpers, run `pnpm run lint:duplicates` before pushing. Do not fork `FileContentViewer` into an editor copy: extend it (component forks are exactly what jscpd flags).
- C5 **pnpm only** in `web-app/` (npm breaks CI silently). Adding `@replit/codemirror-vim` / diff libs: `pnpm add`, commit `pnpm-lock.yaml`; check bundle impact; use dynamic `import()` for vim and diff/merge view.
- C6 **E2E conventions** (CI-checked; `e2e-test-conventions` skill): first line `// @feature session:create, ...` header (use the correct feature ids; new RPCs need registry entries first); NO `waitForTimeout` (use `expect(...).toHaveValue/toBeVisible`, `waitForSelector`); locators by `data-testid` or ARIA role only (no CSS classes: vanilla-extract hashed class names would break them anyway); page helpers under `tests/e2e/pages/`. Mobile: Playwright mobile viewport projects (WebKit emulation); soft-keyboard behavior cannot be asserted in emulation: assert layout via `visualViewport` stubs and keep the real-device check as an owner-run blocker. The e2e server is auto-isolated (`global-setup.ts`); do not start a server manually, and do not use `make install-service` to try the UI (kills live tmux sessions: use the isolated manual instance on ports 62871/62872 with `STAPLER_SQUAD_TMUX_SOCKET`).
- C7 **Feature flag**: must be live-settable via the feature-flag RPC/panel with global + per-scope override, NOT an env var (memory: rollout flags). Both server (reject WriteFile when off) and client (hide editor) must read it; gating only the UI leaves the RPC open to a direct call.
- C8 **Instance field reads** via `Snapshot()`/`Workspace()` (`.claude/rules/instance-lock-free-reads.md`): use `Workspace().WorktreeDir`/`ActiveDir` for write targets, not `ExistingDir` (V5) and not the raw `i.Path`.
- C9 **Go style**: `slog` structured logs; `gosec` flags `os.Open` with variable path (G304) so each needs a justified `#nosec` after the new helper; go-git-over-subshells convention if any git-status refresh follows a save.
- C10 **Generated code not committed**: ent/proto outputs stay out of commits; stage specific files only (no `git add -A`; shared-repo hygiene).
- C11 **Concurrency with agents**: the same worktree is concurrently written by agent sessions (memory: parallel workers in one worktree sweep each other). A file-watch/refresh is NOT in requirements; do not add silent auto-reload of dirty buffers. On external change to an open, CLEAN buffer: offer reload; on DIRTY buffer: banner only.
- C12 **Comments/PR proportionality** (memory): short "why" comments; incident narrative in commit message.

## 5. Explicit "design against" list (carry into plan)

1. Never save from a truncated read; server enforces it (W1).
2. One shared confinement helper with `EvalSymlinks` + leaf-`Lstat` + `O_NOFOLLOW`, used by read, write, and search; fix the existing read-side symlink hole (V3, W2).
3. Write only to the live worktree dir, never the `ExistingDir` repo-root fallback (V5).
4. Atomic same-dir temp+fsync+rename, mode preserved (W4, W5).
5. Content-hash optimistic concurrency token, checked server-side at write time; conflict returns current content for the diff UI (W6).
6. Byte-identical round-trip test over CRLF, mixed EOL, BOM, no trailing newline, latin-1 (read-only), exec bit (W7-W9).
7. Deny `.git` and hooks writes; binary/NUL/invalid-UTF-8 targets are not editable (W10, W11).
8. Server-side flag enforcement + audit log without contents (W12, C7).
9. Search: RE2 only, no shell, hard caps on matches/bytes/files, prune dirs at SkipDir, ctx-honoring scan loops, UTF-16 column offsets, cancel on supersession (S1-S8).
10. Mobile: visualViewport-driven sizing reusing existing plumbing, >=16px editor font, one scroller, composition-safe imperative `EditorView`, vim off by default on touch with Esc button, read-only/degraded mode above ~1 MB or for very long lines, one mounted view with per-tab `EditorState` (M1-M7).
11. Repo gates: new files not grown functions (gocognit/funlen), extract shared RPC preamble (dupl), reuse components (jscpd 0.14%), pnpm, registry regenerate, e2e header/testid/no-sleep rules (C1-C6).
