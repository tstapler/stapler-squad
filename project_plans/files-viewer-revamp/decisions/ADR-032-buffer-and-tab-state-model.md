# ADR-032: Buffer and tab state model

**Status**: Proposed (2026-10-16)
**Plan**: `implementation/plan.md` Stories 0.1.4, 1.2.2, 2.2.2; amended by ADR-036 (Stories 1.6.5, 2.2.5)

## Context
`FilesTab` holds a single `selectedPath` plus in-memory `recentPaths`. Phones have tight memory (CodeMirror docs, syntax trees and string copies multiply) and IME composition breaks if the view is re-created.

## Decision
- State: pure `bufferReducer` + `useOpenBuffers` hook owned by `FilesTab` (no global store/context). `selectedPath` becomes derived from `buffers[activeIndex]`.
- **Session binding**: every `Buffer` arm carries the `sessionId` captured when it was opened, and stat, save and draft writes use `buffer.sessionId`, never the live prop (pre-mortem #2: `FilesTab` is reused across sessions and was rendered without a `key`). `FilesTab` is keyed by `session.id` in `SessionDetailView`. On unmount, dirty buffers are written synchronously to an in-memory `SessionBufferHold` (tab lifetime, <= 1 MB each, <= 5 entries) and, under the cap, to `draftStore`, and offered by the restore prompt when the user returns to that session.
- One mounted `EditorView`; one `EditorState` per buffer, swapped with `view.setState()` (scroll via `scrollSnapshot`). Mode/vim/merge/wrap are Compartments; the view is never re-created and the doc is never replaced from props; no dispatch while `view.composing`.
- `Buffer` is a discriminated union `Loading | Failed | Loaded{..., dirty, mergeBase, mode}` where `mode: Read | Edit` is **per buffer** (not per session or global; not persisted across reload; `Edit` is representable only when the read-only reason is `None`, so the Edit control for a non-editable file is a disabled view with the reason, not a mode); the reducer holds a `dirty` boolean, not the draft text (the text lives in the `EditorState`; `draftStore` reads it on a debounce, avoiding a 1 MB string copy per keystroke through React).
- Tabs: preview (replaced by next single-open) and pinned. A buffer is pinned when it **enters Edit mode** (triad round 3: not on the first keystroke, so a clean buffer in Edit cannot be the preview that the next single-click or the cap replaces); a dirty buffer is therefore always pinned, and it is never replaced by a single-open of another file. Back/forward is a `NavEntry` jumplist independent of tab order. Cap 10 buffers on mobile (`pointer: coarse` or < 768px) and 30 on desktop; one rule (reconciled in triad round 2; the earlier "least-recently-used clean buffer" and "all dirty -> toast" wording let a pinned tab be closed): only a **clean preview** buffer is ever evicted automatically (least recently used), with a polite `aria-live` announcement and an Undo toast of at least 8 s; pinned and dirty buffers are never evicted, and when none is eligible the open is **refused** with "Too many tabs open - close one" and the tab list opens (explicit "Unpin and close the oldest pinned tab" is a user choice in that list, never automatic). Pin/Unpin is available on touch from the tab sheet row's actions menu.
- Persistence: localStorage keyed by (session, device); paths, active index, `ViewState` only; wrapped in try/catch. Server-side persistence deferred (no cross-device requirement).
- **Drafts (owner decision 2026-10-17: localStorage and IndexedDB persistence ALLOWED, no veto; owner may veto; the sizes below are snapshot sizes: ADR-036 redefines the draft as a ChangeSet whose size is edit volume, see the amendment at the end of this section)**: dirty buffers store a bounded draft (<= 256 KB, 24 h TTL, flushed immediately on `visibilitychange`/`pagehide`; **a second IndexedDB tier (triad round 3) holds dirty buffers from 256 KB up to the 1 MB edit cap**, max 5 entries, 24 h, same key and Restore prompt, written asynchronously on a 2 s debounce and started on `visibilitychange`/`pagehide` (best effort), because iOS discards a backgrounded PWA and the in-memory hold alone loses everything then. Why IndexedDB and not a larger localStorage cap: localStorage is synchronous (a 1 MB string write blocks typing), shares a ~5 MB UTF-16 quota with the tab-layout keys (two 1 MB buffers can exhaust it) and a failed write is silent; IndexedDB is asynchronous with a far larger quota. Both tiers sit behind one `DraftBackend` interface; the owner's veto covers both (same plaintext-at-rest exposure); when neither tier can hold a dirty buffer the **priority-1 "Draft not stored" banner** (ux.md 8.2) replaces the old "Not backed up" chip as the standing warning, with Save emphasised and Copy my version) keyed by (session, path, baseToken) and are offered via an explicit "Restore draft" prompt (default focus **Not now**). Switching sessions never opens a blocking dialog: the parent switches without a veto point, so dirty buffers go to the in-memory hold plus a dismissible toast (triad round 2; ux.md 11.1 was corrected to match this ADR). No base text is persisted. If the draft token equals the current disk token, the draft opens with `MergeBase = Available(disk text now)` (disk equals the original base), so Merge remains possible later. If the file changed, the draft opens with `MergeBase = Unavailable` and the conflict dialog is two-way only (Keep editing, Reload, Overwrite, Copy my version; Merge disabled with a reason). This trades a secrets-in-localStorage risk for not losing edits when a session pauses (worktree deletion) or the tab dies; architecture research advised paths-only, UX research advised drafts, and this ADR chooses bounded drafts.
- **ADR-036 amendment (2026-10-16)**: (a) `Buffer.Loaded` gains `source: Full | Windowed{windowStartLine, lineCount?, analysis}`; persisted tab state stores `(path, anchorLine)` for `Windowed` buffers and never chunk text; a dirty region of a windowed buffer is pinned like a dirty buffer (it is never evicted from the chunk cache). (b) **Drafts become the composed pending ChangeSet** (`ChangeSet.toJSON`) plus selection, keyed `(session, path, baseToken)`; the 256 KB localStorage cap and the 256 KB to 1 MB IndexedDB tier now bound **edit volume, measured as serialized edits**, not file size, so a 900 KB file with a few edits fits the small tier and a 50 MB file with a few edits is backed up at all. Tier selection is by serialized size, keys, 24 h TTL, 5-entry limit, the Restore prompt (default Not now) and the priority-1 "Draft not stored" banner are unchanged. A text snapshot is stored only when the engine cannot produce a ChangeSet. Restore with an equal token loads the base and calls `ChangeSet.fromJSON`; a base-length mismatch fails closed with "Draft doesn't match the file" and offers "Copy my edits as patch"; with a changed token the 2-way flow applies and, for T1, the same-position rebase (ADR-034 amendment). Undo history is not persisted. (c) The reducer still holds `dirty: boolean`; pending edits live in the engine (`takePending`), not in React state. Plan: Task 2.2.5d.


## Consequences
Spike 0.1.4 must confirm state swap keeps scroll, selection and undo; if it does not, fall back to one view per recent tab (cap 3) and revisit.

## Alternatives rejected
Global store/context (single owner suffices); one `EditorView` per tab (memory, composition); server-side tab state (extra RPC, not requested).
