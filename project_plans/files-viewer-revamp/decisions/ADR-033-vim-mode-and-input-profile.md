# ADR-033: Vim mode and input profile

**Status**: Proposed (2026-10-16)
**Plan**: `implementation/plan.md` Stories 2.4.1, 2.4.2

## Context
The viewer ships a partial hand-rolled vim keymap (`gg`, `/`, `n`, `N`; `H`/`L` have wrong semantics). `@replit/codemirror-vim` 6.4.0 is the only serious CM6 vim; it takes `Prec.high` over keys including Esc. Soft keyboards lack Esc/Ctrl and Android soft keys often report `keyCode 229` (composition), so vim sees nothing. The owner decided: vim on only when a hardware keyboard is detected. Triad round 2 found the first detector ("first non-229, non-modifier physical keydown") false-positives on soft keyboards, whose Enter, Backspace, Space and Tab keydowns have ordinary key codes, and that Ctrl+Shift+M (the first vim escape) is Chrome's profile menu and Firefox's Responsive Design Mode.

## Decision
- `InputProfile = HardwareKeyboard | Touch`. Resolution precedence (triad repair, ux.md section 8.8): (1) persisted per-device manual override (Auto / Touch / Hardware) always wins, including over Bluetooth detection; (2) auto-detect, conservative and trusted-events-only (`isTrusted`; the key bar's synthetic events never count): `HardwareKeyboard` when **S1** the primary pointer is fine and hover-capable (`(pointer: fine) and (hover: hover)`, not `any-pointer` alone), **or S2** a keydown with Ctrl/Meta held with a non-modifier key, **or S3** a keydown of Escape, F1-F12, Insert, Home/End/PageUp/PageDown or an arrow with a non-empty `code`, or three letter keydowns with `code` = `Key<L>`, `key` = that letter, `keyCode !== 229` and `isComposing === false`; **S4** (focus tap on a coarse device where `visualViewport.height` did not shrink by >= 100 px within 500 ms) counts only together with one S3 letter keydown. Enter, Backspace, Space, Tab, digits and punctuation never count alone. A flip is session-only and not persisted so a disconnected keyboard cannot leave the device stuck; (3) otherwise `Touch` (the default). The rule is encoded as a pure function over recorded event fixtures captured on the owner's phone in the Story 0.1.5 spike (soft keyboard typing, Gboard/iOS special keys, Bluetooth keyboard, IME composition), and the unit tests assert zero flips for every soft-keyboard fixture.
- Vim is lazy (`import()` into a Compartment), default on only for `HardwareKeyboard`, off for `Touch`; the default is **evaluated only at Edit entry** and vim never flips on or off live while a buffer is in Edit mode (a mid-edit profile change hides or shows the key bar and offers an explicit "turn vim on?" chip, nothing more); a persisted explicit vim toggle always wins and vim is never auto-enabled on a touch-resolved device (owner decision). Mobile vim, once explicitly opted in, is best-effort with a mandatory on-screen Esc (`ExtraKeyBar`, first key; the vim key row appears only when vim is on). The mode indicator is `role="status"` with `aria-live="off"` so ordinary mode changes are not announced; only an explicit vim toggle and focusing the segment announce the mode.
- `:w`/`:q` map to the single `useSaveBuffer.save()` path via `Vim.defineEx`; Ctrl-o/Ctrl-i step the `NavEntry` jumplist. The hand-rolled keymap is deleted.
- Dedicated escape that vim cannot consume (triad round 2): **Esc, Esc** (two Escape keydowns within 500 ms while the vim mode is already Normal with no pending operator, count or register; from Insert, Visual or the command line the first Esc returns to Normal as usual) and the status-bar "Leave editor" control, which is the primary documented exit, move focus out of the editor in every vim mode. No modifier chord is used: Ctrl+Shift+M is the Chrome profile menu / Firefox Responsive Design Mode, Ctrl+W cannot be cancelled by pages, and Alt+Left/Right are browser history (chord policy: ux.md 14.1, jest denylist test, per-browser Playwright spec and owner manual check). The handler is a capture-phase keydown listener on the editor DOM registered after the vim extension and re-registered whenever the vim Compartment is reconfigured, covered by tests that run `:nmap <Esc> x` and `:imap <Esc> x` and assert the escape still works. **Triad round 3 refinements** (ux.md 8.4 is the single Esc table): the double Esc is *armed*, not blind: it leaves only if vim was already Normal with nothing pending at the first Esc, the first Esc made the status bar show the chip "Esc again to leave the editor" (1.5 s, polite), the second Esc comes within 500 ms while the chip shows, and the per-device setting "Esc, Esc leaves the editor" (default on) is on; leaving is non-destructive and one Esc (or Enter/Space) on the focused Leave editor control returns focus to the editor with cursor and Normal mode intact. A second keyboard route that vim cannot consume is the ex command `:leave` (`Vim.defineEx`, registered after the user's rc). **Correction**: the earlier text said the control is reachable "by Tab order from the editor"; with vim on Tab is a vim key in Normal mode, so it is not; the true routes are Esc, Esc, `:leave`, pointer/touch and screen-reader navigation, and they are advertised in the overlay and a one-time status when vim is first turned on (WCAG 2.1.2 permits a non-standard exit only when the user is told). Accepted cost, reduced: a habitual double-Esc user can still leave once or twice by accident (it needs the chip and a Normal-mode start) and recovers with one Esc; users who find it intrusive switch the setting off.
- Non-vim: no unconditional `indentWithTab`; Esc then Tab leaves the editor (WCAG 2.1.2). Never bind plain Backspace/Enter/Space.
- **ADR-036 note (2026-10-16)**: Vim is an `EditorEngine` capability (`features.vim`). `@replit/codemirror-vim` stays inside `CmEngine`; an engine without Vim keys (the contingent custom engine) shows "Vim keys unavailable for this engine", the armed Esc, Esc handler is not installed, and the decisions above are otherwise unchanged (plan Story 2.4.1 AC).


## Consequences
Vim fidelity bugs upstream (issues #243, #244) are accepted. iOS PWA behavior is an owner wall-clock check, not claimed from emulation.

## Alternatives rejected
Always-on vim; keep hand-rolled keymap (false-friend bugs); Monaco + `monaco-vim` (no mobile support, bundle).
