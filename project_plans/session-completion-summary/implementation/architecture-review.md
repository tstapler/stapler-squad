## Previously-flagged items — re-verification

1. [PASS] **BLOCKER — `sessionSummaryListener.generator` concrete-pointer DIP violation.** `session/session_summary_listener.go` (Task 1.1.2a, plan.md:186-188) now defines a narrow consumer-side `summaryGenerator` interface (`GenerateAndPersist(ctx, sessionUUID, sessionTitle string, createdAt time.Time, diffStats *git.DiffStats, reason string)`) and `sessionSummaryListener.generator` is typed as that interface, not `*SessionSummaryGenerator` (plan.md:187: "note: `generator` is the **interface** type above, not a concrete `*SessionSummaryGenerator` pointer — this is what makes Task 1.1.2b's fake test double constructible without a real ent client"). Task 1.1.2b (plan.md:192) now constructs `fakeSummaryGenerator` implementing the interface directly, writing to a channel — "this requires no ent client, no `headless.Pool`, and no other `SessionSummaryGenerator` dependency." `WireSessionSummaryListener` (plan.md:188) also takes the interface type. Domain Glossary entries for `summaryGenerator` (plan.md:56-57) and `SessionSummaryGenerator` (plan.md:57) confirm `*SessionSummaryGenerator` satisfies it structurally. Fully fixed, no new problem introduced.

2. [PASS] **CONCERN — flat-bag illegal-states risk (stale markdown/error_message).** The plan now explicitly states the error-path write preserves prior fields. Pattern Decisions table row "Error-path field preservation" (plan.md:84): "the upsert is field-scoped to `status`/`error_stage`/`error_message`/`generation_started_at`... it never clears a prior successful generation's `markdown`/`narrative`/decisions fields." Story 1.5.2's AC-5 (plan.md:300) and Task 1.5.2b step 3 (plan.md:310) both restate this explicitly ("leave `markdown`/`narrative`/decisions fields from any prior successful generation untouched (field-scoped upsert...)"). Task 1.5.2d (plan.md:318) adds a test asserting diff/timeline fields persist on the decisions-stage error row. The decision is documented, not left as an implementation accident.

3. [PASS] **CONCERN — `reconcileStaleness` vs. in-memory dedup guard disagreement.** Task 1.5.3a (plan.md:331) adds a non-blocking `isInFlight(sessionUUID) bool` probe. Task 1.5.3b (plan.md:335) now has `reconcileStaleness` call `g.isInFlight(row.SessionID)` first and return the row unchanged (skip the ERROR flip) if the guard is currently held, with the dead-end scenario from the original concern spelled out explicitly in the task text. Task 2.2.2b (plan.md:397) adds a corresponding test: "staleness reconciliation flips an old GENERATING row to ERROR on read **only when the in-memory guard is not held** (add a case with the guard held via a fake `isInFlight` returning `true` — the row stays unchanged)."

4. [PASS] **CONCERN — Story 1.5.2 "exactly one status-transitioning write" wording vs. actual 2-write design.** Story 1.5.2's header (plan.md:297) now reads "assemble the full document in memory before the **final** status-transitioning write" and an explicit wording note is appended (plan.md:298): "this is 'exactly one *final* write,' not 'exactly one write total' — the design correctly performs an earlier `GENERATING` upsert too, per Task 1.5.2b step 2; Story 1.5.3's restart-survival staleness check depends on that interim write's `generation_started_at` having been persisted." This directly matches the remediation the old review asked for.

5. [PASS] **CONCERN — `GetSessionSummary` undocumented write-on-read (CQS violation).** Task 2.2.1a (plan.md:382) now includes an explicit "Doc comment (CQS note)" instruction with the exact doc-comment text to add to the handler: "GetSessionSummary is a read RPC that may perform a side-effecting write: on a stale GENERATING row (see reconcileStaleness), it upserts the row to ERROR before returning it, as a lazy restart-recovery mechanism (deliberately chosen over a background sweep — see plan.md's Pattern Decisions table)."

6. [PASS] **CONCERN — `RegenerateSessionSummary` live/no-live branching untested + undocumented `SessionSummaryService → SessionService` dependency.** Task 2.2.2b's test list (plan.md:397) now explicitly enumerates both branches: "**Regenerate with a live instance still present** — diff snapshot is refreshed the same way the listener does; **Regenerate with no live instance** (`SessionService.FindLiveInstance` returns not-found) — falls back to the previously-persisted diff/timeline/cost fields as input, including the case where those fields came from a prior *error* row." The dependency is now documented in two places: the Domain Glossary's `SessionSummaryService (RPC)` entry (plan.md:64: "**Dependency**: `RegenerateSessionSummary` additionally depends on `SessionService.FindLiveInstance`...") and the Dependency Visualization diagram (plan.md:142-144: "└── depends on SessionService.FindLiveInstance (live-instance-gone fallback branch, Task 2.2.2a)").

## New Concerns
None. The repair pass added new mechanics (sequential-duplicate short-circuit and Regenerate cooldown, Task 1.5.2b steps 1b/1c; panic recovery, Task 1.5.2b) beyond the minimum needed to close the 6 flagged items, but these are internally consistent with the rest of the plan (covered by Task 1.5.2d's test list, AC-8's sub-cases in Story 1.5.3, and the Dependency Visualization) and don't introduce a contradiction or an untested branch.

One residual gap worth flagging as a concern-adjacent observation rather than a new CONCERN: Task 1.5.2b's step 6 (final-write failure → `error_stage: "persist"`) is not explicitly called out as field-scoped the way step 3 is, even though the Pattern Decisions "Error-path field preservation" row (plan.md:84) states the preservation applies to both step 3 and step 6 ("the decisions-build failure (step 3) or the best-effort persist-failure fallback (step 6)"). Task 1.5.2d's test list (plan.md:318) only asserts field-preservation for the decisions-stage error case, not the persist-stage case. This is a minor test-coverage gap on a path the plan's own design already commits to, not a design defect — kept as a nitpick, not elevated to a new CONCERN since it doesn't reopen any of the 6 previously-flagged items.
