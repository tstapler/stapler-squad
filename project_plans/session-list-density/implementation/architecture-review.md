## Concerns

- [ ] **Task 1.1.1b (Epic 1.1)** — the `truncateMiddle` fallback (imported from `./truncateMiddle` for the "no opaque segment found, still exceeds maxLen" case) special-cases the input's *last* `.` as a file-extension boundary (confirmed by reading `truncateMiddle.ts`: `dotIdx = name.lastIndexOf(".")`, then treats everything after it as a preserved "suffix"). Applied to a full path string rather than a filename, a dotted directory segment (e.g. `.stapler-squad`) or any incidental `.` elsewhere in the path could produce a truncation that misidentifies trailing path content as a "file extension" to preserve, giving a confusing result. Recommendation: add a unit test in Task 1.1.1c covering a fallback path containing an interior dot-segment, or write a path-specific fallback (fixed head/tail ratio split, no extension-detection branch) rather than reusing `truncateMiddle` verbatim.
- [ ] **Dependency Visualization diagram (top of plan.md)** — lists "Epic 3.1 ... needs 2.1" only, but Story 3.1.1's own acceptance criteria also verify `SessionCard`'s three `title` attributes, which is Story 2.2.1's (Epic 2.2's) output, not Epic 2.1's. The diagram is missing the 2.2 dependency edge, which could let Epic 3.1 be executed/verified before Epic 2.2 lands, silently skipping that AC. Recommendation: change the diagram line to "needs 2.1, 2.2."
- [ ] **Task 3.2.1a/3.2.1b (ADR-001, Epic 3.2)** — wraps existing `role="img"` spans (agent icon, memory badge) in a focusable (`tabIndex={0}`) `Tooltip` trigger without revisiting the `role="img"` semantics. A non-interactive ARIA role receiving keyboard focus is an unusual combination that some screen readers announce ambiguously (a focusable "graphic" with no indication that more info is available on focus). Recommendation: during Task 3.2.1d's manual check, verify at least one screen reader announces the combination sensibly, or consider whether `role="img"` should change once the element becomes an interactive tooltip trigger.
- [ ] **Task 1.1.2a (Epic 1.1)** — its hedge language ("use a local placeholder constant `72` here if Story 2.1.1 hasn't landed yet in execution order, then let 2.1.1 supersede it") implies Phase 1 and Phase 2 might not execute in the Dependency Visualization diagram's stated order, creating a throwaway edit. Not a design defect, but worth tightening task sequencing so this conditional branch is unnecessary.
