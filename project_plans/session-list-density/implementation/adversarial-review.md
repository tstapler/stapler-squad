## Concerns

- [ ] **`truncateWorkspacePath`'s fallback silently mishandles paths containing an embedded dot.** Per Task 1.1.1b, when segment-collapsing still leaves the string over `maxLen`, the function falls back to `truncateMiddle(rejoined, maxLen)`. `truncateMiddle` (`web-app/src/lib/utils/truncateMiddle.ts`) is a filename-truncation helper: it finds `name.lastIndexOf(".")` and treats everything from that dot onward as an inviolable "extension" to preserve verbatim. Real paths in this exact repo routinely contain a non-trailing literal dot (e.g. `.stapler-squad`, per requirements.md's own path examples) — if the fallback triggers on such a path, `truncateMiddle` computes a huge "suffix," `keep` goes negative, and it silently degrades to plain right-truncation instead of true middle truncation (no crash, but it defeats the "preserve leading and trailing meaningful segments" goal for exactly the class of paths this feature targets). None of Story 1.1.1's Given/When/Then fixtures exercise a fallback case with an embedded dot — the one no-opaque-segment fixture (`"a-very-long-but-entirely-human-readable-branch-name-with-no-hash"`) has no dot at all. — Add a fixture with an embedded dot that forces the fallback, and reconsider whether raw `truncateMiddle` (built for filenames) is the right fallback for arbitrary paths.

- [ ] **Board-view virtualizer height estimate is left untuned.** `research/pitfalls.md` §1 explicitly names *both* `SessionList.tsx:643-648`'s row virtualizer and `BoardColumn.tsx:48-53`'s card virtualizer as needing `estimateSize` recomputed once the new wrapped baseline height is known. Epic 2.1.3 tunes only `SessionList.tsx`'s row estimate (50→64); no story touches `BoardColumn.tsx`'s `ESTIMATED_CARD_HEIGHT = 220`, even though Epic 2.2 changes `SessionCard`/`BoardCard`'s path rendering and narrow-layout behavior, which can change card height. Board-view users get exactly the first-paint layout jump this epic exists to prevent for List view. — Add a task tuning `ESTIMATED_CARD_HEIGHT` alongside Story 2.1.3, or fold it into Epic 2.2 with the same "measure, then tune" pattern.

- [ ] **Scope drift: Story 1.1.2 retires `WorkspaceSwitcher.tsx`'s `abbreviatePath`, a component outside requirements.md's In-Scope list and outside the sessions sidebar entirely.** requirements.md's In-Scope section names only `SessionRow.tsx`/`SessionRow.css.ts`/`session-columns.ts`/`SessionCard.tsx`/`BoardCard.tsx`; `WorkspaceSwitcher.tsx` (a workspace picker in `components/layout/`) isn't part of the session row/card surface at all. The plan's stated justification — "the jscpd duplication gate doesn't flag near-identical logic" — doesn't actually apply to this file: the jscpd risk `research/pitfalls.md` §4 identifies is about the *new* truncation/column logic being copy-pasted between `SessionRow.tsx` and `SessionCard.tsx`, not about a pre-existing, independently-named function in an unrelated component. This is opportunistic tech-debt cleanup riding along on a Complexity-2 diff whose own Appetite section explicitly warns against extending scope ("cut Board view to a fast-follow rather than extending the appetite"). — Drop the `WorkspaceSwitcher.tsx` portion of Story 1.1.2 (leave its existing `abbreviatePath` alone), or get explicit sign-off to broaden scope.

- [ ] **Task 2.1.2c's "render both budgets, toggle via CSS `display: none`" approach doubles per-row `Tooltip`/ARIA markup.** Rendering a normal-budget `<span>` and a narrow-budget `<span>` for the path, each independently wrapped in the existing `<Tooltip label={session.existingDir}>` with `role="img" aria-label="Path: …"`, means every visible row mounts two Tooltip instances and two identically-labeled `role="img"` elements (only one visible via CSS) instead of one. Beyond the modest DOM/Radix-mount cost across ~20 concurrently-rendered virtualized rows, any future row-scoped `getByRole('img', { name: /Path:/ })`-style locator (Testing Library/Playwright both throw on multiple matches) will break unless it's explicitly scoped past the hidden duplicate — a new failure mode Phase 4's e2e audit (which only checks for *existing* locator breakage) won't catch. — Note this constraint explicitly in Story 2.1.2/Epic 4.1 so future test authors know to scope past the hidden span, or reconsider a single-span + JS container-width check instead.

- [ ] **Several stories state testable acceptance criteria with no task that encodes them as an automated test — only a manual-verification task exists.** Confirmed via `grep` that `SessionRow.test.tsx` today has zero coverage of column visibility or `aria-label` composition:
  - Story 1.2.1's AC ("neither the agent-icon `<span>` nor the memory-badge `<span>` is present in the DOM" by default) has only Task 1.2.1b, a manual/grep verification, no automated regression test.
  - Story 3.2.1's AC extending the row-level `aria-label` with `agent: …`/`memory: … MB` has only Task 3.2.1d, a manual keyboard-tab check — no unit test asserts the extended `aria-label` string.
  Contrast with Story 1.1.1 (Tasks 1.1.1c/d) and Story 3.1.1 (Task 3.1.1b), which do add real tests for their ACs. — Add equivalent Jest assertions for Stories 1.2.1 and 3.2.1 so a later refactor can't silently regress either behavior.
