# Validation Plan: session-list-density

**Date**: 2026-09-24

## Happy Path Scenario

Given the baseline sidebar (fixed 38px single-line rows with ellipsis-truncated
names/paths and default-visible `agent`/`memory` columns showing "—" on most
rows), when the user views the sessions sidebar at its normal ~280px width,
then every session's category/slug is readable on line 1, the workspace path
wraps and shows with its opaque hash/UUID segments collapsed to `…` instead of
being cut off mid-string, and the reclaimed `agent`/`memory` column space is no
longer wasted on rows that have nothing to show there. *(All error paths,
narrow-width variants, and accessibility fixes below are variations on this
core scenario — a still-legible, denser row/card — not equal-priority
concerns.)*

## Test Stack

- **Unit**: Jest + React Testing Library (`@testing-library/react`), matching existing `*.test.tsx`/`*.test.ts` files under `web-app/src/`. Pure-function tests (`truncateWorkspacePath.test.ts`) use plain Jest `describe`/`it`/`expect`, no RTL needed.
  - **jsdom limitation, noted explicitly**: jsdom does not perform real CSS layout, so "wraps onto 2 lines," "exceeds 38px," and "no horizontal scrollbar" cannot be asserted as measured pixels in a Jest test — those rows in the mapping table above assert the *style declarations* (CSS class contents / absence of `nowrap`/`ellipsis`/`maxHeight`) as a proxy, and the real pixel-level claims are pushed to the Playwright suite (`tests/e2e/session-list-density.spec.ts`), which runs in a real browser via `global-setup.ts`'s isolated test-mode server.
- **Integration**: Same Jest/RTL runner — "integration" here means a test that exercises two or more of this feature's units together (e.g., `session-columns.ts`'s defaults + `SessionRow`'s render logic, or `truncateWorkspacePath` + `SessionRow`'s two divergent call sites) rather than a database or external service, since this feature has neither (per requirements.md's Constraints: presentation-layer only, no proto/backend changes).
- **E2E / UX**: Playwright, following `e2e-test-conventions`: every new spec file starts with a `// @feature` annotation header, locators are `data-testid`/ARIA-role only (no CSS class selectors), no `waitForTimeout` (use `expect(locator).toHaveValue(...)`/`waitForSelector`/auto-retrying assertions instead), and any new page helper goes under `tests/e2e/pages/`. New file: `tests/e2e/session-list-density.spec.ts` — no existing spec covers column-visibility, container-query narrow layout, or path-truncation UX, so this is a new file rather than an extension (confirmed by grep: no existing `tests/e2e/*.spec.ts` references `session-columns`, `ColumnPicker`, or `visibleColumns`). `tests/e2e/touch-targets.spec.ts` and `tests/e2e/accessibility.spec.ts` are extended in place, per the plan's own Task 3.3.1c/4.1.1b.
- **Static/Grep**: A handful of plan-mandated grep audits (Tasks 1.1.2c, 3.1.1a, 4.1.1a) are listed as their own "test" rows above because they're repeatable, pass/fail checks with a specific command — but they are not Jest tests and are not wired into `make ci`; run manually during Phase 4 review per the plan's own task list.
- **Manual**: Story 2.1.3's `estimateSize` tuning and Task 3.2.1d's touch-tap check are explicitly manual-only in the plan itself (`build-vs-buy.md`'s "config tweak, not architecture change" framing, and ADR-001's asserted-not-verified Radix tap behavior) — no automated test is invented for either; they're tracked here as manual checklist items so they aren't silently dropped from validation.
- **Migration**: N/A — presentation-layer only, no schema or persisted-data changes (per plan.md's Migration Plan section).
