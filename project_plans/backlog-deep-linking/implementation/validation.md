# Validation Plan: backlog-deep-linking

**Date**: 2026-08-19

## Happy Path Scenario
Given a backlog item created after this feature ships (baseline: today a user can only copy the ambiguous `/backlog?item=<uuid>` address-bar URL, per requirements.md), when the user clicks **Copy Link** in `BacklogItemDetail.tsx` and pastes the resulting `ssq://<host>/backlog/v1/<public_id>` link into a new browser tab on the same host, then the backlog detail panel opens directly on that item with focus on its heading — no interstitial, no manual UUID copy-paste. *(This anchors all test design below; cross-host handoff, error states, and legacy-UUID compatibility are variations on this core round-trip: generate a link → resolve a link → land on the right item.)*

## Test Stack
- **Unit**: Go `testing` package + table-driven tests (repo convention); TypeScript/Jest + React Testing Library for `web-app/` component tests.
- **Integration**: Go `testing` with an in-memory/sqlite-backed ent client for storage-layer tests; `httptest.Server` for resolver/advertisement-endpoint tests; a fake clock (no wall-clock `time.Sleep`) for TTL/liveness-timeout tests, per this repo's flaky-test rule (`.claude/rules/fix-flaky-tests-dont-defer.md`) and the existing precedent (`TestWriteSettingsAtomic_ConcurrentWritesToSameSettingsPath_NeverProduceCorruptJSON`).
- **E2E / UX**: Playwright against the isolated `tests/e2e/global-setup.ts`-managed instance (`data-testid`/ARIA locators only, no `waitForTimeout`, `// @feature` header per spec file — see `.claude/rules/e2e-test-conventions.md`); manual checklist items for macOS/Linux OS-integration surfaces that cannot run in CI (real desktop environment or code-signed bundle required).

## Coverage Targets and How to Measure

| Stack | Coverage command | Target |
|---|---|---|
| Go | `go test ./... -coverprofile=coverage.out && go tool cover -func=coverage.out` | ≥80% line, with 100% of `session/backlog_item_id.go`, `session/deeplink/url.go`, and the dual-ID dispatcher in `session/storage_backlog.go` (small, high-consequence surfaces per `requirements.md`'s backward-compatibility constraint) |
| TypeScript/Jest | `npx jest --coverage --coverageThreshold='{"global":{"lines":80}}'` (run from `web-app/`) | ≥80% line, including `DeepLinkErrorBanner` and the updated `handleCopy` paths in `BacklogItemDetail.tsx` |

- All public service methods (`session/backlog_item_id.go`, `session/deeplink/url.go`, `session/host_identity.go`, `session/host_registry.go`, `server/services/deep_link_resolver.go`): happy path + error paths covered per the mapping table above.
- All external integrations (ent/DB via `session/storage_backlog.go`, the new advertisement HTTP transport, the `--open-url` OS shell-out): unit mocked (dispatcher logic, translation logic) + at least one integration test (real sqlite-backed ent client, `httptest.Server` exchange, or documented manual OS-level check where automation genuinely isn't possible).
- UX acceptance criteria: all 37 criteria in `design/ux.md` map to a test or manual step above — Surfaces 1-8 (interactive) get Playwright coverage except pure contrast/screen-reader checks (manual, per this repo's existing Axe/Lighthouse CI gate on `web-app/src/` PRs); Surfaces 9-12 (condensed/backend) get Go-level or manual coverage since they are CLI/OS/log-facing, not browser-facing.
