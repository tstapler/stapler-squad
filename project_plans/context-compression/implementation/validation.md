# Validation Plan: context-compression

**Date**: 2026-08-21

## Happy Path Scenario

Given a session whose transcript has degraded and the user wants a fresh start, when the user clicks "Restart with summary" on the session's Info tab, waits for `HandoffSummaryGenerator.GenerateAndPersist` to produce a `READY` row, and clicks "Start new session from this summary," then a new `DIRECTORY` session is created in the same working directory, seeded with the REFERENCE-ONLY-prefixed summary as its opening `prompt`, and its Info tab shows "Restarted from: <source session>".

## Test Stack — Ent Schema Migration Approach (Step 5)

**Approach chosen: schema-creation smoke test, not a reversibility test. N/A for "down" migration coverage.**

**Justification**: This repo's ent testing convention (`session/ent/enttest/enttest.go`, generated code) only exposes `Open`/`NewClient`, both of which call `migrate.Create` — ent's forward-only auto-migration. Searching the existing test suite for any convention of testing a migration's reverse/down path found none: the two files with "migration" in their name (`session/workflow_enabled_field_migration_test.go`, `session/backlog_stuck_migration_test.go`) both test **data backfill/correction logic** that runs after a forward migration (e.g. correcting a column's backfilled default based on a sibling column's legacy value), not schema reversibility — there is no `down.go`, no `migrate.Diff`-based rollback helper, and no test anywhere that asserts a table can be dropped/reverted and the prior schema state restored. Since ent auto-migration in this repo is additive-only by construction (new tables/columns, never destructive drops — confirmed by `session/ent_repository_backlog_test.go:311`'s comment "additive/optional-field" migration pattern), inventing a `migration_should_be_reversible` test would test a code path that doesn't exist in this codebase and never has for any of its 25 other ent schemas.

Instead, the equivalent, actually-idiomatic test for `HandoffSummary`'s new schema is a smoke test confirming the schema creates cleanly and round-trips a row — the same shape as every other schema's first test in this repo (see `session/session_summary_service_test.go:46`'s `createTestEntRepository(t)` pattern, reused directly by `TestHandoffSummarySchema_should_DefaultStatusToPending_When_CreatedWithoutExplicitStatus` and `TestHandoffSummarySchema_should_SurviveSessionDeletion_When_NoEdgeExists` above). These two tests jointly cover: (a) `migrate.Create` succeeds against the new `handoff_summaries` table with no error (the smoke-test half), and (b) the specific invariant Story 1.1.1's AC calls out — no cascading delete/FK error when the source `Session` row is removed, since `HandoffSummary` deliberately has no `Edges()`.
