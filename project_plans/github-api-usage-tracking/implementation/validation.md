# Validation Plan: github-api-usage-tracking

**Date**: 2026-08-11

## Happy Path Scenario
Given stapler-squad has been running with GitHub API instrumentation active — the `usageTransport` counting every native request, `runGHCommand` counting every `gh` CLI invocation, and the `GitHubUsageRecorder` persisting both to `analytics.db` — when Tyler opens the GitHub API Usage panel (`/analytics/github-api`) after noticing a rate-limit WARN in his logs, then the panel renders per-resource quota tiles, a volume-over-time table, and a source-breakdown table, all derived from those persisted `AnalyticsEvent` rows, letting him identify which call site is consuming quota with zero fabricated or blended cross-resource numbers.

## Migration Test
**N/A — no schema change.** Per `plan.md`'s Migration Plan section (confirmed by direct read): ADR-027 reuses the existing `AnalyticsEvent` table with a new *value* (`github_api`) in the existing `event_category` column. No `session/ent/schema/*.go` file is added or edited, `--feature sql/upsert` codegen is not run, and there is no `session/ent/**` generated diff in this PR. Reversibility is by construction (reverting the PR stops the writes; existing rows age out through the normal retention path) rather than by a migration-down script, so no migration-reversibility test is designed for this feature.

## Test Stack
- **Unit**: Go stdlib `testing`, table-driven where the plan specifies it; `-race` required for every concurrency-sensitive test (`usageTransport`, `GitHubUsageRecorder.Stop()`, `QuotaSnapshot` publication, `SetUsageRecorder` swap). TypeScript unit/hook tests use Jest + React Testing Library, matching `useApprovalAnalytics.test.ts`'s existing pattern.
- **Integration**: Go tests backed by a real in-memory ent client (`OpenAnalyticsDB` against `t.TempDir()`, per Story 2.1.1c's precedent) rather than mocks, so `AnalyticsEvent` row mapping is asserted against the actual schema. `httptest.Server` for transport-level integration tests (`usageTransport`, `rate_limit_probe`).
- **E2E / UX**: Playwright, per `.claude/rules/e2e-test-conventions.md` — feature annotation header, no `waitForTimeout`, `data-testid`/ARIA-role locators, reusable navigation in `tests/e2e/pages/`. Accessibility criteria not mechanically assertable by Playwright (contrast across themes, live screen-reader announcement behavior) are manual checklist items, per plan Story 5.2.2 and design/ux.md §5.
