# Validation Plan: quota-aware-backlog-gating

**Date**: 2026-08-10

## Happy Path Scenario
Given the Baseline state (`BacklogController.IsEnabled() == true`, no quota signal wired, `Quota.Enabled == true` on a live-verification instance), when a session hits a rate limit (or `computeHeadroom`'s soft signal crosses `PauseBelowHeadroomPct` for `ConsecutiveTicksToPause` ticks), then `QuotaGate.Reconcile` calls `BacklogController.Disable()` within one reconcile-ticker interval, a "Backlog Automation Paused" notification is published naming the observed value and threshold, and once headroom recovers past `PauseBelowHeadroomPct + ResumeMarginPct` for `ConsecutiveTicksToResume` ticks, `Reconcile` calls `Enable()` and a "Backlog Automation Resumed" notification fires. *(One sentence — the anchor for all test design below.)*

## Test Stack
- **Unit**: Go `testing` + `github.com/stretchr/testify` (`assert`/`require`) — repo convention, confirmed in `server/services/capacity_monitor_test.go` and `server/services/feature_flags_test.go`. Frontend: Jest + React Testing Library (`web-app/src/app/settings/features/page.test.tsx`, new file — no existing test for this page today).
- **Integration**: Same Go `testing`/testify stack, but exercising real collaborators instead of fakes where the plan calls for it — the real `*events.EventBus` (Story 3.1.3), the real boot sequence in `server/dependencies_test.go` (Stories 2.2.2/2.2.3/2.3.2), and a real `config.json` round-trip through `LoadConfig`/`SaveConfig` (Task 1.1.1c). Test doubles (fakes, not mocks) are used only for `InstancePoller`, `FeatureController`, and `tokens.TokenStoreReader` in the pure `Reconcile`-logic unit tests, per Story 2.1.1's "narrow, consumer-defined interfaces" design.
- **E2E / UX**: No new Playwright spec — `design/ux.md`'s own summary states this feature adds zero new screens and reuses `NotificationToast.tsx`/`NotificationPanel`/the existing Settings toggle unmodified, so a manual checklist (12 rows above, matching `design/ux.md`'s 12 UX acceptance criteria) is used instead of a new `tests/e2e/*.spec.ts` file, per the task's guidance that the UX surface here is small enough for a manual checklist. Criteria #5, #6, and #9 are exceptions — they resolve to Go/Jest assertions already in the Requirement → Test Mapping table above, since they're message-content/render-conditional checks, not flow checks.
