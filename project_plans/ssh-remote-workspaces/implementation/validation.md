# Validation Plan: ssh-remote-workspaces

**Date**: 2026-08-06

## Happy Path Scenario
Given a fresh `config.json` with no remotes configured (Baseline), when the user registers a remote (`prod-box`) in Settings, trusts its host key, and creates a `new_worktree` session against it from the Omnibar, then the worktree and tmux session are created on `prod-box` over SSH, terminal output streams into the local xterm.js view via the existing delta protocol, and the session card shows a "prod-box" host badge with a "Connected" status. *(Anchors all test design below — error paths and edge cases are variations on this flow.)*

## Test Stack
- **Unit**: Go `testing` package + `testify` (confirmed existing convention — `session/tmux/server_registry_test.go`, `session/tmux/directory_restoration_test.go`, `session/tmux/exec_gate_test.go` already use it); Jest + React Testing Library for TS/React (`web-app/jest.config.js`).
- **Integration**: Go `testing` against a real in-process sshd via `github.com/gliderlabs/ssh` (already present as `v0.3.8` in `go.sum`, confirmed by `grep gliderlabs/ssh go.sum`) — used for all `SSHRunner`, `RemoteWorktreeOps`, `RemoteApprovalRelay`, `RemoteHealthProber`, and remote-target `CreateSession` handler tests, per `research/stack.md`.
- **E2E / UX**: Playwright (`tests/e2e/`), per `.claude/rules/e2e-test-conventions.md` — `// @feature` annotation header, no `waitForTimeout`, `data-testid`/ARIA-role locators only, new page helpers under `tests/e2e/pages/` (`RemotesSettingsPage.ts` per plan Task 6.3.1d).

## Coverage Targets and How to Measure

| Stack | Coverage command | Target |
|---|---|---|
| Go | `go test ./... -coverprofile=coverage.out && go tool cover -func=coverage.out` | ≥80% line |
| TypeScript/Jest | `npx jest --coverage --coverageThreshold='{"global":{"lines":80}}'` | ≥80% line |

- All public service methods (`CommandRunner`, `SSHRunner`, `RemoteWorktreeOps`, `KeyStore`, `KnownHostsStore`, `RemoteApprovalRelay`, `RemoteHealthProber`, `RemoteService` RPC handlers): happy path + error paths covered.
- All external integrations (SSH dial/exec/PTY, keychain via `zalando/go-keyring`, `direct-streamlocal` channel): unit mocked (where feasible, e.g. `LocalRunner` parity) + at least one integration test against a real `gliderlabs/ssh` test server.
- Every UX acceptance criterion in `design/ux.md` has a corresponding Playwright test above; none deferred to "manual only."
- Registry gate: `make registry-generate` run after Phase 6 lands, with `docs/registry/coverage-gaps.json` diffed against its pre-feature state — net-new untested-feature count must not increase, per `.claude/rules/feature-registry.md` and plan Task 6.3.1g.
