## Test Stack

- **Unit**: Go stdlib `testing` + `github.com/stretchr/testify` (`assert`/`require` — confirmed via `go.mod` and universal usage across `session/tmux`, `session/streamhub`, `session/backend_factory_test.go`). Deterministic injection over real sleeps/subprocesses/network for anything timing- or process-dependent (mirrors `tmux.go`'s `ensureServerRunningWithRetry` injection seam — `EnsureDaemonRunning`'s retry/backoff and spawn functions must be package-level vars or function parameters, not hardcoded, specifically so tests can simulate without `time.Sleep` or a real `tymuxd` binary; the internal `context.WithTimeout(15s)` in `TymuxBackend.Start()`/`RestoreWithWorkDir()`, Task 2.1.3a/ADR-004, is exercised via an injected deadline/clock the same way, never a real 15s wait). `-race` required for the `singleflight`-backed concurrent cold-start test (2.1.2g/h, ADR-004) and the existing concurrency-guard style already used in `session/streamhub`'s own race-focused tests (`TestStreamOwnershipLock_should_NeverProduceTwoOwners_When_HubAndLegacyIntentsRaceConcurrently`).
- **Integration**: direct invocation (not a Go test binary) for shell scripts (`fetch-tymuxd.sh`, Makefile targets) and build-tag compile checks (`go build -tags embed_tymux`, ent codegen) — this repo has no bats/shell-test framework, so these run as CI job steps or `make` target assertions, verified via exit code + filesystem state, not `go test` output. RPC-surface integration (`server/server_test.go`) uses whatever Connect-Go test-client pattern `server/server_test.go` already establishes for other services.
- **API/E2E**: out of scope. This plan explicitly carries no UI/UX work (requirements.md's Out-of-Scope), and Phase 3's RPC surface is reachable via `grpcurl`/future UI, not `tests/e2e/`'s Playwright suite — no `web-app/src/` changes are in this plan's scope, so the E2E/Axe/Lighthouse CI gates don't apply here.

## Notes on the Three Adversarial-Review-Flagged Gaps

All three are represented as explicit test cases above, not folded silently into existing rows.
The first two were originally pinned-as-fact placeholders pending an implementation-time design
decision; ADR-004 made that decision, so the tests below assert the *fix's* mechanics, not just
the pre-fix cost:

1. **Synchronous cold-start latency on the `CreateSession` RPC path — resolved by ADR-004.**
   `EnsureDaemonRunning` moved out of `NewProcessManager` (which is on the synchronous RPC path)
   and into `TymuxBackend.Start()`/`RestoreWithWorkDir()` (which only ever run inside the
   existing async goroutine). `TestCreateSession_should_ReturnQuickly_When_BackendIsTymuxAndDaemonIsCold`
   proves the RPC response is no longer blocked; `TestTymuxBackendStart_should_BlockForUpToRetryBudget_When_DaemonColdStarts`
   proves the ~9-11s worst-case cost still exists but is now paid inside the async path (Story
   2.1.3 rows).
2. **No real deadline/cancellation on `EnsureDaemonRunning`'s `ctx` — resolved by ADR-004.**
   `TymuxBackend.Start()`/`RestoreWithWorkDir()` each construct an internal
   `context.WithTimeout(15*time.Second)` rather than relying on a caller-supplied context (which
   the `ProcessManager`/`TymuxManager` interfaces don't carry for these methods in the first
   place). `TestTymuxBackendStart_should_SurfaceTimeoutError_When_DaemonNeverBecomesHealthyWithin15s`
   (Story 2.1.3 row) proves a wedged daemon fails at the bound instead of hanging indefinitely.
3. **Concurrent cold-start race on `EnsureDaemonRunning` — resolved by ADR-004.**
   `TestEnsureDaemonRunning_should_CoalesceViaSingleflight_When_ConcurrentCallersRaceOnColdStart`
   (Story 2.1.2g/h row), run with `-race`. A genuinely new test not present in plan.md's original
   Task 2.1.2f list, now backed by an actual `singleflight.Group` guarantee (exactly one spawn
   attempt, both callers get the same result) rather than the earlier "at most twice, self-heals"
   framing.
