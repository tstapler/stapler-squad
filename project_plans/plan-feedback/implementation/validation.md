# Validation Plan: plan-feedback

**Date**: 2026-09-14

## Happy Path Scenario

Given a `BacklogItem` at status `review` with a recorded plan and an active
work session, when the operator opens the `SendBackFeedbackBox` toggle on
`BacklogItemDetail.tsx`, types feedback describing what should change, and
clicks Submit, then the item transitions to `ready`, its live work session is
stopped, `PlanRejectionReason` is set to the typed feedback, a new
`TriggerTriage` run starts carrying that feedback, and the item detail view
(without navigating away) shows a success toast plus `PlanVerdictBox`'s
"Revisions requested" card echoing the operator's own words back to them.

## Test Stack

- **Unit (Go)**: `testify` assertions run via `gotestsum` (this repo's `make test`/`test-race` wrapper), table-driven where the plan specifies it (`TestTransitionBacklogItemStatus_should_StopLiveWorkSession_When_SentBackToReady`). `backlog_service_lifecycle_test.go`/`backlog_service_triage_test.go` use the existing `createTestStorage`/`mockSessionStopper` test doubles — these read as integration-level (real storage-layer double, no live tmux) rather than pure-function unit tests, consistent with how the rest of that file is already classified.
- **Integration (Go)**: same files as above — `TransitionBacklogItemStatus` tests exercise the real ent-backed (or in-memory) storage layer end to end for a single RPC handler, per `docs/explanation/test-io-storage-isolation.md`'s in-memory-DB isolation strategy.
- **Unit (Frontend)**: Jest + React Testing Library, `cd web-app && npx jest --no-coverage`. `SendBackFeedbackBox.test.tsx` mocks only `onSubmit`; `BacklogItemDetail.sendBackFeedback.test.tsx` mocks the `useBacklogService` RPC functions (`transitionStatus`/`rejectPlan`/`triggerTriage`/`load`), mirroring how `handleRejectPlan`-adjacent behavior is already tested elsewhere in this file family.
- **E2E / UX**: Playwright + Allure, `tests/e2e/`, isolated per-run server via `global-setup.ts` (dynamically assigned port, `--test-dir`-scoped state — never the live `:8543` instance). Page object: `tests/e2e/pages/BacklogItemDetailPage.ts` (locators + `submitSendBackFeedback()` helper, plan.md Task 3.1.1a). RPC-failure scenarios (UX criteria 4-6) use `page.route()` to intercept the specific ConnectRPC call under test rather than standing up a fault-injecting backend.
