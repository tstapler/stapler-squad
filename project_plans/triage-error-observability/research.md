# Research: triage-error-observability

## Code Archaeology

### classifyHeadlessCallError and call sites

**File:** `server/services/backlog_service_triage.go:2689`

The function classifies a headless call error into one of:
`pool_saturated`, `idle`, `fanout_ceiling`, `cost_ceiling`, `timeout`, `shutdown`,
`claude_not_found`, `subprocess_start_error`, `other`.

Call sites:
1. `TriggerTriage` goroutine (line 543): logs bucket + full error, stores bucket in DB via
   `UpdateItemSessionEndedWithReason`.
2. `TriggerReReview` (line 3117): same pattern — logs full error, stores bucket only.

**The gap:** The DB stores only `"other"` (the bucket name). The full `callErr.Error()` string is
logged on the same line but is only ephemeral. After a service restart (and log rotation), it is gone.

### ItemSession ent schema

**File:** `session/ent/schema/item_session.go`

Existing fields relevant to error tracking:
- `end_reason` (string, optional, default ""): stores the bucket name from
  `classifyHeadlessCallError`. Already surfaced in the proto (`backlog.proto:100`).
- `failure_capture_path` (string, optional): stores path to a file containing raw subprocess
  stdout. For `other`-bucket errors that aren't subprocess-output failures, this may be absent or
  empty.

**No `error_detail` field exists** to store the underlying Go error text.

### Proto: ItemSession message

**File:** `proto/session/v1/backlog.proto:76`

The `ItemSession` proto already exposes `end_reason` (field 18) to the UI. Adding `error_detail`
as field 19+ follows the same pattern.

### Parking notification: retryOrphanedTriageWithBackoffGate

**File:** `session/backlog_lifecycle_triage.go:391`

When `RemediationDue` returns `justParked=true`, the function calls `l.notify(...)` per item.
One notification per item, no batching or aggregation window. There is no logic to detect that
multiple items are parking simultaneously.

### Pool concurrency limit and maxQueueWait

**File:** `session/headless/pool.go:102,112`

```go
const defaultMaxConcurrent = 5
var maxQueueWait = 2 * time.Minute
```

A bulk import of 16 items triggers 16 concurrent `TriggerTriage` calls, each trying to acquire one
of 5 pool slots. Items beyond the first 5 wait up to 2 minutes for a slot. If a slot isn't available
within 2 minutes, they fail with `ErrPoolSaturated` → classified as `pool_saturated`, NOT `other`.

So `pool_saturated` would NOT produce `errType=other`. The fact that the 16 items all got `other`
means something happened AFTER pool slot acquisition — either the subprocess failed immediately,
a storage error occurred, or another unclassified error type.

Without the actual error text (lost in log rotation), the root cause cannot be determined from the
existing evidence. This is precisely the gap this item exists to close.

### Stuck context string origin

The context `"triage session headless-triage-<uuid> ended (other) without moving the item out of
idea"` is generated by `reconcileOrphanedTriageItems` in `session/backlog_lifecycle_triage.go` when
it observes a triage ItemSession with `end_reason="other"`. The bucket name is pulled from the
stored `end_reason` DB field, confirming that fixing the persistence gap will make this message
carry the actual error text.

### UpdateItemSessionEndedWithReason

**File:** `session/storage_backlog.go:505`

```go
func (r *EntRepository) UpdateItemSessionEndedWithReason(ctx context.Context, id string,
    endedAt time.Time, reason string) error
```

The signature only accepts the bucket name. Extending to accept an optional `errorDetail string`
(or adding a new method `UpdateItemSessionEndedWithDetail`) is the persistence fix.

### Ent schema migration

Per `CLAUDE.md`, ent schema changes require:
```bash
go run -mod=mod entgo.io/ent/cmd/ent generate --feature sql/upsert ./session/ent/schema
```
Generated files are `.gitignore`d — only the schema change (`session/ent/schema/item_session.go`)
is committed.

## Risk Assessment

| Risk | Severity | Notes |
|---|---|---|
| Ent schema migration | Low | Adding a nullable column with a default; backward-compatible |
| Proto field addition | Low | New optional field; existing clients ignore unknown fields |
| maxQueueWait vs. pool_saturated | Low | 16 items with `other` cannot be pool saturation; confirms the unknown root cause |
| Batch notification aggregation complexity | Medium | Window-based counting across goroutines; atomic counter in BacklogLifecycleListener is simplest |
