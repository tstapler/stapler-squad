# Pre-mortem: session-notes
**Date**: 2026-08-06

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | The feature ships as a web-only affordance, but this repo's own primary "session juggler" is an agent operating through `mcp__stapler-squad__update_session`/`get_session` (per CLAUDE.md's own Agent-tool-first workflow and the backlog automation surface) — the note is invisible and unwritable from that path, so the stated JTBD ("juggling many simultaneous agent sessions... leave yourself a reminder") goes largely unserved. | A user asks their coordinating agent "did I leave myself a note on that session?" and the agent has no tool that surfaces `note`; usage telemetry (if any existed) would show near-zero note creation despite the feature shipping, or notes get created by hand in the UI but never read back by the automation that actually manages sessions. | Add `note` to the MCP `get_session`/`update_session` tool schemas (`server/mcp/tools_lifecycle.go`) as an explicit Story 2.4/Epic, or, at minimum, add an Unresolved Question entry in plan.md stating this is a deliberate v1 cut with a named follow-up — the adversarial review already flagged this gap (see adversarial-review.md's "Requirements' own motivating scenario... isn't served") but the plan was not updated to either close it or explicitly accept it. | P1 |
| 2 | Go's `len()` (Task 1.3.4's cap check) counts UTF-8 bytes while the `<textarea maxLength={10000}>` (Task 2.1.2) counts UTF-16 code units; a user typing CJK text, accented characters, or emoji into a note well under the visible 10,000-character UI limit gets bounced with `InvalidArgument` on Save. | User types a note in a non-ASCII language, clicks Save, gets an unexpected validation error with no prior warning the note was "too long" — directly contradicts the plan's own Risk Control promise that save failure must preserve the user's text and explain why. | Switch the backend check to `utf8.RuneCountInString(*req.Msg.Note)` (still not identical to UTF-16 code units, but far closer to what the user perceives as "characters" than byte length), or size the frontend limit down conservatively and document the unit explicitly. Already flagged as an open Concern in adversarial-review.md; plan.md's Story 1.3 Task 4 was not updated to resolve it. | P2 |
| 3 | The 10,000-char cap is defined three times (ent `.MaxLen(10000)`, Go `session.MaxNoteLength`, frontend `maxLength={10000}`) with only a code comment holding them in sync, and the architecture review's proposed test (round-tripping exactly `MaxNoteLength` and `MaxNoteLength+1` chars through the ent layer directly) is not in plan.md's task list. A future edit to one constant without the others causes `UpdateSession` to accept a note the ent `Create`/`Update` call then rejects. | A note update that passed the handler's own length check fails with an opaque `connect.CodeInternal` (from the persistence layer) instead of the clean `connect.CodeInvalidArgument` Story 1.3's acceptance criterion promises — surfaces as a confusing 500-class error in the UI, and the regression is invisible until someone changes one of the three literals in isolation. | Move the constant into a leaf package both `session/ent/schema` and `session` can import (adversarial review confirmed no actual import-cycle blocks this — `session/ent/schema` imports only `entgo.io/ent/*`) rather than relying on a comment; add the architecture review's ent-layer boundary test (`MaxNoteLength` accepted, `MaxNoteLength+1` rejected by the ent layer itself, not just the handler). | P3 |
| 4 | The `SessionCard` note badge (Story 2.2) is icon-only (`📝`, `role="img"`, `aria-label`) with no visible text label and no `title` fallback, relying solely on a hover/focus-triggered Radix `Tooltip` for the excerpt — on touch devices (no hover state) there is no way to see the note preview at all, and it visually breaks the row's established icon+label convention (`autonomousBadge`, `workflowBadge`). | On a phone or tablet, a user sees the 📝 badge on a session card but tapping/holding it does nothing — no way to preview the note without opening the full session detail view, silently failing the requirements doc's explicit mobile-UX instinct ("touch targets, responsive layout") for the one new touch-facing element this feature adds. | Match the existing badge shape (icon + short visible label, e.g. "📝 Note") and either add a `title` attribute as a native fallback or verify Radix `Tooltip` supports tap-to-open on touch (and test it) before shipping — already flagged as an open Concern in adversarial-review.md; plan.md's Story 2.2 was not revised to address it. | P2 |
| 5 | Story 3.2's e2e test explicitly cannot exercise a real server restart (the Playwright harness spins up one isolated server per run) and substitutes `page.reload()` as a "reasonable proxy," while AC4 ("persist across server restarts") is otherwise covered only by a Go-level unit test against a test SQLite instance. If the test's ent setup (in-memory or throwaway file DB, auto-migration path) diverges even slightly from the production SQLite file's migration/runtime behavior, a genuine restart-persistence bug could ship with fully green CI. | After a real `systemctl --user restart stapler-squad` (or `make install-service`) in production, previously-saved notes are gone even though every automated check passed — discovered by a user reopening a session they'd annotated, not by any test. | Add one manual/scripted smoke check to validation.md: build the binary, set a note via the running dev instance, actually restart the service (or kill/relaunch the process against the same `~/.stapler-squad` state dir), and confirm the note survives — closing the gap between "proxy tested" and "actually restart tested" before this ships. | P3 |
