# Stack Research — backlog-triage-pipeline

**Date**: 2026-05-18  
**Scope**: Technology choices, library versions, and compatibility for the triage pipeline additions.

---

## Backend (Go)

### Go Module
- **Module path**: `github.com/tstapler/stapler-squad`
- **Ent ORM**: `entgo.io/ent` — already used for `BacklogItem`, `ItemSession`, `ReviewVerdict` schema; schema changes require `go run -mod=mod entgo.io/ent/cmd/ent generate --feature sql/upsert ./session/ent/schema` (the `--feature sql/upsert` flag is mandatory per CLAUDE.md)
- **ConnectRPC**: `connectrpc.com/connect` — all RPCs follow `*connect.Request[Msg]` / `*connect.Response[Msg]` pattern; used in `CreateBacklogItem`, `TriggerTriage`, etc.

### Protobuf
- **Proto files**: `proto/session/v1/backlog.proto` (messages + service), `proto/session/v1/types.proto` (enums including `NotificationType`, `NotificationPriority`)
- **Code generation**: `make generate-proto` regenerates `session/gen/proto/go/session/v1/*.go` and `web-app/src/gen/session/v1/*_pb.ts`
- **`NotificationType` enum** (in `types.proto`): already includes `NOTIFICATION_TYPE_INPUT_REQUIRED = 2`, `NOTIFICATION_TYPE_TASK_COMPLETE`, `NOTIFICATION_PRIORITY_NORMAL` — directly usable for R6 and R7 without new enum values

### Event Bus
- **Package**: `github.com/tstapler/stapler-squad/pkg/events` (forwarded via `server/events/forward.go`)
- **Key function**: `events.NewNotificationEvent(sessionID, sessionName, notificationID, notificationType int32, priority int32, title, message string, metadata map[string]string) *Event`
- **Publish call**: `h.eventBus.Publish(event)` — the existing `approval_handler.go` pattern is the reference implementation for publishing `INPUT_REQUIRED` notifications
- **Dependency injection**: `backlogHandlers` struct currently only holds `storage` and `store`; to publish from MCP `submit_triage_result`, an `eventBus *events.EventBus` field must be added and threaded from `mcp/server.go` → `dependencies.go`

### Existing Storage Method
- `session.Storage.UpdateItemSessionTriageResult(ctx, id, jsonPayload string) error` — already implemented in `session/storage_backlog.go`; `triage_result` string field already exists on the `ItemSession` ent schema

## Frontend (React + TypeScript)

### Framework
- **React 18** with `"use client"` directive (Next.js App Router pattern)
- **CSS**: vanilla-extract `.css.ts` for all new components per ADR-009 (`.claude/rules/css-architecture.md`)
- **State management**: `useState` + `useCallback` + `useMemo` — no Redux or Zustand; follows hook-per-service pattern

### RPC Client
- **ConnectRPC Web**: `@connectrpc/connect-web` + `createClient` — client constructed in `useEffect` and stored in `clientRef.current`
- **Generated types**: `web-app/src/gen/session/v1/backlog_pb.ts` (regenerated by `make generate-proto`)

### Notification System
- **`NotificationType.INPUT_REQUIRED = 2`** already handled in `useSessionNotifications.ts` and `notificationMapping.ts`; maps to `"question"` icon type — usable for R6 triage-complete notifications
- **`useReviewQueueNotifications.ts`**: subscribes to `INPUT_REQUIRED` for tier-1 alerts

### localStorage
- Standard `window.localStorage` API — no third-party library; used for per-item dismissed state for R4 triage panel (pattern: `triage-panel-dismissed-<item_id>`)

## Compatibility Notes

- `clarifying_questions` in `TriageResult` proto message: must be `repeated string` (simplest type); no need for a complex message type since R7 only requires forwarding to the existing approval flow
- The `triage_result` JSON field on `ItemSession` is already stored untyped; adding `clarifying_questions []string` to the `triageSuggestion` JSON payload stored there is backward-compatible (JSON omitempty for old records)
- Proto field numbering: next available field on `ItemSession` message is 12; next available on `BacklogItem` is 20; new `TriageResult` message is standalone — no existing field collisions
- `CreateBacklogItemRequest` next available field: 9 (for `skip_triage bool`)
- `CreateBacklogItemResponse` next available field: 2 (for `triage_triggered bool`)
