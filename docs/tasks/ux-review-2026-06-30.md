# UX Review Findings — 2026-06-30

## Critical

### [C1] Resume/Pause invisible on mobile
**File:** `web-app/src/components/sessions/SessionRow.css.ts:141`
**Principle:** Nielsen #1 Visibility of System Status; WCAG 2.5.5 Target Size
**Fix:** Add `(hover: none)` media query override to `primaryActionWrapper` to set `opacity: 1`
- [ ] Edit `primaryActionWrapper` in `SessionRow.css.ts` — add `"@media": { "(hover: none)": { opacity: 1 } }`

---

### [C2] Touch targets too small
**File:** `web-app/src/components/sessions/SessionRow.css.ts:162`
**Principle:** WCAG 2.5.5 Target Size (44x44px minimum); iOS HIG touch target guidance
**Fix:** Add `(pointer: coarse)` media query override to `inlineActionButton` with larger padding
- [ ] Edit `inlineActionButton` in `SessionRow.css.ts` — add `"@media": { "(pointer: coarse)": { padding: "12px 16px" } }` (or equivalent to reach 44px effective height)

---

### [C3] Window selector buttons missing `aria-pressed`
**File:** `web-app/src/components/analytics/ApprovalAnalyticsPanel.tsx:134`
**Principle:** WCAG 4.1.2 Name, Role, Value; ARIA toggle button pattern
**Fix:** Add `aria-pressed` to each toggle button and `role="group"` with `aria-label` on the wrapper
- [ ] Add `aria-pressed={windowDays === opt.value}` to each time-window toggle button
- [ ] Add `role="group"` and `aria-label="Time window"` to the button group wrapper element

---

### [C4] Bar charts entirely inaccessible
**File:** `web-app/src/components/analytics/ApprovalAnalyticsPanel.tsx:57–80`
**Principle:** WCAG 1.1.1 Non-text Content; adjacent table cells carry numeric data
**Fix:** Mark decorative chart elements with `aria-hidden="true"` since data is already present in adjacent cells
- [ ] Add `aria-hidden="true"` to `Bar` and `StackedBar` components at lines 57–80

---

## High

### [H5] `window.confirm()` for mode switching
**File:** `web-app/src/components/rules/RuleBuilderForm.tsx:176`
**Principle:** Nielsen #4 Consistency and Standards; WCAG 4.1.3 Status Messages; native browser dialogs are inaccessible to screen readers in many contexts
**Fix:** Replace `window.confirm()` with an inline confirmation state rendered within the component
- [ ] Add a local boolean state (e.g. `confirmingModeSwitch`) to `RuleBuilderForm`
- [ ] Render an inline confirmation prompt (e.g. "Switching modes will discard unsaved changes. Continue?") instead of calling `window.confirm()`
- [ ] Wire "Confirm" and "Cancel" buttons to the state

---

### [H6] Six session type options creates choice paralysis
**File:** `web-app/src/components/sessions/OmnibarCreationPanel.tsx:26`
**Principle:** Hick's Law; Nielsen #6 Recognition Rather Than Recall
**Fix:** Reduce visible options to 3 primary types with an "Advanced" disclosure for remaining options
- [ ] Identify the 3 most-used session types from usage data or product judgment
- [ ] Move remaining types behind an "Advanced" toggle/disclosure in `OmnibarCreationPanel.tsx`
- [ ] Ensure the expanded state persists within the session (not cross-session) to avoid disrupting power users

---

### [H7] Error state lacks `role="alert"`
**File:** `web-app/src/components/analytics/ApprovalAnalyticsPanel.tsx:149`
**Principle:** WCAG 4.1.3 Status Messages; screen readers never announce the error banner without live region
**Fix:** Add `role="alert"` to the error banner element
- [ ] Add `role="alert"` to the error banner at line 149 in `ApprovalAnalyticsPanel.tsx`

---

## Medium

### [M8] Bulk rule save auto-dismisses after 1.5s
**File:** `web-app/src/components/analytics/ApprovalAnalyticsPanel.tsx:417`
**Principle:** Nielsen #1 Visibility of System Status; users with cognitive disabilities or slow reading speed may miss auto-dismissed feedback
**Fix:** Replace `setTimeout(onDone, 1500)` with an explicit "Done" button
- [ ] Remove the `setTimeout(onDone, 1500)` call at line 417 in `ApprovalAnalyticsPanel.tsx`
- [ ] Render a "Done" button in the success state that calls `onDone` on click
